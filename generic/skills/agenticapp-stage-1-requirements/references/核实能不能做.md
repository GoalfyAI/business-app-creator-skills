# 核实能不能做与能力试用

和开发者沟通的同时，对 PRD 里的每一步做下面五件事。这是你内部的工作：结论用业务话写进 PRD「能不能做」，资产 ID 和试调细节只写进阶段文档 G2。这一段只查不建（例外见 SKILL.md 第 3 步）。

## 1. 逐项查

按步骤找平台上现成的东西：`list_assets(asset_type=…, keyword=…)` → `get_asset(asset_type=…, asset_ids=[…])`。关键词只匹配名称和 ID，用英文短词多试几次。

| 要做的步骤 | `asset_type` | 看什么 |
|---|---|---|
| 脚本要调的外部能力（拉数、发送、查询） | `tool_group` | 工具名、参数、是否要授权卡 |
| 模型步骤 | `fast_agent` | 输入字段、输出形状、模型配置 |
| 整条路线像已有应用 | `scenario_package` | 路线与编排型 TPE |
| 要存的表 | `dataset` | 已有表，列注释里的 `[editable:user\|agent\|system]` |
| 页面 | 读应用工程的 `frontend/registry.json` | 脚手架预置件清单 |

- 别人分享来的工具组搜不到或看不到参数：按 `agenticapp-tool-integration`「分享来的工具组」处理。仍没取到真实返回的，G2 写「能用，没取到样」，PRD 那一行写「已有现成工具，还没真试过，制作时第一次用真实数据试的时候核实；分享人收回或改动后这一步会停」。
- 新 SDK 应用（`frontend/goalfy-app.json` 有 `"executor": "launch_agent"`）的数据只能来自应用自己的数据模板和官方、公开数据集，开发者个人的普通数据集不能当数据来源（`agenticapp-tool-workflow`「编排脚本的额外约定」）。

## 2. 真调一次

名字对上不算。

- 安全只读的工具用 `otpe_tool_test` 取样，看返回是不是 PRD 要的那个对象；哪些工具不能取样、文件参数怎么传，见 `agenticapp-tool-integration`「工具取样」。取样报参数错、路径不存在时，先按同一节核对文件参数收 URL 还是 `/workspace` 路径，再取一次。
- 要外部数据的，用开发者的账号或他给的样例真拿一次。拿回来的真实数据放进 PRD 当样例，客户姓名、电话、证件号这类个人信息打码后再放。
- 取样要花钱时按入口「花费」先问。

## 3. 模型步骤拿不准时试一次

关键模型步骤（报告、方案、诊断这类直接交给使用者的内容）效果或用时拿不准，或拿不准用哪一档，按下面「能力试用」用开发者的一两条真实样例跑，记下输出、用时和花费。试跑先在题里说清份数和约多少积分，同意后再跑；单价还没查到时，等查到再出这道题。

## 4. 判定能不能做

| 情况 | 写进 PRD「能不能做」 | G2 记下 |
|---|---|---|
| 工具返回覆盖需要 | 能做，用平台现成的；要授权的确认已有授权卡，没有的记进 G2「要他提供的」，② 写进运行条件 | 复用 |
| 发信、发布这类不能取样的工具，参数说明覆盖需要（发给谁、发什么） | 能做，用平台现成的，没真发过；④ 只发给开发者自己试一次。发到应用自己的消息中心不算向外发送 | 复用，未取样 |
| 已有 FA 的输出能覆盖「拿出来」 | 能做，用平台现成的 | 直接复用；差一两个字段时复制后改提示词 |
| 官方或他人的场景包像这条路线 | 能做，用平台现成的 | 复制后改；自己的草稿接着改 |
| 已有模板缺列 | 能做 | 加列出新版本（`agenticapp-tool-data-template`），不另建同义表 |
| 平台上没有，外部有现成 MCP 或 Skill 包 | 能做，要接入 | 确认现有工具换更好的指引或组合也做不到，才按 `agenticapp-tool-integration` 接入 |
| 确定性的计算、存取 | 能做，要新做（脚本） | 新做 |
| 要模型、平台上没有 | 能做，要新做（模型）；试过的写「已试过」 | 新做 |
| 都不行、授权接不上、时间或费用达不到 | **做不到**：写原因、影响哪个功能，当轮出替代选择题（换做法 / 改范围 / 等平台） | 要平台补的能力记一条开发需求；开发者选「等平台」时该功能本次不做，按入口「报错和平台问题」汇总 |

- 量级超出单次运行能力时，先看能不能分批、分片做（`agenticapp-ref-platform-limits`），能做就写「能做」并在「中间」写清一次最多多少条；分批也做不到才判「做不到」。
- 工具要使用者各自授权：按 `agenticapp-tool-integration`「授权卡」，记进 G2，② 写进方案「运行条件」。
- 资产受限或脱敏：按「分享来的工具组」处理，结论写进 PRD，开发者确认 PRD 时一并确认。

## 5. 算花费

付费工具按单价算；模型步骤按 [谁来做.md](谁来做.md)「模型选哪一档」定档，有试跑的用实测，没有的写估算（估法见入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)「积分」）。算出三个数：做这个应用（开发和测试，① 到 ⑤）预计多少；上线后每用一次约多少；按用量题的答案算每周约多少。查不到单价写「费用未知，用真实数据试一次后告诉你实际花了多少积分」，不编数字。

## 核实对照表（写进 G2）

| PRD 里的步骤 | 复用什么（资产 ID） | 取样结论（真调返回摘要、花费） | 缺什么 / 怎么处置 |
|---|---|---|---|

「缺什么」那一列就是 ② 编施工单、③ 要造的清单。

## 能力试用

真调一个外部能力、看模型步骤的效果，或用同一份样例比两档模型时按这里做。它是 ① 核实「能不能做」的一种做法，② 要看真实效果才能选的取舍也用它。

### 什么时候用

- ① 核实时要真调一个外部能力（MCP、API、模型、Skill 包），或关键模型步骤的效果、用时、档位拿不准。
- 开发者想先验证某个外部能力好不好用、值不值得做进应用；给了工具链接、包或供应商名，问「能不能用」「效果怎么样」。这时还没有应用：按入口「开工」第 1 步建 write 工单，不进五段；从 ① 进来的沿用原工单。

### 怎么做

1. **先查重**：`list_assets` / `get_asset`。平台上已有的直接取样，不重复接入。
2. **要接入的**按 `agenticapp-tool-integration` 预览、注册、配授权卡。
3. **费用先问**：会产生真实调用费用的取样，先在题里说清份数和约多少积分，开发者同意后再跑；说不出数先不问、不跑（入口「花费」）。
4. **取样**：安全只读的工具用 `otpe_tool_test` 真调，核对返回结构（哪些工具不能取样见 `agenticapp-tool-integration`「工具取样」）。
5. **要模型的，建一个极简试用包**：`clone_asset` 官方基础包得到草稿，加一个已上线的工具集和一份写明「是什么、何时用、注意什么」的 `apc_skill`（最小场景包的组成见 `agenticapp-tool-workflow`），用一两条真实样例跑。比档位时同一份样例两档各跑一次，记下两份输出和花费。
6. 记下输出、用时、每次花费；写进 G2 和 PRD「能不能做」（试过的标「已试过」）。

### 结论怎么交

单独试用时，结论写成三句话交开发者：能做什么（附样例结果、用时、每次花费）、不能做什么、建议做进应用还是放弃。

- 他决定做进应用：转新建（进 ① 写 PRD，试用结论直接写进「能不能做」）或修订（`agenticapp-task-revise`）。
- 从 ① 进来的，回到 ① 接着问。
- 试用包在工单里标明用途，正式制作不沿用它，除非开发者明确要求。
- 试用包不算 ① 的「建」，建它不违反「只查不建」。
