# 按反馈改

开发者看过验收报告后说哪条不对、一次提了几处、或还有条目没通过就要上线时读。

- **他说哪条不对**：开始改时发一条【③ 制作 → 正在做】的进度，受影响的格子改回「在做」；改完重新部署，重测这一条和受影响的条目（页面条目在演示版上重测），报告只更新变了的行。写「重测过」之前核对这次运行跑的确实是改过的版本，旧版本的结果不算。
- **一次提了几处**：照他的原话编号记进 G6，每处标「已改，已验证」「已改，未验证（原因）」或「没改（原因）」，交接消息逐条回，不笼统说「改好了」。改一处时，把用到同一份数据或同一个判断的其他页面和路线一起核对。
- **要改到 PRD 没写的业务条件**（多一道核对、加启用开关、额外限制）：这是要的东西变了，回 ① 确认，不在实现里自己加。
- **结果不对、要换做法**：回 ③；和方案预期差得多的，按 ③ 出选择题请他拍板。
- **还有条目没通过就要上线**：逐条出「接受，先上线 / 等改好再上线」选择题，写清上线后使用者会遇到什么；选了接受的记「没通过，开发者选了接受」。「未测」的不出这道题。
