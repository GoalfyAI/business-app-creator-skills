# ⑤ 上线

开发者说「可以上线」后，你把 ④ 验过、已部署成功的那一版上线：它成为开发者自己的正式版；要自己正式使用或给别人用，需要他在发布管理页发布，发不发布由他决定。然后结单，交一份上线结果：上线的是哪一版、④ 验过什么、没验证的、实际花了多少、发布要准备的描述、Logo 和更新说明、他可以做的事。这一段不请他发布，也不等发布；验证已在 ④ 做完。

这一段最常见的错是**上线了不该上线的那一份**：④ 没部署过、补测没过、④ 之后又改过代码，或者使用者打开是空的、缺配置。其次是上线结果里漏掉没验证的条目，开发者以为全都验过了。上线错一份的后果：它成为开发者的正式版，发布后他自己和已安装的使用者用的就是它。规矩以入口 `agenticapp-creator` 为准。

## 开始前确认

- ④ 交了棒。报告里有「未测」条目时同样进 ⑤，不追问；④ 没部署过的也进 ⑤，按第 1 步处理。
- 开发者这次明确同意上线（什么算同意按入口「开发者确认什么」），原话已记 checkpoint；上线要晚于这句话，补测后请他再说过一次的，晚于再说的那一次。
- 接续时：阶段文档 G6 里没有 ④ 的验收报告和「可以上线」原话的，算 ④ 没验收，先加载 `agenticapp-stage-4-acceptance` 验收。G6 里开发者确认过的结论照旧保留，不重测。
- `business_ui_manage(action="get")` 看 `role`：`owner` 照本段做；`editor` 在第 4 步改为提请属主上线；`viewer` 不进 ⑤。
- 属主接续时发现有协作者的待上线提请，按 `agenticapp-role-collab`「属主处理提请」先问他要不要上线；他说「可以上线」后照本段上线那份协作者草稿。

## 按这个顺序做

1. **认定上线哪一份**：④ 已部署成功的最新草稿。④ 之后改过场景包或应用的，加载 `agenticapp-tool-deploy` 按「部署」重新部署，改动影响到的条目按 `agenticapp-stage-4-acceptance` 的「按反馈改」重测。④ 因为开发者说先别放而没部署过的，按 [references/上线前自查.md](references/上线前自查.md)「没部署过时」做。挂在应用上的本人场景包草稿不单独上线，随应用一起上线。做成：`business_ui_manage(action="get")` 核对 `success` 的部署已写进这份草稿。
2. **上线前自查**：照 [references/上线前自查.md](references/上线前自查.md)「上线前自查」逐条核；要改的改完重新部署再往下。
3. **结单门**：按 `agenticapp-tool-deploy`「结单」核每条路线：最近一次到终态的运行通过（路线冒泡和 ④ 的 `workspace` 真跑都算）。最近一次失败或没法验证的，先问开发者接不接受，接受后写豁免。做成：每条路线有通过的 `run_id` 或 `project_id`，或有一条 `route_verification_waived` checkpoint。
4. **上线与反读**：
   - `owner`：加载 `agenticapp-tool-deploy`，按「上线」做：显式传要上线的 `draft_asset_id`，`resolve` 反读上线版本和场景包版本记进工单，核对上线版本绑定的部署是 ④ 验过的那一份。新 SDK 应用没有场景包，改为核对应用版本上挂的编排与 `tpe_ids`。`resolve` 取不到上线版本说明没上线成功，照实说。做成：`resolve` 取到上线版本且 `entry_url` 非空。
   - `editor`：不调 `finalize`、`resolve`，按 `agenticapp-role-collab`「提请属主上线」提请；后面第 5–11 步照做，上线结果的「上线的版本」写「已提请，等属主上线」。做成：`request_finalize` 成功。
5. **算总花费**：对工单里记下的每个冒泡、真跑项目重新读一次 `cost_credits`，汇总开发期累计，和 ① 的上限、② 的预计比。
6. **写上线结果**：照 [assets/上线结果.md](assets/上线结果.md) 写，`task_manager(action="insert", entry_type="result")` 写进工单，同时写进交付物。④ 有「未测」条目时单列。
7. **汇总平台问题**：本轮记下的已绕过的平台问题和功能诉求，此时汇总成一条提交（入口「报错和平台问题」），没有就不提。
8. **写阶段记录 G7**：`business_ui_stage` 写 G7，`next_stage` 填 `closeout`；阶段标记和方案页同一步按「记下来」改好。
9. **保存到云端**：按 `agenticapp-tool-workspace` 的「云端保存与换机」用 `workspace_push` 保存，成功后把回执记进工单。没拿到成功回执不结单。开发工作集上线后继续绑定在应用上。
10. **结单**：按 `agenticapp-tool-deploy`「结单」调 `task_manager(action="complete")`。上线后即结单，发布不在结单条件里。
11. **发出**：上线结果连同交接消息发给开发者，开头「【⑤ 上线 → 已完成】」，「要你做的」照模板写。

## 这一段要做对的判断

| 判断什么 | 依据 | 判错的表现 |
|---|---|---|
| 上线条件满足了没有 | 「可以上线」在先；上线的是 ④ 验过、部署 `success` 的那一份；补测都通过、开发者选了接受，或判断类他再说过「可以上线」；结单门过了或写了豁免 | 没部署或补测没过就上线 |
| 只在开发工作集里的设定有没有搬走 | 使用者从空库开始，看不到工作集里的数据 | 使用者打开是空的、缺配置 |
| 没验证的和风险有没有如实列出 | ④ 的「未测」条目、开发者接受的没通过条目、能力缺口 | 上线结果里不提未测项，开发者以为全都验过了 |
| 开发者知不知道下一步 | 发布要准备的三样材料、「你可以做的事」；没部署时说清上不了线 | 开发者不知道接下来该做什么；不发布，正式入口和到点自动运行他自己也用不上 |

## 你可能会这么想 → 实际

| 想法 | 实际 |
|---|---|
| 他说了「可以上线」，没部署也先上线 | 没部署成功的草稿上不了线，先如实说，放到在线预览补测后再上线 |
| `finalize` 返回成功就算上线了 | 要 `resolve` 反读到上线版本，并核对绑定的部署是 ④ 验过的那份 |
| 上线后请他去发布一下，再看看正式入口 | 不请他发布、不等发布；正式入口要发布后才能看，写进「你可以做的事」 |
| 他说「先发布再结单」或要你在正式版里跑一次 | 告诉他发布由他决定，验证已在 ④ 做完，照常结单 |
| 未测的在 ④ 报告里说过了，上线结果不用再写 | 单列，写清没确认过什么；不写成请他去看 |

## 记下来

- **工单**：上线结果（`entry_type="result"`）；`workspace_push` 回执；`complete` 成功。
- **阶段文档 G7**：上线结果全文，以及模板里「给后续 Agent 的部分」。
- **交付物**：方案页 `status` 改为 `done`，`.pv-summary` 写上线结论，`.pv-you` 写「你可以做的事」，`.pv-meta` 写开发期累计花费；「已验证 / 未验证」与上线结果一致，「未测」的留在「未验证」。Studio 宿主下上线结果写进开发文档「验收报告」最后一节，按 `agenticapp-host-studio`「验收报告」保存新的一版；保存或登记结果未知时只查原操作结果，不重新写入。
- **阶段标记**：`workspace.json` 的 G7 标 `passed`；阶段记录 G7 `next_stage="closeout"`。

## 结束

全部满足，这张工单就结束了：

- 开发者说「可以上线」之后才上线；上线的是 ④ 验收过、已部署成功的那一版：`resolve` 能取到上线版本且 `entry_url` 非空（协作者为 `request_finalize` 成功）；
- 上线结果照模板写全，有「未测」条目时单列了；
- `workspace_push` 成功，工作区已存到云端；
- G7 阶段记录在 `complete` 之前写了；
- `task_manager(action="complete")` 成功，上线结果已写入工单与交付物。

之后开发者说正式入口里哪条不对、到点触发的结果不对，或要改已上线的应用，开新工单：要改的加载 `agenticapp-task-revise`（新需求从 ① 走），查原因的加载 `agenticapp-task-diagnose`。

## 出问题

| 现象 | 处理 |
|---|---|
| ④ 没部署过就同意上线；部署后补测有「没通过」或「好不好你说了算」 | [references/上线前自查.md](references/上线前自查.md)「没部署过时」 |
| 上线被拒、结单被拒 | `agenticapp-tool-deploy`「常见错误」；结单被拒时补一次路线冒泡或 `workspace` 真跑，或问开发者后写豁免；源码问题回 ③，验收缺口回 ④ |
| `BUSINESS_UI_FINALIZE_OWNER_ONLY`、`PERSONAL_VERSION_STALE_SOURCE` 或提请被拒 | `agenticapp-role-collab` 的协作报错；基线过期先合并 |
| `workspace_push` 两次都失败 | 按 `agenticapp-tool-workspace`「云端保存与换机」处理；不结单 |
| 开发者说发布被拒：新 SDK 版本不在灰度名单 | 把原文告诉他；不为了能发布改回旧应用 |
| 开发者说发布被拒：有运行中的执行 | 等执行结束，或由他决定取消 |
| 要下线、回滚、删除 | `agenticapp-tool-deploy` 的「版本操作、下线与删除」，每一步都要开发者确认 |
