# 制作反例集（12 条真实踩坑）

写编排脚本、拆 FastAgent、设计数据面、交付与验证前各读一遍对应条目（开头写了哪一步读哪几条）。

> 来源：2026-09-02 至 09-04 玖间民宿场景包 9700468 与智能应用 137 的全过程复盘，全部真实发生。每条三段：**错的样子 → 后果 / 报错 → 对的样子**。写脚本前读 1–6，拆 FastAgent 前读 1–2、9，设计数据面前读 3，交付与验证前读 4、6、7、12。
> 这份文档是"照着做"的正例来源之一，配合 [编排示例索引.md](编排示例索引.md) 里的正反例使用；它替代的是规范里一长串"禁止"。

## 1. 同一个 FastAgent 按交付物连调三次

**错**：复用的 `minsu_content_planner` 有个 `deliverable` 枚举（brief / imagetext_copy / card_layout），脚本顺着它在同一节点里调了三次，三次之间没有任何用户确认。

**后果**：成稿段判断单元调用 6 次，其中 3 次是无谓拆分；每次调用都是全新隔离会话，简报里的判断到写文案时已经丢了。

**对**：一个 FastAgent 一次调用出全套——`_output` 同时返回 `brief`、`directions[]`、`layout`、`recommended_direction_id`，`input_schema` 去掉 `deliverable`。只有产出之间隔着用户确认（老板逐张选档）才分成两次。复用旧 FA 时按"一个环节一个 FA"重审粒度，不照抄它的调用形状；需要改就 `clone_asset` 后改。

## 2. 录入环节切成三段

**错**：`shell` 抽 Excel 原始行列 → `jiujian_data_intake` FA 只做文字还原（只挂 file 工具）→ 脚本落盘。

**后果**：FA 退化成不挂工具的文字变换器；抽表逻辑写死在脚本里，换个表格格式就要改脚本。

**对**：挂表格 / 识图工具的一个 FastAgent 自己读、自己还原、自己校验房号白名单，一次返回结构化记录；脚本只负责把结果交给下游。

## 3. 没有配套智能应用却读写智能应用数据集

**错**：包没有配套应用，却挂了 `business_app_dataset` 工具集，两条路线 `record_ledger` / `record_metrics` 读数据集、`record_commit` 三次写入、定稿段"回写笔记档案"。

**后果**：智能应用数据集是用户点开应用时才 copy 出来的库，包单独运行时根本不存在——读只会 `found=false`，写无处可落；入库节点 `ORCH_NODE_FAILED`。包却带着这些脚本过了 Preview 并上线。

**对**：计划书里"记下来 / 存起来 / 看历史"类目标以配套应用为前提：要么把应用一起规划（应用优先，A1/A2 先落数据面），要么把这些目标改成"随交付给到用户的文件"并从包里拿掉数据集步骤与工具集。

## 4. 把输入素材原样映射进交付

**错**：入口表单上传的实拍图路径直接放进 `delivery.mapping` 引用的文件字段。

**后果**：`ORCH_DELIVERY_FILE_UNISOLATED`——交付守卫只认本节点产物目录 `/workspace/task_agent/<taskpoint>/output/`，来源可信不豁免。

**对**：要交付的文件（如修图后的实拍图）复制进 `ctx.output_dir` 再映射；只是输入或参考的不进交付文件字段，需要说明就写进 `output` 的普通业务字段。修法不是补 schema 声明，守卫查的是目录。

## 5. 按 `file_path` 读沙箱 `file_to_url` 的返回

**错**：脚本里 `url_map = {r["file_path"]: r["url"] for r in res["results"]}`。

**后果**：返回里的键是 `workspace_path`，`file_path` 恒为 None，映射为空；上一轮生图拿到的 URL 不是本步转换所得，前两轮真跑的证据作废。

**对**：制作期 External MCP 的 `file_to_url`（prepare → PUT → complete，回 `data.file_ref`）与运行期沙箱工具 `file_to_url`（入参 `file_paths` 列表，返回 `results[]` 每项 `{workspace_path, url, error?}`）是两个工具。写脚本前对拿不准的工具 `otpe_tool_test` 取样一次，`_output` 照真实返回写；`url` 为 null 的项逐项处理，不拿别的 URL 顶上。

## 6. 把聊天入口当作第四层真跑

**错**：三轮端到端真跑全部用 `task="<自然业务需求>"` 从聊天入口启动。

**后果**：聊天直派编排型 TPE 时业务路线 Runtime 不参与、业务事件降级——节点派发、字段映射、运行中表单、Delivery 冻结、最终 Review 一样都验不到；三轮证据边界全部下修。

**对**：第四层主入口是 `manage_goalfymax_project(run, submit_data={...})` 表单直跑（`task` 省略、`scenario_package_ids` 只传一个），运行中表单与最终交付审阅（`delivery.review`）**都是业务表单，一律用 `reply` 应答**（`confirm` 只用于普通聊天确认，应答业务表单会被拒）；聊天入口只另跑一次核 SA 路由。

## 7. `_output` 数组没给 examples，桩跑绿真跑炸

**错**：`_output` 里 `"items": {"type": "array", "items": {"type": "object", "properties": {...}}}`，没有 `examples`。

**后果**：冒泡桩对无样例数组造的是空 `[]`，脚本对元素键名的取值在冒泡里完全不执行；键名写错到真机才爆。

**对**：给数组加单元素 `examples`，让桩真正走到元素取值；嵌套数组的样例要写在祖先数组的样例元素里（make_stub 取到祖先样例后不再读后代 schema）。Preview 对这两种情况都会 warn，看到就补。

## 8. mapping 引用会话目录里的文件

**错**：FastAgent 在自己的任务点目录里生成的文件路径直接写进本节点 `output` 的文件字段并进 mapping。

**后果**：`ORCH_DELIVERY_FILE_UNISOLATED`；或者到了用户手上是空产物。

**对**：FastAgent 返回的 workspace 路径可以在节点间传递，但要随交付给用户的文件必须由最终节点收进自己的 `ctx.output_dir`（复制或写入）再进 mapping。

## 9. 复用旧资产不重审粒度

**错**：从 08-26 的旧包复用 planner / reviewer / visual_producer，连它们"按交付物分发、一次一种产出"的形态一起带进新包。

**后果**：见第 1 条；另外旧 FA 的 `mr_name` 不能猜，`clone_asset` 不传 `name` 是源名 + `_copy`、传了用传的，`mr_name` 跟最终名与新 ID 走。

**对**：复用只复用职责与提示词素材，粒度按当前包的环节重切；克隆后从返回值反读 `mr_name` 再写进脚本。

## 10. 用两条间接迹象推翻工单里三条证据的结论

**错**：工单条目 1565 用平台解析器判定 + 全量列表扫描 + 存量实证三条证据判定某 FA 在 cn-qa 不存在；后来看到"脚本里写了带前缀全名"和"包带着脚本过了 Preview"两条迹象，就把它推翻了。

**后果**：错误结论进了两处后续判断；真实原因是那个 FA 从来不存在，Preview 没拦是因为那五条编排型 TPE 没挂对应工具集，上线也不校验运行期可解析性。

**对**：推翻工单里已有的结论，证据强度至少不低于建立它时，且显式标注"更正条目 N"。最直接的验证往往一次调用就够——`list_assets(fast_agent, keyword=...)` 返回 `total=0`。

## 11. 契约后补

**错**：先写完 19 个后端接口，再用脚本从代码里生成 19 份 OpenAPI YAML。

**后果**：核对时发现路由写的是 `:roomNo`、契约是 `{room_no}`——契约先写这类不一致根本不会发生；前端类型也无从依据契约建立。

**对**：`frontend/schema/api/` 一个接口一个 YAML 先落，再按契约实现 service / route / 类型；`npm run check` 对无契约的路由报错。

## 12. 重写页面丢掉已确认的功能

**错**：A1 里开发者明确选了"在应用里直接跟它说话"，原型实现了；A3 把项目页从演示数据改接真实 SDK 时整页重写，对话面板没带过去。

**后果**：一个开发者点名要的功能静默消失，是 `npm run check` 打出 `-chat.read -chat.write` 才被发现。

**对**：《智能应用计划书》⑤ 功能清单里的每一项在 A3 出口逐条对照实现与 capability 扫描结果；重写任何页面前先列出该页承载的已确认功能。
