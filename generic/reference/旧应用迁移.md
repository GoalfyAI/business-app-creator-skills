# 旧应用迁移

## 适用场景

接续、修订、诊断后要修、按反馈改应用时，发现应用工程 `frontend/goalfy-app.json` 没有 `"executor": "launch_agent"`：这是挂场景包的旧应用。本 Skill 不再按场景包方式修改旧应用，先按本文把它升级成现在的写法（路线与 TPE 挂在应用版本上、以执行为单位），再做本次改动。本文是全书唯一讲场景包的地方；升级完成后一律按其他文件做。

## 规则

### 怎么认出旧应用

- 以应用工程 `frontend/goalfy-app.json` 为准：没有 `executor` 字段的是旧应用；写了 `"executor": "launch_agent"` 的不用迁移。
- 旧应用的特征：应用版本挂一个场景包，路线（`workflow_orchestration`）和 TPE 在场景包里；`business_ui_manage(action="get")` 的返回或 checkpoint 里有 `scene_package_id`；前端用项目句柄、聊天；表单展示定义在场景 Skill 文件 `forms/<form_id>.json`。
- **禁止**只给旧工程手工加 `executor` 当作迁移：`executor` 由新脚手架模板带来（第 5 步）。
- 迁移本身是一次修订：建 write 工单，按 [../tasks/修订.md](../tasks/修订.md) 取应用草稿（`business_ui_manage(action="ensure_draft", change_note="迁移到应用版本直挂路线")`），④ ⑤ 照常做。迁移会改变使用者看到的页面和运行方式，开工前用业务话告诉开发者要做什么、正在用的人会看到什么变化（见「迁移后的注意」），他同意后开始。

### 迁移步骤

1. **取出编排与 TPE 清单**：从应用现挂的场景包读 `workflow_orchestration` 与路线引用的全部 TPE（`get_asset` 看场景包；版本工具面 `asset_type` 写 `scenario_pack`，业务工具面写 `scenario_package`）。编排格式不变，`orchestrations[]`、`orchestration_id`、节点、映射原样保留。
2. **去掉需要 Agent 的写法**：现在执行里没有 Agent 接手，Hub 保存时拒收（400，报错含 `not supported by launch agent` 和节点或路线位置）。
   - 审阅 `review.type = "agent_gate"`、动作 `kind = "agent_gate"`（交由 Agent 处理）改成 `user_gate`：停下等使用者（`message_type:"ask"`）或直接交付（`message_type:"result"`，要求 `delivery.mapping.text` 存在且只声明一个 `complete_business` 动作）。动作 `kind` 只在 `complete_business`、`fail_business`、`start_orchestration` 里选。
   - 节点 `sa_handoff`、节点级 Agent 介入 / 接管删掉；原来靠 Agent 判断的，能用规则判断的写进 TPE（输出校验、`business_gate`），其余交使用者审阅。
   - 原来靠 Agent 在审阅后「再改一版」的，改成修正路线，见 [业务路线.md](业务路线.md)「修正上次交付」。
   - 场景包里普通任务点、SystemAgent 直接执行、`apc_skill` 里写的运行时规则都不能搬：要么改成编排型 TPE 节点（脚本 + FastAgent），要么改成使用者在表单里补的信息；改了「每一步谁来做」的出 PRD 差异版请开发者确认（[../tasks/修订.md](../tasks/修订.md)「从哪一段进」）。
3. **核对节点工具**：节点在旧应用里也只用它 TPE 自己挂的工具集（加上 FastAgent 自己的工具），迁移不改变节点能用的工具；场景包工具箱里的工具是给运行 Agent 用的，不用搬。只需确认每个节点脚本调用的工具都在该节点 TPE 的 `preload_toolset_ids` 里，旧应用里偶有脚本调了 TPE 没挂的工具，借迁移用 `otpe_manage(action="update")` 补上（[业务路线.md](业务路线.md)「路线挂在应用版本上」）。
4. **挂到应用版本**：`business_ui_manage(action="update", business_ui_id, workflow_orchestration, tpe_ids)` 挂到应用草稿，整份编排一次传、`tpe_ids` 写 TPE 资源组 ID 加版本（[业务路线.md](业务路线.md)「路线挂在应用版本上」）。场景包挂载与编排挂载互斥，同一份草稿只留一种；之后 `setup` 不再传 `scenario_pack_id`。
5. **换新脚手架**：按 [脚手架与预置件.md](脚手架与预置件.md)「版本闸门与升级」换成当前模板（带 `"executor": "launch_agent"`），保留已有页面、后端与定制。表单展示定义从场景 Skill 文件 `forms/<form_id>.json` 搬到 `frontend/schema/packs/<pack>/forms/` 与 `orchestrations/`，`goalfy-app.json` 的 `packs` 列出用到的目录。
6. **页面改成以执行为单位**：去掉项目句柄和聊天，改用 `sdk.business.start` 发起、`useExecution(businessId)` 取执行句柄、消息中心聚合待答（[前端页面.md](前端页面.md)「以执行为单位」，写法以模板 `frontend/src/sdk/docs/README.md` 为准）。
7. **脚本按现在的约定核一遍**：`ctx` 只用 [编排脚本.md](编排脚本.md)「ctx 有哪些字段」列的字段；中间文件写 `ctx.process_dir`，外发步骤防重复，见同文件「并行执行的约定」。
8. **重新部署与验收**：冒泡（应用标识只用 `business_ui_id`）、部署、`workspace` 真跑后按 ④ 验收（[部署与版本.md](部署与版本.md)「真跑」、[../stages/4-试用验收.md](../stages/4-试用验收.md)）；开发者说「可以上线」后上线，发布由开发者决定。结单门豁免 checkpoint 写 `business_ui_id`、`business_ui_version_id`、`orchestration_id`，不再写 `scene_package_id`（[部署与版本.md](部署与版本.md)「三道门」）。

### 迁移后的注意

- 同一应用已发布的旧版本仍按旧方式运行；开发者发布迁移后的版本后，新发起的才是执行。
- 发布后，旧方式下停在等待使用者的运行会被平台取消并通知使用者。**上线前**先用业务话告诉开发者这件事，写进上线结果「正在用的人会看到什么变化」。
- 应用里的历史执行列表只列升级后发起的执行；升级前的旧运行记录不删除，但不再出现在应用的历史列表里。使用者库里的业务数据（表里的记录）不受影响，页面照常读出。这两点同样在上线前告诉开发者，一并写进「正在用的人会看到什么变化」。
- 有运行中的执行时发布会失败并返回数量（发布保护，`BUSINESS_UI_EXECUTIONS_RUNNING`）；发布被拒时把原文告诉开发者，**禁止**为了能发布改回旧写法。
- 迁移完成后原场景包不再挂在应用上；它是否下线、删除由属主决定，按 [../SKILL.md](../SKILL.md)「红线」每一步请开发者确认，不擅自处理。
- 发起报 `APP_VERSION_OUTDATED`（`reason=page_outdated`）或冒泡报 `APP_VERSION_NOT_LAUNCH_AGENT`：该版本不是按现在的写法部署的，核对 `goalfy-app.json` 的 `executor` 与部署记录，重新部署（[报错对照.md](报错对照.md)「执行」）。

## 常见错误

- 只手工加 `executor`、不换脚手架和页面。
- 迁移时还建新场景包，或在 `setup` 里传 `scenario_pack_id`。
- 编排沿用「交由 Agent 处理」、`sa_handoff`，保存被拒。
- 只搬改动的那条路线或漏了 `tpe_ids` 里的 TPE，覆盖其他路线或保存被拒（`references unmounted tpe_id`）。
- 把场景包工具箱的工具当节点工具去搬，或节点脚本调的工具没挂在该节点 TPE 上（`invalid tool call name`）。
- 不先告诉开发者发布会取消旧的待答运行。

## 相关工具与契约主题

`business_ui_manage(action=ensure_draft / get / update / setup / finalize)`、`get_asset`、`update_asset_relations`、`scene_package_manage(action=assemble / bubble / cancel)`（工具名是历史叫法，应用标识只用 `business_ui_id`，不传 `scene_package_id`）、`manage_goalfymax_project(action=run / status / wait / reply / stop)`（按 `business_id`）；契约主题 `otpe_multi`。
