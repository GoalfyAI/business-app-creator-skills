# 授权与充值

## 适用场景

应用要让使用者授权外部平台账号（如广告平台）、要在应用里充值、应用后端要自己做外部登录，或处理授权选择冲突、充值未开通时读。

## 规则

授权与支付的接口、参数和宿主支持，以 MCP 返回与应用工程 SDK 文档为准：分别核对授权 `context/authorize/revoke` 与支付 `open` 在 SDK 导出、类型定义和宿主契约里是否存在、签名是否一致；版本号不同不能判定能力缺失，版本号相同也不能证明接口可用。文档、SDK 导出与宿主能力对不上时，写清文件路径、缺失接口和运行错误，不手写桥接、不伪造接口或成功结果。应用依赖与锁文件固定到已验证版本，不自动升级到最新版。

### 能力发现与应用授权选择

PRD 功能清单里写了「外部平台授权」才做。先确定应用草稿及固定场景包；还没有应用时记录候选与充值能力待核查，等 ③ 建好应用、取得 `business_ui_id` 后再查询，不为探测能力提前创建空资产。只用 `business_ui_manage` 当前 Schema 里有的 action；缺少时先刷新连接、核对部署，记录待核查项。

| 调用 | 用途与关键输入 |
| --- | --- |
| `business_ui_manage(action="ensure_draft", task_id=..., business_ui_id=...)` | 取得明确的 `draft_asset_id`；后续读取候选、保存、部署与上线使用同一草稿。 |
| `business_ui_manage(action="list_authorization_candidates", task_id=..., business_ui_id=...)` | 读取草稿候选，将 `platforms` 的名称、图标与 `candidates` 四元组对应。选择默认空；开发者已明确指定平台时据此筛选，不重复确认，存在实质歧义时再澄清。MCP ID 不等于工具组 ID。 |
| `business_ui_manage(action="save_authorization_selection", task_id=..., draft_asset_id=..., ...)` | 传候选原样四元组数组、`authorization_candidates_revision` 和草稿当前 `expected_authorization_policy_digest`。摘要初始为空串，非空为平台返回的 64 位小写十六进制值；空数组表示明确不选，并发字段不可省略。 |
| `business_ui_manage(action="get_recharge_config", task_id=..., business_ui_id=...)` | 只读平台开通状态。`enabled=false` 与查询失败分别记录，不承诺充值可用、不要求开发者填写收款账号或自行构造支付链接。 |

- PRD 与交付物记录选中平台、用途、对应页面及「在哪个应用授权，只有这个应用及其项目可用」；账号数量以实际 OAuth 结果为准。
- 保存冲突时停止部署，用原草稿重读候选与策略，把差异交给开发者确认后再保存；保存的只是开发者确认过的选择。
- 充值能力还要核对应用后端的安全代理、实际路由接线、原始请求体采集、依赖和固定层测试，不能只检查前端 `authorization` / `payment` 导出；平台服务已部署不代表应用源码已具备代理，缺了按 [脚手架与预置件.md](脚手架与预置件.md) 迁移前后端平台固定层。
- 平台收银台与第三方 MCP 写操作分别核查：缺少建投 / 调投工具不代表支付不可用。原范围涉及自动操作而实际仅支持人工处理时，说明差异并由开发者决定。

### 接入与交互

| 场景 | 接入规则 |
| --- | --- |
| 授权状态与交互 | 每次进入页面或重新获得焦点读取 `sdk.authorization.context()`。直接调用 `sdk.authorization.authorize({auth_card_id})` 或 `sdk.authorization.revoke({authorization_id})`，按返回 `status`（success / cancelled）及刷新后的 `context` 更新页面；ID 原样取自 context，请求失败保留重试入口。 |
| 授权检测与业务恢复 | `authorization_required` 是检测结果，不是弹卡指令。「授权账户」直接调 `authorize`，不先启动检测项目或跳转对话找卡。失败或取消不标业务成功、不进入最终交付审核；成功后重新查状态，由使用者继续业务，不自动重放充值或投放。 |
| 身份与凭据 | 宿主处理 OAuth / custom 表单。应用不读取、存储或转发 token、密钥、custom fields，不自行传 user_id、business_ui_id、版本、预览标识或回调 URL；只读或他人实例不允许真实授权。 |
| 预览隔离 | 在线预览支持真实授权和充值，只读取本人、本应用、当前作用域的授权，不回退全局。同一开发者和稳定应用更新草稿、重新部署预览后复用预览授权与订单；发布不复制到正式实例。即使广告账户相同，授权和订单也不跨作用域共用。预览付款是真实付款。协作者的预览不能使用充值相关功能，见 [多人协作.md](多人协作.md)「预览、费用与限制」。④ 在本机版上只走到授权或付款窗口出现为止，判定见 [../stages/4-试用验收.md](../stages/4-试用验收.md)「2.4 逐条判定」。 |
| 充值账户与建单 | 配置实际返回 `enabled=true` 后，让使用者从 `context.recharge_accounts` 明确选择实时核验的账户引用；普通授权记录 ID 不能替代该引用。由专属后端创建订单及 checkout，再调用 `sdk.payment.open({order_id, checkout_id})`。同一充值意图重试复用幂等键。 |
| 支付与到账 | `completed` 仅表示收银台流程结束，`cancelled` 表示关闭或取消；返回后均重新查单。服务端 `payment_status=paid` 才表示已付款，`fulfillment_status=completed` 才表示已到账。 |
| 独立 Mock 与未开通 | 独立 Mock 返回空平台列表及明确未开通结果，不能作真实 OAuth 证据；充值返回 `unavailable/CAPABILITY_UNAVAILABLE`。Mock 里不出现支付成功，收银台只用平台的。 |
| 接口故障定位 | 核对当前 `sdk/authorization.ts`、宿主 RPC、预览会话及容器配置注入，给出具体文件路径、缺失接口和运行错误；分开记「代码已实现」「已部署配置」「真实验收通过」，不能从一次错误推断平台缺少 OAuth 能力，缺口如实记录，不手写桥接或伪造成功结果。 |

测试取消、授权失败后重试、解除后列表刷新、跨应用或跨预览作用域拒绝及应用切换时弹窗取消；自动化测试只用 Mock，不用真实授权或真实支付。

### 应用自管的外部登录

授权卡覆盖不到的外部系统（例如公司内部的单点登录）可以由应用后端自己做 OAuth，凭证只留在后端会话里，仍遵守上表「身份与凭据」。另外守两条：

- 回调地址和域名校验不写死成某一个容器。同一份应用会跑在属主开发容器、每个协作者的草稿容器和每个使用者的实例容器上，域名各不相同；域名只校验是平台应用容器，应用身份用宿主签名里的 `business_ui_id` 校验。
- 外部系统要求按地址登记回调或白名单时，把登记对象、已登记的地址和执行人写进交付物和上线结果。协作者容器和新实例容器各需要登记一次，没登记前该容器的登录会失败，见 [多人协作.md](多人协作.md)「预览、费用与限制」。

### 上线前核对

⑤ 上线前自查时按这几条核一遍（[../stages/5-上线.md](../stages/5-上线.md)「2.2 上线前自查」）：

- 应用实际用到的 SDK、Bridge 协议和授权、支付 RPC，在应用工程的 SDK 文档与宿主契约里都有。
- 要上线的草稿里的授权选择与开发者确认记录一致；修改选择回到新草稿改，已上线版本不动。
- 重新查询 `business_ui_manage(action="get_recharge_config", task_id=..., business_ui_id=...)`，记下应用 ID、查询时间及实际返回。未开通就在上线结果写「充值暂不可用」，不展示收款主体、不宣称收款或到账闭环完成；只有平台真实返回启用且充值闭环通过验收，才展示平台返回的收款主体信息。
- 上线结果的使用说明逐项列出使用者需要授权的平台，说明只对本应用及其项目生效；告诉使用者可在应用内或平台「我的授权」解除同一份授权（卡片显示应用名称及 Logo），解除不影响其他应用各自的授权。

## 常见错误

- 把 `authorization_required` 当成弹卡指令，先起检测项目或跳对话找卡。
- 应用自己读取、存储或转发 token、密钥、custom fields。
- 用普通授权记录 ID 代替充值账户引用。
- 把 `completed`（收银台关闭）当成已付款；以服务端 `payment_status=paid` 与 `fulfillment_status=completed` 为准。
- 保存授权选择冲突后自动用旧选择重试。
- 在独立 Mock 里模拟支付成功，当成真实证据。
- 应用自己做外部登录时把回调域名写死成属主容器，协作者预览和新实例登录失败。
