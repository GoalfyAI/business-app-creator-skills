# 协议三：阶段展示与证据等级

> 共享协议层。回答两件事：每个阶段给开发者看什么、怎么看；什么证据能证明什么。

## 1. 展示不是追加一份长报告

默认只展示：**本阶段结论、关键证据、当前待决定项及其影响**；开发者需要时再展开实现细节。每个阶段的"给开发者看什么"一节规定默认视图；技术实现映射可展开查看。

开发者看到的对象按阶段递进：G1 一页简报 + 产物样例 + 短流程；G2 实际产物对比 + 能力卡；G3 一个完整业务样例 + 业务路线图 + 结果 / 页面预览（争议加泳道图，状态易混加状态图）；G4 单元的预期 / 实际对照 + 标注步骤的脚本；G5 真实运行时间线 + 数据前后对照；G6 可操作的应用 + 一次旅程演示；G7 交付核对单。

每条展示的内容标来源类型：**事实**（材料或反读里有）/ **推断**（Agent 按常识猜）/ **未知**（要验证）/ **挑战**（Agent 唱反调）。

## 2. 同一事实的不同视图

业务规则与公开契约保持唯一权威来源，各视图引用同一节点 / 承诺编号，不维护六份"审核逻辑"。例：节点"审核经营结论"——G1 看哪条结论缺依据、怎样算合格；G3 看自动核数与负责人判断各负责什么、退回走哪里；G4 看核验输入、规则、实际判断与反例；G5 看此次审核在哪个运行实例发生、结果如何冻结入库；G6 看待审内容、可操作项、修改影响、旧版本；G7 看对应承诺是否通过、证据属于哪个版本。

## 3. 开发者怎么说"不对"

四种方式：直接改（文字、样式）；选中批注；流程反馈（在路线图节点上说）；操作记录。每条自动带页面 / 步骤 / 版本上下文。Agent 收到后先判断是改文字、样式、数据、流程还是承诺；只有影响流程、数据、权限或承诺的才回问范围；改完回报实际修改与验证结果，可撤销。

## 4. 证据强度：按能证明什么判断，不按材料数量

| 证据 | 可以证明 | 不能证明 |
|---|---|---|
| 已确认样例、规则、行为演示 | 双方对预期的理解一致 | 平台已具备能力 |
| 真实资产反读、Preview、静态契约检查 | 保存内容、引用和结构成立 | 真实模型内容合格、业务运行成功 |
| 安全工具取样、代表性能力实测 | 该环境、输入、版本下该能力的表现 | 所有输入和整条路线正确 |
| 单条 / 路线 Bubble | 具体覆盖路径的管路与控制接缝 | FastAgent 桩对应的内容质量、被屏蔽的副作用 |
| 真实路线执行 | 实际派发、模型 / 工具输出、表单、交付与审阅 | 应用页面正确、用户实例的数据回流正确 |
| 真实应用实例与浏览器操作 | 当前应用版本的使用与数据闭环 | 长期业务收益已改善 |
| 可比条件下的效果对照 | 特定范围内的改进证据 | 不同人群、未覆盖任务普遍改善 |

状态词只有五个：**待验证、通过、失败、阻断、不适用**。不适用要说明理由；已知偏差写范围、影响、接受人；越权、数据串用、未完成报成功不能豁免。

## 5. 失败怎么展示

专业模块失败时返回明确的问题归属与证据（单元 / 路线 / 数据 / 页面 / 平台），不把失败转述为"请开发者自行处理"。测试不通过时展示失败证据与修复路径；人同意继续不改变测试结果。

## 6. 质量、耗时、费用的口径

成功率分技术成功（无报错）与业务成功（判定通过）；耗时用 p95 并拆模型时间与工具时间；费用按"每次成功交付"计，含失败重试与人的确认时间折算；稳定性看同一输入多次结果的一致率。事实与估算分栏，估算标假设。
