# 协议二：业务承诺—实现—验收的追踪关系

> 共享协议层。解决旧框架"节点测试、路线测试、数据库测试、页面测试各自存在，却没有一条业务承诺贯穿"的断裂。

## 1. 追踪链

```text
业务承诺（G1 基线里的一条）
  → 业务节点 / 关键决策（G3 运行设计）
  → 数据表与字段（G3 数据面；P4）
  → 页面 / 动作（G3 页面设计；P5）
  → 实现资产：工具组 / FastAgent / 工具集 / 编排型 TPE / 业务路线 / 后端接口 / 页面（G4–G6）
  → 验收用例：U 行为项实例 + 专业验收清单项（G3 设计，G4/G5/G6 分层取证，G7 复验）
```

任何页面、字段、接口、脚本步骤都能追到一条承诺；任何承诺都有承载与验证方法。追不到的功能不做；没有承载的承诺不通过 G3-01。

## 2. 三张表 + 一份矩阵

沿用"双副本 + 指纹 + pending"机制（细则见 [表结构与累加机制](../references/表结构与累加机制.md)、[应用结构表与结果检查表](../references/应用结构表与结果检查表.md)）：本地工作副本供每轮定位进度，工单权威快照供续作重建；每个条目带 `hash` 与 `status`（`pending` / `passed` / `waived`），只处理 pending，关联内容改动自动回 pending，`waived` 必须带理由。

| 载体 | 记什么 | 建立 | 更新 |
|---|---|---|---|
| **执行结构表** | 每条编排型 TPE 的步骤、每步执行者（规则 / 模型自主 / 模型+确认 / 人）与证据（试验次数、通过率、稳定性、p95、每次成功费用）、风险等级、确认形式、回退链、预算、依赖与并行组、FastAgent 清单 | G3 | G4 改脚本同步条目；G5/上线后按运行证据更新 evidence |
| **应用结构表** | 每个页面 + 每个后端接口 + 每张模板表，条目走 挑战 → `challenged=true` → 开发者确认 | G3 | G5b/G6 实现时同步 |
| **结果检查表 / 案例库** | 正反例（来源分黄金路径 / 真实历史 / 扰动 / 长尾）、路线校验项、前端与后端校验项；条目带 tier / covers / oracle / stakes / holdout | G1 种子，G3 建立 | G4–G7 分层闭合；只能用真实数据置 passed，mock 只作过程记录 |
| **需求追踪矩阵** | 承诺 → 节点 → 数据 → 页面 → 资产 → 验收例 的映射 | G3 | 任何变更先查它 |

## 3. 三个结论分别记录

同一条 U 行为：G3 记"设计已确认"，G5 记"后台验证通过"，G6 记"用户操作通过"，G7 记"最终版本复验"。不共用一个 passed。工单落账用 `metadata.stage` 与 `metadata.behavior_id`（如 `U5-02`）区分。

## 4. 门禁汇总规则

一条 G 门禁引用多个 U 项时，先逐项列 通过 / 失败 / 阻断 / 不适用，再汇总；任一必需项未验证则该门禁不通过。不以条目数量衡量完整性；看每条承诺是否有规则、实现、证据三样。

## 5. 变更影响

路线、表单、字段、脚本、页面的任何改动，先列受影响项与未影响项及理由（例：从"自动生成即结束"改为"负责人审阅后结束"，要一起检查业务完成标准 → Review 责任与动作 → 运行等待 / 重入 → 待办与应答页面 → 状态与版本留存 → 超时 / 拒绝 / 重复提交测试）。改后沿真实依赖使相关通过记录失效并重验受影响项；只重验受影响项，不全量重做。

## 6. 工单证据标签

以下只出现在工单检查点里，不是工具参数：

| 标签 | 含义 |
|---|---|
| `business_baseline` / `behavior_scope` | G1 业务基线与 U 适用性判断 |
| `capability_matrix` / `trial_report` | G2 能力矩阵与试验报告 |
| `build_book` / `execution_structure_snapshot` / `app_structure_snapshot` / `behavior_design` | G3 运行设计、结构表快照、行为验收设计 |
| `needs_bubble` | 单元缺终态轨迹 |
| `orchestration_static_validated` / `orchestration_bubble_validated`（一条路线一条，带 `orchestration_id` 与 `run_id`）/ `orchestration_runtime_verified` | 路线三级证据 |
| `data_loop_verified` | G5b 应用数据闭环证据 |
| `full_validation_skipped` | 开发者跳过真机验证；存在时不得上线、不得结单 |
| `platform_blocked` | 平台能力不支持已选范围，已停止对应交付 |
| `autotest` / `integration` / `delivery_report` | G7 最终测试、真联调取证、交付报告 |
| `finding_resolved` / `finding_waived` | 问题单处置；waived 必须带理由 |
| `stage_exit` | 阶段出口逐项状态与证据指针 |

除路线 Bubble 标签由结单 Gate 机器核验外，其余标签的准确性取决于如实记录；禁止为让工单完整而标记未真实取得的证据。
