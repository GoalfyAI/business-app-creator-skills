## 1. 参考项目三层深读要点

服务 G2 第 2.1 节第一来源。三层各看什么、能证明什么，逐层对照，缺一层就不算完成。

| 层 | 用什么 | 看什么 | 能证明 | 不能证明 |
|---|---|---|---|---|
| 概览 | `get_project_execution_logs(summary)` | 总轮次、最终用户请求序列、执行阶段、Agent 与工具分布、等待与失败概况 | 全局视图、需要深挖的轮次 | 任何结论 |
| 深读 | `get_project_execution_logs(detail)`，按 `log_type` 分页读完 | 最终用户原始意图与约束、规划逻辑与步骤拆分、工具调用密集阶段的调用链与参数传递、任务点与 FastAgent 输入输出质量、失败重试、等待原因、最终交付是否匹配 | 实际发生了什么 | 为什么发生 |
| 分析 | 写入工单 | 轮次分类统计：有效推进、重复沟通、失败重试、等待；瓶颈定位与根因：缺知识、缺工具、缺指引、缺前置检查、资产边界错误；真实调用链；Skill 使用情况 | 可复核的结论 | 其他项目也如此 |

## 2. 复用与摸底工具、覆盖矩阵六态

服务 G2 第 2.1 节第二、第三来源。三个只读工具各有用途与限制；矩阵每行必须落六态之一。

| 工具 | 用途 | 限制 |
|---|---|---|
| `list_assets` | 按类型搜索可复用资产 | 关键词只匹配名称和 ID，建议用英文短词；不传关键词返回全量，注意上下文开销；结果不是完整契约 |
| `get_asset` | 批量反读完整配置、关系、Schema、状态，一次 1 至 20 个 | 只返回该资产自身，不展开子资产，诊断时逐级下钻；`can_view_params=false` 时配置为空是脱敏，不是空资产 |
| `dataset_read` | 只读查看长期数据集的描述、使用指南、Skill 文件、表、列、行 | 读不到业务应用数据集 |
| `get_scene_package_lineage` | 看一个能力容器的来源与派生 | 用于判断走派生还是新建 |
| `get_diagnosis_doc(scene_package)` | 读当前能力容器契约 | 需要 `task_id` |

| 六态 | 含义 |
|---|---|
| 已覆盖 | 现有资产直接满足，反读过 Schema 与真实配置 |
| 可组合覆盖 | 多个现有资产组合能满足，组合方式已写明 |
| 需维护 | 现有资产能用但要改提示词、指南或配置 |
| 真实缺口 | 平台内外都没有，进第 3 节四层处理 |
| 受限能力 | 有资产但权限受限或脱敏，需要开发者确认后 `allow_restricted=true` |
| 待验证 | 有候选但没有真实证据，进试验问题清单 |

两类不要误认的资产：目录里名为"××档案场景包""业务档案助手"的官方包属于业务档案产品线，不是业务应用数据集的来源，不拿来"留存用户数据"；`business_app_dataset` 工具集只在规划配套业务应用时才挂，计划书第 ⑥ 章形态为"直接使用能力容器"的不挂它。

## 3. 缺口四层处理、外部候选四维度、开发需求说明格式

服务 G2 第 2.3 节。四层按顺序试，每层的适用条件与做法在表里；外部候选逐维度打勾，任一维度否决即出结论；转开发需求照格式写。

| 层 | 适用条件 | 做法 |
|---|---|---|
| 1 Skill 弥补 | 工具能力已覆盖，缺的是调用顺序、前置检查、字段准备或结果审视方法 | 把指导写进正确层级，G3 落实 |
| 2 接入现有能力 | 平台内没有可复用工具组，外部有现成 MCP 服务或 Skill 包 | 先本地验证再注册；去 MCP 官方索引、代码托管平台、包管理平台、开发者私有仓库找 |
| 3 形成开发需求 | 开发者有协作团队，能力需要开发 | 写可直接转交的需求说明 |
| 4 确认后降级 | 前三层都不成立 | 写明未覆盖阶段、对结果的影响、补齐条件、受影响验证，取得确认 |

| 维度 | 为什么要看 |
|---|---|
| 是否仍在维护 | 长期不更新的服务上线后容易失效 |
| 连接方式 | 决定注册时传地址还是启动命令，以及运行环境要装什么 |
| 认证方式 | 全容器共用一份凭证，还是每个最终用户各自授权；后者**必须**配授权卡 |
| 有无破坏性操作 | 决定哪些工具可以取样、哪些**禁止**取样，以及使用指南里要不要加约束 |

**开发需求说明格式**：业务动作；目标系统；必需输入与输出；授权方式；最终用户与项目隔离要求；副作用；失败语义；验收样例。写成开发者能一键转发给工程师的格式。

## 4. 能力形态判定、接入工具与前置依赖、授权卡

服务 G2 第 2.4 节第 1 至 3 步。先按形态表分三类决定试用路径；接入时每个工具都有前置条件，漏了就失败；需要最终用户各自授权的能力必须配卡。

| 形态 | 试用路径 |
|---|---|
| 现成 MCP 服务 | 本地验证、平台接入、取样、试跑 |
| 标准 Skill 包 | 同上，接入用 `import_skill_package` |
| CLI 工具、代码库、普通应用 | 需要先包装成可注册的包。默认只评估包装成本并出结论；开发者明确要求时才包装 |

| 工具 | 用途 | 前置 |
|---|---|---|
| `preview_tool_group` | 预览一个新的 MCP 连接，验证可用性并发现工具 | 注册前**必须**先做 |
| `register_and_refresh_tool_group` | 注册新工具组，或刷新已有工具组的工具列表 | 先 `preview_tool_group`；预览时用过的前置安装步骤，注册时**必须**一并带上；先 `list_assets` 确认无重复注册 |
| `upload_and_register_tool_group` | 上传开发者的私有包并注册 | 先 `file_to_url(purpose="mcp_package")` 取得文件引用 |
| `import_skill_package` | 导入标准 Skill 包，自动创建离线工具集 | 先 `file_to_url(purpose="skill_package")` |
| `create_toolset` | 创建工具集 | 成员工具组或 FastAgent 已存在 |
| `online_toolsets` | 工具集上线 | 安全的运行时测试全部无失败 |
| `otpe_tool_test` | 对已有 MCP 工具做一次真实调用取样 | 已知目标工具组与工具标识；需要文件时先 `file_to_url(purpose="tool_test_fixture")`，再同时提供 `workspace_files` 与 `workspace_bindings`，不传 `project_id` |
| `scene_package_manage(create)` | 建试用包草稿，默认克隆官方基础包 | 立即反读继承 |
| `manage_goalfymax_project(run)` | 草稿态试跑 | 试验授权已取得；`task` 用自然业务需求 |
| `delete_asset` | 作废试用包草稿 | 开发者确认并告知名称 |

| 授权卡工具 | 用途 |
|---|---|
| `create_auth_card` | 为工具组创建授权卡，参数用工具组注册返回的授权绑定标识，**不是**工具组标识 |
| `update_auth_card` | 更新已绑定的授权卡配置 |
| `link_auth_card` | 用授权卡标识关联到已有卡片，共用其授权配置 |

**禁止**把任何个人令牌写入 Skill 文本、脚本或工单。完整的注册流程、调试循环、私有包处理、上线检查见 `references/依赖与MCP接入.md`。

## 5. 复用工具契约看什么

服务 G2 第 2.4 节第 4 步。脚本要直接调用的已有工具，写第一行调用前先读它的实时契约，逐行核下表；拿不准的再取样。读契约与取样都记为该工具的输入约定，G3 写进执行结构表。

| 看什么 | 例子 |
|---|---|
| 文件或路径类参数收什么 | `file_to_url` 换出的 HTTPS URL、`/workspace` 绝对路径、还是文件内容本体；能不能收目录 |
| 必填与互斥 | 哪些必填；哪几个参数二选一 |
| 值域与格式 | 枚举、日期格式、语言码、编码、最大条数或字节数 |
| 返回结构是否声明 | 声明了就据此写 `_output`；没声明或含嵌套数组的，取样定 |
| 副作用与授权 | 是否只读；要不要授权卡 |

取样的两个目的：输入按约定给能不能被接受；真实返回的嵌套形状。可以同时提交一个候选的输出结构让样本顺带校验。工具组刷新或换版本后输入约定可能变，对应条目回 `pending`，按上面两步再过一次。冒泡报"参数格式不对""路径不存在"多半是这一步省掉了。

真实教训：某个外部 MCP 工具的文件参数只接受 `file_to_url` 换出来的 URL，不接受 workspace 路径；没读描述就照别的工具的写法写了脚本，冒泡才发现，改脚本、改上游文件准备、重跑一轮。

## 6. 试验报告八项

服务 G2 第 2.7 节。报告结论先行，八项固定，每项标能证明什么、不能证明什么。

| 项 | 写什么 |
|---|---|
| 结论 | 可行、不可行、需要包装后再评估 |
| 能力形态与接入方式 | 形态判定；注册结果，或包装成本预估与路径 |
| 验证证据 | 本地验证结果；工具清单与真实返回结构要点；逐任务试跑记录 |
| 质量印象 | 结果能不能用、稳定性、与预期的差距 |
| 成本 | 接入耗时、试跑积分、适用时的包装预估 |
| 风险 | 维护状态、认证模式、破坏性边界、许可证 |
| 正式化范围 | 值得时：哪些能力值得进正式资产、适合什么业务场景 |
| 盲区 | 没试到什么；哪些结论是从有限任务外推的；**禁止**夸大覆盖面 |

试用产出在正式流程里的复用：已注册的工具组与工具集在 G4 依赖准备直接引用；工具真实返回结构是 G4 取样要拿的东西；试跑记录是 G1、G3 的参考素材；正式化范围建议是 G3 路线设计的输入。

## 7. 文件与创作型长文本准备

服务 G2 第 2.4 节的取样文件，以及 G4 第 2.4、2.5 节的 Skill 文件、Logo、长脚本、长提示词。先判断提交内容属于哪一类，两类生命周期不同，**禁止**混用。

| 类型 | 典型内容 | 提交方式 | 平台保存结果 |
|---|---|---|---|
| 资产文件 | Skill 文件、辅助脚本、模板、样例、私有包、Logo、工具取样文件 | `file_to_url` 换取文件引用，再把引用绑定到资产或验证项目 | 文件作为独立资产或附件保留 |
| 创作型文本 | 编排型 TPE 脚本、`apc_skill`、业务路线 JSON、FastAgent 提示词、工具集使用指南、普通任务点提示词 | 短内容直接传原文本字段；长内容在实时 Schema 暴露对应 `*_url` 后传服务端可访问的 HTTPS 文本地址 | 服务端只读取一次正文，再按原文本字段的校验、确认、保存链路处理；URL 本身不保存 |

创作型文本 URL 的规则：原文本字段与对应 `*_url` **二选一**；URL 必须是服务端可访问的 HTTPS 地址，不得指向内网、客户端本地路径或需要登录的页面；外部 Agent 的本地 `/workspace` **禁止**作为 `script_file` 传入；提交成功后**必须**反读最终正文确认保存的是解析后的内容；URL、临时上传地址、带签名的查询参数**禁止**写入工单。

**`file_to_url` 的五种用途**：

| 用途 | 用于 |
|---|---|
| `skill_file` | Skill 文件、辅助脚本、模板、样例 |
| `skill_package` | 要导入成工具集的标准 Skill 包 |
| `mcp_package` | 要注册成工具组的私有 MCP 包 |
| `scene_package_logo` | 能力容器 Logo 图片 |
| `tool_test_fixture` | 真实工具取样或冒泡时需要落入隐藏 `/workspace` 的本地测试文件 |

**四个 action**，本地新文件只能三跳：

| action | 说明 |
|---|---|
| `prepare` | 申请上传地址，**必须**传真实字节数 |
| `complete` | 确认上传，换回文件引用；凭据**必须**来自同一工单、同一用途的 `prepare` |
| `from_url` | 已有可信 HTTPS 地址时直接导入；**仅支持** `skill_file`，地址不得指向内网 |
| `export` | 按资产 ID 把编排型 TPE 脚本或 FastAgent 提示词导出成可下载文件 |

**不接收** base64。

**绑定到资产**：资产还没创建，在创建调用里直接带文件引用；资产已存在，用 `upload_skill_files` 补挂；能力容器的场景 Skill 文件用 `scene_package_manage(update)` 带引用；Logo 用 `update_scenario_package_logo`。缺省相反要记住：`scene_package_manage(update)` 缺省 merge，保留既有文件；`upload_skill_files` 缺省 replace，省略参数会覆盖整个 Skill 目录，补挂单个文件时显式传 `skill_files_mode="merge"`，定点删除用 `remove_skill_paths`。

**同名不同物**：制作期的 External MCP 工具 `file_to_url` 与编排型 TPE 脚本运行期的沙箱工具 `file_to_url` 只是名字相同。

| | 制作期 External MCP `file_to_url` | 运行期沙箱 `file_to_url` |
|---|---|---|
| 在哪调 | 你在 MCP 里调 | 脚本里 `tool("file_to_url", ...)` |
| 入参 | `action`、`purpose`、上传凭据 | `file_paths`：`/workspace` 绝对路径列表；可选 `url_ttl`，8h、1d、3d、7d，默认 1d |
| 返回 | `data.file_ref` | `results[]`，每项 `{"workspace_path", "url", "error"?}`，另有 `url_validity` |

脚本侧三条：返回里的键是 `workspace_path` 不是 `file_path`；逐项检查 `url` 为 `null` 的失败项，不拿别的文件的 URL 顶上；URL 有时效，用完即弃，不落库不进交付。
