# 验收清单（人判项）

机器能判的交给 `otpe_manage(action="verify")`、`npm run verify` / `npm run verify:release`、路线冒泡和结单门，这里不重复。下面是只能由你判断的项，G6 逐条写「通过 / 不适用」加一句依据，写进本段阶段文档与工单 checkpoint；做不到的列为未验证项，写进交付报告。

| 查什么 | 证据 | 不过怎么办 |
|---|---|---|
| 1. 确认页每一行都能在资产里找到：规则行有脚本步骤，模型行有 FA，人行有页面或表单 | G3 编译结果与实际资产 ID 对照 | 回 G4 或 G5 补 |
| 2. 用户在在线预览里能走完每条路线：从入口到看到结果，中途要补的信息有地方补 | 开发者在在线预览里的操作结果 | 回 G5 修页面或回 G4 修路线 |
| 3. 结果看得懂：没有路线 ID、项目 ID、`PRJ-…` 任务标题、Runtime/编排等内部术语、字段名、原始 JSON 和原始时间串直接给用户看；`npm run check` 无「界面直接显示」警告 | 预览截图或页面描述 | 回 G5 改展示 |
| 4. 「做不成的时候」真的按确认页发生：至少人为制造一次失败看表现 | 失败那次的 `run_id` 或 `project_id` 与页面表现 | 回 G4 改失败出口 |
| 5. 模型行的输出用真实样例人眼核过一次，不只看形状 | 真跑或 `full_run` 冒泡的输出摘录 | 回 G4 改提示词或输出字段 |
| 6. 数据管理页只开放用户该改的列；系统和路线写的列只读并标来源 | 页面与列注释对照 | 回 G5 |
| 7. 只读权限下发起和写入入口都置灰并说明原因 | 用只读身份或 `permission='view'` 看一次 | 回 G5 |
| 8. 费用与副作用和确认页一致，没有多调工具、多发消息 | 真跑日志里的工具调用清单 | 回 G4，或回 G1 补确认 |
| 9. 离开再回来：关掉页面、换设备后任务和结果能找回，从正确位置继续 | 刷新或重新打开预览后的状态 | 回 G5 |
| 10. 交付报告里每一句「已验证」都能指到证据，未验证的明确列出 | 报告与工单 checkpoint 对照 | 改报告 |

按应用类型追加：

- 有中途表单：挂着表单时再提交入口表单，界面给出「上一张表单还没完成」而不是改走新项目。
- 有写库路线：同一业务重复发起不产生重复行。
- 有文件交付：附件能在交付审阅页下载，内容是本次运行的产物。
- 有自动化：`business_ui_automation(action="run_once")` 跑一次，运行记录与消息中心的表现符合确认页。
- 有授权或充值：取消、失败后重试、解除后列表刷新都走一遍；不用生产真实授权或真实支付做自动化测试。
