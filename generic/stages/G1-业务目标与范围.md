# G1 业务目标与范围

本阶段确定**为什么做、交付什么**。产出一份业务基线：服务对象、用户带入什么、经过什么、得到什么、什么算合格、什么不做。方法见 P1 业务访谈、价值判断与领域依据。

## 1. 进入依据

开发者给出下列材料中的**任意一种**即可进入：一句业务目的、PRD、SOP、参考项目、已有应用的问题。**禁止**要求先交齐完整产品文档。材料不足时由 Agent 提案补齐，并标明哪些是推断。

进入前已完成总入口的任务识别与工单 Gate。接续任务先盘点已有业务基线，只补未满足项。

## 2. 本阶段建设

1. **完整理解材料。** 逐字读完，把内容分为三栏：已知事实、Agent 推断、待确认项。有真实执行项目时，按 P1 第 2 节提炼现有工作法与困难。
2. **诊断目标。** 回答五个问题：使用者要完成什么业务结果；当前怎么完成；困难在生产、专业判断、协作还是持续管理；直接做一次、复用已有能力、制作能力容器、制作完整应用哪一种是必要的；哪些信息必须向业务方确认。框架见 P1 附录。
3. **把动作补成结果。** 写出用户带什么进入、经过什么、最终得到什么。"生成周报"必须补成"负责人能据此判断哪些门店需要跟进"。业务目标分三层：客户期望改善什么、应用负责交付到哪里、一次运行完成什么。三层**不得互相冒充**。
4. **草拟正例与反例。** Agent 先写，业务方修正。来源不足时标为合成示例，**禁止**冒充真实案例；业务方不会写案例时**不得**停住。方法见 P1 第 3.2 节。
5. **定义初始评价方式。** 质量、时间、成本、操作负担各给一条可检查的判断依据。没有基线就写待测，**禁止**编造改善幅度。
6. **写明采购理由与合格交付物。** 客户为什么买；什么算合格：事实无误、素材相符、满足约定要求、文件可用、修改被处理。用户按"通过"只说明接受动作，不替代合格判定。
7. **审查 U1 至 U8 的适用范围。** 逐项判断本应用是否提供首用、续用、历史、修订、长期偏好、跨应用、临时编排。不支持某能力不等于该项不适用；既有承诺**不得**静默删除。

## 3. 给开发者看什么

默认展示三样：**一页业务简报、可检查的目标产物样例、首次与再次使用的短流程**。展示的问题是"如果现在交付这个，你能否完成原来的工作"。**禁止**先展示数据库、任务点或页面。

业务简报固定内容：服务对象与情境；用户带入、经过、得到；正例与反例及其来源；三层目标；采购理由与合格定义；不做什么与先停条件；未知项与验证办法。每条标注来源类型：事实、推断、未知、质疑。质疑至少覆盖三条：客户要的也许不是这个产物；基础组件容易获得，凭什么用你的；模板复制的是方法，不是页面。

## 4. 要确认哪些边界

服务对象与规模；输入来源与可用权限；必须交付项；明确不做项；需要人判断的事项；对外动作，包括发送、发布、写入外部系统。每项区分**硬限制**与**可协商**。

确认方式：Agent 出决策卡，内容固定为当前问题、证据、推荐、替代、选择后改变什么、验收怎么看、需要决定什么。只聚焦关键分歧，**禁止**逐章全文确认。

## 5. 门禁 Checklist

每条必须引用适用 U 项的分阶段结论。完整表见 G 门禁检查清单。

- `G1-01` 首次、处理中返回、查看历史、再次使用的目标分别说明。对应 U1。
- `G1-02` 制作完整应用的理由成立；一次性工作不进入完整流程。
- `G1-03` 关键交付有样例与不合格反例；"专业、好看、智能"已转成判断依据。
- `G1-04` U1 至 U8 适用范围已审查；事实、假设、授权分开记录。
- `G1-05` 每项必须能力都有后续验证责任；未知项未被当作事实。

## 6. 证据与结论

产出**业务基线初版**：简报、样例与来源、决定记录、待测假设。落工单检查点 `business_baseline`；U1 至 U8 适用性判断表落 `behavior_scope`。

本阶段的结论只到"目标与范围已对齐"，**不宣称**能力可行。

## 7. 失败回退

必要目标仍不清：不通过，转入只读调查补事实，**禁止**创建正式资产。业务方改范围：更新基线，重新过门禁。
