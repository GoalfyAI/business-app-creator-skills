# 业务档案预填与读写

业务场景包如何消费用户的长期业务档案：入口表单预填、执行中读取、终局沉淀。三项能力相互独立、全部可选；不声明则运行时与现状零差异。定位与阶段职责见 S2 第 8 节。

## 1. 何时声明

同时满足才用：

1. 业务包服务于用户的**长期业务对象**（门店/账号/品牌/供应商等），不是一次性任务；
2. 该对象**已有官方档案模板**（用户开通后由该模板实例化出私有数据集）；
3. 场景包与档案模板**同业态**——预填按模板强绑定，跨模板不生效。

不满足任一条 → 不声明 `archive_binding`，正常制作。

## 2. 字段对齐是前提（核心）

`field_map` 每一条把路线 `input_schema` 的一个字段（`target`）对齐到模板某表的一列（`table.column`）。没有这层对齐，预填无从建立。所以：

- **`input_schema` 字段要向模板顶表字段看齐**：设计要用档案预填的路线时，其 `input_schema` 字段应参照所绑模板的**顶表（承载核心业务实体的主表，如账号档案的 `account_assets`、门店档案的 `store`）字段**——同一业务事实用一致的语义与类型命名，`target` 才能对齐到顶表 `column`；
- **先读模板再定义**：先用 `get_dataset` 或模板快照读清顶表有哪些字段，再定义路线 `input_schema`，让两者从一开始就能对齐；
- **对不上就没有预填来源**：模板顶表里没有对应列的字段就是没预填来源（正常，不是错误）——不要为凑映射改列名或引用不存在的列；
- **反向修正**：关键字段对不上顶表时，回 S1 调整 `input_schema` 设计，不在 `field_map` 里硬凑。

## 3. archive_binding 声明（`workflow_orchestration` 路线级，与 `entry`/`nodes`/`delivery` 平级）

```json
"archive_binding": {
  "template_ref": {"id": 29, "min_version": 2},
  "field_map": [
    {"target": "account_name", "table": "account_assets", "column": "account_nickname",    "mode": "latest"},
    {"target": "positioning",  "table": "account_assets", "column": "account_positioning", "mode": "latest"},
    {"target": "budget_level", "table": "account_assets", "column": "group_buying_status", "mode": "latest", "enum_hint": true},
    {"target": "package_pick", "table": "verifications",  "column": "package_name",        "mode": "list", "label_column": "package_name"}
  ],
  "archive_relevant": {
    "entry":  [{"field": "account_name", "table": "account_assets", "column": "account_nickname"}],
    "output": [{"field": "final_copy",   "table": "note_records",   "column": "note_title"}]
  }
}
```

- `template_ref`：绑定档案模板；`min_version` 是实例可用的最低模板版本，缺省 1。
- `field_map`：字段映射（第 2、4 节）。
- `archive_relevant`：终局要回写档案的字段（第 5 节）。可选，不沉淀就不写。

## 4. 三种字段模式

| mode | 语义 | 适用 |
|---|---|---|
| `latest` | 取该表当前事实最新一条的该列值；`target` 必须是标量字段（string/number/integer/boolean） | 顶表标量事实：店名、定位、语气 |
| `list` | 取该表候选行（`label_column` 作展示名、`column` 作值），渲染成下拉/候选卡 | 明细表一对多选一：从历史套餐里选 |
| `latest` + `enum_hint:true` | 档案原值与目标枚举可能不同构（如"人均80-120"→低/中/高），平台会做语义转换 | 需映射到 `input_schema` 固定枚举的字段 |

## 5. 硬约束（Hub 发布校验会逐条拒）

- **禁 SQL 片段**：`table`/`column`/`label_column` 只能是小写字母开头的 snake_case 标识符；
- `table`/`column` 必须真实存在于 `template_ref` 指向的模板版本快照；
- `target` 必须是路线 `input_schema` 声明的字段；`latest` 的 `target` 必须是标量；
- `archive_relevant.entry[].field` 必须在 `input_schema`；`output[].field` 在交付节点 `output_schema` 里；归档提示 `table`/`column` 要么都省略、要么都给且真实存在。

发布报错精确到字段，按报错改**同一份契约**，不要发明兼容字段。

## 6. 终局沉淀（`archive_relevant`，可选）

要让路线交付结果回写用户档案，就在 `archive_relevant` 标注字段即可，平台在交付终局自动沉淀：

- `entry[]`：标注入口表单里代表用户亲述事实的字段；
- `output[]`：标注交付输出里应长期保留的结论字段。

不标注就不沉淀。**不要在 Workflow 脚本里自行拼档案写入**——沉淀只通过 `archive_relevant` 声明。

## 7. 执行中读档案：archive_context FA（只在写不死映射时用）

**能用 `field_map` 声明的字段，绝不用 FA。** 只有当某节点需要"按档案实况探索"、制作期无法预先声明要取什么（如"结合该店历史投放偏好和禁用表达生成文案"）时，才起档案读 FA。脚本里：

```python
result = tool(archive_context_fa, _output={
    "type": "object",
    "properties": {
        "archive_available": {"type": "boolean"},
        "brand_tone":   {"type": "string"},
        "banned_words": {"type": "array", "items": {"type": "string"}}
    },
    "required": ["archive_available"]
}, query="提取本店品牌语气与禁用表达，用于笔记生成")
```

`create_fast_agent` 制作纪律：

- `tool_group_ids` 只挂官方 `GOALFYAI_TOOLSET_business_archive_read`（只读），**不挂任何写工具**；
- `_output` 必含 `archive_available`（boolean, required），其余是本路线真正消费的切面，每个都有下游 `input_mapping` 引用；
- **空档案协议（违者会 fail 整条 business）**：FA 提示词必须写明"工具返回 `archive_available=false` 或无相关内容时，立即以 `{"archive_available": false}` 收口，禁止重试、报错或编造"；
- 下游节点把 `archive_available=false` 当缺省处理；每 business 至多起一次。

## 8. 制作 checklist

- [ ] 第 1 节判据三条都满足才声明；
- [ ] 先读模板顶表字段，再定义 `input_schema`，二者语义/类型对齐；
- [ ] `field_map` 的表/列先核对存在于模板快照；`latest` 配标量 `target`、`list` 配 `label_column`、需枚举转换标 `enum_hint`；
- [ ] `entry.input_mapping` 的 `path` 用 `$.<单段字段名>`（嵌套路径拿不到预填）；
- [ ] 入口表单里被预填的字段允许用户改，不设只读；
- [ ] 要沉淀的字段标进 `archive_relevant`，不写脚本内档案写原语；
- [ ] 需执行中语义读档案才加 archive_context FA（只挂只读工具集 + 空档案协议）；能声明映射的不加。
