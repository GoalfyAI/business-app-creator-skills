# 应用验收检查清单

> A4 预部署完成后**逐条执行**：每条给出 通过 / 不适用 的判定并留下依据；整体宣称"验收通过"而没有逐条判定的，视为未验收。验收依据是当前部署物、真实模板 schema 与预部署环境的真实运行——页面能打开、请求已受理，都不能代替这里要求的证据。

## 一、契约与调用

- 与 Max 的全部交互符合 C组契约：启动编排是 §4.1 的 `chat.start + metadata.submit_data`（project_id 照传，四件套齐全，`content` 空串），运行中交互是 §5 三次握手；没有发明字段或改语义。
- 创建态/进行态分界成立：新建在表单提交时创建项目；复用下拉框的选项只来自后端项目列表（无本地记录）；发起后跳转项目页；项目页内不存在发起新编排的入口。
- 提交按钮防双击生效；`server_ack` 未被当作受理结果，提交 loading 到 `business_interaction_result` 才结束。

## 二、后端

- 全部响应经 `ok/okEmpty/list/fail` 构造：字段为 `msg`、`data` 是非 null 非数组对象、业务失败仍 HTTP 200、自定义码 ≥1100；平台保留码（1~999）未被后端发出。
- 每个写接口幂等（用户手动重试不产生重复数据）。
- 每个 `async` 路由有 try-catch 或 `next(error)` 兜底；无请求会 hang 到超时。
- 数据库判空在函数体内；模块顶层无抛错路径。
- 无 `CREATE TABLE` / `ALTER TABLE`；无 information_schema 查询（结构读 manifest）。
- 单查询均在 `statement_timeout`（10s）内；列表接口有分页。
- 身份一律取自宿主注入头（`getContext`），无自造鉴权、无第三方密钥假定。

## 三、数据面

- schema 真名零硬编码：所有查询经 `tableOf(handle, table)`。
- 逐列 COMMENT 可编辑性声明齐全（`[editable:user|agent|system] 业务说明`），`describe` 反读可见；无声明列已按 user（最保守）处理。
- 所有写入带来源标记（`user_edited` / `generated`）并落库。
- 文件只存 workspace 路径索引，后端不收文件体。
- 大数据经 `project.upload`，接口请求均 ≤256KiB。

## 四、编辑（用户自主编辑信息）

- 数据管理页只对 `editable:user` 列开放编辑；`agent`/`system` 列只读展示且界面有区分。
- 前端表单校验与后端写权校验一致；后端拒绝的写入在界面呈现可读错误（信封 `msg`），不静默失败。
- 删除有确认语义（软删或二次确认，按 A1 设计）；批量操作有范围提示。
- ***用户编辑过的字段未被生产回流静默覆盖***——按 A1 冲突规则验证一例：先手动改，再跑一次生产，检查该字段。
- 编辑后的改动即时反映到看板/列表（或明确标注刷新时机）。
- 审计可查：任一行能回答"谁改的、何时改的、来源是什么"。

## 五、看板（展示信息）

- 每个数值可溯源：能说出来源表与查询口径，抽查两个指标与直接 SQL 结果一致。
- 空数据状态完整（新用户零数据时页面可用且有引导）。
- 统计口径与编辑实时性有说明（实时/延迟多久）。
- 大列表分页；无单请求超时。
- 图表在窄屏与明暗主题下可读。

## 六、前端通用

- 用户可见文案全部简体中文；无开发术语直出（Pending/Workflow/Schema 等）；无内部 ID、原始 JSON、workspace 路径、堆栈外显。
- 契约字段的 description 未被搬上界面当说明文案；把常驻解释性文字删掉界面仍可用。
- 渲染核对用真实数据（预部署环境），非 mock；生产产出的业务字段完整呈现。
- 同一份业务事实只有一个数据源：服务端知道的事实以服务端为准，本地状态只承载草稿态。
- 破坏性动作（提交/删除）不在"同一位置按条件切换"的控件上。
- demo 的页面结构与视觉未被复用；设计有具体参考点与唯一识别点，非空泛形容词。
- 刷新、深层路由直开、权限变化、错误恢复路径可用；深链对账读服务端权威数据非本地镜像初值。

## 七、构建与测试证据

- 前端 `npm run check`、后端 `npm test`（含信封契约自检）全绿。
- Playwright 页面专属用例全部通过；覆盖表含四类页面，编辑场景（写权/误删/编辑后刷新）与看板场景（空态/分页）未遗漏；断言谓词证明过自己能失败。
- SaaS 链路闭环在预部署环境完整走通一次：发起 → 生产 → 回流 → 编辑 → 看板刷新。

## 八、裁决和输出

- 任一契约违约、信封违约、写权失守、用户编辑被覆盖、构建失败或链路未闭环，裁决为 `blocked`；应用不得发布。
- 通过时输出并写入工单：`passed`、应用版本、依赖的场景包版本、覆盖的页面与接口清单、剩余盲区（明说未验证什么）。
