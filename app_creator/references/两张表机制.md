# 两张表机制（应用版）

自 scene-creator 平移：指纹绑状态的累加机制原样沿用，只换分组对象。本文是操作细则正本。

## 1. 双副本

| 副本 | 位置 | 职责 |
|---|---|---|
| 本地工作副本 | `app-{应用标识}/应用结构表.md`、`app-{应用标识}/结果检查表.md` | 每轮直接读它定位进度；修改先落这里 |
| 工单权威副本 | `task_manager(insert)` 结构化条目，`metadata.evidence_type` 分别为 `app_structure_snapshot` / `result_checklist_snapshot` | 跨轮次续作的唯一事实源；本地变更后**必须**回写快照 |

续作时从工单**最新快照**重建本地文件，禁止沿用残留本地文件不对账。

## 2. 应用结构表

按三类对象分组：**每个页面、每个后端接口、每张模板表**各一组。条目结构：

```json
{
  "group": "<page:看板 | api:POST /notes | table:profiles>",
  "items": [
    {
      "id": "<条目标识>",
      "content": { "what": "<这一项承诺做什么>", "checks": ["<挑战判据要点>"] },
      "hash": "<内容指纹>", "status": "pending", "evidence": null, "waive_reason": null
    }
  ],
  "challenged": false
}
```

挑战判据（应用版）：

- **页面组**：职责单一且归入四类原型之一；数据来源与动作去向明确；`editable` 区分在设计中体现；
- **接口组**：信封、幂等、写权校验、分页/超时预算逐项可答；写接口的来源标记落点明确；
- **模板表组**：数据设计五问（存什么/逐列可编辑性/审计/冲突规则/回流语义）全部有答案；逐列 COMMENT 声明齐备。

`challenged`（组级布尔）：全组条目 `passed`/`waived` 后置 `true`；任一条目回退 `pending` 同步回退。全部组 `challenged=true` 才算"表已出"，才能提交开发者确认。

## 3. 结果检查表

```json
{
  "id": "<稳定条目标识>",
  "kind": "test_case | frontend_check | backend_check",
  "content": {
    "input": "<测试输入；test_case 必填，来自 A1 正反例>",
    "expected": "<期望产出/期望行为>",
    "polarity": "positive | negative"
  },
  "hash": "<内容指纹>", "status": "pending", "evidence": null, "waive_reason": null
}
```

- `test_case` 来自 A1 的典型用户操作正例与数据边界反例（含"用户编辑不被生产覆盖"这类共治用例）；
- `frontend_check` 来自 A3 的 Playwright 门；`backend_check` 来自 A3 的接口测试；
- **闭合必须用预部署环境的真实数据**（A4），mock 不足以闭合；
- 修订类任务从上一工单最新快照继承全部条目，指纹对新版本重算、受影响条目回退 `pending`——修订不坏旧例的回归机制。

## 4. 状态机与指纹（与 scene-creator 完全一致）

```text
              （新建 / 关联内容变化 → hash 变化）
                        │
                        ▼
      ┌────────────  pending  ────────────┐
      │ 挑战或校验通过                      │ 确认不适用/开发者接受偏差
      ▼                                   ▼
    passed                             waived（必须带 waive_reason）
      │                                   │
      └──── 关联内容再次变化 → 回退 pending ──┘
```

- 指纹对条目 `content` 与关联源（代码片段、schema 定义）的规范化文本取摘要；时间戳等无关变动不计入；
- **只处理 pending**：`passed`/`waived` 不重复检查——控制重复成本的核心机制；
- 修改关联内容后必须重算指纹，变化即回退 `pending`（含组级 `challenged` 回退）；禁止带着过期的 `passed` 推进；
- `evidence` 置 `passed` 时记录判定依据（挑战结论、测试运行标识、核对记录的工单条目位置）。
