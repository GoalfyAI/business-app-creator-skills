# A1 应用设计

从选定的已上线场景包，推出业务应用的完整设计：数据、页面、回流语义、产品文档与原型，经开发者一次确认后进入制作。

## 1. 进入前提

- 目标场景包**已上线**（未上线转 scene-creator 先完成）；
- 有 `write` 工单；
- 开发者已说明应用的业务意图（给谁用、解决什么持续经营问题）。

## 2. 契约基线提取

从目标场景包**反读**四类事实，作为一切设计的确定性输入（禁止推测）：

| 来源 | 确定什么 |
|---|---|
| `schema/forms/*.json` | 发起表单的字段、类型、必填、file 字段 |
| `schema/orchestrations/*.json` | 有几条路线、入口表单、交付审阅动作 |
| Workflow `output_schema` / `display` | 生产产出的业务字段——**回流入库的字段来源** |
| 业务事件契约 | 有无阶段状态可供进行态展示 |

## 3. 数据设计（本阶段的重心）

应用表是**用户的业务资产**，不是内部存储。逐表设计，每表回答全五问：

1. **存什么**：用户信息组（场景包所需 + 个人信息）、业务历史、项目产出、看板统计所需字段、"读数据优化后续选择"的预留字段；
2. **逐列可编辑性**（约束 9）：`user`（用户资产，生产不得覆盖）/ `agent`（生产写入）/ `system`（仅系统）——落成每列的 PG 注释声明 `[editable:x] 业务说明`，业务说明同时是给 FA 和平台展示的字段语义；
3. **审计**：谁改的、何时改的、来源标记（`user_edited` / `generated`）落在哪些列；
4. **冲突规则**：用户编辑过的字段，下次生产是跳过、并列存草稿、还是提示用户——***没有"静默覆盖"这个选项***；
5. **回流入库语义**：生产产出**直接入库**还是**先作草稿、用户在编辑页确认后入库**——按业务风险定（对外表达类建议草稿确认，内部统计类可直接入库）。

产出：模板 schema 草案（表 / 列 / 类型 / 逐列注释声明），交 A2 落成真实模板。

## 4. 页面设计（四类原型）

按 SaaS 链路把页面归入四类原型，逐页给出：用户在这做什么、数据从哪读、动作往哪发。

| 原型 | 职责 | 设计要点 |
|---|---|---|
| **看板**（展示态） | 聚合统计、图表、列表——用户看现状、决定干什么 | 每个数值可溯源到表和查询；空数据状态；统计口径与编辑实时性说明；大结果分页 |
| **数据管理**（编辑态） | 用户直接增删改业务数据 | 只开放 `editable:user` 列；批量操作与误删确认；表单校验与后端校验一致；改动即时可见 |
| **业务发起**（创建态） | 动作按钮：新建 = 表单提交时建项目、再由 SDK 发起编排运行；复用 = 项目下拉框用户选中、在该项目里发起 | 下拉框选项只来自后端项目列表；提交防双击；发起后跳转项目页 |
| **项目页**（进行态） | 看进度、应答服务端下发的运行中表单（下发 → 填写应答 → 业务确认的三次握手） | 不在此发起新编排；结果回流后引导回看板/编辑页 |

## 5. 产品设计文档与原型确认门

- **竞品调研**：先问开发者有无参考（品牌规范、喜欢的产品）；没有再调研 3 个以上同类产品（模块划分、交互、视觉层级），截图报告留存进工单；
- **产品设计文档**：产品定位、四类页面的划分与流转、模块决策账本（含明确不做的）、文案与术语检查（契约字段 description 不上界面）、一句话风格主张。验收标准：不懂前端的人能读完并提得出意见；
- **本地可交互原型**：生产级、所有路由可开、每页有贴合业务的演示数据、主动线可点通；只跑本地**绝不部署**；交给开发者前先用 `impeccable` 做一轮 critique + audit；
- **一次确认**：设计文档 + 原型本地地址一起交开发者；***确认后才进入 A3 正式编码***。

设计与构建全程按 [前端设计工作流](../references/前端设计工作流.md) 执行（理解产品 → 定方向 → 设计交互 → 组件构建 → 工艺打磨 → 真实渲染修正 → 交付）。

## 6. 出口条件

- 契约基线四表已反读并记入工单；
- 数据设计五问逐表回答完毕，模板 schema 草案（含逐列声明）经开发者确认；
- 回流入库语义、可编辑性与覆盖规则经开发者确认；
- 设计文档 + 原型经开发者一次确认；
- 应用结构表已初始化（按 页面 / 接口 / 模板表 分组），结果检查表已转入正反例种子。

以上全部满足后，落一条 `stage_exit` 账，进入 A2（模板 schema 工具可用时）或 A3。
