# A3 应用实现

按 A1 确认的设计完成前后端编码与本地验证。工程细则的正本在脚手架仓（见路由器第 7 节正本地图），本文只写应用制作特有的纪律与顺序。

## 1. 进入前提

- A1 设计确认门已通过（设计文档 + 原型经开发者确认）；
- 模板 schema 可用（A2 定稿；A2 工具未上线期间由平台侧同学手工建好，拿到 handle 与 manifest）；
- 脚手架为 `goalfy-app-scaffold` 当前版本（前端 `src/` + 后端 `backend/` 双目录），首次修改业务代码前完整读取：根 `README.md`、`CLAUDE.md`、`src/sdk/docs/README.md`、`backend/README.md`。

## 2. 后端实现

**正本是 `backend/README.md`，动手前通读；本节是应用制作的落地顺序与易错点。**

按 models → services → routes 三层实现三类 API：

| API 类 | 内容 | 特有纪律 |
|---|---|---|
| **CRUD**（编辑回流） | 数据管理页的增删改查 | 写入前按**列注释声明**校验写权（`editable:user` 才接受用户写）；写入带来源标记 `user_edited`；***写接口必须幂等***；删除走确认语义（软删或二次确认由 A1 设计定） |
| **统计聚合**（喂看板） | 看板页的指标与列表 | 单查询 `statement_timeout`（10s）内；大结果**必须分页**；聚合口径与 A1 看板设计一致，每个指标能说出来源表和查询 |
| **生产回流** | 场景包产出入库 | 按 A1 的入库语义实现（直接入库 / 草稿待确认）；来源标记 `generated`；***`editable:user` 列不得覆盖***——按 A1 冲突规则处理 |

后端硬约束速查（正本细则在 backend/README，此处只列最易踩的）：

- 响应一律用 `response.ts` 的 `ok/okEmpty/list/fail` 构造——**字段是 `msg` 不是 `message`**、`data` 非 null 对象、业务失败也 HTTP 200、自定义码从 1100 起；
- 查询一律 `tableOf(handle, table)`，***绝不硬编码 schema 真名***；表结构用 `listTables()/columnsOf()` 读 manifest，不跑 information_schema；
- **禁 CREATE / ALTER TABLE**——要改表回 A2 改模板 schema；
- `async` 路由必须 try-catch（Express 4 不转发 rejected promise，漏写 = 请求 hang 到超时）；
- 数据库判空在函数体内（模块顶层判空 = import 即 throw = Pod CrashLoopBackOff）；
- PG 占位符 `$1 $2`；自增 id 用 `INSERT ... RETURNING`；
- 身份从 `getContext(req)` 取宿主注入头（隔离维度 = viewer × 实例；projectId 可能缺省）。

## 3. 前端实现

**正本是脚手架根 README 与 `src/sdk/docs/`；demo 只用于理解协议，禁复用其结构与视觉。**

- **SDK 4.0 两层**：顶层 sdk 管实例上下文与项目集合（`getProject/createProject`、inbox 聚合）；项目作用域能力全部经保留件 `useProject / useProjectDraft / useInbox`，组件内不绕开；
- **四类页面**按 A1 设计实现：
  - 看板：数据只来自后端统计 API；图表选型自由（无组件库锁定），但每个数值可点问出处；
  - 数据管理：控件按列类型渲染，**只对 `editable:user` 列开放编辑**（其余只读展示）；提交走后端 CRUD，错误按信封 `code/msg` 呈现；
  - 业务发起：新建 = 表单提交时按现有流程创建项目 → `chat.start`（C组 §4.1 原样，`metadata.submit_data` 四件套）；复用 = 项目下拉框（选项只来自后端项目列表）→ `chat.start` 带选中 project_id；提交按钮防双击；发起成功跳转项目页；
  - 项目页：进度与运行中表单按 §5 三次握手；`server_ack` 不是受理结果，等 `business_interaction_result` 才结束提交 loading；
- **一切平台调用经 SDK**：后端 API 走 `sdk.api.request`（path 纯路径、GET/DELETE 无 body、复杂查询 POST、≤256KiB）；文件走 `project.upload` 只传路径；禁 fetch/XHR/axios（ESLint 硬禁）。

## 4. 本地测试

正本 `docs/dev-host-testing.md`。顺序：

1. mock 4.0 下跑通四类页面主线（多项目实例剧本、两段式建项目）；
2. dev-host 连真后端联调（后端 `npm test` 信封契约自检先过）；
3. **Playwright 动态验收门**：按真实页面与契约动态编写用例，覆盖表**必须包含编辑场景（写权校验、误删确认、编辑后看板刷新）与看板场景（空数据、分页）**；基础冒烟不代表业务通过；
4. 断言谓词先证明自己能失败（哨兵先命中一次再计入通过）。

前端校验项与后端校验项转入结果检查表（状态 `pending`，A4 用预部署真实数据闭合）。

## 5. 出口条件

- 后端三类 API 实现且 `npm test` 全绿（含信封契约自检）；
- 前端四类页面实现，`npm run check` 通过；
- Playwright 页面专属用例全部通过，覆盖表无遗漏（含编辑与看板场景）；
- 应用结构表相关条目重挑战通过；前端/后端校验项已入结果检查表（`pending`）；
- 逐列可编辑性在实现中可验证：describe 反读声明与前端只读渲染、后端写权校验三者一致。

以上全部满足后，落一条 `stage_exit` 账，进入 A4。
