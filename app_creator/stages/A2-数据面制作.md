## 一期红线（建 schema 时必须落实）

- **业务应用项目只绑业务应用数据集这一个**：写权限是项目级放开的（`dataset_mode=writer` 会让项目绑定的所有长期数据集都可写），多绑一个就多放开一个；
- **模板表的 owner 定为服务账号**（而非用户写账号）：这样 `GRANT ALL` 不含 ALTER/DROP，"模板结构只增不改"从提示词升级为数据库级约束；agent 自建的新表归它自己、可随意改——这正是想要的边界。目前该硬护栏未落，模板结构仅靠 FA 提示词保护。

## 骨架（正文待写）

1. 按 A1 的模板 schema 草案，经模板 schema 工具创建模板 schema；
2. **每列同步写 COMMENT 可编辑性声明 + 业务说明**（`[editable:user|agent|system] 说明`，约束 9）；
3. 取 PG 连接本地验证：describe 反读确认表结构与逐列声明可见；
4. 写最小真实样例 + 跑 A1 设计的典型业务查询（看板聚合、编辑读写）；
5. 按 PG 报错与查询结果修模型；
6. 开发者确认最终表结构与逐列可编辑性 → 定稿（copy 语义生效：一用户一份）。

## 出口条件（骨架）

- 模板 schema 定稿，describe 可见全部声明；
- 典型查询在 statement_timeout 内返回预期结果；
- 定稿记录（表清单 + 声明摘要）写入工单，落 `stage_exit`。
