# 验收清单

验收条目之外，每个应用都要逐条判的人判项。机器能判的（`otpe_manage(verify)`、`npm run verify`、路线冒泡、结单门）不在这里重复。

每条写四种结论之一加一句依据（这个应用没有这一项的写「不适用」，不算结论），进阶段文档 G6 和工单 checkpoint。怎么测、证据要到什么程度、哪些情况能记「未测」及原因怎么写，都按 [证据与未测.md](证据与未测.md)；页面上的项在演示版上看。没通过的按 [按反馈改.md](按反馈改.md) 改，第 9、10 条做不到的回 ①。

| # | 查什么 | 证据 |
|---|---|---|
| 1 | PRD「每一步谁来做」每一行都找得到：脚本步骤有脚本，模型步骤有 FA 且是 PRD 定的那一档，人的步骤有页面或表单 | 施工单与实际资产、FA 模型配置对照 |
| 2 | 使用者能走完每条路线：从入口到看到结果，中途要补的信息有地方补 | 实际跑到终态的 `project_id`，加演示版从入口到结果页的步骤和截图 |
| 3 | 使用者看到的是 PRD「谁来用」写的样子，没有做成多人分工（审核、复核、共用数据） | 演示版首屏和导航截图，对照 PRD |
| 4 | 结果看得懂：没有路线 ID、项目 ID、内部术语、字段名、原始 JSON 和原始时间串直接给使用者看；前端检查没有「界面直接显示」警告 | 演示版截图或布局回归截图 |
| 5 | 「做不成怎么办」真的按 PRD 发生：每个失败条目都造过一次；造不出来的记「未测」并在报告「未测的」里逐条列出 | 失败那次的 `run_id` 或 `project_id`、怎么造的、页面表现 |
| 6 | 模型步骤的输出用真实样例逐条读过；要人判断的已把实际结果附进报告 | 实际跑或 `full_run` 的输出摘录 |
| 7 | 数据管理页只开放使用者该改的列；系统和路线写的列只读并标来源 | 页面与列注释对照 |
| 8 | 只读权限下，发起和写入入口都置灰并说明原因 | 演示版 Mock 设 `permission='view'` 的截图；Mock 做不到时记「未测」，原因「要用真实账号登录才看得到：平台登录身份」 |
| 9 | 花钱和对外动作和方案「运行条件」一致：没多调工具、多发消息、多写正式数据；实际花费和估算差得多的已告诉开发者 | 实际跑的工具调用清单与 `cost_credits`（新 SDK 应用读本次执行的，口径见入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)「积分」） |
| 10 | 用量：按 PRD 的上限跑得完，超出时有提示 | 接近上限的一批在 `workspace` 实际跑的结果 |
| 11 | 离开再回来：关掉页面、换设备后任务和结果找得回，从正确位置继续 | 演示版刷新、重新打开后的状态 |
| 12 | 报告和上线结果里每一句「通过」「已验证」都指得到证据，没验证的明确列出 | 报告与工单 checkpoint 对照 |
| 13 | 空库也能用：没数据时有引导或首次设置；资料不全、处理中、失败各有页面表现；存过的资料不让重填；发布后必须有的设定不依赖预览数据 | 演示版清空 Mock 数据后的表现 |
| 14 | 首屏与导航按使用者的业务任务组织；界面上没有 mock、运行状态、日志这类平台信息 | 演示版首页与导航截图 |
| 15 | 页面样子和方案「功能与页面」一致：开发者给的参考网站、截图、原型都做到了，不是只换了品牌色和圆角的起始应用 | 参考图与演示版对应页面并排截图 |

按应用类型追加：

- 有中途表单：挂着表单时再提交入口表单，界面提示「上一张表单还没完成」，不改走新项目。
- 有写库路线：同一业务重复发起，不产生重复行。
- 有文件交付：附件能在交付审阅页下载，内容是本次运行的产物。
- 有自动化：处理逻辑在开发工作集里冒泡跑一次符合 PRD；到点真触发记「未测」。
- 有授权或充值：演示版走到授权或付款窗口出现为止，取消、关闭后的页面表现照条目核对；真实授权和支付记「未测」（真实宿主桥接）。

## 交报告前自查

要改的按 [按反馈改.md](按反馈改.md) 改完再部署、再上线。

| 查什么 | 没满足时 |
|---|---|
| ④ 里确认过、发布后还要用的设定，是不是只存在开发工作集里（使用者从空库开始，看不到它） | 搬到代码默认值、场景包配置或首次设置入口（放哪按 `agenticapp-tool-data-template`） |
| 有外部平台授权或充值的 | 加载 `agenticapp-tool-integration`，按它的「交报告前核对」核一遍，结论写进上线结果的使用说明 |
| 新 SDK 应用：部署之后又改过编排 | 重新部署一次再上线；部署记录对着旧契约时，开发者之后发布会被拒（`BUSINESS_UI_CONTRACT_OUTDATED`） |
