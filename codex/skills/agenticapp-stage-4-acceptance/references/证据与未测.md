# 证据与「未测」

判每一条验收条目时读。

## 什么算证据

只认你自己这次取得的东西。部署成功本身、开发者的口头回报、他在在线预览或演示预览（含 Studio 里的演示）里看到的、已发布的版本，都不算。宿主提供的检查工具的机器结果可以作补充，和你在演示版上的操作分开记，不能代替页面条目的演示版操作。

| 条目要看的 | 怎么测 | 「通过」要的证据 |
|---|---|---|
| 业务结果：报告、内容、识别结果、写进库的记录、发出的消息 | `workspace` 实际跑；条目点名的样例没跑到的，照条目再跑一次 | 这次实际跑的 `project_id`（新 SDK 应用为 `business_id`）、`workflow_trace` 里对应步骤的摘要、库里查到的那一行（不写库的写拿到的产出） |
| 页面上的操作和显示：点哪、跳到哪、空态、提示文字、必填校验、打回和重新生成、只读置灰、离开再回来 | 演示版上用无头浏览器照条目操作 | 操作步骤、截图路径或断言原文、打开过的演示版路由 |
| 到点或有新记录时自动开始的 | `business_ui_automation(action="bubble")` 按自动化入口跑一次 | 冒泡的 `run_id` 与结果；「到点真触发」另列一条记「未测」 |
| ② 标「要人判断」的：能不能直接对外、语气像不像、业务判断对不对 | 照样做一遍，不下结论 | 实际结果原文附进报告，结论「好不好你说了算」 |

读写应用库的条目只有冒泡证据（读库返回 `not_a_business_app_project`、写库被 `ctx.dry_run` 跳过）时，记录写「冒泡无法验证真实读写」，不算通过，要回去用 `workspace` 实际跑；开发者说先别放到在线预览的记「未测」。

页面条目还要按 ③ 记下的业务含义核对文案和动作，加载中、空态、只读、暂停、失效都要看。只读置灰在演示版 Mock 里设 `permission='view'` 验；Mock 做不到时记「未测」（平台登录身份）。

## 外部平台授权条目

应用挂的路线要外部平台授权时（`agenticapp-tool-integration`「读授权摘要」），授权条目这样判。

新 SDK 应用：

1. 放到在线预览后，开发者先在在线预览里授权（③ 交棒前已告诉他）。他授权后，再调 `business_ui_manage(action="authorization_status")` 读一次摘要：看 `data.card_source`（`selection` 或 `candidates`），每张卡 `authorizations[]` 里 `scope_kind=preview` 那条的 `status`（`active` / `expired`，没有这一条就是没授权）。`next_action` 是给你的提示，不原样写进报告或说给开发者。
2. 本应用预览那一处是 `active`、卡来源是 `selection`，才用真实数据跑：开发工作集实际跑（`manage_goalfymax_project`，`business_ui_data_space="workspace"`，见 `agenticapp-tool-deploy`「实际跑」）或新 SDK 应用的路线冒泡，跑一条只读路线。只用只读路线和只读工具，不调写入、花钱或不可逆的工具。卡来源是 `candidates`（还没保存授权选择）时，先保存授权选择、重新放到在线预览，再读摘要，不直接跑。
3. 「通过」的证据：这次运行的标识（`project_id` 或 `run_id`）加需授权工具真实返回的摘要（如广告主列表几条），写法见验收报告模板「怎么测的」和「证据」。授权卡工具组的取样（`otpe_tool_test`）成功不算证据：取样用不到开发者在本应用预览里的授权。
4. 没跑通的，归进下面四类之一，写清谁做什么；不记「通过」，也不笼统写「未验证」。前两类读摘要就能判断，不用先跑。

| 看到的 | 记成 | 谁做什么 | 报告怎么写 |
|---|---|---|---|
| 摘要里本应用预览没有记录（撤销过的授权不返回，同样显示成没授权） | 没授权 | 开发者在在线预览里授权 | 结论（`result`）「没通过」；`seen` 写类别和谁做什么；`actual` 只附授权记录（账号、状态、到期时间）或工具错误原文，不带 `next_action`；`evidence` 里跑过的写运行标识，读摘要判断的写读摘要的时间和卡 |
| 摘要里本应用预览是 `expired` | 授权失效（过期） | 开发者在在线预览里重新授权 | 同上 |
| 摘要是 `active`，用真实数据跑时需授权工具被拒 | 按工具报错原文判：含 `This project is not permitted to use this authorization`，是这张卡不在当前授权选择里，或放到在线预览的版本里没有这张卡，重读候选、保存授权选择并重新放到在线预览后再跑；含 `No active account is authorized in this application`，记「没授权」；其他报错（如 `Error executing tool …`、第三方鉴权失败、平台 5xx）记「平台或第三方故障」 | 前一句：保存授权选择、重新放到在线预览；后一句：开发者在在线预览里授权（或重新授权）；之后再跑仍报同样原文的，记「平台或第三方故障」、交平台，附摘要和报错原文；其他报错交开发者或平台，附错误原文和运行标识 | 同上 |
| 工具调用成功但没有数据 | 查询成功但无数据 | 开发者确认账户里有没有数据 | 结论「好不好你说了算」；`actual` 写查询条件 |

- `authorization_status` 自己报错（平台报错、「不支持的 action」）时，不据此判断授权，按用真实数据跑的结果记；跑不了的记「未测」（真实宿主桥接）。
- 工具报上面两句授权原文时，执行状态里的「外部工具或数据源没有返回有效结果」「外部服务恢复后可以直接重新发起」、可重试标记和指向改脚本的修复建议都不适用：以工具报错原文为准，不改脚本，也不原样重跑。
- 写进报告和对开发者说时，用词按 `agenticapp-tool-integration`「读授权摘要」：说「放到在线预览」「用真实数据跑一遍」「用测试数据跑一遍」。

旧写法应用（挂场景包）：不跑路线冒泡取证（冒泡用的是全局授权），摘要不当本应用预览能用的证据；授权条目记「未测」（`untested.kind=bridge`），写明要账户持有人在预览里授权一次。

## 「未测」只能用于这几类

演示版能看的部分拆成一条照常测，其余部分结论「未测」、后三列写「无」，原因照下表原文写。第三列告诉开发者「没验证」意味着什么，让他自己判断要不要在意；不写成请他去看、去试，那是请他代测。

| 情况 | 原因原文 | 这意味着 |
|---|---|---|
| 依赖平台登录身份：按真实账号显示的内容、协作者打开自己的草稿、要另一种账号才看得到的 | 「要用真实账号登录才看得到：平台登录身份」 | 按真实账号显示的内容没确认过 |
| 依赖真实宿主桥接：从宿主消息提醒跳进应用、宿主弹出的授权与付款窗口、真实付款、旧写法应用（挂场景包）的真实授权；新 SDK 应用的真实授权按上面「外部平台授权条目」记 | 「要在 GoalfyMax 里打开才看得到：提醒、授权和付款窗口」 | 从提醒跳进应用、授权和付款这几处没确认过 |
| 依赖 Studio 里的真实窗口（只用于 Studio 宿主下 ② 单独写的「在 Studio 里打开看各页面」那一条）；其他页面条目照演示版结论写，不写成在 Studio 里也通过，也不因此记「未测」 | 「要在 Studio 窗口里打开才看得到」 | 页面在 Studio 窗口里的样子没确认过，内容和演示一致 |
| 演示版起不来，按「演示版页面验收」修过仍不行 | 「演示版跑不起来」，加做过的处理和错误原文 | 页面上的操作没确认过 |
| 开发者说先别放到在线预览，条目依赖已部署版本 | 「你说先不放到在线预览」 | 放到在线预览后的表现没确认过 |
| 条目要开发者手上的真实样本，他没有或没给 | 「缺你手上的样本：<哪一份>」 | 用你的真实样本时的结果没确认过 |
| 已部署，但部署后的页面你不能打开：线上能不能打开、线上页面的保存和读取走不走得通 | 「在线预览里的页面我打不开」 | 在线预览里页面能不能打开、保存和读取走不走得通没确认过；后台和数据库那一侧已经测过的写在别的条目里 |
| 路线含付费工具，`consent_status` 读到预览范围还没有同意，开发者暂时不点 | 「预览还没有付费同意：」加 `pending_tools` 里的工具名 | 这几条路线真跑的结果没确认过；在工作台「在线预览」里打开这个应用、在弹出的付费同意清单里点同意后，我再读一次状态并补测 |
| Studio 演示连接真实后端，无法安全取得已授权的空测试数据 | 「缺少可安全使用的空测试数据，未清空真实数据库」 | 空数据时的页面表现没确认过，其他可安全操作的页面条目继续验证 |
| 到点真触发 | 「到点触发要等真实时间」 | 到点会不会自动开始没确认过；发布并在应用的「自动化」面板打开规则后才会自动跑 |
| 使用者从目录或分享打开 | 「从目录或分享打开要先发布」 | 使用者从目录或分享打开的样子没确认过 |
| 失败条目按条目里的做法造不出这次失败，换过其他做法也不行 | 「测试中造不出这种失败」，加试过哪些做法 | 真遇到这种失败时页面怎么提示没确认过 |

写方案时就知道测不了的事，不写成验收条目，直接放进报告的未测（`agenticapp-stage-2-plan` 的验收条目写法）。

不在这张表里的情况不能记「未测」：要么测出结论，要么记「没通过」。
