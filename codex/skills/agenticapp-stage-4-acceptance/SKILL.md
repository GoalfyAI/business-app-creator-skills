# ④ 试用验收

开发者不会逐条去试。你拿证据证明每一条验收条目做到了，他只看你的报告，最后说「可以上线」或「第几条还要改」。

这一段最常见的错是**说通过了，其实没有证据**：把只用模拟数据跑通的冒泡当成业务验证、把页面显示「成功」当成做成了。他按你的报告说「可以上线」，没证据的条目就带着问题上线。

规矩以入口 `agenticapp-creator` 为准。做法不对 → 回 `agenticapp-stage-3-build`；要的东西不对 → 回 `agenticapp-stage-1-requirements`；他同意上线 → `agenticapp-stage-5-launch`。

## 开始前确认

- ③ 交了棒：应用根 `npm run verify` 全绿；每个功能做好了或写明没做成；读写应用库的路线在阶段文档 G4 有反读自查四项且都是「有」。缺一条就回 ③，不部署。
- 本轮需求都做完了。Studio 宿主下开发者随时能在「演示预览」看当前工程（`agenticapp-tool-workspace`「演示预览与在线预览」），他看了不算验收（硬门 3）；他在上面改过的文字或样式已在工作区里的工程里，按最新代码测。
- 手边有 ② 定稿的验收条目，以及 [references/验收清单.md](references/验收清单.md)。

## 按这个顺序做

1. **先在演示版上测**。不用部署的先做完：页面条目、`npm --prefix frontend run check`、布局回归、清空 Mock 数据看空库表现。演示版怎么起、怎么用无头浏览器操作和截图，见 `agenticapp-tool-workspace`「演示版页面验收」。做成：每个页面条目记了操作步骤、截图路径或断言原文、演示版路由（内容区空白的截图不算），`check` 与 `test:e2e:layout` 的结果已写进报告。
2. **放到在线预览**。② 的方案确认过就直接做，不再问。
   - 加载 `agenticapp-tool-deploy`，部署到 `success`。已经放过、这次是更新的，先在交接消息里照抄「接下来更新在线预览，几分钟内打开的页面可能提示没准备好，没保存的填写会丢，更新好我告诉你。」，更新好再说一句已更新。放好或更新好时说一句它在哪能看到（Studio「在线预览」或发布管理页「预览」），不给地址，也不请他去试。部署的必须是在演示版上测过的那一份；之后又改了代码或挂载，先重测受影响的条目再打包。报告里写明部署的 `source_sha256` 对应最后一次演示版测试。做成：`business_ui_manage(action="get")` 看到部署已写进当前草稿，`deployment_id`、`source_sha256`、`deployed_scaffold_version` 已记 checkpoint。
   - 开发者说先别放：不部署，依赖部署的条目记「未测」，照常交报告。
3. **工作集真跑**。有模型步骤、读写应用库或调外部接口时必做；只有脚本步骤且 ③ 的 `full_run` 已覆盖的可以不做，写明原因。做法见 `agenticapp-tool-deploy`「真跑」：
   - 先用 `dataset_template_workspace(action="connect")` 往开发工作集写好例子要用的测试数据，G6 记下写了哪些行；
   - 第一次真跑只跑一份最小的例子（一个品种、一家店），这一份就放齐容易出错的形状：空值、JSON 列、日期时间，不留到后面的例子。读回写入的行对了，再跑其余样例。整批一起跑，错一次就白花一批的钱，还看不出错在哪一份；
   - 验收条目里点名的样例都跑到；`workflow_trace` 逐步看，模型步骤的输出逐条读，写库的去库里查到那一行；
   - 读写应用库的路线，每条 TPE 用这次的 `project_id` 跑 `otpe_manage(action="verify")` 到 `passed`；冒泡和结单门豁免代替不了它；
   - 记下每个按钮实际花了多少（`cost_credits`，新 SDK 应用跑完用 `status` 带 `project_id` 查），和方案的估算比；
   - ③ 标「做好了，等在线预览时实际跑」的功能，真跑通过后补发「我先跑了一遍」，和验收报告分开发；
   - 失败就在同一草稿上改了再跑，每次只改一处，不同时改脚本和路线；不为排查另建试探用的 TPE、FA、工具集或场景包，也不靠单独上线场景包、上线应用或发布来排查。
   - 每次重跑前先在 G6 写这次失败的根因、改了什么、重测哪几条；写不出根因的不重跑，先查。
   - 做成：返回的 `business_ui.version` 是要验的那一版，`route_runs` 里各路线到了终态，读写应用库的每条 TPE 用这次 `project_id` verify 为 `passed`。
4. **逐条判定**。照条目的「用什么、按什么顺序做」做一遍，按「怎样算过」判。结论只有四种：**通过 / 没通过 / 好不好你说了算 / 未测**。结果不对、报错、该写的行没写，记「没通过」，按「按反馈改」修；「没通过」挡上线，开发者选了接受的除外。什么证据算数、「未测」只能用于哪几类，见 [references/证据与未测.md](references/证据与未测.md)。做成：报告「全部条目」每行的结论、怎么测的、看到的结果、证据都填了（未测的后三列写「无」），验收清单逐条有结论。
5. **主动造失败**。PRD 里每个「做不成怎么办」，按条目造一次失败看页面表现，报告写明失败是怎么造出来的。另外都要测：接近用量上限的一批、空库首次打开、同一输入跑两次会不会重复写入、必填留空、非法值、保存被拒后在同一张表单改正再提交、改了不保存就切页、手机宽度。做成：每个失败条目都有失败那次的 `run_id` 或 `project_id`、怎么造的、页面表现；造不出来的记「未测」并写试过哪些做法。
6. **交验收报告**。过了下面三道硬门才交，模板见 [assets/验收报告.md](assets/验收报告.md)。
7. **等开发者回话**。说哪条不对，照「按反馈改」做；说「可以上线」，按「交棒」写阶段记录，加载 `agenticapp-stage-5-launch`。

## 交报告前的三道硬门

1. 每条「通过」都有你自己取得的证据，报告「全部条目」表的后三列都填了；读写应用库的条目只有冒泡证据的，不满足；
2. 每条「未测」都属于 [references/证据与未测.md](references/证据与未测.md) 列出的一类，原因原文对得上；条目之外另列的没验证的事也算进「未测」的条数，结论行不写成未测 0 条；
3. 报告和交接消息只请开发者看报告、回话，不请他去在线预览、演示预览或正式入口里看、点、试。

有一条不满足：阶段记录 G6 写 `failed`，回第 3、4 步补齐，不请他说「可以上线」。

## 这一段要做对的判断

| 判断什么 | 判错的表现 |
|---|---|
| 证据够不够：只认自己取得的真实产出 | 页面显示「成功」就判通过；把代操作写的「视觉通过」记成开发者确认；开发者照报告说「可以上线」，没做成的跟着上线 |
| 四种结论分清 | 要人判断的条目替开发者下了结论；能测的写成「未测」，它会在上线结果里单列成没验证的 |
| 测的范围够：真实入口、手机宽度、边界输入、空库、按需求的量 | 只做演示版验收，真实入口打不开没发现；有「必填校验」条目却没测出留空能提交；从没按需求的量跑过 |
| 报告让开发者看得懂、证据点得开 | 报告里满是 `project_id`、`workflow_trace`；截图点不开 |
| 按反馈改后结论同步 | 报告改成 5 通过 4 没通过，制作进度还写着 12/12 |

## 你可能会这么想 → 实际

| 想法 | 实际 |
|---|---|
| 页面显示「成功」「已完成」，算通过 | 要看到真的产出：报告内容、库里那一行、发出的消息 |
| 冒泡跑通了，读写库的条目算通过 | 不算，按 [references/证据与未测.md](references/证据与未测.md)「什么算证据」记 |
| 开发者说他在预览里看过了，没问题 | 他的回报只用来定位问题，不作证据 |
| 页面地址请求返回 200，页面条目算通过 | 要有演示版上的操作步骤，加截图或断言原文 |
| 截图生成了就行 | 自己看一遍：文字挤成一字一行、被遮住、翻页或切换入口不在、首屏被空记录占满，都记「没通过」 |
| 部署成功、在线预览能打开，就算验过了 | 部署成功只说明容器起来了，条目还要逐条测 |
| 改完重跑通过了，写「重测过」 | 先核对跑的是改过的版本：只改 `tpe_ids` 时路线仍跑旧版，接口不报错 |
| 放到在线预览前再问他一句稳妥 | 方案确认过就不问；多问一次，他只会追问「这是什么」 |

## 按反馈改

开发者看过报告说要改，或还有条目没通过就要上线时，读 [references/按反馈改.md](references/按反馈改.md)。

## 记下来

工单 checkpoint、阶段文档 G6、方案页各记什么，Studio 宿主下报告怎么保存，读 [references/记下来.md](references/记下来.md)。

## 交棒

全部满足，再加载 `agenticapp-stage-5-launch`：

- 最近一次部署 `status=success`；开发者说先别放的，依赖部署的条目都记了「未测」；
- 每条验收条目的结论是：通过（带证据）/ 好不好你说了算（附了实际结果）/ 未测（属于允许的一类、写了原因）/ 没通过且开发者选了接受；已部署时，读写应用库的条目有 `workspace` 真跑的 `project_id`，对应 TPE 最近一次 verify 为 `passed`；
- ③ 标「做好了，等在线预览时实际跑」的功能，真跑通过后都已补发「我先跑了一遍」，和验收报告分开发；
- 验收清单逐条有结论；
- 报告过了三道硬门并已发出，开发者看过后明确说了「可以上线」（有「未测」照样算），原话已记；
- 「可以上线」之后用 `business_ui_stage` 写 G6：全部通过 `passed`；有未测或开发者接受的没通过 `partial`，`completion` 逐条写这些条目与原因。

## 出问题

| 现象 | 处理 |
|---|---|
| 部署或运行报错、开发者说在线预览打不开 | `agenticapp-tool-deploy`「常见错误」；源码问题回 ③；你不打开在线预览，不为此上线或下线 |
| 演示版或无头浏览器起不来 | `agenticapp-tool-workspace`「演示版页面验收」 |
| 协作者预览要求用新版脚手架重建 | 预期限制，见 `agenticapp-role-collab` |
