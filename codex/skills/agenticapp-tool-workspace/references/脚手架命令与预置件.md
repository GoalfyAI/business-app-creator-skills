# 脚手架命令与预置件

要跑工程命令、找工程里的说明文件时读。工程命令、测试范围与打包规则的正本是应用根 `README.md` 和 `package.json`，前后端细则在各自的 `README.md`；这里只列各命令做什么、什么时候用。所有命令都在应用根执行。

## 命令

| 命令 | 做什么 | 什么时候用 |
|---|---|---|
| `npm run scaffold:init -- --app-name "<应用名>"` | 生成三件套、方案页、阶段文档；默认在应用根 `git init` 并提交模板基线。可加 `--without-demo-pack`、`--environment`、`--no-git` | 新建应用 |
| `npm run scaffold:repair -- --app-name "<应用名>"` | 补齐缺失的工作区文件（含 `docs/proposal/proposal.css`），保留已有事实 | 接续时缺文件 |
| `npm run scaffold:bind -- --business-ui-id <ID>` | 原子回填 `app.json` 与 `WORKSPACE.md` 的应用 ID | 建好应用身份后、进 G5 前 |
| `npm run setup` | 准备工程（做哪些事见应用根 `README.md`） | 初始化、接续、升级后 |
| `npm run doctor` | 校验工作区文件、方案页版式、Git 根 | 初始化、接续、升级后；失败先修第一条 `FAIL` |
| `npm --prefix frontend run check` | 前端检查：路由模板、packs、业务页面直接显示内部 ID 的警告等 | 改页面后 |
| `test:e2e:layout`（脚手架自带，怎么跑见 `frontend/docs/dev-host-testing.md`） | 布局回归：无头、只连演示版内置 Mock，查 390/768/1440px 下的溢出与裁切 | 改页面后、④ 演示版验收 |
| `npm run verify` | 标准完整验证（`scripts/verify.mjs`） | 在工作区检查；③ 交棒前、升级后 |
| `npm run verify:release` | 完整校验并打出要上传的 `.pack/business-ui-bundle.tar.gz` | 部署前，见 `agenticapp-tool-deploy`「部署」 |
| `npm run dev` / `npm run dev:restart` | 后台起演示版（工作区里起的后端加 Dev Host） | 演示版联调、布局回归、演示版验收 |
| `npm run dev:status` / `npm run dev:stop` | 看演示版是否在跑 / 停掉 | 同上 |
| `npm run gen:pages -- --table … --label … --spec …` | 按表生成数据页、OpenAPI、后端 CRUD 与测试 | 做数据管理页，见 `agenticapp-tool-frontend`「数据管理页」 |

- 改了前端行为后另跑前端测试；类型检查和构建不能代替测试。
- `npm run dev` / `dev:restart` 起的是给你自己测试用的演示版，不是 Studio 里开发者看的「演示预览」窗口；后台启动由命令自己做，不用前台命令、`&` 或 `nohup` 自己拼。
- 部署用的源码包只由 `npm run verify:release` 产出，不用 `npm run pack`、直接运行打包脚本或手写 tar 代替。
- 命令、端口和首次安装 Chromium 的细节见应用里的 `frontend/docs/dev-host-testing.md`。

## 工程里的说明文件

| 要找的 | 读 |
|---|---|
| 组件、页面块、生成器、后端通用层的用法 | 脚手架根 `README.md`、`frontend/registry.json`（选件清单） |
| 页面规则、SDK | `frontend/README.md`、`frontend/docs/business-ui-guide.md`、`frontend/src/sdk/docs/` |
| 场景包契约格式 | `frontend/schema/README.md` |
| 审计列与 `buiTable` 写法 | `backend/README.md` |
| 演示版与无头浏览器 | `frontend/docs/dev-host-testing.md` |
| 升级时的固定层清单 | 目标模板的 `AGENTS.md` 与 `README.md` |

`frontend/registry.json` 缺失时，按「脚手架升级」核对当前工程、实际版本和迁移是否完整，不从文件存不存在猜版本；满足版本要求后再用页面块与生成器。

旧工程缺件、缺配置项、缺命令时，一律按「脚手架升级」升级，不照旧做法自写兼容代码。
