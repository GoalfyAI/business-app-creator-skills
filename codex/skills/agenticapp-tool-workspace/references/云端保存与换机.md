# 云端保存与换机

调 `workspace_push`、`workspace_pull`，或工作区里缺文件、换了机器时读。

## 三个工具

- `workspace_remote_status` 看云端状态，`workspace_pull` 取回，`workspace_push` 保存。
- `workspace_push` 是**整份覆盖**：这次没列出的旧文件会从云端删掉，所以每次都按同一份清单传全，不只传改动。

## `workspace_push` 传什么

`workspaceId` 用 `WORKSPACE.md` 里的工作区标识；`files` 每个文件传相对路径和完整文本：

| 传 | 不传 |
|---|---|
| 应用根下的 `app.json`、`WORKSPACE.md`、`workspace.json` | 方案页旧版副本 `docs/proposal/history/` |
| `docs/stages/` 下的阶段文档 | Studio 开发文档副本 `docs/studio/` |
| 方案页当前版 `docs/proposal/index.html` 和它引用的样式、脚本（Studio 下没有方案页就不传） | 截图等图片 |

不传的那些换机后用不到，还会让一次调用太大。

## 保存失败

参数不是合法 JSON、内容被截断、平台报错时：先检查每个文件的全文是否完整、转义是否正确（反斜杠、引号、换行），改好再传一次。第二次还失败：不结单，把两次的报错原文告诉开发者，按入口「报错和平台问题」提交。不能因为文件多或内容长而跳过这一步。

## 接续与换机

- 先读工作区；工作区里缺失或换了机器才 `pull`。已有内容先比较、保留差异再合并，不默认用云端覆盖工作区。
- 同步了对话记录、恢复了阶段文档，都不代表恢复了脚手架代码；代码以应用目录的 Git 与 `scaffold-release.json` 为准。已有应用先恢复真实目录与阶段资料，再核脚手架版本。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| `workspace_push` 只传改动的文件 | 每次按同一份清单传全，没列的会被删掉 |
