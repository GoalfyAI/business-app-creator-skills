# 界面风格、参考网站与 Logo

定页面外观前读：开发者给了参考网站或截图时怎么做，没说过要什么样时怎么自定，Logo 怎么做。

## 开发者要的样子优先

- 开发者说过要什么样，就做成那样：可以完全自己写前端，也可以大改起始应用和预置件；用不用预置件、用多少、改到什么程度由你按开发者要求判断。开发者要的样子优先于少写代码，只换品牌色、圆角不算满足他的风格要求。
- 预置件是少写代码的工具，不是页面的样子：选件先读 `frontend/registry.json`，用法读脚手架 README；样子对得上就直接用，不另用组件库重画已有的块；对不上就复制到 `pages/`、`components/` 改，或整页自己写。外壳（导航、布局、配色体系）也可以自己写，不受 `config.ts` 几个外观开关的限制。
- 不改 `ui/`、`blocks/` 源码，要改就复制出来改，免得丢掉脚手架升级能力。
- 可以换或加 UI 框架、组件库、图表库与样式方案，只要在脚手架的 React/Vite 运行边界内、能通过 `npm run verify:release`、不污染宿主页面。
- 示例页面（`examples/`）只用来理解协议，不复用它的结构和视觉。
- 自写或大改时保住的是平台行为：照样经 SDK 的 hook 和组件接平台；消息中心未读角标、历史记录找回、项目状态、表单应答、交付审阅、只读置灰、宿主保留区避让、亮暗跟随与预置件一致。拿不准就读对应预置件的源码照着实现。

**配色和亮暗跟随一起做**：开发者的原型、截图或参考站通常只有一套配色（多半是亮色）。把它原样用作亮色主题；暗色主题按同一套色相自己配（背景、文字、边框换成暗色，品牌色保持可辨），宿主切换亮暗时跟着切。原型只有一套配色不影响跟随宿主，跟随宿主也不改亮色下的原型配色。开发者明确说过「只要一种配色、不跟宿主」时照他说的做，并在页面说明里写一句「宿主切暗色时应用仍是亮色」。

## 参考网站

开发者给了参考网站，先拆成设计说明写进 G5 再实现，只借样式、不搬 Logo 图片文案，不保留对参考站接口或 CDN 的引用。

开发者给了喜欢的网站时，按它的样子做：

1. 先把参考站的版式、配色、字体、间距、组件形态拆成一份设计说明（颜色值、字号层级、圆角、阴影、栅格、导航形态），写进阶段文档 G5，再按它实现。做成：G5 里这份设计说明的颜色值、字号层级、圆角、阴影、栅格、导航形态各项都有。
2. 可以用网站复刻类工具从公开页面抽设计令牌和页面结构作起点，例如开源的 Ditto（MIT，可输出 Vite 代码，带 MCP）或 ai-website-cloner 类 Skill；也可以直接读参考页面的公开 HTML/CSS。抽出来的代码改造进本应用：数据一律经 SDK 与自家后端，不保留对参考站接口、脚本或 CDN 的引用，不引入 fetch / XHR。做成：应用代码里找不到参考站的接口、脚本或 CDN 地址，也没有 fetch / XHR 调用。
3. **只借样式，不搬内容**：参考站的 Logo、品牌名、图片、插画、文案和字体文件都不照搬（字体用开源或系统字体近似）；第三方代码按其许可证使用。
4. 只抓开发者给的公开页面，不用开发者的账号或会话；需要登录的页面、GoalfyMax 自身页面和在线预览地址不抓（入口「红线」的浏览器一条）。
5. 环境里没有这类工具或抓不到时，请开发者给截图，按截图实现，不因此降级成默认样子。

## 开发者没说过要什么样

按下表自定外观，不照搬脚手架默认。写页面前先定这几项，写进阶段文档 G5，一句话一项：

| 项 | 在哪配 | 怎么定 |
|---|---|---|
| 品牌色 | `src/app/config.ts` 的 `APPEARANCE.accent`（6 位 hex，优先于宿主主色） | 按行业与调性选：内容种草类偏红、金融财务类深蓝或墨绿、餐饮零售暖色、工具效率类冷静色。主色只用在可点的东西与品牌处；状态色（告警、成功、提醒）另有，不拿主色表示状态 |
| Logo | `BRAND.logo` | 见下面「Logo」 |
| 导航图标 | `NAV` 每项的 `icon` | 线性图标，同一套风格；不用单字方块 |
| 布局 | `LAYOUT` | `sidebar` 功能多、层级深；`topbar` 页面少（≤5 个）、内容要铺满；`topbar-sidebar` 功能多又要品牌感（顶栏放品牌与通知、账号） |
| 圆角 | `APPEARANCE.radius` | `sharp` 数据密集的工作台；`default` 通用；`round` 面向消费者、内容类 |
| 首页重点 | `pages/HomePage` | 按使用者每天打开要先看什么来组织（经营数据、待办、内容库、最新结果），见 SKILL「首屏与导航」；`HomeBlock` 可用作骨架，内容区按业务自己拼 |

- 缺省蓝色、名字首字方块、单字导航只是没配置时的兜底，交付时不应还是这个样子。
- 外壳外观优先改 `config.ts`；`config.ts` 的开关做不出 PRD 要的样子时自写外壳。装饰（插画、背景）写在 `src/components/` 或页面里，颜色跟随宿主亮暗。

## Logo

- Logo 是应用工程里的一个图片文件，放在 `frontend/src/` 下（优先 SVG），`BRAND.logo` 引用它；发布时要的 Logo 用同一个文件。做成：`frontend/src/` 下有这个图片文件，`BRAND.logo` 引用的就是它。
- 开发者给了就用他的；没给时自己做一张贴合业务的简单图形（可以从线性图标起稿，配品牌色），不用名字首字方块，不照搬别家的品牌标识。

## 确认过的样子是基线

开发者确认过的页面样子（哪个页面、什么排法，例如「对标账号是三列紧凑列表」）一句话一项记进 G5，之后所有修改都以它为基线。

- 返工和修订只改他点名的地方，别的页面和区块不重排、不换样式，也不顺手「优化」。
- 改完把 G5 里记的基线逐项和实际页面对一遍，变了的改回来；这一步要做，因为改 A 动到 B 时不会报错，开发者只会看到确认过的页面又变了。
- 要改基线本身，先告诉他要变什么、为什么，他同意后更新 G5。
- 他一次提了几条修改：逐条回做了没有，受阻的单独列出原因；不只回做完的那几条。做成：G5 的每条基线和实际页面一致，他提的每条修改都有结论。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 照搬参考站的 Logo、图片、文案，或保留对参考站接口、CDN 的引用 | 只借样式 |
