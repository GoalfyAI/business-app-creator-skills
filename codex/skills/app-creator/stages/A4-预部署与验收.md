# A4 预部署与验收

把 A3 完成的应用变成**可部署的发布单位**，在真环境把链路走通、把清单闭合。写动作全部要求 `write` 工单（工具校验 task_id 模式）。

## 1. 进入前提

- A3 出口条件满足（前后端实现、本地测试、Playwright 门全过）；
- 目标场景包已上线；模板 schema 已定稿（A2 定稿或平台侧手工建好）；
- 有 `write` 工单。

## 2. 建立发布单位（business_ui）

业务应用的发布单位是独立资产 **business_ui**：自己的家族 ID 与版本，独立于场景包与项目。一个 business_ui 挂载**恰好 1 个场景包**（发起编排时用它的 apc_id 建项目）和**至多 1 个业务应用数据集模板**。

- `business_ui_manage(action="create", name=..., scenario_pack_id=<场景包家族 id>, dataset_template_id=..., task_id=...)`；create 幂等（`operation_id` 缺省由工单与名称派生，重复调用不会建出第二个）；
- `scenario_pack_version` 缺省 latest，**定版上线时钉到当时的具体版本**；`dataset_template_version` 缺省钉模板最新版，***禁止 follow latest***；
- `business_ui_id` 传家族 ID 或任一版本行 ID 均可：传了旧行或家族根时工具自动重定向到家族最新 live，并在 metadata 标注 `redirected_from_asset_id`——看到该标注说明手里的 ID 已过期，后续一律改用解析后的 ID。

## 3. 源码包上传与构建发布（business_ui_bundle）

打包**只用** `./scripts/pack.sh`（打包 + 归档自检 + 算 sha256 三步原子，产物 `.pack/business-ui-bundle.tar.gz`；它会拒掉缺 `Dockerfile`、含凭证 `.env`、AppleDouble、`node_modules/`、超 50 MiB 等情况）——tar 带时间戳，手工分步打包会让 `deploy` 的 `source_sha256` 对不上。判据只有一条：根目录有 `Dockerfile` 才走镜像通道（有后端）；**镜像必须用户无关**，用户差异只在注入的 env，编译期写死 schema 名或用户 ID 的产物无法给第二个用户复用。然后：

```
prepare_upload(file_name, size_bytes) → complete_upload(bundle_key)
→ deploy(source_sha256) → status(deployment_id) 轮询到终态
```

- `deploy` **必带** `source_sha256`；构建发布必须达到终态 `success`，中间态不算完成；
- 构建失败按返回的结构化报错修同一份源码重新上传部署，不得跳过；
- 上传/部署动作作用在**草稿行**上；已上线版本先出草稿（见 A5 修订节）。

## 4. 预部署环境验收

1. `business_ui_manage(get)` 与 `status` 反读部署终态，证据入工单；
2. 真环境把 **SaaS 链路闭环**完整走一遍：发起 → 生产 → 回流 → 编辑 → 看板刷新。其中**经表单入口发起的路线真实运行**（入口表单提交、运行中表单应答、业务事件与 Delivery 的真实链路、审阅动作）是本线独有的验收，场景包 S4 不做——S4 只用自然业务需求真跑资产。应用前端未就绪或要单测契约时，可用 `manage_goalfymax_project(action="run", submit_data={business_id, orchestration_id, form_id, formdata}, workspace_files[].formdata_pointer=...)` **直跑表单入口**（不经 SA，由确定性 Workflow 直接执行；文件先经 `file_to_url(tool_test_fixture)` 上传，`formdata_pointer` 指向 formdata 里的空占位字段）；
3. 按 [应用验收检查清单](../checklists/应用验收检查清单.md) **逐条执行**（每条给判定与依据）；
4. 结果检查表用预部署环境的**真实数据**闭合——mock 证据只能作为过程记录，不得置 `passed`。

## 5. 出口条件

- deploy 达 `success` 终态且反读证据在案；
- 验收清单全部 通过/不适用；结果检查表全绿；
- SaaS 链路闭环在真环境完整走通一次；
- 应用结构表全组 `challenged=true` 保持成立（部署期无回退遗留）。

以上全部满足后，落一条 `stage_exit` 账，进入 A5。
