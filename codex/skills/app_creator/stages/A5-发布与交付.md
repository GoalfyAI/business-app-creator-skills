# A5 发布与交付

把验收通过的草稿定版上线，交付报告，结单。上线是高危动作：**开发者明确授权后才执行**（拍板节点）。

## 1. 上线（finalize）

`business_ui_manage(action="finalize", draft_asset_id=...)` 把草稿定版上线。上线闸门用三个稳定错误码拒绝未就绪的定版，处置对照：

| 错误码 | 含义 | 处置 |
|---|---|---|
| `BUSINESS_UI_NO_BUNDLE` | 还没有源码包 | 回 A4 第 3 节：上传并 deploy 后再 finalize |
| `BUSINESS_UI_NOT_DEPLOYED` | 源码包没有成功构建发布 | `deploy` 到终态 `success` 再 finalize |
| `BUSINESS_UI_CONTRACT_OUTDATED` | 挂载场景包的 Workflow 契约已变化 | 重新 `deploy`（吸收新契约）后再 finalize；契约变化波及页面时先回 A1 变更检查 |

上线成功后**必须反读**：`business_ui_manage(action="resolve")` 返回消费者视角的 `entry_url` 与挂载场景包身份——这是上线证据；resolve 报"还没有上线版本"说明 finalize 未生效，不得宣称已上线。定版时场景包引用钉到当时具体版本，**把该版本号记入工单与交付报告**。

## 2. 修订已上线版本

已上线版本不可直接改：`update` 会自动派生新草稿（或先 `ensure_draft` 显式出草稿）→ 修改（改元信息经 update；改源码经 A4 第 3 节重新上传部署）→ `finalize` 新草稿。两条纪律：

- 改挂载（场景包或数据集模板版本）属于**契约变更**，先回 A1 做变更影响检查再实现；
- 每次修订走完 A4 验收再 finalize，不存在"小改免验"。

## 3. 删除（约束 6 高危）

`delete` **永久删除**界面及其全部实例、Pod、Schema、项目文件和源码包，不可恢复。必须开发者明确授权，且显式传 `confirm_permanent_delete=true`。返回语义：

- `deleting`：资源仍在收口，重复 `delete` 幂等推进并查询最新状态；
- `cleanup_failed`：收口失败但删除围栏仍生效，修复下游后重复 `delete` 重试。

当前工具面没有"仅下线不删除"的操作；要停用一个在用的应用，先与开发者确认业务后果（发布版不下线纪律见路由器约束 7），删除是唯一且毁灭性的收口。

## 4. 交付报告与结单

报告**结论先行**，包含：

- 应用名称与上线版本、`entry_url`、依赖的场景包版本（定版钉住的那个）、业务应用数据集模板与版本；
- 四类页面清单与接口清单；
- 验收结果：清单通过情况、遗留问题、明说的盲区（未验证什么）;
- 运行语义说明（开发者需要知道的平台行为）：用户首次打开时按模板 copy 出该用户的 schema 并部署实例；无流量实例会被静默缩容，首次访问冷启动稍慢。

结单前：结果检查表快照全绿、两张表最新快照已回写工单。

## 5. 出口条件

- finalize 成功且 resolve 反读 `entry_url` 非空；
- 交付报告已交付；工单结单；落 `stage_exit`。
