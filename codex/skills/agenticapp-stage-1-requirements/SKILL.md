# ① 需求确认

这一段交给开发者一份他确认过的需求文档（PRD）：给谁用、要解决什么、每一步谁来做、能不能做、做不到的怎么替代，都画在一张业务流程图里。花多少、对外做什么在 ② 方案里请他确认，这一段只把花费上限和用量问定。他读完要看得出这个应用能不能满足他的业务、每件事会怎么走，才指得出哪里不对。② 照它出方案，③ 照它做，④ 照它验收。这一段只交 PRD 这一份。

这一段最常见的错是**没核实就写「能做」**：名字对上就当有现成能力，没问量级就照单全收，把材料里的审核、复核照搬成多人流程，到 ④ 或上线后才暴露，那时只能退回 ① 改 PRD、重做一遍、再请他确认。所以和开发者沟通的同时就去平台上真查、真调，PRD 交出去时已经带着核实结论；做不到的给替代，写清比原来少了什么。

规矩以入口 `agenticapp-creator` 为准；判断能不能做时同时加载 `agenticapp-ref-platform-limits`。PRD 已确认 → `agenticapp-stage-2-plan`；应用已上线，查原因 → `agenticapp-task-diagnose`，要改 → `agenticapp-task-revise`。

## 开始前确认

- 入口「开工」已做完（方向还不清楚时，第 1–3 步等方向定了再做）：有 write 工单，应用工程已初始化或接续，交付物已有最小草案（Studio 下见 `agenticapp-host-studio`「各段和任务在 Studio 下的不同」）。
- 开发者给过至少一样材料：一句话目的、需求文档、SOP、会议纪要、原型、截图、草图、参考项目、已有应用的问题。
- 要问开发站点，或是从修订、讨论进来的：按 [references/按轮问.md](references/按轮问.md)「开始前的几种情况」做。

## 按这个顺序做

**第一轮只读 [references/按轮问.md](references/按轮问.md)**：开始前的几种情况、读材料要记什么、按轮问、每轮的样例都在这一份里。其余参考文件不在第一轮读，到下面写着「到这一步再读」的那一步再读。

1. **读材料**。读完开发者给的全部材料，不加推测，写明的事记成「已定的事」，缺的留着问；要记什么见 [references/按轮问.md](references/按轮问.md)「读材料要记什么」。别人参与（审核、复核、领导看汇总）按 [references/谁来做.md](references/谁来做.md)「谁来用」处理（材料里有别人参与时再读）。做某类具体业务时加载 `agenticapp-ref-experience`，看这类业务的写法和要问清的规则。
2. **马上发第一轮**。按 [references/按轮问.md](references/按轮问.md) 排树，看完材料就发，不等核实做完；方向还不清楚时第一轮只问方向。开发者明确说「帮我先理一理业务」「不确定该做什么」时，按 [references/谁来做.md](references/谁来做.md)「先理一理业务（咨询模式）」做，到这一步再读。
3. **同时核实**。第一轮发出后，对每一步按 [references/核实能不能做.md](references/核实能不能做.md) 逐项查、真调一次、判定、算花费，到这一步再读；量级和单次运行能力对照 `agenticapp-ref-platform-limits`；效果、用时或档位拿不准的关键模型步骤，按同一份的「能力试用」试跑（花钱先问）。**只查不建**：开发者确认这一版之前，工作区最多标到 G2，不建业务资产、不写编排脚本、不建表、不部署；开工建的工单和工作区、能力试用包不算「建」。
4. **一轮一轮问到没有空节点**。每轮按上一轮的答案和查到的结果，问新变成能问的题；「每个应用都要问的题」都要问到。每轮一条交接消息，开头「【① 需求确认 → 等你确认】」。
5. **问完就写 PRD**。树上没有空节点就写，不另发一条清单请他回「对」：PRD 就是给他核对的那份，按默认定下的在 PRD 原处标出。
6. **写 PRD**。照 [assets/PRD.md](assets/PRD.md) 写，「谁来用」「每一步谁来做」照 [references/谁来做.md](references/谁来做.md)；写进方案页（[references/方案页.md](references/方案页.md)）。各种情况怎么写、写完自查见 [references/PRD的写法.md](references/PRD的写法.md)。这三份到这一步再读。
7. **发出，改到确认**。交接消息「要你做的」列什么，读 [references/PRD的写法.md](references/PRD的写法.md)「交接消息「要你做的」列什么」。批注后按 [references/PRD的写法.md](references/PRD的写法.md)「版本、批注和确认」出新一版，直到他确认当前这一版。
8. **新 SDK 应用建占位**。`frontend/goalfy-app.json` 有 `"executor": "launch_agent"` 的，开发者确认 PRD 后就 `business_ui_manage(action="create", task_id, name)` 建应用占位，`business_ui_id` 记进工单 checkpoint；不建场景包。

## 这一段要做对的判断

| 判断什么 | 依据 | 判错的表现 |
|---|---|---|
| 有没有多人分工（审核、复核、领导看汇总、共用数据） | 平台没有团队，每个使用者用自己的一份（[references/谁来做.md](references/谁来做.md)「谁来用」） | 照搬多人流程，或承诺权限 |
| 每一步有没有现成能力 | 真调拿回来的东西（核实第 1–3 步） | 名字对上就写「能做」 |
| 量级：一次多少条、多久一次 | 用量题的答案，对照 `agenticapp-ref-platform-limits` | 没问量级；超出单次运行能力仍写「能做」，不提分批 |
| 外部数据拿不拿得到、谁授权 | 真拿一次，结论记进 G2，② 写进方案「运行条件」 | 假设数据现成 |
| 每个环节的「怎样算做成」能不能照着测 | 写成照着做、应该看到什么 | 写成「效果好」「准确」 |
| 做不到时有没有替代、少了什么 | 「做不到的和替代」 | 直接砍掉，或替代比原需求小太多却不说 |
| 业务事实是不是开发者的原话 | 「已定的事」；名字、字段、选项、唯一规则一字照用 | 表名、状态值、唯一键和开发者说的不一致（他说按「门店 + 周开始日」唯一，写成「店名 + 周结束日」） |
| 这道题该不该给推荐 | 只有他知道的事（站点、账号、现在记在哪）出事实题 | 把开发站点做成带推荐答案的选择题 |
| 开发者读得懂、知道还剩多少 | 每轮「下一步」写还剩几轮；上限题写出约合多少元 | 问了十几题才说完、没提前说几轮 |

问的时候就要想到哪些情况、写进哪个刚需，读 [references/按轮问.md](references/按轮问.md)「问的时候就要想到的情况」。

## 你可能会这么想 → 实际

| 想法 | 实际 |
|---|---|
| 先把题问完，再去平台上查 | 第一轮马上发，同时查；只有依赖查询结果的题等结果 |
| 工具名字对得上，算能做 | 安全只读的真调一次，看返回是不是要的那个对象 |
| 开发者回了「是」，方向就定了 | 方向题和事实题回「是」不算答了 |
| 写 PRD 前先列一遍「我理解的是这些」，请他回「对」 | 不另确认：一个应用只确认三次（入口「开发者确认什么」），列清单再请他回「对」就成了第四次 |
| 他说「可以」就算确认 PRD | 只有对当前这一版的明确同意才算 |
| 他回「确认这一版」又补了两句，再请他确认一次 | 补的话只是照写进去、不改取舍、费用和验收要求的：照改，交接里说改了哪几处，算已确认；改到取舍、费用或验收要求的，出新一版再确认 |
| 「下一步」说了要问提醒发到哪，题够多了，按默认吧 | 写过要问的题下一轮必须出现；按默认定掉，他的钉钉要求就没机会说 |
| 他说「别问了」，剩下的都按默认 | 只有他知道的事实（站点、账号、业务规则）仍要问 |
| 先把表建起来，后面省事 | 确认前只查不建：PRD 确认前还会改，先建的表和资产多半要删掉重建 |

## 记下来

阶段文档 G1、G2，方案页，工单 checkpoint，阶段标记与阶段记录各记什么，读 [references/PRD的写法.md](references/PRD的写法.md)「记下来」。

## 交棒

全部满足，再加载 `agenticapp-stage-2-plan`：

- 开发者确认了当前这一版 PRD（Studio 下读回这一版已确认）；
- 每个环节都有核实结论，节点都有输入、输出、重要信息，最后一步写了这样算对、这样不行、怎样算做成；
- 每个节点都标了使用者、应用或 AI；做不到的都有开发者选过的替代；
- 选择题都有答案（开发者答的、需求方答的或标「按默认」），用量有；花费上限是一个具体积分数，写在工单 checkpoint 和 G1 里，「待定」「看情况」不算；
- 交付物里没有开发者看不懂的词，没有模板占位文案；
- G1、G2 的阶段标记和阶段记录已写。

## 出问题

| 现象 | 处理 |
|---|---|
| 开发者说不清要什么 | 按 [references/按轮问.md](references/按轮问.md)「从开发者给的东西开始」探讨方向，给两三个具体做法让他选 |
| 取样报参数错、路径不存在 | `agenticapp-tool-integration`「工具取样」：核对文件参数收 URL 还是 `/workspace` 路径，再取一次 |
| 工具要使用者各自授权 | `agenticapp-tool-integration`「授权卡」，记进 G2，② 写进方案「运行条件」 |
| 分享来的资产搜不到、受限或脱敏 | `agenticapp-tool-integration`「分享来的工具组」，结论写进 PRD，确认 PRD 时一并确认 |
| 核实发现关键功能做不到 | 当轮写进「能不能做」，出替代选择题（换做法 / 改范围 / 等平台） |
| 开发者只想讨论、暂不开发 | 直接在对话里回答；讨论落到具体应用时，至少写出交付物的最小草案 |
