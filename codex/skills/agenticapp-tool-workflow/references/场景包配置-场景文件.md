# 场景包配置详解（三）：场景 Skill 文件

要给场景包上传场景 Skill 文件（`场景_*.md`），或诊断场景文件写法时读。

本文分 4 份：[场景包配置-名称描述工具集.md](场景包配置-名称描述工具集.md)、[场景包配置-Skill文本.md](场景包配置-Skill文本.md)、[场景包配置-场景文件.md](场景包配置-场景文件.md)、[场景包配置-知识文件与分工.md](场景包配置-知识文件与分工.md)。

## Skill 文件

上传知识文件。SA 启动时能看到文件的**路径列表**（知道有哪些文件），但看不到文件内容——SA 需要主动决定读取某个文件才能获取内容。这就是为什么 Skill 文本中必须有场景索引表和文件指南：它们告诉 SA 每个文件是什么、什么时候该去读。

Skill 文件分为两类：**场景文件**和**知识文件**。

### 场景文件

一个业务目标对应一个场景文件，包含完整的操作流程（SOP）。SA 匹配到用户意图后读取对应文件，按步骤执行。

#### 配置范式

> **命名**：`场景_{场景名}.md`
> **插拔操作**：新增 = 加文件 + 索引追加一行；删除 = 删文件 + 索引删一行

**场景文件模板**：

```markdown
# 场景：{场景名}

## 涉及工具集与 FA
- {工具集名称 1}
- {工具集名称 2}（含 FA: {FA名称}）
- ...

## 前置条件
- {条件}

## 执行流程

### 步骤 1：{步骤概述}【直接工具调用】
工具集：{工具集名称}
操作：
1. 调用 `{tool_name}`，参数：{关键参数说明}
2. 调用 `{tool_name}`，参数：{关键参数说明}
说明：{为什么这样做}

### 步骤 2：{步骤概述}【调用 FA】
调用 FA：{FA名称}（位于{工具集名称}）
输入：{描述输入参数和来源}
预期输出：{描述输出结构}
后续处理：{拿到 FA 结果后 SA 做什么}

### 步骤 N：...

## 注意事项
- {关键约束}

## 常见问题
- {问题} → {处理方法}
```

**步骤类型标注规范**：

- **【直接工具调用】**：SA 自己调工具。写明用哪个工具、**该场景下需要填的业务值**（不是描述工具接口，而是描述这个场景需要什么数据）
- **【调用 FA】**：SA 把 FA 当工具调用，只关心输入输出。FA 内部怎么执行是 FA 自己的事
- **【发起路线】**：SA 发起一条业务路线。写明 `orchestration_id`、需要收集的入口信息、拿到交付后的后续处理
- **【派发 TPE】**：SA 将任务派发给 TA 执行，只用于不在路线里的 TPE。写明匹配的 TPE 名称、需要收集的输入信息、拿到结果后的后续处理

> **有 TPE 时**：TPE 处理的任务类型**不需要**单独的场景 Skill 文件。执行方法论在 TPE 系统提示词或脚本中，领域知识在 TPE Skill 文件中。场景文件只覆盖 SA 直接处理的场景。某个步骤要用路线里的 TPE 时标【发起路线】，要用不在路线里的 TPE 时标【派发 TPE】。

#### 合格示例

**场景_新员工入职.md**

```markdown
# 场景：新员工入职

## 涉及工具集与 FA
- 账号管理工具集
- 权限管理工具集（含 FA: 权限合规检查 Agent）
- 通知工具集

## 前置条件
- 已获取新员工的基本信息（姓名、部门、职级、入职日期）

## 执行流程

### 步骤 1：创建企业账号【直接工具调用】
工具集：账号管理工具集
操作：
1. 调用 `create_account`，参数：员工姓名、部门、职级、邮箱
2. 调用 `setup_email`，参数：账号 ID、邮箱别名
说明：邮箱格式统一为 姓名拼音@公司域名，账号创建后默认未激活

### 步骤 2：分配系统权限【直接工具调用】
工具集：权限管理工具集
操作：
1. 调用 `get_role_template`，参数：部门 + 职级（获取该岗位的标准权限模板）
2. 调用 `assign_permissions`，参数：账号 ID、权限模板 ID
说明：权限按"最小必要"原则分配，先用标准模板，特殊权限后续单独申请

### 步骤 3：权限合规检查【调用 FA】
调用 FA：权限合规检查 Agent（位于权限管理工具集）
输入：{account_id: 步骤1创建的账号ID, department: 部门, role: 职级}
预期输出：合规报告（是否有越权风险、是否有互斥权限冲突）
后续处理：
  - 如果有合规问题 → 回到步骤 2 调整权限后重新检查
  - 如果全部通过 → 进入步骤 4

### 步骤 4：发送入职通知【直接工具调用】
工具集：通知工具集
操作：
1. 调用 `send_email`，参数：员工邮箱、入职欢迎邮件（含账号信息、系统访问指南）
2. 调用 `send_notification`，参数：部门负责人、新员工到岗通知
说明：确保员工和部门负责人都收到通知

## 注意事项
- 实习生和正式员工使用不同的权限模板
- 涉及财务系统权限需额外审批

## 常见问题
- 邮箱已被占用 → 在姓名拼音后加数字后缀
- 权限模板不存在 → 确认部门和职级是否正确
```

**含 TPE 派发步骤的场景文件示例**（步骤中混合使用直接工具调用和 TPE 派发）

```markdown
# 场景：供应商评估报告

## 涉及工具集与 FA
- 供应商管理工具集
- TPE：deep_research（深度研究）

## 执行流程

### 步骤 1：获取供应商基础信息【直接工具调用】
工具集：供应商管理工具集
操作：
1. 调用 `get_supplier_info`，参数：供应商 ID
说明：获取供应商的基本资料、历史合作记录

### 步骤 2：深度调研供应商背景【派发 TPE】
TPE：deep_research
输入：基于步骤 1 的供应商信息，构造研究主题"该供应商的行业口碑、财务状况、合规记录"
后续处理：拿到研究报告后，与步骤 1 的基础信息合并

### 步骤 3：生成评估报告【直接工具调用】
...
```

#### 不合格示例与问题

| 问题 | 表现 | 正确做法 |
| --- | --- | --- |
| 步骤中描述工具接口 | "调用 `create_account`，它接受 name(string)、dept(string)、level(enum)..." | 只写该场景需要传什么业务值，工具接口是 MCP 层的事 |
| 步骤中写了 FA 内部逻辑 | "FA 内部会逐条检查权限，比对互斥矩阵..." | 只写 FA 的输入/预期输出/后续处理 |
| 步骤中写了 TPE 的执行方法论 | "TA 会先拆解查询，然后多轮搜索..." | 只写 TPE 名称和输入/后续处理，执行方法论是 TPE 系统提示词的事 |
| 缺少步骤类型标注 | 步骤没标明【直接工具调用】/【调用 FA】/【发起路线】/【派发 TPE】 | 每个步骤必须标注类型 |
| 路线里的 TPE 标成派发 | 步骤写【派发 TPE】，TPE 却在业务路线里 | 改标【发起路线】；单独派发时运行不报错，但页面收不到进度，交付和审阅都不生效 |
| 为 TPE 任务写了场景文件 | 为"深度研究"单独写了场景文件 | TPE 处理的任务类型不需要场景文件 |
| 混入领域知识 | 场景文件中写了 3 页退款政策说明 | 领域知识放知识 Skill 文件，场景文件只引用 |
| 缺少涉及的工具集声明 | 直接写步骤但不说用哪个工具集 | 开头声明涉及的工具集和 FA/TPE |
