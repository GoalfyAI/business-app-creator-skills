# TPE 配置详解（二）：系统提示词、推荐模型、工具集与 Skill 文件

写或诊断普通任务点（TPE）的系统提示词、推荐模型、工具集和 Skill 文件时读。

本文分 2 份：[TPE配置-定位与输入输出.md](TPE配置-定位与输入输出.md)、[TPE配置-提示词工具集与文件.md](TPE配置-提示词工具集与文件.md)。

## 系统提示词

TA 启动时加载的系统提示词，定义 TA 的角色、执行流程和行为约束。对 SA 不可见。

### 配置范式

TPE 的系统提示词和 FA 的系统提示词结构类似，但定位不同：

| | TPE 系统提示词 | FA 系统提示词 |
| --- | --- | --- |
| 执行者 | TA（独立 Agent，有自己的工具集） | FA（作为工具被调用） |
| 范围 | 完整任务的执行规范 | 子任务的执行规范 |
| 工具来源 | 通过工具集获取（挂载后加载） | 直接配置的工具 |

**应该包含**：
- **角色定位**：TA 是谁、负责什么类型的任务
- **执行流程**：拿到输入后按什么步骤执行
- **工具使用策略**：什么时候用哪些工具集的工具
- **输出要求**：返回什么格式（与输出要求字段配合）
- **Skill 文件指南**（如有）：告诉 TA 有哪些文件、什么时候去读

**核心原则**：
- 系统提示词要短而精，详细的知识内容（规则清单、案例等）放 Skill 文件
- **不写**单个工具的描述和参数——工具在 MCP 层已自带完整说明
- 重点写 TA 的**执行方法论**——这是 TPE 的核心价值

> Skill 文件的路径会自动拼接到系统提示词末尾，TA 可按需读取。

**模板**：

```markdown
# {TPE名称}

## 角色
你是{专业领域}专家，负责{核心任务类型}。

## 执行流程
拿到任务后按以下步骤执行：

1. {步骤描述}
   - {具体操作}
   - 如果{条件}，则{处理}

2. {步骤描述}
   - {具体操作}

3. {步骤描述}
   - 汇总结果，按{规则}生成{输出}

## 工具使用策略
- 需要{能力}时，加载{工具集名称}
- {工具/FA}：用于{场景}，注意{要点}

## 输出要求
返回以下结构：
- {字段1}：{说明}
- {字段2}：{说明}

## Skill 文件指南（如有）
- {文件名}：{内容}，{阅读时机}
```

### 合格示例

**深度研究 TPE**

```markdown
# 深度研究

## 角色
你是深度研究专家，负责接收研究课题，通过多轮搜索和交叉验证生成结构化研究报告。

## 执行流程
1. 分析研究课题，拆解为 3-5 个子查询
2. 对每个子查询，加载搜索工具集，执行多轮搜索
   - 每轮搜索后评估信息完整性，不足则调整关键词继续搜索
   - 对关键事实进行交叉验证（至少 2 个独立来源）
3. 汇总所有发现，去重和分类
4. 生成结构化研究报告

## 工具使用策略
- 需要网络搜索时，加载搜索工具集
- 需要读取网页内容时，使用网页阅读工具
- 搜索结果不充分时，调整关键词或扩大搜索范围

## 输出要求
返回结构化研究报告，包含：摘要、详细发现、信息来源列表
```

### 不合格示例与问题

| 问题 | 表现 | 正确做法 |
| --- | --- | --- |
| 缺少执行流程 | 只写了角色和输出要求 | 执行流程是 TPE 的核心价值，必须有 |
| 描述单个工具接口 | "`search_web` 接受 query(string)、count(int) 参数" | 工具接口 MCP 层已有，提示词写工具使用策略即可 |
| 提示词过长 | 系统提示词写了 3000 字的详细规则 | 规则多时拆到 Skill 文件，提示词只留执行流程框架 |
| 混入其他任务类型 | 深度研究的提示词里写了代码执行的逻辑 | 一个 TPE 只负责一种任务类型 |

### 诊断要点

- 是否包含角色 + 执行流程 + 工具使用策略 + 输出要求 + Skill 文件指南（如有文件）
- 执行流程是否清晰体现了该任务类型的核心方法论
- 是否包含了单个工具的描述/参数（不应有，MCP 层已有）
- 提示词是否过长（超过 800 字考虑拆分到 Skill 文件）
- 是否混入了其他任务类型或上层场景逻辑

## 推荐模型

TA 执行该任务类型时推荐使用的模型。

### 配置范式

根据任务复杂度选择模型：
- 需要多模态视觉、复杂推理、策略设计 → 强模型
- 高频批量检索、结构化提取、成本优先 → 轻量模型

---

## 工具集配置

定义 TA 执行任务时可使用的工具集。

### 配置范式

TA 的工具集**统一为挂载模式**（按需加载）。TA 启动时只能看到工具集的名称和描述，需要时调用 load_toolset 加载详细信息（工具集技能、FA、工具等）。

选择工具集时，只选该任务类型所需的能力域，不要选无关的工具集。

> 同一个工具集可以同时被场景包（SA 用）和 TPE（TA 用）引用。工具集的技能内容应对 SA 和 TA 两种读者都适用。

### 诊断要点

- 所选工具集是否覆盖了系统提示词中提到的所有能力需求
- 是否有多余的工具集（系统提示词未涉及但被选中）
- 是否有遗漏的工具集（系统提示词提到的能力无工具集支撑）

---

## Skill 文件

上传知识文件，TA 在执行过程中可按需读取。对 SA 不可见。

### 配置范式

适合放的内容：

| 内容类型 | 示例 | 为什么放 Skill 文件而非系统提示词 |
| --- | --- | --- |
| 详细执行规则 | 深度研究的信息评估标准和可信度判断矩阵 | 规则多，放系统提示词太占 token |
| 领域知识 | 该任务类型涉及的行业术语和规范 | 内容长且按需读取效率更高 |
| 输出格式示例 | 研究报告的完整样例 | 帮助 TA 理解预期格式 |
| TA 专属知识 | 只有该任务类型需要的参考资料 | 内容多且场景包知识文件 TA 读不到 |

**与系统提示词的分工**：
- 系统提示词 = 执行流程和行为规则（短、精），每次执行自动加载
- Skill 文件 = 详细参考资料（长、全），TA 需要时主动读取

**TPE Skill 文件 vs 场景包知识 Skill 文件**：

| | TPE Skill 文件 | 场景包知识 Skill 文件 |
| --- | --- | --- |
| 读者 | TA（对 SA 不可见） | SA（对 TA 不可见） |
| 内容粒度 | TA 执行该任务类型的专属知识 | 多场景共享的通用知识 |
| 示例 | "深度研究的可信来源评估标准" | "公司核心业务指标定义" |

Skill 文件的路径在 TA 启动时自动拼入系统提示词末尾。如果有 Skill 文件，应在系统提示词中加上 Skill 文件指南，告诉 TA 什么时候去读哪个文件。

> **关键**：如果 TA 需要某份场景包的知识 Skill 文件中的内容，需要在 TPE 的 Skill 文件中提供 TA 视角的版本——TA 只能读自己的 Skill 文件。

### 诊断要点

- 系统提示词是否过长（应拆分详细规则到 Skill 文件）
- 如果有 Skill 文件，系统提示词是否有 Skill 文件指南
- Skill 文件内容是否与场景包知识文件或工具集技能重复
- Skill 文件的内容是否是 TA 执行所需的专属知识（而非通用领域知识）
