# 读长期数据集

路线要参考**长期数据集**（`list_assets(asset_type="dataset")` 列出的 FAQ、知识库、历史数据）里的记录时读。智能应用自己的应用库按 [读写应用库与反读自查.md](读写应用库与反读自查.md)，两者规则不同，不混用。

## 规则

- 由脚本先用 `shell` 在沙箱里执行 `ds-cli exec` 读出数据，再把结果作为参数交给 FA。`shell` 是编排型 TPE 默认可调用的工具，不用放进工具集；脚本调用了它，平台会建沙箱并注入当前使用者的数据集身份，`ds-cli` 经 dataset-proxy 用这个身份读库。
- 长期数据集只能由脚本读：编排里的 FA 拿不到沙箱，也看不到数据集的使用说明，只能看到数据集名字。只把 `dataset_id` 交给 FA 的提示词或参数、指望它自己去读，拿到的数据是空的。（应用库不同：FA 可以挂工具只读查。）
- 只写只读 `SELECT`。表名写成全限定名 `<pg_schema>.表名`：`pg_schema` 取 `list_assets(asset_type="dataset")` 的返回，表名和列名用 `dataset_read(action="tables")`、`dataset_read(action="columns")` 查实。筛选条件、关键字匹配、排序都写进 SQL，带 `LIMIT`，只取 FA 用得上的列。
- 不加 `--max-rows` 时最多返回 1000 行，超出部分会被截断，而且命令不报错；要全量数据时用 `--output <ctx.process_dir 下的路径>` 导出成 CSV，再按文件处理，不把大结果直接交给 FA。
- 命令加 `--format json`，输出是以列名为键的对象数组；`_output` 声明成对象数组，由平台解析终端回显。小数列在输出里是字符串，`_output` 声明成 number 时平台会转成数字。
- `ds-cli` 命令没有参数占位，输入值要拼进 SQL：先在脚本里校验成枚举或数字；自由文本里的单引号写成两个单引号，双引号不放进命令；自由文本用于 `LIKE` 时，先把 `\`、`%`、`_` 前面各加一个反斜杠。（这条只适用于长期数据集；应用库的值一律经 `db()` 的 `params`。）
- 权限按运行应用的使用者算：数据集所有者本人和被分享了该数据集的人能读，其他人会报 `permission denied`，`shell` 以非零退出码失败。应用给别人用时，PRD 要写明所有者需要先把数据集分享给使用者。新 SDK 应用不能依赖开发者个人的普通数据集（[新SDK应用的路线.md](新SDK应用的路线.md)「编排脚本的额外约定」）。
- 冒泡时 `shell` 真实执行，读数这一步用冒泡验证。

## 示例

```python
    if input["category"] not in ("video", "image"):
        return {"status": "needs_input", "note": "category 只能是 video 或 image", "faq": []}
    faq = await tool(
        "shell",
        action="shell_exec",
        command=(
            'ds-cli exec "SELECT question, answer FROM <pg_schema>.faq '
            f"WHERE category = '{input['category']}' ORDER BY updated_at DESC LIMIT 20\" --format json"
        ),
        _rationale="生成前取该品类最近的 FAQ 作为素材",
        _output={"type": "array", "items": {"type": "object",
            "properties": {"question": {"type": "string"}, "answer": {"type": "string"}}}},
    )
```
