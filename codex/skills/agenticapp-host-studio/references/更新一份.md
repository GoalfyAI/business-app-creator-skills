# 更新一份开发文档

已经保存过的开发文档要出新一版时读。

1. 改应用工程里的 `docs/studio/<documentType>/data.json`：只改变化的部分，`version` 加一，`updated` 写这次的实际时间，`changes` 写这一版改了什么（一条一句）。不顺带重写另外几份。
2. 工程里没有 `data.json`（换了机器、别人保存的新一版）：用 `studio_read_creation` 带 `includeProposalContent=true` 读当前一版的 `index.html` 存下来，跑 `node <本 Skill 目录>/scripts/build_studio_doc.mjs extract index.html docs/studio/<documentType>/` 取回 `data.json`（方案连同 `demos/` 下的 Demo 文件）。`extract` 报「没有数据块」（旧 Skill 手写的页面）时，按 SKILL.md 表里这份文档的数据说明，照旧页面的内容新写 `data.json`，`version` 接着旧版加一，再往下生成。
3. 重新生成、看过、保存，同 SKILL.md「怎么写一份」第 3–6 步；`baseArtifactId` 传当前一版的 `artifactId`。

两处例外：
- ④ 里验收报告每出一版有没通过的条目（含开发者提的修改），制作进度在同一条回复里跟着更新：还没开始改时，时间轴加一条事件逐条列出没通过的（等他决定的标 `blocked`）、`now` 写「验收有 N 条没通过」和正在改还是等他决定，功能格子不动；开始改时格子按 `agenticapp-stage-4-acceptance`「按反馈改」退回，`changes` 写改的是哪条、为什么改；改好测过再改回「做好了，……」。④ 不另起一份进度。
- 已确认的 PRD 和方案什么时候出新一版，按 `agenticapp-stage-1-requirements` 的版本与确认规则。

验收报告出新一版（例如 ⑤ 收尾时补「上线结果」）时，沿用的截图仍放在 `shots/`、随 `files` 一起提交；不把图片转成 `data:` 内嵌，内嵌图片会让保存失败。
