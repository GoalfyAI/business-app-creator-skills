# 方案：数据说明与完整样例

写 `docs/studio/proposal/data.json` 时照这里写，每个功能的 Demo 照 [../references/Demo怎么写.md](../references/Demo怎么写.md) 写在 `demos/` 下，生成用 `build_studio_doc.py proposal`。**写什么**按 `agenticapp-stage-2-plan` 的[方案模板](../../agenticapp-stage-2-plan/assets/方案.md)，这里只说每一块放进哪个字段。施工单不给开发者看，不放进来。

页面只有三块：制作范围 → 01 运行条件（五件事，放在功能之前）→ 02 功能与页面（每个功能一个完整页面 Demo，上面 Demo、下面编号说明）。验收条目写在 `acceptance` 里，脚本只校验不显示。

## 字段

| 字段 | 必填 | 写什么 | 方案模板里的 |
|---|---|---|---|
| `app`、`version`、`updated`、`changes` | 是 | 同需求说明 | — |
| `prd_version` | 是 | 依据的需求说明版本号 | — |
| `scope.route` | 是 | 这个应用把什么变成什么，2–5 个短语，按顺序 | 制作范围 |
| `scope.summary` | 是 | 做哪些功能和页面、这次不做什么、非刚需做不做，两三句；接着写信息架构三项及理由 | 制作范围 |
| `conditions.data / account / cost / access / effects` | 是 | 五件事，每件写 `now`（现在的情况）、`impact`（影响什么），再写 `decide`（还要他定的问题）**或** `settled`（已定的结论）之一 | 运行条件 |
| `brand.name`、`brand.workspace` | 是 | Demo 左上角的应用名、顶栏的工作台名 | — |
| `features[]` | 是 | 一个刚需一个功能，按使用顺序 | 功能与页面 |
| `features[].title / how / fail / after / example` | 是 | 完成什么业务、怎么完成、做不成时、完成后、例子（真实数据，或标「预期」） | 功能与页面 |
| `features[].page` | 是 | Demo 里这个页面的名字，也是左侧导航的名字 | 页面 |
| `features[].demo` | 是 | Demo 文件的相对路径，如 `demos/01.html` | 页面 |
| `features[].notes[]` | 是 | 编号说明，和 Demo 里 `data-pin` 一一对应：`title`、`text`；**第一条**另写 `input`（一条一句：用到什么、从哪来、要什么授权和费用），**最后一条**另写 `output`（得到什么、存在哪）；中间的只写操作说明 | 怎么完成 |
| `features[].context` | 否 | 页面里的状态提示（数据没接、服务没定）：`tone`（`warn` 或 `info`）、`title`、`impact`、`action`、`items[]` | — |
| `acceptance[]` | 是 | 验收条目，不显示：`id`、`who`、`entry`（从哪进、先看到什么）、`do`（用什么、按什么顺序做）、`get`（最后拿到什么）、`pass`（怎样算过）、`judge`（`AI 能判断` 或 `要人判断`）；Studio 下的「在 Studio 里打开看各页面」也是一条 | 验收条目 |

五件事各放什么：`data` 数据从哪来、多久更新；`account` 要他准备的账号、授权、材料；`cost` 制作还要花多少、上线后每次和每周、和上限比、收费工具、失败重试会不会再扣；`access` 谁能看谁能改、资料和结果保存多久；`effects` 自动发生的事、会写入或发出去什么、资料交给谁。

同目录还要有 `acceptance.json`（格式按 `studio_write_proposal` 的说明）：每条存数据的验收条目在 `crud` 里有同编号的一项，脚本会核对。

## 容易写错的

- 运行条件写成「待定」：五件事各自说清现在是什么情况；没定的用 `decide` 写成一个他能答的问题。平台没有团队，`access` 按「每个使用者用自己的一份」写，不承诺多人权限。
- 把还没选定的外部服务写成已接入：没定的写在 `decide` 里，Demo 里用 `context` 标「数据未连接」。
- 每条编号说明都重复输入输出：只有第一条写输入、最后一条写输出。
- Demo 只做一小块表单：每个功能做完整页面（标题、操作区、结果区），见 Demo 怎么写。
- 照旧写 `steps`、`cost_review`、`summary`：脚本会拦，内容分别并进需求说明的 AI 节点、`conditions.cost` 和 `effects`、`scope.summary`。
