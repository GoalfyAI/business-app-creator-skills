# 制作进度：数据说明与完整样例

写 `docs/studio/progress/data.json` 时照这里写，生成用 `build_studio_doc.py progress`。**写什么**按 `agenticapp-stage-3-build` 的[制作进度怎么写](../../agenticapp-stage-3-build/references/制作进度怎么写.md)和[我先跑了一遍怎么写](../../agenticapp-stage-3-build/references/我先跑了一遍怎么写.md)；进度消息照常在聊天里发，这份文档和消息在同一条回复里更新、内容一致。

页面长这样：当前在做什么（完成数和进度条由脚本按功能格子算）→ 每个功能做到哪（后台、页面、存数据三格）→ 制作时间轴（可回放）→ 我先跑了一遍 → 和方案不一样的地方、页面说明、遇到的问题。

**时间轴只写真实发生过的事**：时间从工作记录（阶段文档、checkpoint）里取，不估、不补；还没做的写 `todo`、不写时间。回放只是把已有记录按顺序亮一遍。

## 字段

| 字段 | 必填 | 写什么 |
|---|---|---|
| `app`、`version`、`updated`、`changes` | 是 | 同需求说明；`changes` 写这次更新变了什么 |
| `state` | 是 | `working` 在做 / `done` 方案里的功能都做好了 / `blocked` 卡住了（要写 `problems`） |
| `now.title / detail` | 是 | 现在在做什么，一句标题加一句说明 |
| `next.title / detail` | 否 | 下一步 |
| `features[]` | 是 | 方案里的全部功能，一个不漏：`name`；`backend` 只写 `做好了，实际跑过` / `做好了，只用模拟数据试过` / `做好了，等在线预览时实际跑` / `在做` / `没开始` / `不需要`；`page`、`data` 只写 `做好了` / `在做` / `没开始` / `不需要`。判定按「制作进度怎么写」的进度表规则 |
| `events[]` | 是 | 时间轴：`time`（`14:20` 或 `11-05 14:20`）、`title`、`detail`、`status`（`done` / `doing` / `todo` / `blocked` 受阻，`detail` 写卡在哪）、`steps[]`（小步骤，同样三个字段）。整份卡住时 `state` 写 `blocked` 并补 `problems` |
| `trials[]` | 标了「实际跑过」就要 | 我先跑了一遍：`feature`（功能名，和 `features` 一致）、`test_data`（编的数据为 `true`）、`example` `why` `used` `steps` `result` `cost`，六项写全 |
| `diffs` | 否 | 和方案不一样的地方，一条一句 |
| `pages[]` | 否 | 页面说明：`name` `for` `shows` `buttons` |
| `problems[]` | 卡住时要 | 当前遇到的问题：`what` `why` `affects` `who`（谁在处理）`when`（什么时候能继续） |
| `pending[]` | 否 | 还要明确的条件：`what` `affects` |

## 容易写错的

- 第一份就写成「做好了」：③ 开始时第一份多数格子是「没开始」，这一份在建任何东西之前保存。
- 只在 ③ 结束时写一份：每做好一个功能、跑完一次「我先跑了一遍」、出现或解决一个问题就更新一次。
- `state` 写 `done` 但还有格子没做好：脚本会拦；`done` 也不等于验收通过。
