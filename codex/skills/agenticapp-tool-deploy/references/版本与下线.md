# 版本操作、下线与删除

修订已上线的应用、回滚、作废草稿、单独上线场景包、下线、删除时读。回滚、下线、删除每一步都要开发者确认。

## 草稿、上线、发布各能做什么

| 要做的事 | 草稿部署成功即可 | 要先上线 | 还要发布 |
|---|---|---|---|
| 开发者在 Studio「在线预览」里看 | ✓ | | |
| 路线冒泡、不带 `business_ui_id` 的实际跑、带 `business_ui_id` 和 `workspace` 的实际跑 | ✓ | | |
| 保存自动化声明、`business_ui_automation` 的 `validate` / `bubble` | ✓ | | |
| `business_ui_automation(run_once)`、`resolve` 反读、发布管理页预览 | | ✓ | |
| 带 `business_ui_id` 不传 `workspace` 的实际跑（读写开发者本人的正式实例） | | ✓ | ✓ |
| 开发者本人从正式入口打开、在「自动化」面板开到点规则 | | ✓ | ✓ |
| 使用者从目录或分享打开 | | ✓ | ✓ |

要发布的几项不属于制作和验收，写进上线结果里开发者「你可以做的事」。

**写到哪份库**：在线预览和带 `workspace` 的实际跑写开发工作集（同一份）；带 `business_ui_id` 不传 `workspace` 的实际跑写开发者本人的正式实例，要应用已上线并发布，制作和验收不用它；自动化和使用者的运行写各自的实例。

## 修订、回滚、作废

先 `list_asset_versions` 看清现役上线版本和有没有搁浅的草稿。

| 动作 | 工具 | 规则 |
|---|---|---|
| 取草稿 | 应用 `business_ui_manage(action="ensure_draft")`，场景包 `scene_package_manage(action="ensure_draft")`，其他 `ensure_editable_asset_draft` | 之后一律用返回的 `draft_asset_id`；`reused: true` 表示沿用已有草稿。应用建草稿（含 update、对已有应用的 `setup`、`ship` 自动派生）带 `change_note` 写这次改了什么，首次 `setup` 建应用身份不用带 |
| 比较 | `compare_asset_versions(base_version_id, target_version_id)` | 只比配置不比效果，结论写进上线结果 |
| 作废草稿 | `abandon_asset_version_draft` | 只能作废没上线、没被引用的草稿；先 `get_asset_usage_impact` 看影响面告诉开发者 |
| 回滚 | `rollback_asset_version(version_id)` | 用历史版本内容克隆出新草稿；部署并上线后走 ④ 验收 |

- 派生出的新草稿不继承部署，要在新草稿上重新部署并反读。做成：`business_ui_manage(action="get")` 里新草稿 `has_ui: true` 且 `entry_url` 不为空。
- TPE 上线新版本后，路线和挂载仍指旧版本。`otpe_manage(update)` 带着场景包草稿时会自动采用新版本（返回开头有【自动采用】）；`mounted_by_stale` 列出的场景包逐个 `attach`，或记下不跟进的理由。
- 改挂载（换场景包或模板版本）属于契约变更，先按 `agenticapp-task-revise` 评估影响。

## 场景包上线

- 挂在应用上的本人场景包草稿**不单独上线**：预览直接跑草稿，上线应用时一起上线。所以制作中建、改 TPE 和场景包一律传 `publish_mode="staged"`；返回里提示上线场景包的不照做。`otpe_manage(action="online")` 只启用这条 TPE，照常做。
- 只有不经应用、直接给别人用的场景包才单独上线：`finalize_asset_version_online(asset_type="scenario_pack", draft_asset_id, change_note)`，或 `scene_package_manage(action="finalize", scene_package_id, draft_asset_id)`，两种都可以。
- 已上线的应用要改场景包：`business_ui_manage(action="update", business_ui_id, scenario_pack_id, scenario_pack_version=<场景包草稿版本号>)` 换挂到草稿，再重新部署。

## 下线与删除

- **下线** `business_ui_manage(action="offline", business_ui_id)`：拆掉全部容器，使用者的库、源码包、版本记录都保留，可以恢复。确认时说清使用者会失去入口但数据不丢。已发布到目录的要开发者先在发布管理页取消发布。重新上线 = 重新部署当前版本再上线。
- **删除** `business_ui_manage(action="delete", confirm_permanent_delete=true)`：永久删除整个家族的所有版本、实例、库和源码包，不能恢复。要开发者明确授权；有在线或已发布版本的，逐字复述应用名请他确认。进度用 `deletion_status` 查：`cleanup_failed` 且 `retrying=true` 是删除中；终态 `failed` 要开发者确认下游修好后带 `retry_failed=true` 重发。
- 停用在用的应用用下线，不用删除。
