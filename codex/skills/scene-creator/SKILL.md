# 场景包制作与优化

## 工作目标

把场景包作为整体交付，不把某一种资产当成默认答案。先理解共同业务终点、候选路线、业务档案、里程碑、权限和验收证据，再选择 SA、普通任务点、FastAgent、工具、Workflow、编排和业务界面的组合。

遵守三层事实边界：

1. 当前 MCP `tools/list`、线上资产、服务端校验和 Max Runtime 是机器事实。
2. `get_diagnosis_doc` 返回的当前契约解释机器事实；冲突时停止使用冲突条款并回到第 1 层核对。
3. 本 Skill 只定义外部制作流程、业务设计方法、授权和证据门，不复制 Max 内部状态机或 Workflow 长契约。

禁止虚构工具、action、ID、Schema、版本、返回字段、资产状态或运行证据。

## 任务启动

### 识别模式

| 模式 | 启动条件 | 默认工单模式 |
|---|---|---|
| 创建 | 新建场景包，或把业务材料沉淀为能力 | `write` |
| 诊断 | 只读检查场景包、项目日志或运行问题 | `read` |
| 优化 | 修改已知问题或落实诊断结论 | `write` |
| 续作 | 已有 `task_id` 或明确要恢复未完成任务 | 读取原工单 |
| 验证发布 | 验证、上线或检查既有制作结果 | 按是否写入选择 |

只执行一次普通业务任务、只咨询概念或开发无关应用时不要进入本 Skill。

### 连接检查与工单 Gate

开始任务时读取 [外部 MCP 工具路由](references/external-mcp-tools.md)，再核对实时工具 Schema。

安装或连接验证只执行只读 `tools/list` 和一次只读资产查询，不创建工单、资产或项目。

进入一个具体制作、诊断或优化任务后：

1. 新任务的第一项业务 MCP 调用使用 `task_manager(action="create", mode=...)`。`write` 模式同时传入本文件 description 中的完整 `skill_version`。
2. 已知 `task_id` 的续作先单独 `task_manager(action="get")`。
3. 明确是续作但不知道 ID 时先单独 `task_manager(action="list")`；唯一匹配再 `get`，没有匹配才 `create`，多个候选请用户选择。
4. 等待 Gate 成功后再读取服务端制作契约、搜索资产、规划或写入；`list_assets/get_asset` 不接收 `task_id`，重要选择结论用 `task_manager(insert)` 记录。
5. `read` 诊断转入修复时新建 `write` 工单并传 `continued_from_task_id`，不在只读工单中执行写 action。

工单只记录业务事实、资产标识、决策和验证摘要。不要写入密钥、Cookie、预签名 URL、原始敏感日志、供应商完整输出或内部挂载路径。

## 场景包模型

场景包是一张通往共同业务终点的路线地图：

- **候选路线**：不同目标、准备状态、档案事实或限制对应的可行路径；
- **稳定路段**：输入输出和依赖在制作期可确定，适合工具、FastAgent 或 Workflow；
- **选路节点**：需要理解自然语言、业务档案、风险或当前结果，保留给 Agent、用户或平台已支持的 Gate；
- **到达标准**：证明业务终点和用户可见交付已经成立的证据。

参考项目只提供候选路线和证据，不能自动成为所有用户的唯一 SOP。业务档案只读取足以改变本次路线、参数、优先级或解释的最小充分信息；当前用户表达优先于历史记录，Agent 推断保持为假设，档案缺失、过期或冲突时补充事实或使用明确的安全默认。

### 选择执行形态

按职责而不是复杂度或资产数量选择：

| 需要 | 形态 |
|---|---|
| 少量、低风险、一次性的确定调用 | SA 直接执行 |
| 独立上下文、开放式判断或执行中自然语言交互 | 普通任务点 / TaskAgent |
| 一次输入、自包含推理、一次输出 | FastAgent |
| 至少两个稳定真实步骤、固定数据流或高频复跑 | 单 Workflow |
| 多个 Workflow 的固定扇出、汇合、映射和单次交付 | 当前服务端支持的固定 DAG 编排 |
| 多入口、用户动作、重入、受控循环或多交付 | 仅当实时 Schema 和版本化服务端契约明确支持图编排时使用 |
| 场景专属可视化 Workflow 交互入口 | 当前业务界面能力 |

当前实时 `scene_package_manage` 只公开固定 DAG 时，只制作固定 DAG。设计稿、集成分支、旧资产和示例不能证明新图能力已上线；禁止从这些资料复制 `capability`、Gate、边或 Runtime 字段。实时工具和服务端契约出现新版本后，再按该版本提供的形状制作，不能把固定 DAG 与新图对象混写。

业务界面是交互层，不执行或解释内部 DAG。当前 `scene_package_ui_bundle` 要求场景包至少挂载一个 Workflow 时，没有 Workflow 的场景包不能通过该工具制作定制界面；记录当前平台限制并回落对话界面。以后只有实时 Schema 明确解除该门槛时才改变此结论。

### 信息归属

| 信息 | 权威位置 |
|---|---|
| 单工具用途、参数和正式 Schema | Tool Group / 实时工具契约 |
| 工具或 FastAgent 的搭配和加载方式 | Toolset 使用指南 |
| FastAgent 自包含推理方法 | FastAgent Prompt |
| 普通任务点的交互式执行方法 | 任务点 Prompt |
| 单阶段稳定步骤和数据流 | Workflow 脚本与 IO Schema |
| 多 Workflow 依赖、映射和交付 | 当前版本的 `workflow_orchestration` |
| 共同终点、候选路线、选路、权限和知识读取时机 | `apc_skill` |
| 长知识、模板、案例和详细 SOP | 场景 Skill 文件 |
| 数据语义和查询规则 | Dataset Skill |
| 页面与公开交互契约 | 业务界面源码和宿主 SDK |

同一规则只保留一个权威位置。不要在 `apc_skill` 复制 DAG、工具完整 Schema或制作说明，也不要因为避免重复而删掉 SA 必须始终知道的业务路由、关键前置检查和能力加载时机。

### `apc_skill`

`apc_skill` 至少说明：

- 场景解决什么问题、共同终点和适用条件；
- 业务里程碑、每阶段目标和用户可见产出；
- 候选路线、适用条件和选路节点；
- 必需业务输入、预期交付和验收标准；
- Agent 可判断、用户必须决定和高风险授权的边界；
- 业务档案的最小读取规则、证据优先级和缺失处理；
- 尚未被其他资产固化的关键业务规则、前置检查和能力选择；
- 在哪个阶段按名称读取哪个场景 Skill 文件；
- 如何通过现有投稿和审稿机制整理候选事实。

关键瓶颈需要可执行指导，但不要复制单工具参数：例如说明“先确认授权和输入完整性，再加载某能力域完成采集”，具体工具链放 Toolset Skill，确定步骤放 Workflow。

## 九阶段制作流程

### 1. 建立证据基础

在工单 Gate 后收集：用户提供的项目、SOP、文档和数据；完整项目日志；可访问的场景包、经验、任务点、Toolset、FA、Tool Group、Dataset 和业务界面；当前服务端规范。

用户提供参考项目时，不只看摘要。读取需求、关键调用、TaskAgent/FA 结果、失败重试、等待、最终交付和必要的原始日志，提炼真实调用链、瓶颈和有效经验。

### 2. 形成场景包蓝图

蓝图覆盖目标用户、触发场景、共同终点、里程碑、候选路线、业务档案影响、输入输出、交付证据、Agent/用户/确定性资产边界、能力缺口和剩余盲区。没有真实基线时只做定性价值判断。

### 3. 选择资产并挑战方案

先反读关键资产的完整配置、权限、版本、Schema 和在线状态，再按“选择执行形态”分配职责。创建任何资产前完整读取 [方案挑战检查清单](references/方案挑战检查清单.md)。

向用户展示业务方案、交付、能力缺口和授权边界。用户确认整体方案后，该授权覆盖同一范围内可逆的离线草稿创建和修复；只有范围或业务路线发生实质变化时重新确认方案。

### 4. 创建或更新场景包草稿

优先复用和更新原资产。调用实时 `scene_package_manage` 创建离线草稿；当前 create 默认克隆官方基础场景包时，反读继承关系并只修改真实需要的部分。保存 `scene_package_id`，后续修复更新同一草稿，不创建平行资产绕过错误。

上传场景 Skill 文件时使用 `workflow_file_upload`，再以 `skill_files_mode="merge"` 绑定；每个文件必须在 `apc_skill` 中有明确读取时机。

### 5. 补齐依赖资产

只有真实缺口才创建或维护 Tool Group、Auth Card、FA、Toolset、普通任务点和 Dataset 关系。共享资产修改前核对影响范围；不能保证不影响其他场景包时克隆后替换目标引用。

没有可信 output Schema 的安全只读 MCP 工具，使用两组代表性输入取样并复验最小候选 Schema。破坏性、发布、凭证、金融或不可逆调用未经授权不得取样。

### 6. 按需制作 Workflow 和编排

确认需要 Workflow 后读取 `workflow_authoring`；写脚本前读取 `workflow_single`；确认需要多 Workflow 后读取实时 `workflow_multi`。特殊原语、文件、handoff 或失败模式按需读取匹配示例，同一工单不重复通读同一 topic。

每条 Workflow 执行：依赖闭包和 Toolset 上线反读 → Preview → 修复同一草稿 → Create/Update → bubble → 轨迹语义验收。使用 [Workflow 验收检查清单](references/Workflow验收检查清单.md)。

编排前再次读取实时场景包工具 Schema和服务端版本契约。固定 DAG 使用完整对象整体替换；新图只在实时能力明确支持时制作。所有节点先满足单 Workflow 契约，编排保存通过不能替代整条路线运行证据。

### 7. 按需制作业务界面

先核对实时 `scene_package_ui_bundle` 的 Workflow 门槛和宿主 SDK 能力。当前场景包已挂载 Workflow 且用户需要定制入口时，读取 [业务界面制作契约](references/业务界面制作契约.md)，从 `download_template` 返回的官方模板开始，不从空目录、通用项目或历史模板开始。

界面只消费宿主公开输入、状态和交付契约，不接收 TPE ID、工具清单、提示词、脚本、DAG 或 Agent 控制动作。运行契约变化后重新冻结界面契约并回归验证。

### 8. 分层验收

证据分层记录，不用上层文字检查冒充下层运行：

- `asset_contract_validated`：资产存在、关系、权限和 Schema 已反读；
- `workflow_bubble_passed`：目标 Workflow 当前版本有终态轨迹和语义验收；
- `orchestration_static_validated`：Hub 保存门通过节点、映射、交付和版本结构；
- `orchestration_runtime_verified`：真实运行命中目标编排并验证顺序、Gate/handoff 和交付；
- `ui_deployment_verified`：当前契约对应的源码、构建、部署和反读通过；
- `full_validation_skipped`：用户跳过全真运行，并记录 FA 内容、未触达分支和副作用盲区。

发布前读取 [场景包验收检查清单](references/场景包验收检查清单.md)；有业务界面时同时读取 [业务界面验收检查清单](references/业务界面验收检查清单.md)。缺少整图运行工具时只能记录静态通过和运行盲区，不能声称编排已全真验证。

### 9. 发布、全真运行和关闭

发布前反读最终场景包和所有引用，确认 `apc_skill`、Skill 文件索引、资产状态、专项验证、授权和盲区一致。发布是外部状态变更；只有用户当前请求或已确认方案明确包含发布时执行，随后反读线上状态。

真实 Max 项目会启动真实 Agent、FA、工具和外部副作用。只有用户批准覆盖所选路线可能执行的全部 Workflow 后才运行；跳过时继续交付并记录 `full_validation_skipped`。复用同一 `project_id` 查询、回复和读取日志，不为轮询或小修复反复新建项目。

最终用 `task_manager(insert)` 记录资产、验证层级、全真决定和剩余盲区，再 `task_manager(complete)`。只有发布状态和实际证据都成立时才能说“可直接使用”。

## 诊断与优化

诊断先反读场景包全貌，再按真实引用关系检查：

```text
场景包与 apc_skill
→ 普通任务点 / Workflow / 当前编排
→ Toolset
→ FastAgent / Tool Group / Dataset
→ 业务界面
→ 项目日志和交付物
```

全量诊断覆盖每层，但只沿异常证据下钻；聚焦诊断完成用户指定范围。发现按严重、警告、建议分级，包含位置、证据、根因、影响和建议。

修复顺序为结构和关系 → IO 契约 → 运行知识和 Prompt → 界面表现。整体方案授权内的可逆原资产修复无需逐字段重复确认；共享资产替换、范围扩大、删除、发布、收费、凭证和不可逆副作用单独确认。修改 Workflow 重做 Preview、bubble 和语义验收；修改 IO 或编排还要重验接缝；修改公开 UI 契约还要重新部署验收。

## 授权边界

用户确认的整体方案可以授权同一范围内的离线草稿创建、可逆更新、上传和验证。以下动作必须有明确授权，除非用户当前请求已经清楚包含它们：

- 修改会影响其他场景包的共享资产；
- 删除资产、替换凭证或扩大权限；
- 发布场景包或业务界面；
- 收费、邮件、通知、正式业务写入和其他外部副作用；
- 真实 Max 全真运行。

发现受限资产时区分“配置不可见”和“运行不可用”，说明影响后再决定保留、克隆或替换，不把脱敏空字段误判为空资产。

## 恢复规则

- 工具或 action 不存在：重读实时 Schema，更新调用，不虚构平行工具。
- 工单模式或 Skill 版本不匹配：按结构化错误切换工单或执行受控升级，不绕过 Gate。
- Preview、bubble、Hub 或部署失败：修复同一资产或源码包，再重跑受影响验证。
- 路线需要临场规划：停止强行固化 Workflow，交还 Agent 或普通任务点。
- 当前平台不支持计划中的图或 UI 模式：保留业务蓝图，采用当前可表达的安全路径或记录平台阻断，不用前端或脚本伪装能力。
- 基础设施错误：只有返回明确可重试且操作幂等时才带变化重试。
