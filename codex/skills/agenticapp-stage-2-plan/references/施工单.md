# 施工单

把 PRD 和取舍的答案编成要造的东西，只给你和后续 Agent 用，写进阶段文档 G3，不给开发者看。③ 照它做。

## 逐行映射

把 PRD「每一步谁来做」逐行映射，顺序固定：工具集 → FA → 编排型 TPE → 路线。表里各项的写法都在对应的工具 Skill，编施工单时就读，不等到 ③。

| PRD 里的 | 变成 | 怎么定 |
|---|---|---|
| 脚本步骤 | 编排脚本里的一步 `await tool(…)` | 从 `agenticapp-tool-workflow` 的三种模板里选一种改。路线要读写应用库的，现在就按 `agenticapp-tool-workflow`「读写应用库」逐行写清：哪些固定读写由脚本做、哪些数据由 FA 按情况查、有没有应用后端回流 |
| 模型步骤 | 一个 FastAgent（复用或新建） | 定输出对象每个字段的含义和非成功状态（`needs_input`、`insufficient_evidence` 等）；档位照 PRD，建法见 `agenticapp-tool-workflow`「建 FA」 |
| 人 · 开始 | 路线入口表单 | 入口字段放哪见 `agenticapp-tool-data-template`；组装见 `agenticapp-tool-workflow` 的 assemble |
| 人 · 在应用页面上操作（选一项、改字段、采纳或不采用、标记状态，不需要模型） | 页面 + 应用后端接口写表，不经路线 | 写哪张表、哪几列（列为 `user` 可编辑），接口见 `agenticapp-tool-frontend`「业务页面」；操作后要模型接着做的，由页面发起下一条路线，入口只传业务键，路线自己读库 |
| 人 · 中途补信息 | 节点级运行中交互（中途表单） | `agenticapp-tool-workflow` 的「什么时候用路线、用哪种」 |
| 人 · 审阅结果 | 路线的交付审阅 | `agenticapp-tool-workflow` 的「交付与审阅」；要「修改后重跑」的加跳转到另一条路线 |
| 放进去 / 拿出来 | TPE 的 `input_schema` / `output_schema`，以及模板表 | 字段名用英文蛇形，含义写进 `description`；文件字段见 `agenticapp-tool-workflow`「文件产物」 |
| 会停下的情况（停下 / 标记继续 / 重试一次） | 脚本的失败出口 | `agenticapp-tool-workflow`「失败出口怎么写」 |
| 会记下来的东西 | 数据模板里的表与列 | 每列定 `user / agent / system`，每张表回答五问，见 `agenticapp-tool-data-template` |
| 页面 | 预置件、生成页或定制页 | 按 ① 问到的界面答案，见 `agenticapp-tool-frontend` |
| 用量上限 | 一次最多处理多少条、单次运行时长 | 超过平台单次运行能力的改成分批或分片（`agenticapp-ref-platform-limits`）；做不到回 ① |

核实对照表（G2）里「复用什么」那一列有资产的，照它复用、复制后改，不重复新建。

## 再定三件事

- **路线数**：按 `agenticapp-tool-workflow` 的「什么时候用路线、用哪种」定拆几条。只有脚本步骤的应用也建一条最小路线，只作平台要求的挂载依赖，不为纯数据管理应用虚构额外业务流程。一条路线步骤太多、业务说明讲不清时，按 `agenticapp-stage-1-requirements`「谁来做」的填写规则考虑拆成两条，业务说明里讲清。
- **数据怎么进出**：每个业务输入从入口来还是读库，同一个值只走一边（`agenticapp-tool-data-template` 的「入口字段放哪」）。每个产出写到哪：更新已建行，还是回流建新行。同一业务再做一次时，是更新原记录（写明业务键，如「同一门店同一周」），还是每次新增一条（如巡检历史），按 `agenticapp-tool-data-template` 的「谁建行、谁写列」。
- **只有脚本步骤时**：施工单写一行「一条最小路线 + N 张表 + 数据页」即可；功能与页面和验收条目照写。

## 新 SDK 应用

`frontend/goalfy-app.json` 有 `"executor": "launch_agent"` 的，施工单这样改：

- 不建场景包；路线与编排型 TPE 挂在应用版本上（`workflow_orchestration` + `tpe_ids`），节点脚本调用的工具挂在该节点的 TPE 上。
- 运行时没有 Agent：审阅只用 `user_gate`（等使用者确认，或直接交付），动作只在 `complete_business`、`fail_business`、`start_orchestration` 里选；不写交由 Agent 处理、Agent 接管。
- 使用者要在上一趟基础上改的，审阅加一个 `start_orchestration` 动作指向修正路线，修正路线在上一趟交付上改，不从头重做。
- 含外部发送（发信、发消息、下单）的步骤，失败后重试会重跑：用幂等键或先查后发防重复。多个执行可能同时改同一条业务数据，怎么兜住见 `agenticapp-tool-data-template`「建表时的列规则」。

具体写法见 `agenticapp-tool-workflow`。

## 写进 G3

| 清单 | 每项写什么 |
|---|---|
| 资产清单 | 类型、名称、复用还是新建、来源资产 ID、FA 的模型 |
| 路线草图 | 每条路线：`orchestration_id`、节点顺序、入口字段、中途表单、审阅方式 |
| 表清单 | 表名、列、每列可编辑性、唯一键、谁建行 |
| 页面清单 | 预置件 / 生成页 / 定制页，各自读写哪张表或哪条路线 |

编完核对：PRD 每一行在施工单里都找得到；每个外部调用有失败出口；每张会重复写入的表有业务键。
