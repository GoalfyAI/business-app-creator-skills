# 协议一：事实、决定、授权与变更

各阶段使用同一套规则。规则按事实、决定、授权、变更四组排列，编号供其他文件引用。违反任一条，任务视为失败。

## A. 事实

**F1 零捏造与参数溯源。** **禁止**虚构工具、action、资产 ID、Schema、返回字段、资产状态、业务数据、运行证据。每个工具参数必须能追溯到五种来源之一：开发者输入、上游真实输出、已反读的资产配置、服务端契约、已明确记录的假设。真实数据不可得时如实说明；估算**不得**写成运行结果；统计值与结论必须标明来源、假设、盲区。

**F2 材料完整读取。** 开发者指定的文档、项目、日志必须完整读取；截断或分页时续读到结束。参考项目必须完成三层分析，方法见 P2 第 2.1 节。

**F3 标识与结果必须反读。** 传入任何 ID 前，先用 `get_asset` 或 `list_assets` 读回，确认它对应的真实名称。家族根 ID 会自动解析到最新 live 版本；核对旧版本必须传物理行 ID。每次创建、更新、关联、上线之后，读回确认实际结果。返回成功**不等于**内容正确。

**F4 受限资产不等于空资产。** `can_view_params=false` 时配置为空是脱敏结果，资产运行时仍可调用。必须先向开发者说明并等待确认；确认后重试时带 `allow_restricted=true`。

**F5 工具定义是唯一事实。** 本 Skill 写的工具名、action、字段可能滞后于服务端。两者冲突时以当前工具定义为准，差异记入工单。列表里找不到的工具**不得**假设存在，**不得**虚构平行工具。探测凭证只做只读查询，**禁止**为此创建工单、资产或项目。

**F6 取证纪律。** 判定"平台限制"之前，先全文检索 Skill 与清单，复核实时工具定义与结构化报错；归因平台必须给出错误码、文档条款或复现记录。判定"文档没写"之前，先做关键词全文检索，命中不为零则按原文执行。修复一个现象之前，先确认它的直接触发条件。结论方向恰好是"不是我的问题"时，把取证标准再抬一档。

**F7 如实汇报。** 证据分层记录，**禁止**用上层文字检查冒充下层运行验证。核心目标达成而次要细节受限时可以停止重试，但交付必须说明没做到什么、原因是什么、什么条件下可以改进。**禁止**对任务给出时间预测或承诺。只有发布状态与实际证据都成立，才能说"可直接使用"。

## B. 决定

**D1 四个角色。** 开发者：使用本 Skill 制作、维护、发布业务应用的人，代表客户方回答业务事实，拥有产品形态、业务契约、授权的决定权。最终用户：业务应用上线后使用它的人，只在开发者确认的入口、表单、审阅、授权节点参与。开发 Agent：此刻执行本 Skill 的 Agent，负责调查、提案、制作、验证，**不代替**开发者决定。运行 Agent：业务应用运行时在能力容器里执行任务的 Agent。称谓规则见 SKILL.md 第 1.1 节。本 Skill 写"向开发者确认"时指当前使用者。**禁止**把开发者与最终用户合称"用户"后自行补全意图。

**D2 确认节点。** 只在改变产品结果、契约、风险或责任的节点确认：业务理解与目标；候选路线；聚焦还是泛化；执行形态；路线依赖图；交付对象；最终审阅责任与动作；最终用户或 Agent 介入点；能力削减或替换；影响其他应用的改动；外部副作用；删除；发布；收费；真机运行；数据留存范围与隐私；逐列可编辑性与覆盖规则；回流入库语义；页面范围；设计与原型；上线授权。只读调查、候选草案、同一确认范围内的机械实现、离线修复、可逆验证**自主推进**。

**D3 决策卡。** 每次给开发者的决策卡只含七项：当前问题、证据、推荐、替代、选择后改变什么、验收怎么看、需要决定什么。目标、责任、范围变化时确认业务决定；费用、权限、发布、外部副作用变化时确认动作授权；同一范围的实现与修复由 Agent 自主完成；测试不通过时展示失败证据与修复路径，人同意继续**不改变**测试结果；非阻塞的改善想法记为后续建议，**不扩张**本次功能。

**D4 两种对齐方式。** 多个相互影响的决策先形成 Plan，一次列清已确认事实、候选项、推荐项及理由、各项影响、待开发者选择的事项、验收标准；涉及路线时附依赖图与交付方案。统一确认前**不得**写正式契约，**不得**创建资产。只有一个决策，或缺少只有开发者能提供的事实时，直接单项询问。业务路线、聚焦与泛化、执行形态、最终审阅、最终用户介入、能力削减、外部副作用**没有安全默认**。

**D5 面向开发者的表达。** 业务方案只说六件事：能解决什么问题、分几个阶段、各产出什么、有哪些候选与推荐、需要开发者决定什么、最终用户在哪些节点参与。**禁止**在业务方案里出现资产数字 ID、技术字段名、代码片段、内部调用链。平台术语由 Agent 转译。内部记录带 ID 消歧；方案用名称。工作语言跟随开发者，**不得**中途切换。

**D6 最终用户的确认不替代专业判断。** 最终用户能核实事实，不能承担专业判断。系统必须拿出证据并说明不确定性，必要时引入专家。**禁止**用一个确认按钮转移专业责任。

## C. 授权

**A1 工单先行。** 新任务的第一项业务调用必须是 `task_manager`。`read` 与 `write` **不得**混用；`write` 必须传完整 `skill_version`。工单建立后每次调用带 `task_id`。`task_id` 是审计范围，不是资产标识。

**A2 高风险操作需明确授权。** 修改影响其他应用的共享资产；替换开发者指定或权限受限的能力；删除、替换凭证、扩大权限；能力容器上线、应用定稿上线、目录发布；收费、发信、通知、正式业务写入等外部副作用；在真实项目中运行。Plan 只有明确写出上线动作时才同时构成上线授权。范围、路线、能力削减或风险发生实质变化时必须重新确认。试验授权与正式制作授权**分开取得**。

**A3 修改共享资产前先克隆。** 被其他应用引用的工具集、FastAgent、普通任务点先用 `clone_asset` 复制，在副本上修改，再更新当前容器的引用。副本调用名一律从返回值反读，**禁止**推算或拼接。脚本里的 `tool("<mr_name>")` 与预加载声明必须换成副本的调用名。

**A4 能力削减或替换必须先确认。** 对开发者引用或明确预期的能力，**禁止**静默削减、替换、降级。必须单独说明原能力、不能沿用的原因、替代方案的能力边界，然后暂停等待确认。**禁止**混在长篇汇报里带过。

**A5 后端边界与身份。** 专属后端由 p2s 部署在公网域名上，不是内网 Service。链路固定为：App 经 `sdk.api.request` 到宿主，宿主经 Max 后端 `api-proxy` 服务器到服务器转发到本后端。Max 只发三个头：`Content-Type`、`X-Goalfy-Business-Request-Id`、`X-Goalfy-Context`；其余请求头与 cookie 属平台内部，应用**不得**读取或依赖。`X-Goalfy-Context` 是 base64 claims；是否签名以 `backend/README.md` 为准，截至 2026-09-07 未签名。未签名期间基于 claims 的判权只拦误操作，不是安全边界；资金、批量删除、对外发布类动作**不得**只凭 claims 放行。由此三条纪律：写权限由后端自判，用 `canWrite`，宿主不区分读写、不兜底；生产态不开 CORS；没有第三方密钥注入通道。响应一律 `{code, msg, data}` 信封，业务失败也返回 HTTP 200，自定义码 ≥1000，其中 1000 至 1099 是脚手架保留段，业务码从 1100 起。

**A6 调用契约零改动。** 应用与平台只有两种交互。第一种是发起一次业务路线运行：`chat.start` 携带 `metadata.submit_data`。第二种是应答运行中表单，即三次握手：服务端下发表单、应用提交应答、服务端返回业务确认；提交的 Promise 到业务确认才完成。最终交付审阅 `delivery.review` 也是业务表单，用 `reply` 应答；`confirm` 只用于普通聊天确认。**禁止**发明字段、改语义、绕开 SDK。创建态与进行态分界：应用是唯一发起入口；项目页**不发起**新运行。

**A7 桥层与数据面硬限制。** `GET` 与 `DELETE` 不带 body；嵌套查询走 POST；请求 ≤256KiB；响应 ≤1MiB；上游超时 13 秒，`statement_timeout` 10 秒；写接口必须幂等，键是 `X-Goalfy-Business-Request-Id`；文件只传路径。连接经 dataset-proxy，**禁止** `BEGIN`、`COMMIT`、`ROLLBACK`、`SET ROLE`、`SET search_path`。应用代码**禁止** `CREATE TABLE` 与 `ALTER TABLE`，加表改表回模板。一个应用只绑一个数据模板。schema 真名**禁止**硬编码，引用表只用 `buiTable('表名')`。镜像必须用户无关。

**A8 编辑与生产共治。** 逐字段可编辑性的唯一正本是 PG 列注释 `[editable:user|agent|system]`。`user` 列 FastAgent 与生产回流**不得**覆盖；读不到声明的列按 `user` 处理。所有写入带来源标记 `user_edited` 或 `generated`。回流入库语义由开发者在 G3 声明。

**A9 apc_skill 禁写。** **禁止**写资产数字 ID，只用名称引用；**禁止**复制业务路线依赖图；**禁止**写单个工具的完整 Schema；**禁止**写制作过程；**禁止**写最终用户的私有业务数据。

**A10 设计纪律。** 脚手架 demo 只用于理解协议与 SDK，**禁止**复用其页面结构与视觉。生产级原型经开发者确认后才编码。与 demo 高度相似且说不出业务理由，视为设计未做。

## D. 变更

**C1 自底向上的创建顺序。** 工具组与授权卡、FastAgent、工具集、普通任务点、能力容器草稿、编排型 TPE 创建与挂载、其他关联与业务路线。**不得**跳跃。草稿容器与最终关联是两个阶段；单元未通过验收前**不得**写最终路线。单条编排型 TPE 只要声明业务事件，正式运行也必须有单节点业务路线。

**C2 变更影响必须展示。** 任何改动先按需求追踪矩阵列出受影响的页面、数据、执行、测试，以及未影响项与理由；改后回报实际修改与验证结果。相关通过记录沿真实依赖失效。**禁止**只改路线 JSON 却保留原页面验收结论。规则见协议二。

**C3 从受影响阶段重新进入。** **禁止**全量重做。同一确认范围内修同一资产，**禁止**反复建新资产规避问题。

**C4 部署与下线纪律。** 先预部署验证再交付。下线走 `business_ui_manage(offline)`：拆容器，保留库与源码，可重新上线。已发布到目录的先取消发布才能下线。删除才是不可逆的。回滚应用**不等于**数据库可降级。

**C5 先包后应用只是工程前置。** 能力容器上线是应用制作的契约基线，不是产品探索的顺序；G1 至 G3 已把业务与应用一并设计。能力容器工单结单**不等于**应用已交付。
