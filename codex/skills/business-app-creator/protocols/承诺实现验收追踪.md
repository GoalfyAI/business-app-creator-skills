# 协议二：承诺、实现、验收的追踪

每条业务承诺必须贯穿节点、数据、页面、资产、验收用例。节点测试、路线测试、数据库测试、页面测试各自存在**不算**追踪。

## 1. 追踪链

```text
业务承诺，来自 G1 基线
  → 业务节点与关键决策，来自 G3 运行设计
  → 数据表与字段，来自 G3 数据面，方法见 G3 第 8 节
  → 页面与动作，来自 G3 页面设计，方法见 G3 第 8 节
  → 实现资产：工具组、FastAgent、工具集、编排型 TPE、业务路线、后端接口、页面，产自 G4 至 G6
  → 验收用例：U 行为项实例与专业验收清单项；G3 设计，G4、G5、G6 分层取证，G7 复验
```

任何页面、字段、接口、脚本步骤都必须能追到一条承诺；任何承诺都必须有承载与验证方法。追不到承诺的功能**不做**；没有承载的承诺过不了 G3-01。

## 2. 三张表与一份矩阵

沿用双副本、指纹、pending 机制，细则见 `references/表结构与累加机制.md` 与 `references/应用结构表与结果检查表.md`。本地工作副本供每轮定位进度；工单权威快照供续作重建。每个条目带 `hash` 与 `status`，状态只有 `pending`、`passed`、`waived` 三种。只处理 pending；关联内容改动后自动回 pending；`waived` 必须带理由。

| 载体 | 记什么 | 建立 | 更新 |
|---|---|---|---|
| **执行结构表** | 每条编排型 TPE 的步骤；每步的执行者，四种之一：规则、模型自主、模型加确认、最终用户；证据：试验次数、通过率、稳定性、p95 耗时、每次成功费用；风险等级；确认形式；回退链；预算；依赖与并行组；FastAgent 清单 | G3 | G4 改脚本时同步条目；G5 与上线后按运行证据更新证据列 |
| **应用结构表** | 每个页面、每个后端接口、每张模板表；条目先挑战，`challenged=true` 后交开发者确认 | G3 | G5b 与 G6 实现时同步 |
| **结果检查表** | 正反例，来源分四层：黄金路径、真实历史、扰动、长尾；路线校验项；前端与后端校验项。条目带层级、覆盖步骤、判定方式、风险、是否留出 | G1 种子，G3 建立 | G4 至 G7 分层闭合；只能用真实数据置 passed，mock 只作过程记录 |
| **需求追踪矩阵** | 承诺到节点、数据、页面、资产、验收例的映射 | G3 | 任何变更先查它 |

## 3. 三个结论分别记录

同一条 U 行为，G3 记"设计已确认"，G5 记"后台验证通过"，G6 记"用户操作通过"，G7 记"最终版本复验"。四个结论**不共用**一个 passed。工单落账用 `metadata.stage` 与 `metadata.behavior_id` 区分，例如 `U5-02`。

## 4. 门禁汇总规则

一条 G 门禁引用多个 U 项时，先逐项列出通过、失败、阻断、不适用，再汇总。任一必需项未验证，该门禁**不通过**。完整性不看条目数量，看每条承诺是否同时有规则、实现、证据。

## 5. 变更影响

路线、表单、字段、脚本、页面的任何改动，先列受影响项、未影响项及理由。例如把"自动生成即结束"改为"负责人审阅后结束"，必须一起检查六处：业务完成标准、Review 责任与动作、运行等待与重入、待办与应答页面、状态与版本留存、超时与拒绝与重复提交测试。改后沿真实依赖使相关通过记录失效，只重验受影响项。**禁止**全量重做。

## 6. 工单证据标签

以下标签只出现在工单检查点里，不是工具参数。

| 标签 | 含义 |
|---|---|
| `business_baseline`、`behavior_scope`、`decision_list`、`route_sketch` | G1 业务基线；U 适用性判断；关键决策清单；业务路线草图 |
| `capability_matrix`、`trial_report` | G2 能力矩阵；试验报告 |
| `build_book`、`execution_structure_snapshot`、`result_checklist_snapshot`、`app_structure_snapshot`、`behavior_design` | G3 运行设计；执行结构表与结果检查表快照；应用结构表快照；行为验收设计 |
| `app_plan` | G3 确认版《业务应用计划书》正文与截图目录指针 |
| `needs_bubble` | 单元缺终态轨迹 |
| `orchestration_static_validated`、`orchestration_bubble_validated`、`orchestration_runtime_verified` | 路线三级证据。Bubble 标签一条路线一条，带 `orchestration_id` 与 `run_id` |
| `data_loop_verified` | G5b 应用数据闭环证据 |
| `full_validation_skipped` | 开发者跳过真机验证；存在时**不得**上线，**不得**结单 |
| `platform_blocked` | 平台能力不支持已选范围，已停止对应交付 |
| `autotest`、`integration`、`delivery_report` | G7 最终测试；真联调取证；交付报告 |
| `finding_resolved`、`finding_waived` | 问题单处置；waived 必须带理由 |
| `stage_exit` | 阶段出口逐项状态与证据指针 |

路线 Bubble 标签由结单 Gate 机器核验；其余标签的准确性取决于如实记录。**禁止**为了让工单看起来完整而标记未真实取得的证据。
