# 交接消息：每次只说四件事

每段结束、③ 的每次进度更新、退回到前一段时，给开发者发一条交接消息。它是开发者了解进度的唯一入口，开发者只看它也能知道现在该做什么。

## 格式

```text
【① 需求确认 → 等你确认】
刚做完：PRD 第 2 版：4 个刚需、2 个非刚需，每个刚需都写了放进去什么、拿出来什么；识别、报告、内容都用真实商家试过一次。
下一步：你确认后，我把它翻成方案，每个功能一道判断题请你答。
要你做的：① 读 PRD，不对的地方直接说是哪一条、哪里不对；② 答 8 道选择题；③ 请需求方把门店数据表分享给你的账号；④ 都没问题就回「确认这一版」。
花了多少：本段 760 积分（试跑一份完整报告）；累计 760；上限等你在第 6 题定。
```

| 项 | 写什么 | 不写什么 |
|---|---|---|
| 开头 | 【段名 → 状态】，状态只有四种：等你确认 / 正在做 / 卡住了 / 已完成 | 节点编号 G1–G7 |
| 刚做完 | 这次交出的东西，用业务话；① ④ ⑤ 有真实结果就带一句真实结果，③ 说做到哪了，后台做好的附「我先跑了一遍」（见 [../stages/3-制作.md](../stages/3-制作.md) 2.3）；还在查的写「正在查……，结果下一轮告诉你」；你替开发者定了的事（用哪个工具、哪一档模型）加一句「我定了……，影响是……」 | 建了几个资产、跑了几次验证、改了哪些文件 |
| 下一步 | 你接下来做什么；要等开发者的写「等你……后我……」 | 内部步骤清单 |
| 要你做的 | 编号列出，每项是开发者能做的动作；没有就写「没有」 | 开发者判断不了的技术确认（见 `SKILL.md` 第 3 节） |
| 花了多少 | 固定写成「本段 N；累计 N；上限 N」，三个数都要有，单位积分；有超支风险时再加「按现在的速度，到 ④ 结束约 N，超出上限 M」 | token、美元以外的口径；只写一次运行的花费 |

## 规则

- **③ 的进度消息必带「我先跑了一遍」**：后台标「做好了，真跑过」的功能，每个例子四项都写：例子、为什么挑、每一步的结果、最后的结果（表格见 [../stages/3-制作.md](../stages/3-制作.md) 2.3）；缺一项，这个功能的「后台」不能标「做好了，真跑过」。只写「示例跑通了」「制作和自测结果正常」不算。
- **④ 的交接必带验收报告**：「全部条目」用 [../stages/4-试用验收.md](../stages/4-试用验收.md) 2.4 的六列表头；只交「部署好了」「请你试一下」不算交报告。
- **花费三个数缺一不发**：本段 = 这一段到现在所有运行的积分之和（没花钱写 0）；累计 = 这张工单从 ① 起所有段之和；上限 = ① 里开发者确认的数，从工单 checkpoint 读。只有 ① 在开发者确认 PRD 之前，上限可以写「等你在第 N 题定」；之后写不出上限，说明 ① 没交棒，回 ① 补，不发交接消息。
- **花费只写实测或注明的估算**：实测读 `manage_goalfymax_project` / 冒泡终态里的 `cost_credits`，口径见 [../reference/平台对象速查.md](../reference/平台对象速查.md)「积分怎么算」；`cost_partial=true` 写「至少 N」，`cost_credits=null` 写「没取到」；还没跑的写「估算约 N」。
- **累计到上限的 80% 时**，交接消息开头改成「等你确认」，把「继续做 / 减少测试份数 / 提高上限」做成选择题；没得到回答前不再做会花钱的事。
- **卡住了**：写卡在哪、谁在处理、对开发者的影响和预计什么时候能继续；平台问题的报错原文不放正文，放方案页 `.pv-raw`。
- **退回**：写退到哪一段、为什么、要开发者重新看哪一部分（只列受影响的条目）。
- 同一条消息里不夹阶段评分；评分按 [阶段评分.md](阶段评分.md) 另发一条。
- 发消息的同时更新方案页 `#status`：`.pv-summary` 写「刚做完」，`.pv-you` 写「要你做的」，`data-state` 与开头状态一致（等你确认 = `waiting`，正在做 = `working`，卡住了 = `blocked`，已完成 = `done`），`data-stage` 写当前工作区阶段。
