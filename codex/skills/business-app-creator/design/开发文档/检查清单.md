# 开发文档检查清单

每份文档交给 Studio 之前逐条对照。P0 有一条不满足就不交，改完再查；自查结果写进当段阶段文档。

## P0 版式

- [ ] 开头是 [样式.md](样式.md) 那段，原样复制，`<style>` 里一个字符没改；整页只有这一个 `<style>`。
- [ ] 没有 `<script>`、`<link>`、`<iframe>`、`<button>`、`<input>`、`<textarea>`、`<select>`、`<form>`；没有 `onclick` 这类属性。
- [ ] 正文结构照骨架：版块齐全、顺序不变，只用骨架和组件里出现过的类名，没有自造的类名和样式；行内 `style` 只出现在 `--done`、`--estimate`、`--stop` 三处。
- [ ] 全文搜不到「【填」和 `<!--`。
- [ ] 链接只有页内锚点（`#…`）和 `https://` 网址；没有指向本机文件、工作区路径的链接。
- [ ] 展开、收起只用 `<details>`；骨架里默认展开的只有方案的验收表。

## P0 内容

- [ ] 数一致：制作进度的完成数、进度条和表里的格子对得上；验收报告的结论数和全部条目对得上；PRD 预算条和上面的数字对得上。
- [ ] 没有编出来的数字和结果：每个数字来自真跑、真调、开发者给的，或标了「估算」「预期」；还没做出来的样例标「预期」。
- [ ] 用业务话：正文里搜不到 FA、TPE、工具集、Runtime、schema、编排、冒泡、资产 ID、接口名、表名英文、文件路径（验收报告「全部条目」表是给证据的，除外）。
- [ ] 写的是当前段的文档：没有提前写后面段的文档。
- [ ] PRD、方案、验收报告页脚的版本号比上一版加了一；制作进度写了这次的更新时间和「本次」变了什么，不写「第几次更新」。
- [ ] 方案：页面验收表的每条存数据的条目，在 `acceptance.json` 里都有同一编号的一项，反过来也一样。
- [ ] 验收报告：结论是「通过」的行，`project_id`、过程、证据三列都有内容；页面上没有请开发者去预览或正式入口里试的话。

## P1 读起来

- [ ] 正文每段不超过三句；规则、依据、异常都收在折叠里。
- [ ] 标题和摘要一眼能读懂：节点、功能卡、折叠的 `<summary>` 不靠展开也知道讲什么。
- [ ] 开发者或需求方自己说过的词照用；同一个东西全文只用一个叫法。
