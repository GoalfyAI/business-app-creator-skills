# 验收报告版式

④ 交给开发者的验收报告，在 Studio 里写成这一份 HTML。内容和硬门按 [../../stages/4-试用验收.md](../../stages/4-试用验收.md) 2.4 写，这里只规定每项放在哪、用什么组件。页面开头用 [样式.md](样式.md)，写完按 [检查清单.md](检查清单.md) 自查。

## 各部分放什么

| 部分 | 放什么 | 组件 |
|---|---|---|
| 开头 | 应用名、一句话结论 | `.eyebrow`、`h1`、`.lead` |
| 结论数 | 四格依次：没通过、通过、要你判断（好不好你说了算）、未测；有开发者选了接受的没通过条目，写进结论提示 | `.counts` |
| 结论提示 | 还有没通过、未测的条目时说清影响；全部通过时删掉 | `.callout.warn` |
| 好不好你说了算 | 每条一个折叠，展开放实际结果：报告节选、内容原文、前后对比 | `.sectiontitle`、`details.trial`、`.trialbody` |
| 未测的 | 每条写为什么没测（例如「到点触发要等真实时间」「从目录或分享打开要先发布」「只有线上才能验证：平台登录身份」）、做过的处理、看到的错误 | `.sectiontitle`、`<table>` |
| 全部条目 | 默认折叠，六列，一条验收条目一行 | `details.trial` + `<table>` |
| 用真实数据跑出的结果、自动发生的、实际花费 | 和方案的预期、估算对照 | `.sectiontitle`、`.bodytext`、`<table>` |
| 上线结果 | ⑤ 定版后在这份报告最后补上：定版的版本、④ 验过什么、未测的、实际花了多少、发布会怎样、你可以做的事，内容按 [../../stages/5-上线.md](../../stages/5-上线.md) 第 3 节写；④ 交报告时没有这一节 | `.sectiontitle`、`.callout`、`<table>` |
| 页脚 | 第几版、和上一版比改了哪几条 | `.footerline` |

- 结论只用四种：通过、没通过、好不好你说了算、未测。只能发布后才看得到的（到点真触发、从目录或分享打开）记「未测」，原因写清；到点触发的处理逻辑照样用开发工作集验，只有「到点真触发」这一点记未测。
- 「全部条目」里结论是「通过」的行，后三列（`project_id`、过程、证据）每格都要有内容；页面条目的 `project_id` 写「本机版」。缺一格就不能写「通过」。
- 结论数四格的数，和「全部条目」里各结论的行数一致，四格相加等于总条数。
- ⑤ 的「上线结果」里单列所有未测条目，写清发布后开发者可以自己在哪里看。
- 页面只用来读：**禁止**放按钮、输入框、表单；也**禁止**请开发者去在线预览、演示预览或正式入口里点、试、查。
- 按反馈重测后出新一版：只改变了的行，页脚写「第 N 版 · 重测了第几条」。交给 Studio 时 `documentType` 用 `acceptance`，见 [README.md](README.md)。

## 骨架

照抄下面的结构，把每个【填：…】换成真实内容。标着「重复」的块按实际数量复制，多余的删掉；`<!-- -->` 注释写完后全部删掉。

```html
<article class="sheet">
<div class="eyebrow"><span></span>【填：应用名】 · 验收记录</div>
<h1>验收报告</h1>
<p class="lead">【填：一句话结论，例如「24 条验收条目里 21 条通过，2 条要你判断，1 条没测」】</p>
<div class="counts"><div><b>【填】</b>没通过</div><div><b>【填】</b>通过</div><div><b>【填】</b>要你判断</div><div><b>【填】</b>未测</div></div>
<div class="callout warn"><strong>【填：还有什么没过】</strong>【填：影响什么、接下来怎么办】</div><!-- 全部通过时删掉 -->

<div class="sectiontitle"><h2>好不好，你说了算</h2><span class="evidence">【填：几条】</span></div>
<details class="trial"><summary><span>【填：编号 · 验收条目】<small>【填：要你判断什么】</small></span></summary>
<div class="trialbody"><p>【填：实际结果：报告节选、内容原文或前后对比】</p></div></details><!-- 重复 -->

<div class="sectiontitle"><h2>未测的</h2></div><!-- 没有就删掉这个标题和下面的表 -->
<table><thead><tr><th>条目</th><th>为什么没测</th><th>做过的处理与看到的错误</th></tr></thead><tbody>
<tr><td>【填】</td><td>【填】</td><td>【填】</td></tr><!-- 重复 -->
</tbody></table>

<details class="trial"><summary><span>全部条目（【填：总条数】条）<small>每条的结论和证据</small></span></summary><div class="trialbody"><table><thead><tr><th>#</th><th>验收条目</th><th>结论</th><th>project_id</th><th>过程摘要 / 页面操作步骤</th><th>查到的行 / 截图与地址 / 拿到的产出</th></tr></thead><tbody>
<tr><td>【填】</td><td>【填】</td><td>【填】</td><td>【填】</td><td>【填】</td><td>【填】</td></tr><!-- 重复：每条验收条目一行 -->
</tbody></table></div></details>

<div class="sectiontitle"><h2>用真实数据跑出的结果</h2></div>
<p class="bodytext">【填：本段真跑与 ③ 真跑的结果摘要，和方案的预期对照】</p>
<div class="sectiontitle"><h2>自动发生的</h2></div><!-- 应用没有到点或有新记录时自动开始的流程，就删掉这个标题和下一段 -->
<p class="bodytext">【填：冒泡结果】</p>
<div class="sectiontitle"><h2>实际花费</h2></div>
<table><thead><tr><th>操作</th><th>实际花了</th><th>估算</th><th>每次要等多久</th></tr></thead><tbody>
<tr><td>【填】</td><td>【填】</td><td>【填】</td><td>【填】</td></tr><!-- 重复 -->
</tbody></table>

<!-- ⑤ 定版后在这里补「上线结果」，④ 交报告时不写 -->
<div class="sectiontitle"><h2>上线结果</h2><span class="evidence">【填：月-日 定版】</span></div>
<div class="callout"><strong>已定版第【填】版</strong>【填：和上一版比改了什么】</div>
<table><thead><tr><th>项</th><th>内容</th></tr></thead><tbody>
<tr><td>④ 验过什么</td><td>【填】</td></tr>
<tr><td>未测的</td><td>【填：逐条写条目、为什么没测、发布后你可以在哪里自己看；没有就写「没有」】</td></tr>
<tr><td>实际花了多少</td><td>【填：本段 N；累计 N；上限 N；以后每用一次约多少，每周约多少】</td></tr>
<tr><td>发布会怎样</td><td>发布后已安装的使用者会更新到这一版；正式入口和到点自动化在发布后才能用；发不发、发给谁由你定</td></tr>
<tr><td>你可以做的事</td><td>【填：编号列出，都由你决定做不做】</td></tr>
</tbody></table>

<div class="footerline"><span>【填：④ 写「都没问题在聊天里回『可以上线』，有问题回『还要改：第几条』」；⑤ 补上线结果后写「已定版，发不发布由你定」】</span><span>第【填：N】版 · 【填：月-日 时:分】</span></div>
</article>
```
