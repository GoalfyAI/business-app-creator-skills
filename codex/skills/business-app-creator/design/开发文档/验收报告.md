# 验收报告版式

④ 交给开发者的验收报告写成这一份 HTML，⑤ 上线后在同一份最后补「上线结果」再出一版。每项写什么、「全部条目」表头和「要你做的」照抄文本见 [../验收报告与上线结果.md](../验收报告与上线结果.md)「验收报告」「上线结果」；逐条结论和「未测」的原因按 [../../stages/4-试用验收.md](../../stages/4-试用验收.md)「2.4 逐条判定」，过了「2.5 交验收报告」的硬门才交。这里只规定每项放在哪、用什么组件；通用写法见 [README.md](README.md)「怎么写一份」。

## 各部分放什么

| 部分 | 放什么 | 组件 |
|---|---|---|
| 开头 | 应用名、一句话结论 | `.eyebrow`、`h1`、`.lead` |
| 结论数 | 四格依次：没通过、通过、要你判断（好不好你说了算）、未测；四格相加等于总条数 | `.counts` |
| 结论提示 | 还有没通过、未测的条目时说清影响；有开发者选了接受的没通过条目，在这里单列几条；全部通过时删掉 | `.callout.warn` |
| 好不好你说了算 | 每条一个折叠，展开放实际结果：报告节选、内容原文、前后对比 | `.sectiontitle`、`details.trial`、`.trialbody` |
| 未测的 | 每条一行：为什么没测、做过的处理与看到的错误、以后你自己怎么看（前后两列照 stages/4「2.4 逐条判定」「未测」表的原文） | `.sectiontitle`、`<table>` |
| 全部条目 | 默认折叠，六列，一条验收条目一行 | `details.trial` + `<table>` |
| 用真实数据跑出的结果、自动发生的、实际花费 | 和方案的预期、估算对照 | `.sectiontitle`、`.bodytext`、`<table>` |
| 上线结果 | ⑤ 上线后补在最后，一项一行；④ 交报告时没有这一节 | `.sectiontitle`、`.callout`、`<table>` |
| 页脚 | 要你做的最后一句；第几版、更新时间 | `.footerline` |

- 按反馈重测后出新一版：只改变了的行，页脚写「第 N 版 · 重测了第几条」。

## 骨架

```html
<article class="sheet">
<div class="eyebrow"><span></span>【填：应用名】 · 验收记录</div>
<h1>验收报告</h1>
<p class="lead">【填：一句话结论，例如「24 条验收条目里 21 条通过，2 条要你判断，1 条没测」】</p>
<div class="counts"><div><b>【填】</b>没通过</div><div><b>【填】</b>通过</div><div><b>【填】</b>要你判断</div><div><b>【填】</b>未测</div></div>
<div class="callout warn"><strong>【填：还有什么没过或没测】</strong>【填：影响什么、接下来怎么办】</div><!-- 全部通过时删掉 -->

<div class="sectiontitle"><h2>好不好，你说了算</h2><span class="evidence">【填：几条】</span></div>
<details class="trial"><summary><span>【填：编号 · 验收条目】<small>【填：要你判断什么】</small></span></summary>
<div class="trialbody"><p>【填：实际结果：报告节选、内容原文或前后对比】</p></div></details><!-- 重复 -->

<div class="sectiontitle"><h2>未测的</h2></div><!-- 没有就删掉这个标题和下面的表 -->
<table><thead><tr><th>条目</th><th>为什么没测</th><th>做过的处理与看到的错误</th><th>以后你自己怎么看</th></tr></thead><tbody>
<tr><td>【填】</td><td>【填】</td><td>【填】</td><td>【填】</td></tr><!-- 重复 -->
</tbody></table>

<details class="trial"><summary><span>全部条目（【填：总条数】条）<small>每条的结论和证据</small></span></summary><div class="trialbody"><table><thead><tr><th>#</th><th>验收条目</th><th>结论</th><th>project_id</th><th>workflow_trace 摘要 / 页面操作步骤</th><th>查到的行 / 截图与本机路由 / 拿到的产出</th></tr></thead><tbody>
<tr><td>【填】</td><td>【填】</td><td>【填】</td><td>【填：页面条目写「本机版」】</td><td>【填】</td><td>【填】</td></tr><!-- 重复：每条验收条目一行 -->
</tbody></table></div></details>

<div class="sectiontitle"><h2>用真实数据跑出的结果</h2></div>
<p class="bodytext">【填：本段真跑与 ③ 真跑的结果摘要，和方案的预期对照】</p>
<div class="sectiontitle"><h2>自动发生的</h2></div><!-- 应用没有到点或有新记录时自动开始的流程，就删掉这个标题和下一段 -->
<p class="bodytext">【填：冒泡结果】</p>
<div class="sectiontitle"><h2>实际花费</h2></div>
<table><thead><tr><th>操作</th><th>实际花了</th><th>估算</th><th>每次要等多久</th></tr></thead><tbody>
<tr><td>【填】</td><td>【填】</td><td>【填】</td><td>【填】</td></tr><!-- 重复 -->
</tbody></table>

<!-- ⑤ 上线后在这里补「上线结果」，④ 交报告时不写；每项写什么见 design/验收报告与上线结果.md「上线结果」 -->
<div class="sectiontitle"><h2>上线结果</h2><span class="evidence">【填：月-日 上线】</span></div>
<div class="callout"><strong>已上线第【填】版</strong>【填：「上线的版本」一项】</div>
<table><thead><tr><th>项</th><th>内容</th></tr></thead><tbody>
<tr><td>【填：项名】</td><td>【填】</td></tr><!-- 重复：每项一行，依次 ④ 验过什么、未测的、实际花了多少、发布会怎样、发布要准备的、你可以做的事 -->
</tbody></table>

<div class="footerline"><span>【填：④ 写「要你做的」第 ③ 句；⑤ 写「上线的版本」里的照抄句】</span><span>第【填：N】版 · 【填：月-日 时:分】</span></div>
</article>
```

## 完整样例

「小红书商家分析报告」④ 交的第 2 版（节选）：28 条里通过 21、要你判断 5、未测 2，四格相加等于 28；「好不好你说了算」留 1 条、「全部条目」留 2 行示意，真实报告每条验收条目一行；「用真实数据跑出的结果」照骨架写。

```html
<article class="sheet">
<div class="eyebrow"><span></span>小红书商家分析报告 · 验收记录</div><h1>验收报告</h1><p class="lead">28 条验收条目里 21 条通过，5 条要你判断，2 条没测。</p>
<div class="counts"><div><b>0</b>没通过</div><div><b>21</b>通过</div><div><b>5</b>要你判断</div><div><b>2</b>未测</div></div>
<div class="callout warn"><strong>第 21、23 条没有测</strong>这几条没有测，原因见报告；你仍然可以回「可以上线」，上线结果会单列它们，并写清你以后怎么自己看。</div>
<div class="sectiontitle"><h2>好不好，你说了算</h2><span class="evidence">5 条</span></div>
<details class="trial"><summary><span>09 · 通读三份报告<small>能不能直接发给商家</small></span></summary><div class="trialbody"><p>莫定标娘惹糕点报告第 1 章节选：「1933 年创立，2025 年获必比登推荐；近 30 天『娘惹糕』搜索指数下降 31.4%。」官方小红书账号没查到，报告开头写在「数据缺口」里，没有推断。</p></div></details>
<div class="sectiontitle"><h2>未测的</h2></div>
<table><thead><tr><th>条目</th><th>为什么没测</th><th>做过的处理与看到的错误</th><th>以后你自己怎么看</th></tr></thead><tbody><tr><td>21 · 点消息提醒跳进应用</td><td>只有线上才能验证：真实宿主桥接</td><td>开发工作集里查到 1 条提醒记录；本机版里应用内的提醒列表正常</td><td>发布后在正式入口看</td></tr><tr><td>23 · 从分享链接打开报告</td><td>从目录或分享打开要先发布</td><td>本机版里打开报告、复制、下载都正常</td><td>发布后从目录或分享打开看</td></tr></tbody></table>
<details class="trial"><summary><span>全部条目（28 条）<small>每条的结论和证据</small></span></summary><div class="trialbody"><table><thead><tr><th>#</th><th>验收条目</th><th>结论</th><th>project_id</th><th>workflow_trace 摘要 / 页面操作步骤</th><th>查到的行 / 截图与本机路由 / 拿到的产出</th></tr></thead><tbody>
<tr><td>3</td><td>只填海底捞火锅、北京，点开始创建，再点不同候选</td><td>通过</td><td>本机版</td><td>填写资料页只填两项 → 开始创建 → 依次点 3 家候选</td><td>截图 03-候选门店.png，本机路由 /stores/confirm；断言「候选 3 家，均在王府井一带」</td></tr>
<tr><td>4</td><td>填清水缘和服租、京都</td><td>通过</td><td>61042</td><td>搜索 → 核实 → 无可靠候选 → 手动补充</td><td>projects 表 1 行，门店为手填地址，没有清水寺官网</td></tr>
</tbody></table></div></details>
<div class="sectiontitle"><h2>实际花费</h2></div><table><thead><tr><th>操作</th><th>实际花了</th><th>估算</th><th>每次要等多久</th></tr></thead><tbody><tr><td>生成一份报告</td><td>736–781 积分</td><td>750 积分</td><td>20–26 分钟</td></tr></tbody></table>
<div class="footerline"><span>都没问题在聊天里回「可以上线」，有问题回「还要改：第几条」</span><span>第 2 版 · 10-26 18:20</span></div>
</article>
```
