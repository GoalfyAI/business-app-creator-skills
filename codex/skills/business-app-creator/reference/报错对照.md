# 报错对照

## 适用场景

工具返回错误码、运行失败、结单或定版被拒、部署被拦，需要判断归属和处置时读。先看返回里给的出口和提示；本表只补返回里没说清的部分。脚手架版本类错误码见 [脚手架与预置件.md](脚手架与预置件.md)，工具接入类问题见 [依赖与MCP接入.md](依赖与MCP接入.md)。

## 规则

### 通用原则

- 按返回的结构化错误改同一份对象再试；**禁止**自造兼容字段、另开工单、改名重试来绕过闸门。
- 同一错误连续两次（`repeated_error_count>=2`）就换思路，不原样重跑。
- 疑似平台问题用 `submit_dev_feedback` 报上去，能绕过就先继续。
- 余额不足、鉴权失败这类 `recoverable=False` 的错误，不重试，如实告诉开发者。

### 工单闸门

**`SCENE_SKILL_UPGRADE_REQUIRED`** — Skill 版本过期，工单**未创建**。立即停止所有写操作，
在**本次会话内**完成升级：先判断所在平台，从 `metadata.update.update_guides` 取该平台的
升级文档链接，拉取后逐步照做；再搜索已安装的 SKILL.md，从 description 读出
`[skill-version:...]` 标记，原样填入 `skill_version` 重试（Claude Code 平台可直接
`grep -r "skill-version" ~/.claude/plugins/cache` 定位；其他平台按各自安装目录搜索）。

合法版本串**只能**来自升级后已安装的 SKILL.md。拒单响应里不含可用于重试的版本串，
**禁止**从响应、changelog 或记忆里取值重试。搜不到已安装的 SKILL.md、或文件里没有
`[skill-version:...]` 标记，说明未安装或安装已损坏，改取 `metadata.update.install_guides`
里该平台的安装文档重新安装后再读标记，**禁止**因为读不到就编造一个版本串。升级成功并重试
通过之后，才提示开发者重启客户端让新 Skill 内容生效——重试只解除闸门，你上下文里的 Skill
内容仍是旧版。

**`SCENE_SKILL_UPGRADE_RECOMMENDED`** — 有新版本但**不阻断**，工单已正常创建，`task_id` 可直接使用。
继续当前任务，交付时顺带提示开发者升级即可。

**`WORKFLOW_TASK_MODE_MISMATCH`** — 工单模式与动作不匹配。按 `metadata` 里的 `actual_mode` 和
`required_mode` 纠正：只读工单要执行写操作时，新建 `mode="write"` 工单并传 `continued_from_task_id`。**禁止**误判为工单不存在或属于他人。

### 编排与路线

| 现象 | 处理 |
|---|---|
| 工具或 action 不存在 | 回看当前工具定义，按实际 action 和字段改。工具确实不在列表里时如实告诉开发者该能力当前不可用，**禁止**虚构平行工具 |
| 预览报字段、工具或路径错误 | 按报错精确修同一份草稿，再重跑预览 |
| 冒泡未到终态 | 用同一 `run_id` 续等；修了脚本后重新冒泡取新证据 |
| `ORCH_NODE_FAILED` | 兜底错误码，**禁止**按码本身归因。先看排查信息里的失败类别：`business_gate` 是脚本按规则主动停止，查业务条件与输入；`contract_error` / `script_bug` / `shell_exit` 归制作侧，修同一份脚本或契约；`tool_error` 看上游工具与 `recoverable` / `attempts`；`fa_error` 是 FA 预算或异常退出；`timeout` 先查最慢的一步。信息是「结果为空」且判失败与上一条工具返回只隔几十毫秒，多半是没等分段返回收齐 |
| `Workflow business event requires persisted Runtime identity` | 正式运行时是把带事件的 TPE 直接派发了：建单节点或多节点路线后从路线入口重跑；冒泡时是服务端没分配验证身份，报平台问题。**禁止**伪造 Runtime ID |
| `WORKFLOW_RUNTIME_IDENTITY_INCONSISTENT` | 三元身份部分缺失，是调用链内部错误，不是业务输入问题；核对入口是否完整传递服务端生成的身份，**禁止**手工补齐 |
| 路线保存被拒 | 按返回的节点、字段、路径错误修同一个对象；节点只能读直接依赖的上游输出 |
| `WORKFLOW_FORM_PENDING` / `ORCH_INTERACTION_PENDING` | 项目里还有表单没答完，又在同一项目提交了入口表单。不是故障：让用户回该项目答完，新业务新建项目；应用侧复用下拉框过滤这类项目 |
| `ORCH_DELIVERY_FILE_UNISOLATED` | 声明为文件的交付不在最终节点产物目录；先复制进 `ctx.output_dir` 再返回 |
| `ORCH_DELIVERY_FILE_UNVERIFIED` | 旧环境拒收未声明的 workspace 路径；区分真正附件、出处引用和意外路径，不靠删 `required` 或给无用途路径补声明消除 |
| 交付出现「内部资料：文件名」或该交付的文件没成为附件 | 有意保留的出处引用属正常；本来要交付的文件，逐项核对真实文件、最终节点目录、文件声明和交付映射 |
| 工具集关联成功但运行时加载不到 | 有工具集仍是离线；`online_toolsets` 后反读 |
| 需要最终用户各自授权的工具调用失败 | 授权卡没配或没绑定 |
| 外部工具报参数格式错、路径不存在 | 回该工具的当前契约看文件参数收 URL、`/workspace` 路径还是内容本体；拿不准就取样一次 |
| 云端沙箱（官方 Shell 等）访问 `huggingface.co` 超时或 `Network is unreachable` | 平台沙箱连不上 `huggingface.co`，重试也没用，不是脚本或工具故障。改用镜像站 `https://hf-mirror.com`，路径不变，只换域名（页面、`/api/...` 都可用）；其他境外站点连不上时，G2 取样确认后换一个能访问的来源，没有替代来源就如实告诉开发者 |
| `get_project_execution_logs(download)` 报不存在或受保护目录 | 不存在：先 `outputs` 看清单，节点产物在 `/workspace/task_agent/<taskpoint>/output/`；受保护目录（`input/`、`skills/`、`.env` 等）本来就不提供下载 |
| 资产详情字段为空 | 先判断是权限脱敏（`can_view_params=false`）还是真的空，告诉开发者后再决定 |

### 版本与结单

| 现象 | 处理 |
|---|---|
| 版本闸门拒绝（如 `PERSONAL_VERSION_FINALIZE_REQUIRED`） | 内容修改撞了上线行：先取可编辑草稿；上线动作撞了未定稿草稿：走定稿上线。**禁止**绕过闸门改状态字段 |
| `task_manager(insert)` 带 `format_warning`（检查点建议一条路线一条） | 记录已写入，但多条路线合在一条里；补成每条路线一条，各带自己的 `run_id` |
| `WORKFLOW_TASK_ROUTE_BUBBLE_EVIDENCE_REQUIRED` | 有路线没有对得上的运行证据（路线冒泡或真跑）：没跑、跑失败、`run_id` 属于别的路线、或证据早于最后一次路线修改。补一次路线冒泡或真跑，或问过开发者后写 `route_verification_waived`（真跑失败时 `run_id` 填 `project_id`）（见 [../flow/G7-上线交付.md](../flow/G7-上线交付.md)） |
| `has_ui: true` 但 `entry_url` 为空 | 部署后又派生了新草稿行，地址留在旧行；在当前草稿行重新部署并反读 |

### 应用定版

| 错误码 | 含义 | 处置 |
|---|---|---|
| `BUSINESS_UI_NO_BUNDLE` | 还没有源码包 | 回 G6：上传并部署后再定版 |
| 报错带 `metadata.asset_state=draft`（文案以「草稿态」开头） | 发生在挂本人场景包草稿的部署、预览或定版联动上；`draft_asset_ids` 是涉及的草稿行。按原错误码处理，向平台反馈时注明是草稿态 |
| `BUSINESS_UI_NOT_DEPLOYED` | 源码包没有成功构建发布 | `deploy` 到终态 `success` 再 finalize |
| `BUSINESS_UI_TEMPLATE_REQUIRED` | 带代码包的智能应用定版没有挂智能应用数据集模板 | 回 G5 建表并 `extract` 出模板版本 → `business_ui_manage(update, dataset_template_id, dataset_template_version)` 挂到草稿 → 重新 `deploy`（模板进指纹）→ finalize |
| `BUSINESS_UI_NOT_RELEASED`（`resolve` 时返回，不是 finalize） | 上线了但从未发布，使用者打开的是"已发布"版本所以打不开 | 在发布管理页发布一版；上线只影响开发者自测，不会推给使用者 |
| `BUSINESS_UI_CONTRACT_OUTDATED` | 挂载场景包的编排型 TPE 契约已变化 | 重新 `deploy`（吸收新契约）后再 finalize；契约变化波及页面时先按修订评估影响 |
| `BUSINESS_UI_TEMPLATE_SWITCHED` | 换绑到另一个模板家族（等于换库） | 不允许；需要新库就新建智能应用 |
| `BUSINESS_UI_TEMPLATE_UPGRADE_PATH_BROKEN` | 模板升级链缺迁移脚本 | 回 G5：破坏性变更的 `extract` 随带 `migration_script` |
| `BUSINESS_UI_TEMPLATE_REGRESSION` | 回滚钉回了更老的模板版本 | 没有降级：把旧结构重新抽成一个新版本再挂 |
| `BUSINESS_UI_UPGRADE_REHEARSAL_FAILED` | 迁移脚本在临时库彩排失败 | 按返回的错误修脚本，重新 `extract` |

## 常见错误

- 看到 `ORCH_NODE_FAILED` 就判定是工具坏了。
- 被闸门拒绝后另开工单或改名重试。
- 把 `submit_dev_feedback` 提交成功当成问题已解决，放行验收。
- 余额不足时反复重试。
