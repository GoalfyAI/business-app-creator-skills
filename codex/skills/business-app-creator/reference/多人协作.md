# 多人协作

## 适用场景

开发者要操作的智能应用不是他本人创建的（他是协作者），或开发者本人的应用有协作者、有待定版清单、要加人改档移人时读。`business_ui_manage(action="list")` 和 `business_ui_manage(action="get")` 返回的 `role` 决定走哪条路线。

## 规则

### 先认角色

| `role` | 是谁 | 能做 | 不能做 | 走哪条路线 |
|---|---|---|---|---|
| `owner` | 属主，应用的创建人 | 全部操作，包括定版、发布、下线、删除、加人改档移人 | — | SKILL.md 原流程；开工先处理待定版清单 |
| `editor` | 编辑协作者 | 派生自己的草稿、改各层资产和开发库结构、部署自己的草稿、预览、提请定版 | 定版应用、发布、下线、删除、再分享应用；改表间关系与治理规则、绑定或关闭工作集 | 本文「编辑协作者：修订路线」 |
| `viewer` | 只读协作者 | 看版本和草稿、预览、下载源码包、读部署记录、执行日志、使用者反馈和各层资产详情，用只读连接查开发库 | 任何写入 | 本文「只读协作者：诊断路线」 |
| `none` | 没有权限 | — | — | 告诉开发者他没有这个应用的权限，请属主把他加为协作者 |

- 角色只认平台返回。**禁止**按应用名、聊天里的说法或资产的 owner 字段自己推断。每次开工和接续都重新读一次，属主可能已经改档或移除了他。
- `list` 返回三组：我的应用、协作中的应用、待接受的协作邀请。有待接受的邀请时告诉开发者：到 GoalfyMax 的分享兑换入口输入站内信里的分享码接受邀请，接受后才能看到和操作这个应用。你**禁止**替开发者兑换分享码。
- 协作者移除或降级后立即生效：新请求按新角色判定，已签发的开发库连接最长约 10 秒后被拒并断开。遇到原来能做的事突然被拒，先重读 `role` 再判断。

### 开工和接续先读协作状态

对已有应用先调 `business_ui_manage(action="get", task_id, business_ui_id)`，看 `role`、全部草稿（创建人、变更说明、基线是否过期 `baseline_stale`）、待定版清单和共享工作集。

- **属主**：待定版清单不为空时，先告诉开发者谁提请了哪份草稿、改了什么，问他要不要定版。要定版时先请他在预览里看过这份草稿，再用 `compare_asset_versions` 对比当前上线版，然后按 [../flow/G7-上线交付.md](../flow/G7-上线交付.md) 定版这份草稿（`draft_asset_id` 用协作者的草稿行）。基线已过期的草稿定版会返回 `PERSONAL_VERSION_STALE_SOURCE`，告诉开发者需要提请人先合并新版本。
- **协作者**：自己的草稿 `baseline_stale=true` 时，先按本文「基线过期的合并」处理，再做本轮改动。
- **协作者本地没有应用工程**：用 `business_ui_bundle(action="download")` 取最新上线版（或自己要接着改的草稿）的源码包，解压到开发者中心分配的 `apps/<应用目录>/`，再按 SKILL.md「开工」第 2、3 步核脚手架版本、补工作区文件。

### 只读协作者：诊断路线

1. 建 read 工单，按 [../tasks/诊断.md](../tasks/诊断.md) 取证。
2. 可以用的读取：`business_ui_manage(action="get")` 看版本、草稿和部署记录；`business_ui_bundle(action="get" / "download")` 下载源码包读代码；对 `get` 返回的属主预览项目调 `get_project_execution_logs`；`business_ui_feedback` 的 list、get 读使用者反馈；`get_asset`、`list_asset_versions`、`compare_asset_versions` 看各层资产；开发库只用 `dataset_template_workspace` 的只读连接或只读查询执行 SELECT。
3. **禁止**：派生任何草稿（`ensure_draft`、`update`、`ensure_editable_asset_draft`）；`connect` 申请写连接；执行写数据的 SQL 或 DDL；跑 `ship`、部署、冒泡、真跑这类写流程；处理使用者反馈；用 `dataset_read` 读应用开发库（它只读长期数据集，查开发库会被拒）。
4. 诊断报告照常交给开发者。要修时告诉开发者两条路：请属主把他升为编辑协作者后按修订路线改，或把报告交给属主或编辑协作者去改。你不自己改。
5. 预览：只读协作者能打开任一已部署草稿或版本的预览，页面只读，保存类按钮禁用并显示原因。

### 编辑协作者：修订路线

按 [../tasks/修订.md](../tasks/修订.md) 走，建 write 工单同样带 `skill_version`，以下几处和属主不同：

1. **只在自己的草稿上改**：应用草稿用 `business_ui_manage(action="ensure_draft", change_note=…)` 从最新上线版派生，`get` 返回的草稿里已有自己创建的就接着用。别人创建的草稿**禁止**改。`change_note` 必填，写这次改了什么；开发者没说就问一句，**禁止**填「更新」这类空话。
2. **各层自下而上**：工具组 → 工具集或 FA → 场景包路线 → 应用挂载。每一层派生自己的草稿（`ensure_editable_asset_draft`，场景包用 `scene_package_manage(action="ensure_draft")`），改完按 [../flow/G4-能力制作.md](../flow/G4-能力制作.md) 验证，再自己定版（`finalize_asset_version_online`，场景包用 `scene_package_manage(action="finalize")`），然后到上一层的草稿里把引用改到新版本。最后在自己的应用草稿上用 `business_ui_manage(action="update")` 换挂场景包版本。资产层定版只是多出一个新版本，已上线的应用钉着旧版本，不受影响。
3. **数据模板**：开发库是属主绑定在应用上的共享工作集，属主和全部协作者共用同一份库，改结构会影响所有人的预览。改结构前：
   1. `dataset_template_workspace(action="inspect")` 记下当前模板版本，作为这次改动的基线；
   2. 告诉开发者要加改哪些表和列，请他先和属主及其他编辑协作者说一声，避免两人同时改；
   3. 用写连接或 `create_table` 在这个工作集上做幂等改动，规则见 [数据模板.md](数据模板.md)「改已上线的模板」；
   4. `extract` 抽新版本（带基线版本，参数按工具 Schema），再在自己的应用草稿上 `update` 挂新模板版本、重新部署。
   `extract` 返回 `TEMPLATE_BASELINE_CHANGED` 说明别人先抽了新版本：重新 `inspect`，核对对方的改动和自己的表列都在，再按新基线 `extract`。**禁止**删除或回退别人加的结构。`set_relations`、`set_rules`、`bind`、`close` 只有属主能做，需要时请属主操作。
4. **部署**：`business_ui_bundle(action="ship")` 只部署到自己的草稿，自动派生草稿时同样要带 `change_note`。源码包存放在属主名下，这是正常结果。
5. **预览验收**：由开发者本人在 GoalfyMax 里打开自己这份草稿的预览（在线试用）逐条验收，限制见本文「预览、费用与限制」。你仍然**禁止**用浏览器打开这些地址。
6. **应用设置、自动化规则、挂载版本**：在自己的应用草稿上 `update`。
7. **上线**：G7 改成提请定版，见本文「提请定版」。

### 提请定版

编辑协作者的草稿部署成功、开发者在预览里验收通过、基线没有过期后：

1. 调 `business_ui_manage(action="request_finalize", task_id, …)`，草稿参数按工具 Schema，缺省取自己的草稿。
2. 成功后对开发者说：「已提请，等属主定版」，附草稿版本和变更说明；属主会收到站内信。**禁止**说已上线，也**禁止**为此去 `finalize`、`resolve` 或请属主以外的人定版。
3. 返回 `BUSINESS_UI_FINALIZE_REQUEST_NOT_READY` 回 G6 把这份草稿 `ship` 到 `success`；返回 `PERSONAL_VERSION_STALE_SOURCE` 先按「基线过期的合并」处理。

### 基线过期的合并

协作者自己的草稿 `baseline_stale=true`、提请或定版返回 `PERSONAL_VERSION_STALE_SOURCE`、或站内信通知基线已过期时，说明属主已经定版了更新的版本，这份草稿是从旧版派生的。按顺序做：

1. 告诉开发者原因和下面的步骤，确认后开始。
2. 先把本地当前改动提交到 git（应用目录还没有 git 仓库就先初始化再提交）。
3. `business_ui_bundle(action="download")` 下载最新上线版的源码包，放到另一个分支，用 git 合并到自己的改动上。冲突逐处给开发者看，按他的决定改。**禁止**直接用新版覆盖本地，或用本地覆盖新版。
4. 从最新上线版重新派生自己的应用草稿（`ensure_draft` 带 `change_note`）。返回的仍是那份过期草稿时，告诉开发者后先用 `abandon_asset_version_draft` 作废它，再重新派生。
5. 合并后的代码跑 `npm run verify:release`，`ship` 到新草稿，开发者在预览里重新验收。
6. 再次提请定版。

场景包、工具集等资产层的草稿过期时同理：从新上线版重新派生，把改动重做到新草稿上。

### 属主：加人、改档、移除

- 用 `business_ui_manage(action="collaborators")` 的 list、add、update、remove 子动作，参数按工具 Schema。
- add、update、remove 执行前**必须**先向开发者复述对象账号、档位和影响，开发者明确同意后才带 `confirm_collaborator_change=true` 执行；没有这个确认时工具只返回待确认提示，不会写入。影响要讲清：编辑协作者能改各层资产和开发库结构、能部署自己的草稿，不能定版和发布；移除后对方立即失去全部协作访问。
- 编辑档只给指定账号（邮箱或手机号）。分享码模式只能发只读档。
- add 之后对方收到带分享码的站内信，要到 GoalfyMax 的分享兑换入口输入分享码接受；接受前 list 显示「待接受」。对同一人重复 add 返回已存在，不会发新码。
- 对方还没接受时不能改档：要换档就先 remove 这份邀请，再按新档位 add。经分享码加入的人不能升为编辑：先 remove，再用指定账号按编辑档 add。

### 协作中新建或克隆的资产

- 编辑协作者在协作应用的工单里新建资产（`create_fast_agent`、`create_toolset`、`create_tpe`、`create_derived_scene_package` 等）或 `clone_asset`，资产落在属主名下：属主是 owner，操作的协作者是 creator，并自动得到同档位的编辑权。新建前把这一点告诉开发者；他被移除或降为只读后，这份编辑权随之收回。
- 只读协作者不新建、不克隆。

### 借来的资产

属主的应用里可能引用了别人分享给属主的资产（例如别人的 FA、长期数据集）。协作者看不到这类资产的详情，也不能改、不能写入；读取被拒或显示为 blocked，预览和运行照常。碰到时告诉开发者：

- 这个资产属于把它分享给属主的人；返回里能看到资产属主就写出来，看不到就如实说查不到，请属主确认是谁分享的。
- 你不能改它。要改有两条路：属主先 `clone_asset` 克隆到自己名下再换引用（能不能克隆按资产本身的设置），或者找分享方修改。
- **禁止**反复重试，也**禁止**换别的工具绕过去读写。

### 预览、费用与限制

- 协作者只能预览用新版脚手架模板构建并已部署的草稿或版本。返回 `BUSINESS_UI_COLLAB_PREVIEW_SCAFFOLD_OUTDATED`（页面提示该应用需用新版脚手架重新构建后才能协作预览）说明这份部署用的是旧模板；属主本人预览不受影响。要属主，或编辑协作者在自己的草稿上，按 [脚手架与预置件.md](脚手架与预置件.md) 迁移到新模板后重新部署。
- 协作者在预览里不能使用广告充值相关功能（读取充值订单、执行充值），返回 `BUSINESS_UI_RECHARGE_OWNER_ONLY`，页面提示该功能需由应用属主操作。充值相关的验收交给属主。
- 只读协作者在预览里提交表单、保存等写入被拒是预期结果，不是故障，不提 `submit_dev_feedback`。
- 费用：冒泡、真跑和预览里的运行按平台当前规则，从发起运行的账号扣积分。向开发者说明费用时只写这个现状，**禁止**写成「协作者自付」或「属主承担」这类长期承诺，计费规则以后可能调整。

### 协作相关报错

| 错误码 | 含义 | 处置 |
|---|---|---|
| `BUSINESS_UI_FINALIZE_OWNER_ONLY`、`BUSINESS_UI_COLLABORATION_OWNER_ONLY` | 协作者调了定版、发布、下线、删除、再分享这类属主动作 | 告诉开发者这些由属主操作；改好的草稿用 `request_finalize` 提请 |
| `BUSINESS_UI_COLLABORATION_FORBIDDEN` | 没有权限：不是协作者、已被移除、只读协作者做写操作，或改的是别人创建的草稿 | 重读 `role`；只读的走诊断路线；换回自己的草稿。`reason=account_inactive` 表示账号已停用，如实告诉开发者，不重试 |
| `BUSINESS_UI_COLLABORATION_READ_ONLY`、`TEMPLATE_WORKSPACE_WRITER_FORBIDDEN`、`PERSONAL_VERSION_NOT_OWNER` | 只读协作者写数据、申请写连接或建草稿 | 不重试；要改请属主升档 |
| `CHANGE_NOTE_REQUIRED` | 建应用草稿或 `ship` 时没带变更说明 | 向开发者要一句改了什么，带 `change_note` 重调 |
| `PERSONAL_VERSION_STALE_SOURCE` | 草稿基线已过期 | 协作者按「基线过期的合并」处理；属主告诉提请人先合并 |
| `TEMPLATE_BASELINE_CHANGED` | 抽模板时别人已先抽出新版本 | 重新 `inspect` 核对后按新基线 `extract` |
| `BUSINESS_UI_FINALIZE_REQUEST_NOT_READY` | 提请的草稿还没有部署成功 | `ship` 到 `success` 后再提请 |
| `BUSINESS_UI_FINALIZE_REQUEST_OWNER_SELF` | 属主自己提请 | 不用提请，直接按 G7 定版 |
| `BUSINESS_UI_COLLABORATOR_PENDING` | 对方还没接受邀请就改档 | remove 这份邀请后按新档位 add |
| `BUSINESS_UI_COLLABORATION_CODE_READ_ONLY` | 把经分享码加入的人升为编辑 | 先 remove，再用指定账号按编辑档 add |
| `BUSINESS_UI_COLLABORATOR_NOT_FOUND` | 对方不是这个应用的协作者 | 用 collaborators list 核对 |
| `BUSINESS_UI_COLLABORATION_MANAGED_BY_OWNER` | 在「我的资产」里移除经协作得到的资产 | 协作带来的资产由属主在协作者列表里管理 |
| `BUSINESS_UI_COLLAB_PREVIEW_SCAFFOLD_OUTDATED`、`BUSINESS_UI_RECHARGE_OWNER_ONLY` | 旧模板部署、广告充值 | 见「预览、费用与限制」 |

## 常见错误

- 只读协作者为了修问题去派生草稿或申请写连接。
- 编辑协作者调 `finalize`，或提请之后对开发者说「已上线」。
- 在别人创建的草稿上改，或复用别人的草稿部署。
- 改共享工作集结构前不打招呼；后抽模板被拒后按旧基线硬抽，或删掉别人加的表列。
- 用 `dataset_read` 查应用开发库。
- 替开发者兑换分享码，或没经开发者确认就执行 add、update、remove。
- 把旧模板预览提示、充值被拒、只读写入被拒当成平台故障提反馈。
- 把费用写成「协作者自付」之类的承诺。
- `change_note` 填空话。
