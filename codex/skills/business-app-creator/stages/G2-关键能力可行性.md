# G2 关键能力可行性

> 阶段层文件。固定七项结构；方法在 [P2 能力发现、工具接入与模型试验](../modules/P2-能力发现与模型试验.md)，证据裁决在 [P6](../modules/P6-验证与证据裁决.md)。

## 1. 进入依据

G1 最小目标与边界成立；关键未知项可以列成试验问题。试验授权（数据、环境、费用）与正式制作授权分开取得。

## 2. 本阶段建设

1. **承诺—能力—证据—缺口矩阵**：每条业务承诺列所需能力、已有证据、缺口。反读真实资产与工具契约（P2 的 S2 §2.1–2.4：参考项目三层深读、复用已有能力、覆盖矩阵、缺口四层处理），检查权限、文件形态与运行环境。
2. **按风险先试最可能失败的部分**：取不到数据、模型不能可靠判断、外部工具效果差、成本或时间不可接受。
3. **试用与取样前移**：先本地验证，再经授权建立**明确标识的最小试用包**（P2 的 ST 流程），不先建全套正式资产；复用工具先读契约再真实取样（P2 的 S3 §2.2）。
4. **同一代表性输入比较候选**：模型 / 工具候选各跑同一输入，记录质量、耗时、费用、失败形态；样本量不足不声称稳定成功率。改稿类承诺试"旧产物 + 修改约束"，续作类承诺试恢复所需的状态 / 产物读取，不能只证明从零生成。
5. **缺口归因六分**：工具缺失 / 认证不足 / 数据缺失 / 知识不足 / 模型判断不足 / 平台表达不支持；各给复用、接入、补开发、人工接手或改范围的方案。差分归因顺序固定：权限 → 工具 → 信息 → 模型。
6. **U 前提验证**：U2 数据粒度、权限、文件读取、上下文传递；U3 模型判断与连续执行的关键样例（应继续 / 应补充 / 应停止三种情境）；纳入范围时 U7 发现与授权、U8 平台可表达的动态行为。

## 3. 给开发者看什么

**实际产物对比 + 关键路径能力卡。**每张卡回答：要证明什么、试了什么、结果怎样、现在能承诺到哪。候选路线有显著取舍时才并列，不为凑数量造方案。费用与耗时给事实与估算两栏。

## 4. 要确认哪些边界

试验数据；隔离环境；允许的读写；费用 / 调用范围；停止条件；人工兜底是否可接受。使用更大模型不自动扩大费用和数据外发范围。

## 5. 门禁 Checklist（G2）

- `G2-01` 试验覆盖本次实际使用方式（改稿、续作），不只从零生成（U4/U5）。
- `G2-02` 已用实际对象核实数据粒度、权限、文件读取、上下文传递；受限详情不误判为空资产（U2/U5-02）。
- `G2-03` 模型判断与连续执行有真实证据，覆盖应继续 / 应补充 / 应停止；桩跑不算判断能力（U3）。
- `G2-04` 质量、耗时、费用的事实与估算分开；超限方案未被默认采用。
- `G2-05` 关键路径缺口已解决或业务方明确改范围；"以后补"不能让原承诺通过。
- `G2-06` 试验环境与资产有标识及清理 / 保留计划，未擅自上线、无未授权副作用。

## 6. 证据与结论

产出：试验报告、真实输出、能力矩阵、选择依据与剩余盲区；落工单 `capability_matrix` 与 `trial_report`。能力矩阵是 G3 决定"规则 / 模型 / 人"分工的直接输入。

## 7. 失败回退

能力失败先换试验策略（换工具、补信息、升级模型）；目标本身不成立回 G1 修改承诺范围。

## 继承与调整

S2 复用 / 摸底 / 缺口处理 + ST 能力试用 + S3 工具取样前移到正式制作之前。主责 P2 / P6。
