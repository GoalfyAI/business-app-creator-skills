# G3 运行设计与验收基线：确定"它到底会怎样工作"

> 阶段层文件。这里**联合设计**路线、人机分工、数据与页面状态，一次形成运行设计与验收基线；不再是"包做好再反推页面"。方法分别在 P1（规则与样例）、P3（执行形态与路线）、P4（数据）、P5（页面）、P6（验收用例）。

## 1. 进入依据

关键能力已验证到足以选择路线；剩余假设列明不隐藏。G2 能力矩阵在手。

## 2. 本阶段建设

1. **节点职责与执行形态**：从业务节点决定规则 / 模型自主 / 模型 + 确认 / 人的职责，依据 G2 证据（通过率、稳定性）× 风险（低 / 中 / 高；高风险永远至少一次确认）。由证据支持固定路线、普通任务点、FastAgent、编排型 TPE 的选择（P3 的 S2 §3–4），不让开发者先选术语。
2. **三类路线关系分开画**：实现候选的取舍 / 运行中的条件分支 / 用户的不同业务入口；不混成一条 DAG（P3 的 S2 §5）。
3. **每个节点八项**：做什么、为什么、谁做、依据、输入来源、输出去向、失败出口、人工介入与交付核验；并行先看数据依赖、副作用、共享资源、限流。
4. **关键决策表**（P1 附录 D2）：只挑改变价值 / 投入 / 承诺 / 后续路径的决定，逐项写依据分列（事实 / 历史 / 外部证据 / 专业规则 / 待验证假设）、错误后果、三条独立轴（证据够不够 / 谁判断 / 什么授权）、会翻案的真实反例。
5. **同时设计应用与数据**：入口、状态、结果呈现与修改方式（P5 的 A1 §5）；表、字段归属、写权、版本、审计、回流、下一轮读取点（P4）。四时机分离：模板制作期 / 客户初始化 / 每次运行 / 周期复盘。
6. **知识绑定**：把领域知识绑到实际执行者与决策点（P3 的 S3 §8）；好坏样例转成验收用例。设计"下次使用哪里读到此次反馈"，不是只建反馈表。
7. **结构表与追踪**：建立执行结构表（每步 executor / evidence / stakes / confirm / fallback / budget）、应用结构表、需求追踪矩阵（承诺 → 节点 → 数据 → 页面 → 资产 → 验收例）；方案挑战只查 pending（[方案挑战检查清单](../checklists/方案挑战检查清单.md)）。
8. **U 行为实例化**：对适用的 U1–U8 逐项写成本项目的验收设计（编号 / 适用条件与承诺 / 前置状态 / 输入或操作 / 预期 / 失败判据 / 开发者要看的信息 / 责任 / 证据类型与版本），见 [U 业务行为验收明细](../checklists/U业务行为验收明细.md)。此时只能记"设计已确认"。

## 3. 给开发者看什么

**先演示一个完整业务样例，再展示必要的图。**默认：业务路线图 + 结果 / 页面预览；职责有争议加泳道图；状态易混加状态图。每个可解释节点给出做什么 / 为什么 / 谁做 / 依据 / 输入输出 / 异常 / 修改影响；技术实现映射可展开查看。用真实案例在决策图上走一遍，展示该自动继续、该停下来、该拒绝、该改路线时分别发生什么。

## 4. 要确认哪些边界

信息缺失 / 冲突 / 过期；无权限；部分成功；取消与恢复；模型 / 工具兜底；文件生命周期；局部修改；重复提交；隐私与跨对象隔离；临时需求是否在支持范围。确认用户审阅与 Agent 审阅的分工；业务决定与动作授权分开记录。不能只确认画面好不好看。

## 5. 门禁 Checklist（G3）

- `G3-01` 每条承诺都能追到节点、数据、页面 / 动作和验收例；没有"写在计划里却无承载"的功能。
- `G3-02` 节点职责与执行形态有依据；分支可解释；没有为步骤数机械增建 TPE / FA。
- `G3-03` 每个入口字段写明来源、必需 / 可选 / 可推断、冲突处理和接收节点；修改入口另声明目标产物 / 版本与保留约束（U2/U5）。
- `G3-04` U3 暂停 / 授权规则、U4 恢复状态表、U5 修改影响表按适用项确认；响应未知、部分成功、用户取消分别定义出口。
- `G3-05` 资料冲突、用户编辑与生产写入、单次 / 对象级 / 长期偏好、效果回传均有规则；每个留存字段能指出下次谁读、何时读（U2-04/U6）。
- `G3-06` 开发者已看过覆盖关键分歧的正反情境；业务决定与动作授权分开记录（U3/U7/U8）。
- `G3-07` 验收基线已冻结到当前版本；实现中发现新事实可提变更，不以"已定稿"禁止沟通。

## 6. 证据与结论

产出：运行设计（含制作书 ⑧⑨⑩ 章，P3 的 S2 §7.2）、执行结构表、应用结构表、节点说明、边界案例、验收索引；落工单 `build_book`、`execution_structure_snapshot`、`app_structure_snapshot`、`behavior_design`。

## 7. 失败回退

路线的业务含义没对齐 → G1；依赖能力没证据 → G2。设计变更沿真实依赖使相关通过记录失效（协议《承诺—实现—验收追踪》）。

## 继承与调整

合并旧 S2 执行设计、S3 样例选择 / 事件 / 知识、A1 页面与数据设计；细化而非重复访谈。主责 P1 / P3 / P4 / P5 / P6。
