## 改了什么

R-438 第 4 版「智能应用一键升级」（D-3962）。

脚手架（已有应用升级后能看到的变化）：

- 新命令 `npm run scaffold:upgrade`（`scripts/upgrade-scaffold.mjs`）：按固定层清单替换固定层，应用改过的文件生成 `<path>.upgrade-new` 并列进 `docs/upgrade/conflicts.md`。合并文件：应用没改过的直接取目标内容；模板这次没改过的保留应用版本、不生成 `.upgrade-new`，在 `conflicts.md` 单列为「无需处理」；两边都改过的才生成 `.upgrade-new` 待合并。另有 `npm run scaffold:version -- --json` 读当前版本。
- 模板已删除的固定层文件（含旧版 SDK 目录里残留的旧文件：升级计划对没有随包清单的旧版本，会列出固定层独占目录中目标已没有的旧文件）：应用没改过的自动删除，改过的列为冲突、不删。
- 升级会同步 `package-lock.json`：合并后的依赖与模板一致时直接取模板锁文件；应用自己加过依赖时在临时目录运行 `npm install --package-lock-only` 重新生成，需要能访问 npm 源，失败则这次升级整次不写文件。
- `conflicts.md` 每处冲突附 diff（过长时截断），完整 diff 在 `docs/upgrade/diffs/`；再次运行升级时保留上次写下的「处置」。
- 固定层清单新增合并类文件 `frontend/src/vite-env.d.ts` 与 `frontend/src/locales/` 下被合并文件引用的 json（如 `bootstrap-error.zh-CN.json`）。
- `backend/tests/test-database.ts`、`backend/tests/env.ts` 改为合并文件：`gen:pages` 追加的业务表保留，不再被整文件替换。
- 应用根新增固定层清单 `scaffold-fixed-layer.json`；`npm run pack` 要求应用根有这个文件，缺了打包失败。
- `scaffold-release.json` 写回 `version`、`sdk_version`、`skill_version`、`upgraded_at` 四个字段，升级时其他字段不带回。
- `npm run verify` 遇到没处理的 `*.upgrade-new` 报 `VERIFY_UPGRADE_PENDING` 失败。
- `npm run doctor` 在有清单时按清单检查全部 replace 类固定层文件和合并文件是否存在（合并文件内容由应用维护，只查存在）。
- `docs/upgrade/history.json` 是对象 `{upgrades, applied_guides}`：升级脚本往 `upgrades` 追加每次升级记录，旧版的数组格式读到后放进 `upgrades`；是合法 JSON 但类型不对（`null`、字符串、数字，或 `upgrades` 不是数组）时，原文另存为 `history.json.broken-<时间>`，再写新记录；`applied_guides` 由制作 Skill 记已处理的升级指南。

制作 Skill（business-app-creator）：新增 `tasks/升级.md`。先取计划，逐条判断升级指南（不适用、已满足、要做），换固定层后按指南改业务代码、逐条提交和测试；换固定层后 `doctor` 报的问题不直接回滚，在适配阶段结合指南修（固定层升级带来的问题没有指南覆盖也修），整体 `verify` 是放行关，不过再按条回退或整次回滚；收尾统一写升级手册、`docs/upgrade/latest.json` 与 `history.json` 的 `applied_guides`。

制作 MCP：`business_ui_bundle(action="upgrade_plan")` 除固定层差异外，还返回本应用还没处理过的升级指南（读本仓库 `upgrade-guides/`，按 OA 发布状态与替代/撤回关系算出），入参 `applied_guides` 取自 `history.json`。

## 对已有应用的影响

不需要单独改业务代码。按《升级》任务升级一次，固定层清单、`scaffold:upgrade` 脚本、新的 `scaffold-release.json` 与对象格式的 `history.json` 都由第 4 步写好，本指南判为已满足；收尾时 `applied_guides` 记下本指南，之后不再返回。三条测试在第 4 步之后都通过；没升级过的应用前两条失败，可以用来区分。

升级之后不要再按旧的三方对照手工迁移固定层：打包要求的 `scaffold-fixed-layer.json` 只有升级脚本会写。
