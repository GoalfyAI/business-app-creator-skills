# 能力容器组成与执行形态速查

能力容器在平台里叫场景包。它定义运行 Agent 在某个业务场景里能做什么、怎么做、用什么做，是一组各有权威位置的能力，不是一段提示词。

## 1. 能力容器由什么组成

场景包定义了运行时 Agent 在某个业务场景里能做什么、怎么做、用什么做。它是一组各有权威位置的能力，不是一段提示词。

```text
能力容器
├── apc_skill              始终注入，运行时 Agent 每轮都能看到
├── 场景 Skill 文件 ×N      按需读取，启动时只看到文件名列表
├── 任务点（TPE）×N         同一类资产的两种类型，见下方说明
│   ├── 普通任务点          执行中需要开放式判断或与最终用户交互的完整任务
│   └── 编排型 TPE           稳定、确定、可复跑的执行管道
├── 业务路线             单节点或多条编排型 TPE 的固定业务路线
├── 工具集 ×N               加载模式分预加载（启动即加载）和动态（按需加载）
│   ├── 使用指南            工具集加载后可见
│   ├── FastAgent ×N       视为工具调用
│   └── 工具 ×N
└── 长期数据集 ×N           已有数据集的引用关系，不拥有数据
```

业务应用的前端、后端与数据模板不在此树中，它们消费能力容器的公开契约；组成见 SKILL.md 第 0 节。

最小场景包的形态、组合 / 继承 / 派生的边界、普通任务点与编排型 TPE 同属 TPE 两型的含义，正本在 [平台对象与运行模型](references/平台对象与运行模型.md) 第五章。


## 2. 执行形态速览

四种执行形态不在同一层：**SystemAgent 直接执行**（不产生资产，只在 `apc_skill` 写规则）／**FastAgent**（可被当作工具调用的完整执行单元：挂上工具后能在一次调用里多轮调用工具做完一个业务环节；每次全新隔离会话、不能与最终用户交互、不自带文件命令邮件能力）／**普通任务点**（派给 TaskAgent 的任务模板：独立上下文、步骤临场决定、**可中途向最终用户提问**）／**编排型 TPE**（确定性脚本：需要推理的步骤调 FastAgent，单条不能与最终用户交互）。普通任务点与编排型 TPE 自带文件读写、命令执行、邮件发送三项能力，设计时直接当已有能力使用，**不当工具缺口**；FastAgent 不自带。

各形态的构成、能力边界、输入定义硬要求、最大轮次取值与默认能力细则，**正本在 [平台对象与运行模型](references/平台对象与运行模型.md) 第二章**；**怎么选**在 P3 第 2 节。


## 3. 出现在工具调用里的标识

工具名、action、参数名、各类标识（`task_id` 是工单不是资产、`tpe_id` 两型共用、`mcp_id` 不是 `tool_group_id`、`run_id` / `project_id` 轮询时复用……）**以你看到的工具定义为准**；标识速查表与版本体系四个术语（家族 / 物理行 / 草稿态 / 上线）在 [工具标识与版本术语速查](references/工具标识与版本术语速查.md)。写错了调用会返回结构化错误，按报错更正，**禁止**自行发明兼容字段。本文与各阶段文件**禁止**用"发布"指代上线动作。
