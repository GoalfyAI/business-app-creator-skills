# G5 数据与应用

建应用身份、数据模板和页面：页面按确认页「界面」做，脚手架预置件和按表生成器合适就用。本地 `npm run verify` 全绿是出口。

## 1. 进入条件

- 页面要调用的路线已经能跑（每条 TPE verify passed、路线冒泡到终态）；只改表、页面或后端、不碰路线时不需要重做 G4。
- 应用工程里有 `frontend/registry.json`。没有说明脚手架早于 0.8，先按 [../reference/脚手架与预置件.md](../reference/脚手架与预置件.md) 升级，升级前不要照本段的页面块与生成器写法。

## 2. 做什么

1. **应用身份**（先于把 `current_stage` 改成 G5）：`business_ui_manage(action="setup", task_id, name, scenario_pack_id=<场景包家族 ID>, operation_id=<稳定键>)` 得到 `business_ui_id`；在应用根执行返回的 `scaffold_bind_command`（`npm run scaffold:bind -- --business-ui-id <id>`）回填 `app.json` 与 `WORKSPACE.md`。重复调用按 `operation_id` 复用，不会建出第二个应用。工作区在 G5 及以后要求真实的 `business_ui_id`。
2. **数据模板**（确认页有「会存下来的东西」才做），细则见 [../reference/数据模板.md](../reference/数据模板.md)：
   1. `dataset_template_workspace(action="open", task_id, name, description)` 记下 `data_uid`；返回的连接串填进 `backend/.env`，**禁止**进工单和聊天。
   2. 每张表 `create_table(task_id, data_uid, table_name, target_columns=[…])`：至少一列 `primary_key=true`；每列 `comment` 以 `[editable:user|agent|system]` 开头再写中文名，选项列在注释里加 `{options:a|b|c}`；有写入的表带审计列 `created_at`、`updated_at`、`updated_by`、`last_run_id`、`row_version`（都是 `system`）。
   3. `inspect` 反读，确认列与注释都在；与 G3 表清单不一致就改到一致。
   4. `extract(task_id, data_uid, template_name, template_description)` 出模板版本，记下模板 ID 与整数版本号。
   5. `business_ui_manage(action="setup", task_id, business_ui_id, dataset_template_id, dataset_template_version, data_uid)` 一次挂模板（版本钉整数）并把开发工作集绑到应用；已挂同版本的步骤会跳过。返回 `success=false` 时看 `steps` 里哪步 `failed`，修正后原参数重调；仍失败再用 `business_ui_manage(action="update")` 与 `dataset_template_workspace(action="bind")` 单步处理。工作集留到 G7 结单前再关。
3. **数据页一条命令**：把 `inspect` 返回的 `columns` 原样存成 `<表名>.json`（形如 `{"table","label","columns":[…]}`），执行 `npm run gen:pages -- --table <表名> --label <中文名> --spec <表名>.json`。它生成列表 / 详情 / 新建 / 编辑页、OpenAPI、后端 CRUD 与测试，接好路由、导航和挂载；再跑一次不会覆盖。
4. **场景包契约进前端**：场景包契约写进 `frontend/schema/packs/<pack>/`（见 `frontend/schema/README.md`），路线的入口表单、项目层、表单应答、交付审阅由预置件按它自动推导；去掉示例包（`demo-pack`）并同步 `goalfy-app.json` 的 `packs`。
5. **按确认过的界面写业务页**：确认页有「界面」一节或开发者给过截图、参考时，页面结构和样子照它做；没有时按 [../reference/前端页面.md](../reference/前端页面.md)「界面风格」定品牌色、Logo、导航图标、布局、圆角与首页重点，配进 `src/app/config.ts`，写进本段阶段文档。读 `frontend/registry.json`，现成页面块对得上就用，对不上就复制到 `pages/` 改或自己写（规则见《前端页面》「预置件怎么用」），不为了套用页面块改掉确认过的样子；不改 `ui/`、`blocks/` 源码。正式版每个使用者从空库开始（见《数据模板》）：页面要有空库时的引导；上线后必须存在的设定（口吻、默认参数等），所有人一样的写成代码默认值或场景包配置，每人不同的做首次设置入口。
6. **后端接口**：生成的 CRUD 够用就不写；要统计或生产回流时在 `backend/src/common` 上包一层（`createCrudService` 的 `applyGeneratedResult` 写 agent 列），先写 `frontend/schema/api/<operationId>.yaml` 再实现。
7. **外部平台授权、充值、自动化**（确认页列了才做）：分别见 [../reference/授权与充值.md](../reference/授权与充值.md)、[../reference/自动化.md](../reference/自动化.md)。
8. **本地跑**：`npm run check`（前端契约门禁）、`npm run verify`（脚手架诊断、契约、前后端测试、构建）。`npm run dev` 起本地链路，在开发者中心的「演示预览」里看（服务在后台常驻，本轮结束后仍可看）。

**不要做的**：不写占位页、不留 demo 路由（`npm run verify:release` 会拦）；不用 antd 重画已有的块，不引新图表库；不手写 OpenAPI 与后端 CRUD（生成器出的可以改）；应用代码**禁止** `CREATE / ALTER TABLE`，表结构只走数据模板。

## 3. 产出与落盘

- 工单 checkpoint：`business_ui_id`、`data_uid`、模板 ID 与版本、`npm run verify` 结果。
- 本段阶段文档记录表结构（`inspect` 结果的业务说明）与页面清单的实际结果。
- 方案页 `status` 写当前进展；「哪些页面能在本地预览」写进「未验证」（本地预览不算真实链路）。
- 阶段标记：G5 `passed`。

## 4. 给开发者看什么

一句话加一个本地预览入口：「数据页和业务页已经搭好，本地预览里能看到；下一步部署后在『在线使用』里用真实账号走一遍。」

## 5. 出口

- `business_ui_id` 已绑定到本地工作区；
- 有数据模板时：模板版本已挂到应用、工作集已绑定；
- 应用根 `npm run verify` 全绿。

## 6. 出问题怎么办

| 现象 | 先看 | 回到 |
|---|---|---|
| `npm run doctor` / `verify` 失败 | 先修第一条 `FAIL`；`GIT_ROOT_MISMATCH` 见 [../reference/开发者中心与工作区.md](../reference/开发者中心与工作区.md) | 本段 |
| `create_table` / `extract` 被拒 | 返回的列与 diff；破坏性变更要带迁移脚本 | 本段第 2 步 |
| 前端契约门禁报 packs 不一致 | `goalfy-app.json` 的 `packs` 与 `frontend/schema/packs/` 目录 | 本段第 4 步 |
| 页面要的数据路线不给 | TPE 的 `output_schema` 缺字段 | G4 改 schema，或 G3 改页面清单 |
| 连接串过期 | `dataset_template_workspace(action="connect")` 重签 | 本段 |
