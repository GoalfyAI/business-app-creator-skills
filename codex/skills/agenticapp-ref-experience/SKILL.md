# 业务经验

这里收的是几类业务的现成写法：每一步谁来做、做不成怎么办、哪些做法不行。它们来自线上在用的应用和写过的样例，用来让你在 ① 写「每一步谁来做」、② 编施工单时有个起点，少走已经走过的弯路。

## 按业务场景找文件

| 业务场景 | 文件 | 来源 |
|---|---|---|
| 从平台拉数据写进台账、看到期提醒，只有脚本步骤（例如同步广告授权） | [references/授权同步台账.md](references/授权同步台账.md) | 线上在用的应用 |
| 输入一个账号，拉数据后由模型诊断（例如小红书账号运营诊断） | [references/账号运营诊断.md](references/账号运营诊断.md) | 线上在用的应用 |
| 材料里有审核、复核的单据整理（例如报销） | [references/报销整理.md](references/报销整理.md) | 写法样例 |
| 生成内容写进库、由使用者确认发布，或中间要到外部平台手动操作（例如小红书选题到发布、聚光投放） | [references/内容选题到发布.md](references/内容选题到发布.md) | 线上在用的应用 |
| 按店名找门店、查公开数据、写能直接发给商家的报告 | [references/商家分析报告.md](references/商家分析报告.md) | 写法样例 |

## 怎么查

1. 先按开发者描述的业务找最像的一行；一个应用可能同时像两类（例如先拉数再写报告），两个文件都看。
2. 打开文件先看「现成写法」那张表，再逐条看下面的条目：每条写成「触发条件 / 规则 / 原因」，触发条件对得上的才用。
3. 都对不上就不用这个 Skill，照 `agenticapp-stage-1-requirements` 从头写。

## 查到后怎么用

- **当起点改，不照搬**：现成写法是「每一步谁来做」的一个起点，按开发者的业务逐行改。开发者说过的名字、步骤、规则优先，他确认过的 PRD 高于这里的任何一条。
- **平台事实要重新核实**：条目里提到的平台服务、单价、次数上限是那个应用或样例当时的情况，写进 PRD 前按 `agenticapp-stage-1-requirements` 真查、真调过再写「能不能做」和花费；没测过的花费标「估算」。
- **原因一起带上**：采用一条规则时，把「原因」用业务话告诉开发者，让他判断自己的业务是不是同样的情况。
- **多人分工不照做**：条目里提到审核、复核、多人共用数据的，按 `agenticapp-stage-1-requirements` 的「谁来用」规则处理，平台没有团队。
- 模型档位只写「快而便宜的一档」「强的一档」，选法和对应的模型见 `agenticapp-tool-workflow`。
