# 方案挑战检查清单

> 业务方案形成后、创建任何资产之前读取，**由你自己逐项执行**，没有可以代劳的审查工具。没有真实资产证据时**禁止**在证据不足时判定通过。

---

## 证据

先用 `list_assets`、`get_asset` 和按需的 `dataset_read` 核对真实资产，再判断方案。输入至少包括访谈事实、完整材料阅读结果、项目三层分析、用户目标、使用角色、业务里程碑、候选路线、理想态、能力覆盖矩阵、验收标准，以及拟复用或新建的场景包、Workflow、FastAgent、Toolset、Tool Group、数据集和业务档案。**禁止**凭名称、历史对话或记忆推断资产能力。

## 必查项

### 业务完整性

- 意图、关键参数和成功标准明确；平台知识缺口由 Agent 调查，没有被错误地抛给用户。
- 用户指定的文档、项目和日志已经完整读取；参考项目已完成概览、深读、分析三层工作，没有只看摘要。
- 解决的是稳定、可复用的业务问题，而不是固化一次性项目。
- 主流程、异常路径和最终交付完整；每个阶段有明确输入、输出和责任方。
- 里程碑、候选路线、选路条件、Focus/泛化取舍和理想态都有证据或明确假设；参考项目没有被写成所有用户的唯一 SOP。
- 授权、外部写入、通知、邮件、发布和收费等高风险动作有用户确认与 `ctx.dry_run` 护栏。

### 工具、数据和资产依赖完整性

- 每个里程碑都有真实工具或 FastAgent 支撑，参数和能力匹配。
- 所需 Toolset、Tool Group、FastAgent、Workflow、数据集和业务档案会实际挂载；不能假设用户可能拥有。
- 每个里程碑在能力覆盖矩阵中有“已覆盖/可组合/需维护/缺口/验证方式”结论；用户明确能力没有被静默削减或替换。
- 数据源名称与绑定资产一致，不存在引用缺失或无用途的冗余绑定。
- 不依赖创建者本地路径、外部 Agent 沙箱或其他 Max 项目的临时文件。

### Workflow、普通 TPE 和 FastAgent 选型

- 稳定、重复、无需临场判断的多步流程优先 Workflow。
- 只有内容判断、归纳和写作等确需大模型的步骤才使用 FastAgent；确定性搜索、取数、转换和发送直接调用工具。
- 只调用一个 FastAgent 后原样返回的 Workflow 不提供任何价值，应直接使用该 FastAgent。
- Workflow 输入能由用户、业务档案或上游 Workflow 提供，输出是用户或下游真正需要的稳定对象。
- 只有路线内部依赖固定时才配置多 Workflow 无环 DAG；路线需要临场规划时交给 Agent。
- 多候选路线、用户 Gate、改稿和重做使用当前 2.0 多路线契约与新 Runtime；中途用户补参和 Agent 介入分别使用已声明的 `business_interaction` 与节点 `sa_handoff`，不在同一 DAG 画回边。
- 工具定义、编排保存门与目标 Max Runtime 对 2.0 的支持**必须**一致；只有静态保存能力时记录 `platform_blocked`，不声称运行可用。
- 定制业务界面当前只用于至少挂载一个 Workflow 的场景包；纯 SA 或只有普通任务点时回落对话界面，不伪造依赖绕过平台门槛。

### 鲁棒性和运行时 Skill

- 数据缺失、格式变化、工具失败和外部系统变化有明确失败或降级规则。
- `apc_skill` 包含业务里程碑、权限边界、操作策略和必要系统认知，不含数字资产 ID、制作说明或第二份 DAG。
- 对照理想态中每个预期减少的失败、绕行或沟通轮次，`apc_skill`、Toolset、场景 Skill 或 Workflow 中存在对应的可执行指导；不存在“调用相关工具”“输出高质量结果”等空话。
- 每个场景 Skill 文件都由 `apc_skill` 在明确阶段按名称索引，且信息没有跨层重复。
- Toolset Skill、FastAgent Prompt 与真实工具一致，不使用会让 Agent 自由发挥的泛化描述。

## 输出

输出并写入工单简洁检查点：

- `关键问题`：位置、后果、精确修改办法；未解决前**不得**创建。
- `改进建议`：不阻断但会影响稳定性或质量的问题。
- `确认项`：证据不足或属于业务取舍的问题，由用户决定。
- `证据`：审查视角和实际读取的资产 ID。

**不得**把方案审查写成运行验证，也**不得**在证据不足时判定通过。
