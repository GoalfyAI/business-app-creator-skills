# 确认页：一页说清，一次确认

G1 发给开发者的只有这一页，内容写进方案页 `docs/proposal/index.html`：「它帮你做什么」写进 `.pv-goal`，分工表写成业务过程的 `.pv-steps`，其余各节写进「开发内容」，`status` 为 `waiting`、`.pv-you` 写「确认这份方案，或告诉我要改哪里」。版式见 [../reference/开发者中心与工作区.md](../reference/开发者中心与工作区.md)「方案页」。用开发者的词，不出现 FA、TPE、工具集、Runtime。

```
## <应用名>

**它帮你做什么**：一句话。

**功能清单**
1. <功能一>：用户在哪里点什么，得到什么
2. <功能二>
3. 数据管理：可以看和改哪些表

**分工表**（有需要模型判断或人工介入的步骤时才有）
<每条路线一张表，来自 design/分工表.md>

**会存下来的东西**
| 对象 | 存在哪张表 | 字段 | 谁能改 |
|---|---|---|---|
| 广告主清单 | advertisers | 名称、到期时间、状态（正常 / 即将到期 / 已过期，默认正常） | 系统写，用户只看 |
| 停投名单 | stop_decisions | 笔记、原因、决定（停投 / 保留） | 用户写 |

**做不成的时候**
<有分工表时把第四列汇总成三句话；没有时写拉不到数、写不进库时用户会看到什么>

**需要你准备的**（有才写）
- <账号授权 / 密钥 / 示例数据 / 群或机器人>：用在哪一步，缺了影响什么

**费用与副作用**
- 会调用：<外部工具名>，每次约 <N> 积分
- 会写入 / 发送：<有就写，没有写「不会向外发送任何东西」>

**上线范围**
- 部署预览前要先把场景包上线为你的个人资产（不进目录、别人看不到），这是平台要求
- 先在开发者中心的在线预览里验收，你说「可以上线」再定版应用；发布到目录由你在发布管理页操作
- 用的人：<谁>
```

规则：

- 开发者回复「可以」或等价表述即视为确认，进 G2；回复里有改动就改页，改完不用再问一遍，直接做。
- 「会存下来的东西」列出每张表的表名、字段、选项列的全部取值与默认值，照抄开发者原话。
- 只有规则步骤的应用去掉「分工表」一节，其余各节照写。
- 开发者对这一页说「可以」，即同意其中列出的场景包上线与费用；预览通过后的应用定版仍要开发者再说一次「可以上线」。确认页没列的上线、花钱、对外发送动作不得执行。
- 「费用与副作用」这一段不能省。费用一律写积分，不写 token；算法见 [../reference/平台对象速查.md](../reference/平台对象速查.md)「积分怎么算」，查不到单价就写「费用未知，真跑后告诉你实际花了多少积分」，不编数字。
- 「需要你准备的」只列开发者本人才能提供的东西，写进方案页的 `needs` 一节。
