# G6 用户操作闭环验证：确定"已做好的能力，用户真的用得上"

> 阶段层文件。方法在 [P5](../modules/P5-应用脚手架与页面实现.md)（脚手架、SDK、页面、本地测试）与 [P6](../modules/P6-验证与证据裁决.md)（A4 时序验收与真实环境）。使用侧行为按 [U 业务行为验收明细](../checklists/U业务行为验收明细.md) 逐项验。

## 1. 进入依据

后端关键闭环（G5）成立；页面设计与真实公开契约一致；未就绪的业务切片不伪装可用。

## 2. 本阶段建设

1. **在脚手架上实现已确认页面**（P5 的 A3 §4）：保留件必经（`useProject` / `useProjectExecution` / `useProjectDraft` / `useInbox` / `useRuntimeUserFiles` 等）；首页、项目列表、消息中心等平台要求与业务特有功能分开说明；接口先有 OpenAPI 契约；没有表单预填通道，稳定信息由后端在发起时带入。
2. **把权威事实转成可理解状态**：提交中 / 已受理 / 运行中 / 待补充或审阅 / 失败 / 完成；不自己猜进度（P5 的 A3 §4.3.1 应答提交到运行的过渡）。
3. **实现完整旅程**：首次使用、已有任务、返回历史、局部修改、结果预览 / 下载、必要的数据管理与反馈入口；不是把后台管理界面直接交给用户。
4. **本地 Mock 验状态结构，真实预部署验证真实运行**（P5 的 A3 §5：Direct Mock 不打本地后端，不算联调证据）；可提前预部署。
5. **实际操作检查**：看得懂、点得对、回得来；长文本、空态、错误态、窄屏、键盘与权限变化。

## 3. 给开发者看什么

**可操作的应用 + 一个用户旅程的实际演示**；同时显示当前页面对应的业务节点、数据来源和验收项。开发者说"这里不对"时，定位到具体状态 / 动作与影响范围，不让其自行描述 SDK 实现。

## 4. 要确认哪些边界

哪些信息常驻显示、哪些只在决策时出现；修改作用范围；删除 / 提交的确认语义；长期偏好保存意图；信息显示不等于授权；按钮不可用须说明原因。

## 5. 门禁 Checklist（G6）

- `G6-01` 分别用零历史、已有资料、未完成任务、历史结果四种状态进入应用（U1）。
- `G6-02` 用户能核对本次对象、输入来源、推断 / 冲突提示和完整产物，并完成 U2/U5 动作；不读内部 JSON 或日志。
- `G6-03` accepted/running 乱序、其他项目推送、切页与刷新不误报成功、不闪回旧表单、不重复提交；提交锁与执行展示各有依据。
- `G6-04` 按 U4 在真实页面执行离开 / 返回、补充、重试；上传失败后的替换与提交拦截。
- `G6-05` 从指定旧版本发起局部修改、关联修改、失败重试，逐项核对 U5-02—U5-05。
- `G6-06` 分别完成 U6 的复用、单次隔离、纠正 / 撤销、效果回传；核对实际执行输入，不只看设置页已保存。
- `G6-07` 实际浏览器操作与基本可访问性通过；Mock 与截图不代替当前真实部署物的证据。

## 6. 证据与结论

产出：操作录像或逐步截图、页面专属自动化测试、真实运行与数据库关联记录；按 [应用验收检查清单](../checklists/应用验收检查清单.md) 前端部分裁决。

## 7. 失败回退

交互实现错误在 G6 修；数据 / 运行事实错误 → G5；原设计不可用 → G3。

## 继承与调整

保留 A1 设计工艺、A3 SDK / 状态 / 文件实现、A4 时序与真实环境测试；把用户使用问题逐项变成开发验收。主责 P5 / P6。
