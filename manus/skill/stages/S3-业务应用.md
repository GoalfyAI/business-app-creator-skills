# S3 业务应用（已移交 app-creator）

业务应用（前后端应用）的制作、部署与验收已整体移交同插件市场的 **app-creator** Skill，不再是场景包的阶段与交付物。本文件保留编号作为转介，不含制作内容；**不得按历史版本的 S3 流程执行任何界面制作**。

## 1. 分工

- **本 Skill（scene-creator）**：只制作场景包（能力面），并为业务应用准备接缝事实；
- **app-creator**：在场景包**上线后**（先包后应用），以场景包为契约基线制作业务应用——数据面、后端、前端、部署与验收全在那条线完成。

要制作或修改业务应用时，结束本工单相应诉求的路由，转用 app-creator Skill。

## 2. 场景包为业务应用提供的接缝物

以下事实在本 Skill 各处制作，是 app-creator A1 契约基线的输入：

| 接缝物 | 制作位置 |
|---|---|
| 入口表单 Schema（`schema/forms/`） | S2 表单制作 |
| 业务路线编排与审阅动作（`schema/orchestrations/`） | S2 第 8 节 |
| 业务事件契约（事件候选结合系统消费需要确认） | S2 6.4 |
| 面向系统的公开语义（路线业务名称、里程碑、交付、到达标准） | S2 8.3 |
| 业务应用数据集读写通道（Workflow 经 `dscli_business_dataset` 取数与回写） | S2 3.4 |
| `output` 业务字段与渲染语义（含 display 兜底） | [平台对象与运行模型](../references/平台对象与运行模型.md) |

## 3. 存量附属界面

历史上随包部署的附属界面（`scene_package_ui_bundle` 链路）只做**存量维护**：诊断走 `stages/SD-诊断与维护.md`；带存量界面的包派生新草稿行后，部署地址不继承（`entry_url` 为空），上线前须在新行重新部署并反读确认非空。不再用该链路制作新界面。
