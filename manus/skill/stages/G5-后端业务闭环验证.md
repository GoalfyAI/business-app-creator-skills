# G5 后端业务闭环验证

本阶段确定**部件组合后能完成业务并留下正确事实**。分两个可辨认的子闭环：G5a 执行闭环，验证能力容器内的业务路线真跑；G5b 应用数据闭环，验证数据模板、后端与验证实例。方法见 P3 路线组装、P6 全真、P4 数据、P5 后端、P7 能力容器定稿上线。

## 1. 进入依据

所用单元已通过适用验收；数据与交互契约与 G3 一致。

## 2. 本阶段建设

**G5a 执行闭环**

1. **组装业务路线。** 将已验单元装入路线；保存、反读、检查映射与依赖；做静态接缝检查。方法见 P3 路线组装一节。
2. **真跑路线。** 先做路线 Bubble，再在获授权的真实项目中验证路线控制、真实模型与工具、业务表单、交付冻结、审阅。真跑四步：建项目、绑数据、看运行、拿结果，方法见 P6 全真一节。三个身份的口径固定：`orchestration_id` 取自路线定义；`business_id` 由调用方生成，同一业务实例内不变；`workflow_runtime_id` 只由服务端生成。
3. **定稿上线能力容器。** 达到能力容器自身标准并获授权后执行，方法见 P7。能力容器上线**不等于**应用已交付。

**G5b 应用数据闭环**

4. **制作数据模板。** 建工作集，`create_table` 逐列写可编辑性注释，`inspect` 反读，`extract` 出模板版本。方法见 P4。
5. **实现后端服务。** CRUD、统计、回流三类接口；引用表只用 `buiTable`；写接口幂等；写权由 `canWrite` 自判；写入带来源标记与 `row_version`。方法见 P5 后端实现一节。
6. **建立验证实例。** 按平台前置条件准备 `business_ui` 草稿与最小验证部署物，方法见 P6 发布单位与源码包两节。在真实应用实例验证五步：发起时带入、执行中取数、结果回流、编辑、再次读取。此时**不要求**完整界面，但**不能缺**实例与数据通道证据。

两条线可穿插推进，依赖次序由真实契约决定。能力容器在无应用数据的项目里跑通，只证明该输入与回退路径，**不得**据此判 G5b 通过。平台不允许提前提供测试实例时，落工单标签 `platform_blocked` 并补能力；**禁止**把必需项豁免后上线。

另须实现：异步任务定位；输入、产物、版本关联；幂等与冲突；部分失败恢复策略；错误归因；引用旧产物的权限与有效性。优先使用当前 Runtime 的重入方式；**禁止**承诺平台未验证的任意节点断点续跑。

## 3. 给开发者看什么

按业务节点排列的真实运行时间线；预期与实际路线对照；数据读入与写回的前后对照；停止、恢复、部分失败记录。每个显示"完成"的节点都能指出实际成立的事实。

## 4. 要确认哪些边界

未取到必要数据时补充还是拒绝；部分成果是否可交付；哪些修改重用旧结果、哪些重算；历史结果与运行实例如何保留；后台持续执行与费用上限；越界临时请求如何转为新决策。

## 5. 门禁 Checklist

- `G5-01` U3 适用项逐条验证：信息与授权齐备时连续执行；必要暂停有明确原因；补充后继续正确任务。同时核对真实路线的映射、介入、交付与审阅，**禁止**拼接单元日志。
- `G5-02` 从实例记录能反查一次任务实际消费了哪份资料、哪个对象或周期，产物回到哪个实例、任务、版本。数据库里"有资料"**不算**已用上。对应 U2-06、U6-01。
- `G5-03` 重复请求或回调、后端写权拒绝、并发版本冲突三类用例分别有结论；一个通过**不能**替另一个打勾；只验前端禁用**不算**。对应 U4-05、U6-01。
- `G5-04` U4 的离开、补充、结果未知、部分失败、重复请求、取消各有处理记录。关闭页面不取消任务；结果未知不盲重试。
- `G5-05` 交付完整性、文件可取用、业务审阅、外部动作回执分别核验；无可靠回执的动作保持未知，**不标**完成。对应 U5-01、U5-06。
- `G5-06` U5 修改与版本保护、U6 事实与偏好复用分别取证。可追溯不等于会复用；保存偏好不等于下次生效。
- `G5-07` 路线证据与应用数据证据分别闭合；实例缺失、数据通道未测明确阻断对应承诺。

## 6. 证据与结论

产出路线真实日志、应用实例测试记录、数据库前后状态、版本关系、恢复与权限案例。能力容器部分按场景包验收检查清单裁决；后端与数据面部分按应用验收检查清单裁决。落工单标签 `orchestration_runtime_verified`、`data_loop_verified`。

## 7. 失败回退

单元问题：回 G4。路线或数据语义问题：回 G3。真实能力不可用：回 G2。
