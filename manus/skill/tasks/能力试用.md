# 能力试用

## 识别信号

- 开发者想先验证某个外部能力（MCP、API、模型、Skill 包）好不好用、值不值得做进应用。
- 开发者给了工具链接、包或供应商名，问「能不能用」「效果怎么样」。
- ① 核实时要真调一个外部能力，或模型档位拿不准、要用同一份样例比两档：按本文做，结论写回 PRD「能不能做」（① 里什么时候用见 [../stages/1-需求确认.md](../stages/1-需求确认.md)「2.3 同时核实」）。

## 先读什么

1. 建 write 工单，`skill_version` 按 [../SKILL.md](../SKILL.md)「开工」建工单（从 ① 进来的沿用原工单）。
2. 平台上先查重：`list_assets` / `get_asset`；已有的直接取样，不重复接入。
3. 要接入的按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md) 预览、注册、配授权卡。
4. 费用先问：会产生真实调用费用的取样，先在题里说清份数和约多少积分，开发者同意后再跑；说不出数先不问、不跑（[../SKILL.md](../SKILL.md)「花费」）。
5. 取样：安全只读的工具用 `otpe_tool_test` 真调，核对返回结构（哪些工具不能拿来取样见 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md)「工具取样」）。需要模型的，建一个临时试用应用：`business_ui_manage(action="create", task_id, name)` 建应用占位（名字标「试用」）；建一个单节点编排型 TPE，里面调要试的 FastAgent 或工具（工具挂在这个 TPE 上）；用 `business_ui_manage(action="update", business_ui_id, workflow_orchestration, tpe_ids)` 挂上一条只有这个节点的路线；再用冒泡 `scene_package_manage(action="bubble", task_id, business_ui_id, orchestration_id, workflow_input=<样例>, full_run=true)` 跑一两条真实样例（组成与写法见 [../reference/平台对象速查.md](../reference/平台对象速查.md)「应用由什么组成」、[../reference/业务路线.md](../reference/业务路线.md)「冒泡」）。比模型档位时同一份样例两档各跑一次，记下两份输出、实测用时和估算花费（平台暂时给不出每次的实际花费）。

## 从哪一段进

不进五段，本任务就是 ① 核实的做法。结论写成三句话交开发者：能做什么（附样例结果、用时、每次估算花费）、不能做什么、建议做进应用还是放弃。

- 开发者决定做进应用时，转新建（进 ① 写 PRD，试用结论直接写进「能不能做」）或修订；从 ① 进来的回到 ① 接着问。
- 临时试用应用和它的 TPE 在工单里标明用途，正式制作不沿用，除非开发者明确要求。
