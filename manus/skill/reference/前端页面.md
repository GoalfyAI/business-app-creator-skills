# 前端页面

## 适用场景

搭或改应用页面、接 SDK、做入口表单、项目页、交付审阅、数据管理、看板时读。页面规则的正本在应用工程里：`frontend/README.md`、`frontend/docs/business-ui-guide.md`、`frontend/src/sdk/docs/`；本文只列最容易出错的约束。

## 规则

### 预置件怎么用

页面长什么样，以确认页「界面」一节和开发者后来的反馈为准；没说过的才按下一节「界面风格」自己定。预置件是帮你少写代码的工具，不是页面的样子：

- 动手前读 `frontend/registry.json`，看有哪些现成件：首页（含最近记录）、消息中心、入口表单、项目层、表单应答、交付审阅、列表 / 详情 / 表单数据块；数据管理页可以用 `npm run gen:pages` 按表生成。
- 预置件的样子和确认过的界面对得上就直接用；对不上就复制到 `pages/` 改，或在 `pages/`、`components/` 里自己写，**不为了用预置件把确认过的界面改掉**。不改 `ui/`、`blocks/` 源码。示例页面只用来理解协议，不复用它的结构和视觉。
- 必须保住的是**行为**，不是外观：自己写的页面照样经下面「SDK 两层与保留件」列的 hook 和组件（`useProjectDraft`、`useProjectExecution`、`useInbox`、表单渲染等）接平台，消息中心、项目状态、表单应答、交付审阅、只读置灰、保留区避让的行为与预置件一致。

### 界面风格

每个应用按自己的业务定外观，不照搬脚手架默认。写页面前先定下面几项，写进本段阶段文档，一句话一项：

| 项 | 在哪配 | 怎么定 |
|---|---|---|
| 品牌色 | `src/app/config.ts` 的 `APPEARANCE.accent`（6 位 hex，优先于宿主主色） | 按行业与调性选：内容种草类偏红、金融财务类深蓝或墨绿、餐饮零售暖色、工具效率类冷静色；主色只用在可点的东西与品牌处，状态色（告警、成功、提醒）另有，不拿主色表示状态 |
| Logo | `BRAND.logo` | 用贴合业务的图标（`@ant-design/icons`）或 `frontend/src/` 下的图片；不要用名字首字方块凑数 |
| 导航图标 | `NAV` 每项的 `icon` | 线性图标，同一套风格；不再用单字方块 |
| 布局 | `LAYOUT` | `sidebar` 功能多、层级深；`topbar` 页面少（≤5 个）、内容要铺满；`topbar-sidebar` 功能多又要品牌感（顶栏放品牌与通知、账号） |
| 圆角 | `APPEARANCE.radius` | `sharp` 数据密集的工作台；`default` 通用；`round` 面向消费者、内容类 |
| 首页重点 | `pages/HomePage` | 按用户每天打开要先看什么来组织（经营数据、待办、内容库、最新结果），不照搬 `HomeBlock` 的默认结构；`HomeBlock` 可用作骨架，内容区按业务自己拼 |

- 缺省蓝色、名字首字方块、单字导航只是没配置时的兜底，交付时不应还是这个样子。
- 外壳外观一律改 `config.ts`，不复制 `AppShell`；要做 SDK 以外的装饰（插画、背景）写在 `src/components/` 或页面里，颜色取 `--g-*` 变量，亮暗跟随宿主。
- `src/app/config.ts` 没有 `APPEARANCE` / `LAYOUT` 说明脚手架较旧，按 [脚手架与预置件.md](脚手架与预置件.md) 升级后再配。

### SDK 两层与保留件

- **App 层**（顶层 `sdk`）：`session`（实例上下文与权限，`permission='view'` 时置灰全部发起与写入入口）、`projects`、`getProject` / `createProject`、`inbox`、`api`（自家后端）、`storage`（界面意图）、`ui.reservedAreas`（宿主浮层占用区，交互组件要避开）、`theme`、`file`（应用级文件）。
- **项目句柄层**：`business`（start / onCall / reply / onResult / 查询）、`upload`、`file`、`chat`、`observe`、`info`。
- **保留件必经，不改不删**：`useProject`、`useProjectExecution`、`useProjectDraft`、`useInbox`、`useRuntimeUserFiles`、表单渲染、错误归一化、`FileField`、`MarkdownContent`、局部错误边界。表单预填已下线，残留的相关文件不接入；表单 schema 的唯一来源是契约包 `forms/` 与 `getForms(formId)`。
- **一切平台调用经 SDK**：后端走 `sdk.api.request`（纯路径、GET/DELETE 无 body、载荷 ≤ 256 KiB；`code !== 0` 必须给用户反馈，不静默失败、不自动重试）；**禁止** fetch / XHR / axios（ESLint 硬禁）。

### 必备页面

| 页面 | 要求 |
|---|---|
| 首页 | 根路由是欢迎页或业务展示页（可以就是看板），不是占位或空白；待办入口带 `useInbox().unreadCount` 角标 |
| 历史运行入口 | 用户要能找回以前每次发起的进度与结果。默认用首页 `HomeBlock` 的「最近记录」（分页可翻到全部，`recordsTitle` 按业务对象命名）；业务要按对象管理时用 `useOwnedProjects` 自写业务化视图（如「诊断记录」）；脚手架版本较旧、没有这两个件时，按同样的取数规则自写。**禁止**向客户放通用「项目列表」页，导航与文案不出现「项目」。取数规则不变：打开、翻页、手动刷新时拉 `sdk.projects.list`，**禁止**轮询，`onStatusChange` 按 `projectId` 就地更新；空态引导去发起第一次业务 |
| 消息中心 | 必经 `useInbox()`；条目带归属项目、表单显示名、文案；点击导航到对应项目的应答状态 |

### 业务页面

- **看板**：数据只来自后端统计接口；每个数值能点开看口径；空数据有引导态；跟随 `sdk.theme` 亮暗。
- **数据管理**：只对 `editable:user` 列开放编辑，`agent` 列只读并标来源；批量与删除有确认；错误按后端信封 `code/msg` 呈现。
- **业务发起（入口表单）**：必经 `useProjectDraft(draftKey)`，`restoring` 期间禁提交；按 `getForms(formId)` 渲染，没有预填，稳定信息由后端发起时拼进 `submit_data`；文件字段经 `project.upload`，全部上传完成才允许提交；`accepted` 导航到项目页，`rejected` 原窗重填，`failed` 展示错误不自动重试。复用已有项目的下拉框不列还有表单没答完的项目；新业务一律新建项目。
- **项目页与交付审阅**：阶段进度按业务事件归约，**禁止**轮询；服务端调起表单时导航到可恢复的应答状态；交付审阅按 `display` 的 `headline / facts / notices / sections` 渲染，只在有活动调用时渲染动作按钮、只提交 `action_key`，`agent_gate` 只读；已提交表单以 key-value 展示，不露裸 JSON 和裸路径。
- **让宿主小喇叭能跳进来**：`goalfy-app.json` 的 `routes` 声明项目页、表单应答页与交付审阅页的路径模板（脚手架默认带 `project: /projects/{project_id}`、`form: /projects/{project_id}/forms/{form_id}/calls/{call_msg_id}`、`delivery_review: /projects/{project_id}/runtimes/{workflow_runtime_id}/delivery`，SDK 随握手交给宿主），用户在宿主小喇叭点一条失败、待填表单或交付消息时按它直接落到应用里对应的页面；改了这些页面的路由必须同步改声明，另有单独执行详情页的可加 `runtime`（占位符只有 `{project_id}` `{workflow_runtime_id}` `{business_id}` `{orchestration_id}` `{form_id}` `{call_msg_id}`）。`npm run check` 校验每条模板都对得上 `App.tsx` 注册的路由，对不上直接失败；**禁止**留下对不上的模板，没有对应页面的应用去掉那条声明即可，宿主会退到项目页或在自己的面板里展开消息详情。
- **交付审阅只提交所选动作**：`reply(callMsgId, { action_key })`，**禁止**把业务数据（如确认后的商家信息）塞进审阅应答——缺 `action_key` 或夹带字段时 SDK 本地判 `rejected`，`npm run check` 直接失败。要让用户在审阅前后修改数据，在路线里设计中途表单，或声明带表单的审阅动作（`start_orchestration`）。审阅与所有表单的 `rejected` 都要把 `data.field_errors` 的原因展示给用户，不能当成已提交。
- **给使用者看的都是人话**：业务用中文名（`useOrchestrationNames` 按路线契约取 name），时间用本地时间（`formatDisplayTime` / `formatDisplayDateTime`），执行过程按「第 N 步 · 状态」合并（`taskpointSteps`），都在 `@/shared`；**禁止**在界面上显示路线 ID、项目 ID、`businessId` / `workflowRuntimeId` / `taskpointEventId` 等内部 ID、`Runtime` / `编排` / `TaskPoint` 这类术语和原始时间串。脚手架预置的项目页已按这个口径显示，旧应用升级脚手架后重新部署才生效；`npm run check` 对业务页面直接显示内部 ID 会给警告，要清零。
- **应答到运行的过渡**：项目层 `useProject(projectId)` 与 `useProjectExecution(project)` 只建一次，应答页、进度页、审阅页共享；应答用 `execution.reply`，不绕过它自己调 `project.business.reply`；**禁止**在每个子路由或因 inbox 变化重建句柄。提交后立即显示「正在提交」，`accepted` 显示「已受理」，收到 `running` 立即切到执行中。

### 表单与文件

- 三类回显各归其位：草稿回显（`sdk.storage`）、驳回回显（`rejected` 返回的参数原窗重填）、已提交回显（`getRuntimeForms`）。
- 校验失败：顶部一条提示，全部无效项高亮，首个无效项滚入并聚焦；提交中禁用写入口。
- 文件值只能由上传产生；展示 URL 经 `getViewUrl` 现取现用；下载只在用户点击时调用。应用级持久文件用 `sdk.file` 与 `shared/ApplicationFileField`，只存 `path`。
- **禁止**把当前路由写进 `sdk.storage`，业务代码不调 `sdk.notifyRoute` / `onHostNavigate`。

### 做完怎么查

- `npm run check` 通过；用脚手架本地布局回归查桌面与移动宽度下的溢出与裁切，并对照代码检查键盘、焦点、对比度和长文本，至少修一轮。需要人眼确认的，请开发者在开发者中心「演示预览」里看；你不开浏览器访问任何线上地址（见 [开发者中心与工作区.md](开发者中心与工作区.md)「看页面只用开发者中心」）。
- 能点、能填、能切换的地方都要有人操作过：本地由测试覆盖或开发者在演示预览里点，真实链路由开发者在「在线试用」里点。
- 设计做不了（SDK 拿不到的数据、路线不发的事件）时回 G3 改清单或回 G4 改契约，**禁止**静默改设计继续做。
- 文案与注释用中文；组件单一职责，超过约 200 行考虑拆分。

## 常见错误

- 用 fetch 直连后端，ESLint 拦下或上线后跨域失败。
- 每个子路由各建一个项目句柄，重新订阅触发重放，把用户拉回旧表单。
- 表单在上传未完成时就能提交。
- 下拉框列出挂着未答表单的项目，用户在那里提交新入口表单被当成答复。
- 数据管理页让用户改 `agent` 列。
- 项目页、记录页直接显示路线 ID、`PRJ-…` 任务标题或 `2026-09-29T03:31:50` 这样的原始时间，使用者看不懂。
- 留着起始页占位或示例包，`verify:release` 失败。
