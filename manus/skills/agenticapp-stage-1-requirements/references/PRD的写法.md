# PRD 的写法、改版、确认与记下来

照 [../assets/PRD.md](../assets/PRD.md) 写的时候读：线上应用的各种情况画在流程图哪里、开发者批注后怎么出新一版、什么算确认、写完怎么自查，以及各处要记下什么。

## 写在哪、怎么交

- 非 Studio 宿主写进方案页 `docs/proposal/index.html`（[方案页.md](方案页.md)），同时在聊天里发交接消息（入口「交接」）。
- 开发者看不到方案页时（命令行宿主，没有右栏），把 PRD 正文贴进聊天：概览四行，流程图按环节逐个节点写；「确认这一版」针对贴出的这一版。不给文件路径。
- Studio 宿主写成开发文档「需求说明」，按 `agenticapp-host-studio`。

## 交接消息「要你做的」列什么

读需求文档，哪里不对直接说；答选择题、定替代做法、同意或不同意试跑；都没问题回「确认这一版」。需求方不是开发者本人时加一项「把需求文档转给需求方看，或让需求方直接答第 N 题」。

## 线上应用会出现的情况画在哪

| 分组 | 情况 | 画在哪、怎么写 |
|---|---|---|
| 怎么开始 | 使用者点按钮、在聊天里发起 | 环节第一个节点是使用者的一步：点什么、填什么 |
| 怎么开始 | 到点自动、有新记录时自动 | 第一个节点画「到点开始」或「有新记录时开始」的应用节点。自动化能做到什么（多久一次、中途能不能等人）以 `agenticapp-tool-automation` 为准，做不到的按替代写。「怎样算做成」分两条：发起一次能出对的结果（④ 验）；到点或有新记录时真的自动开始（发布后才会真的自动运行，④ 记「未测」） |
| 中间 | 模型判断或写内容 | AI 节点：输出放模型写出的内容样例，重要信息写依据什么写。模型不能和使用者来回对话 |
| 中间 | 从外部平台拿东西 | 节点输入写从哪个平台拿什么；要使用者自己授权、要付钱的在重要信息里标出 |
| 中间 | 中途停下等使用者补信息 | 画一个使用者节点「补填……」 |
| 中间 | 按情况走不同的路 | 重要信息写「如果……就……」；超过两种情况拆成节点 |
| 中间 | 几件事同时做、一批东西逐个处理 | 重要信息写「一个一个……」「同时……」和一次最多处理多少条 |
| 中间 | 交给 Agent 接手 | 重要信息写「你可以手动交给 Agent 继续」；新 SDK 应用没有运行 Agent，不写这一种 |
| 中间 | 上传文件、结果里带附件 | 输入或输出写清是什么文件 |
| 怎么结束 | 直接给结果 | 最后一个节点输出写「结果直接给你」 |
| 怎么结束 | 等使用者确认 | 最后画使用者节点，写可选的几种：接受 / 不要 / 交给 Agent（新 SDK 应用没有）/ 重新生成 |
| 记录 | 读哪些记录、存到哪 | 输入写读了哪些记录；存到哪写在保存那一步的重要信息 |
| 做不成时 | 停下，或记下来接着做 | 节点的「做不成时」写使用者看到什么；要重试的写「重试一次」（平台不会自动重试） |
| 跨次、跨天 | 记住上次做到哪 | 重要信息写「接着上次做，不重复」 |
| 跨次、跨天 | 中间要使用者到外部平台手动做 | 拆成两个环节，中间画使用者节点「照方案在聚光后台投放，2 天后回来」 |
| 记录页 | 只是增删改记录、不走流程 | 一个环节两三个节点（录入 → 校验并保存）；流程写进去的内容写明在页面上只能看、不能改 |

## 版本、批注和确认

- **批注**：开发者用聊天指出是哪个环节、哪一步、哪里不对。需求方的意见由开发者转来，或开发者让你直接按需求方的文档改。
- **每出新一版**：标出这一版改了哪里（方案页存历史版、升版号、高亮改动，做法见 `agenticapp-tool-workspace`「方案页」；Studio 保存新的一版），交接消息「刚做完」写这一版改了哪几处。批注引出的新问题照 [按轮问.md](按轮问.md) 问，已定的事不再问。
- **什么算「确认这一版」**：开发者对**当前这一版**的明确同意——回「确认这一版」，或「可以，开始吧」这类明确说法（文字或语音转写都算）；Studio 下按 `agenticapp-host-studio`「确认怎么登记」。你的总结、引用、含糊的回复（「行」「嗯」「看着行吧」）、对旧版的同意都不算。回复里同时有改动时，改完再发一版，请他对这一版再确认一次；新一版不继承旧版的确认。
- **确认 PRD 即同意**要做的这些事和花费上限；花多少、对外做什么在 ② 方案里确认。PRD 确认后只进方案。方案确认后可以放到在线预览（入口「红线」），上线要 ④ 交报告后开发者说「可以上线」。

### 开发者改花费上限

80% 时选了提高上限，或自己提到多花、少花、给了新数（「钱不够就多花点」也算）：

- 新数不低于已累计的花费：他的原话就是对新上限的同意。记 checkpoint，按新上限做，之后的交接写新数；PRD 和方案不出新一版。
- 没给具体数，或新数低于已累计的花费：先不记、不改文档，告诉他已经花了多少，请他给一个不低于这个数的具体积分数；给之前按原上限做。

## 写完自查

- 每个环节都有核实结论；最后一步的重要信息写了这样算对、这样不行、怎样算做成，「怎样算做成」是照着做能看到什么，不是「效果好」「准确」。
- 服务对象写了给谁用、多久用一次；提到的别人参与已写成使用者自己的一步，或放进 ② 的「这次不做的」。
- 每个节点都标了使用者、应用或 AI，AI 节点写了档位和每次花费；会记下来的东西写在保存那一步。
- 花费上限是具体积分数，上线后的用量有答案（开发者答的或按默认）。
- 做不到的都标了「做不到，见替代」，并有替代选择题。
- 选择题里没有入口「开发者确认什么」之外的技术事；有就删掉改由你处理。
- 没有开发者看不懂的词：搜一遍 FA、TPE、工具集、Runtime、schema、编排、冒泡、资产 ID，有就改成业务话；没有模板占位文案。

## 记下来

① 每轮定下事、核实完、PRD 确认后，往阶段文档、方案页和工单里记东西时读。

- **阶段文档 G1**：「已定的事」（每条写是什么、谁说的或按默认、哪一轮定的）、开发者和需求方原话里的关键事实、界面三问的答案、花费上限、确认版 PRD 全文（只在这里存一次，之后各段写「依据 PRD 第 N 版」）、每一版的改动、选择题及谁答的、确认时间与原话。
- **阶段文档 G2**：核实对照表（[核实能不能做.md](核实能不能做.md)「核实对照表」），含外部数据、要他提供的、每一步的花费，② 写运行条件时用。
- **方案页**：PRD 按 [../assets/PRD.md](../assets/PRD.md) 的位置写。
- **工单 checkpoint**：`PRD 已确认`，附应用名、环节列表、表名、花费上限、用量、核实对照表摘要；新 SDK 应用加 `business_ui_id`。
- **阶段标记与阶段记录**：G1、G2 标 `passed`，用 `business_ui_stage` 写 G1、G2 各一条（`agenticapp-tool-workspace`「阶段记录」）。
