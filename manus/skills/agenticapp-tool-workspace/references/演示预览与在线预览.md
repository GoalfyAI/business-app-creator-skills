# 演示预览与在线预览

开发者问去哪看页面、说演示预览打不开、问在线预览打不开时读。

## 三个地方各证明什么

| 用途 | 在哪里 | 要不要同意 | 能证明什么 |
|---|---|---|---|
| 当前工程的页面 | Studio 右栏「演示预览」，由桌面在工作区里起的开发服务（就是演示版），不用部署 | 不用；③ 页面做好时告诉他一句，不等他回话 | 页面渲染、交互、工作区里起的后端与 Mock 联调 |
| 真实身份、真实路线、运行中表单、交付审阅、数据管理 | 草稿部署成功后，Studio 右栏「在线预览」，不需要上线 | 方案确认后直接做（入口「红线」） | 真实链路；开发者自己想看时用，你不打开 |
| 发布后的正式应用、到点自动运行 | 开发者从 GoalfyMax 打开这个应用（开发者本人也要先发布；「自动化」面板只在这里有） | 发不发布由他定 | 不用于 ④ 验收 |

开发者在哪里看过都不算验收证据（见 `agenticapp-stage-4-acceptance`）。

## 演示预览

「演示预览」操作的是工作区里当前真实的工程，改了代码就能看到，不需要等做完，也不需要生成副本。Studio 桌面负责启动和管理应用自己的开发服务：你只准备工程和依赖，不自己起普通开发服务，不手写运行时声明，运行环境和 `.workbench/dev-host.json` 由它提供（按 `agenticapp-host-studio`）。

页面能显示只说明演示版跑得起来：平台能力是 Mock，真实链路要看在线预览。

开发者说演示预览打不开时：

1. 右栏提示「脚手架版本过旧，请升级」：按 `agenticapp-tool-workspace`「脚手架升级」升级后再试。
2. 其他情况：先确认工程和依赖齐全（`npm run doctor`），按右栏给的原因处理。端口被占用时如实说明，不结束不属于本应用目录的进程。

## 在线预览

- 工作台用绑定的 `business_ui_id` 换一次性凭据打开；凭据不写进应用、交付物或工单。
- 只要求当前草稿部署成功，不要求上线。数据写在开发工作集里，和 `workspace` 真跑是同一份库，测试写入的数据不进使用者实例（见 `agenticapp-tool-data-template`「开发工作集」）。
- 保留桌面注入的 `GOALFY_DEV_FRAME_ANCESTORS` 与来源限制；预览端口和连接声明沿用工作台与脚手架生成的值。

部署怎么做见 `agenticapp-tool-deploy`「部署」；在线预览报 `PREVIEW_NOT_READY`、显示「Agentic APP 不存在或加载失败」（3024）时，按 `agenticapp-tool-deploy`「部署与在线预览」的报错表处理。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 演示预览能看到就说真实链路已通 | 演示预览只证明演示版能渲染、能和 Mock 联调 |
| 在 Studio 宿主下自己 `npm run dev` 起服务给演示预览用 | 演示预览由桌面管理，你只准备工程和依赖 |
