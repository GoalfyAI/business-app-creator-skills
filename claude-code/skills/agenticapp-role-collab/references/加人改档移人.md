# 属主：加人、改档、移除

开发者是属主，要加协作者、改档位、移除协作者或撤销邀请时读。

## 调用

`business_ui_manage(action="collaborators", task_id, business_ui_id, collaborator_action=…)`，`collaborator_action` 取 `list`、`add`、`update`、`remove`：

| 动作 | 参数 |
|---|---|
| `add` 指定账号 | `visibility="specified"`（缺省）、`recipient_accounts=[邮箱或手机号]`、`role="viewer"` 或 `"editor"` |
| `add` 分享码 | `visibility="public"`，`role` 只能是 `"viewer"` |
| `update` | `collaborator_user_id`（取自 `list` 返回的 `items[].user_id`）和新的 `role` |
| `remove` | `collaborator_user_id`；未接受的邀请也用它撤销 |

## 先确认再执行

复述和确认的要求见 SKILL.md「属主：加人、改档、移除」；没有这个确认时工具只返回待确认提示，不会写入。

影响要讲清：

- 编辑协作者能改各层资产和开发库结构、能部署自己的草稿，不能上线和发布；
- 移除后对方立即失去全部协作访问；
- 协作者部署的容器，库连接记在他名下。`list` 返回的 `items[].deployed_preview=true` 表示这个人部署了当前运行的预览容器：remove 或把他改为只读之前要告诉开发者，之后这个容器会断开数据库，属主要重新部署一次才能恢复。remove 和改为只读的 update 返回里也会带这条提醒。

## 邀请与档位的限制

- 编辑档只给指定账号（邮箱或手机号）；分享码模式只能发只读档。
- add 之后对方收到带分享码的站内信，要到 GoalfyMax 的分享兑换入口输入分享码接受；接受前 `list` 显示「待接受」。对同一人重复 add 返回已存在，不会发新码。
- 对方还没接受时不能改档：要换档就先 remove 这份邀请，再按新档位 add。
- 经分享码加入的人不能升为编辑：先 remove，再用指定账号按编辑档 add。

## 报错

| 错误码 | 处置 |
|---|---|
| `BUSINESS_UI_COLLABORATOR_PENDING` | 对方还没接受邀请就改档：remove 这份邀请后按新档位 add |
| `BUSINESS_UI_COLLABORATION_CODE_READ_ONLY` | 把经分享码加入的人升为编辑：先 remove，再用指定账号按编辑档 add |
| `BUSINESS_UI_COLLABORATOR_NOT_FOUND` | 对方不是这个应用的协作者：用 `collaborators list` 核对 |
| `BUSINESS_UI_PREVIEW_ACCESS_SYNC_FAILED` | 移除本身已生效，预览访问名单没同步成功：告诉开发者移除已生效；用同样参数加 `share_code=<报错 metadata.share_code>`、`confirm_collaborator_change=true` 再调一次 `collaborators remove` 完成同步，这次不用再问开发者 |
| `BUSINESS_UI_COLLABORATION_MANAGED_BY_OWNER` | 在「我的资产」里移除经协作得到的资产：协作带来的资产由属主在协作者列表里管理 |
