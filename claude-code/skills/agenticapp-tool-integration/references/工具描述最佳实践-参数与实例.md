### 四、 JSON Schema 参数定义的最佳实践

很多人忽略了 JSON Schema 中的 `description` 字段。**这是对参数进行 Prompt 的最后机会。**

#### 1. 不要只解释“是什么”，要解释“怎么填”

*   _Bad_: `path`: "The file path."

*   _Good_: `path`: "The **absolute** path to the file. Do NOT use relative paths. Example: `/home/user/project/src/index.js`."

#### 2. 注入业务逻辑

*   _Bad_: `commit_message`: "The message for git commit."

*   _Good_: `commit_message`: "A concise (1-2 sentences) message focusing on the 'why'. Follow the Conventional Commits specification."

#### 3. 利用 Enum 和 Defaults 限制幻觉

*   如果参数只有几个固定值，务必使用 `enum`。

*   如果参数可选，明确 `default` 行为（如：`default: false`）。

### 五、 风格与语法速查表

| 维度 | 建议 | 示例 |
| --- | --- | --- |
| **语态** | 祈使句，强动词 | "Use this tool to...", "Prefer X over Y" |
| **否定句** | 明确的负面约束 | "Do NOT use `grep` via Bash", "Skip this tool when..." |
| **格式化** | Markdown, Bullet points | 使用列表让模型更容易解析规则。 |
| **强调** | 全大写 | **MUST**, **NEVER** |
| **逻辑连接** | If-Then 结构 | "If the output exceeds X chars, it will be truncated." |

### 六、 完整实例演示

假设我们要定义一个 `**SQLQuery**` 工具，以下是应用了所有最佳实践的说明：

```markdown
## SQLQuery

Executes a read-only SQL query against the production database to retrieve user or transaction data.

#### When to Use
- When you need specific data points that are not available in the conversation history.
- When performing data analysis or generating reports for the user.

#### When NOT to Use
- **Do NOT** use for `INSERT`, `UPDATE`, or `DELETE` operations. This tool is strictly read-only.
- Do NOT use if the user asks for "system logs" (use the `LogSearch` tool instead).

#### CRITICAL REQUIREMENTS
- You **MUST** limit your query results using `LIMIT 100` unless explicitly asked otherwise.
- **NEVER** query the `passwords` or `credit_cards` tables directly.
- If the query fails, check the schema using the `GetSchema` tool before retrying.

#### Usage Notes
- Prefer specific column selection (`SELECT id, name`) over wildcard (`SELECT *`) to reduce token usage.
- Dates are stored in UTC.

#### Examples
<example>
User: "Show me the last 5 users who signed up."
Assistant: [Calls SQLQuery]
{
  "query": "SELECT id, email, created_at FROM users ORDER BY created_at DESC LIMIT 5"
}
</example>

---
JSON Schema:
{
  "properties": {
    "query": {
      "type": "string",
      "description": "The Standard SQL query to execute. Must be a SELECT statement. Must include a LIMIT clause."
    }
  }
}
```
