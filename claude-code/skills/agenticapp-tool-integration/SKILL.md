# 接入工具、授权与工具集上线

管路线要用的外部能力怎么进平台、怎么让使用者授权、怎么让运行时真的加载到。几个词：

- **工具组**（`tool_group_id`）：一个 MCP 服务注册后的资产，里面是若干工具（`tool_id`）。注册返回还有 `mcp_id`，配授权卡用它，它不是工具组标识。
- **工具集**（`toolset_id`）：把工具组和 FA 装在一起、附使用指南，供 TPE 预加载。新建或导入的工具集是**离线**的：可以被关联配置，但运行时不会被加载，编排型 TPE 也建不了。
- **授权卡**：让每个使用者用自己的第三方账号授权，凭证留在平台侧。
- **取样**：`otpe_tool_test` 真实调用一次工具，看真实返回。

要不要接入新能力由 ① 判定（`agenticapp-stage-1-requirements`）。你实际看到的工具定义与服务端报错始终优先于本文。

## 接入前先查

先用 `list_assets(asset_type="tool_group", keyword=…)` 和 `get_asset` 确认平台上没有可复用的工具组。重复注册同一个 MCP 会产生互相冲突的重复资产。关键词只匹配名称和 ID，用英文短词多试几次。

## 接入现有 MCP 服务

先预览、再注册：预览确认连接可用并发现真实工具清单，跳过预览直接注册会把不可用的连接写成正式资产。

1. `preview_tool_group`：传连接类型，以及地址或启动命令。做成：预览返回成功，并列出了真实工具清单。
2. 成功 → `register_and_refresh_tool_group`：传相同的连接参数，选择要纳入的工具。记下 `tool_group_id` 和 `mcp_id`。
3. 失败 → 按 [references/预览失败的调试循环.md](references/预览失败的调试循环.md) 调试。
4. 注册成功后按需配授权卡。

## 私有包与 Skill 包

- **私有包**（开发者提供的本地包）：`file_to_url` 上传 → `upload_and_register_tool_group` 用返回的文件引用注册，同样支持前置安装步骤。包里用了 `zoneinfo` 的要声明 `tzdata` 并在无时区环境里真调一次，见 [references/私有包与时区检查.md](references/私有包与时区检查.md)。做成：无时区环境里收到 `tools/call` 的响应且 `isError` 不为 `true`；只启动不调用工具不算。
- **标准 Skill 包**（含 Skill 入口文件的压缩包）：`file_to_url` 上传 → `import_skill_package` 导入。导入会自动解析入口文件并创建**离线**工具集，之后仍要过「工具集上线」的检查。

## 授权卡

看授权凭证是每个使用者一份，还是全场景包共用一份：

| 情况 | 处理 |
|---|---|
| 每个使用者用自己的第三方账号授权 | 配授权卡；没配时使用者无法完成授权，工具调用会失败 |
| 服务级认证，全场景包共用一份凭证 | 写在连接配置的请求头里，不需要授权卡 |

漏配授权卡时，制作期你自己测试可能正常（用的是你的凭证），交给使用者后全部调用失败。

| 需求 | 工具 | 要点 |
|---|---|---|
| 新建一张卡 | `create_auth_card` | 传 `mcp_id`（不是 `tool_group_id`）、授权类型和授权配置 |
| 改已绑卡片的配置 | `update_auth_card` | 只传要改的字段 |
| 复用别人已有的卡 | `link_auth_card` | 需要卡片标识 `auth_card_key`；替换已绑卡片要显式确认，替换前先请开发者确认 |

- 授权配置的必填内容随授权类型不同：标准授权流程需要三个服务端端点；自定义方式需要字段清单，每个字段要有键名、展示名、类型和是否必填。具体必填项以实时 Schema 为准。
- 创建成功后返回的卡片标识记进工单 checkpoint，不交给开发者；之后要让别的 MCP 共用这张卡的使用者授权时，从 checkpoint 取它 `link_auth_card`。
- 个人令牌、Cookie 或密码不写进 Skill 文本、脚本、提示词或工单（入口「红线」）：授权卡的作用就是让凭证留在平台侧。

## 工具集上线

两道检查都要做。

**第一道：编排型 TPE 创建前**

1. 根据脚本确定完整的预加载工具集清单：把核实过的工具组、FA 用 `create_toolset(name, description, tool_group_ids, fast_agent_ids)` 装成工具集，一条路线通常一个；脚本要读写应用库的，工具集里装上工具组「query_business_app_dataset」。
2. 本轮新建或导入、含 MCP 工具组的工具集，用 `otpe_tool_test` 做一次安全的真实取样（[references/工具取样.md](references/工具取样.md)）；只含 FA 的工具集没有单独的测试入口，`get_asset` 反读 FA 配置无误即可，首次运行测试放到路线冒泡；读写应用库的路线首次运行测试放到 ④ 工作集实际跑。做成：取样返回的 `structured_content` 是脚本要的那个对象。
3. 全部无失败后 `online_toolsets`，只传本轮新建的标识。
4. `get_asset` 反读，确认清单里每一个都已上线。通过后才创建编排型 TPE，在此之前只做 preview。

**第二道：④ 部署前**，对待上线清单里尚未上线的工具集：含 MCP 工具组的逐一做安全的真实取样，破坏性操作跳过，只含 FA 的按第一道的口径 → 全部无失败后 `online_toolsets` → `get_asset` 反读确认全部已上线。第一道里上线过的只反读、不重复上线。

- **失败与中断**：任一测试失败、余额不足、授权中断或流程异常时，保留原资产和进度，恢复后从未完成的验证继续；验证都通过才上线。
- **开发者已有的离线工具集**（不是本工单新建）：开发者本人名下的，按上面两道检查测过后由你上线并关联；别人的不改它的上线状态，停下告诉开发者影响哪个功能，由他决定。

新 SDK 应用：节点脚本调用的工具集要挂在该节点 TPE 上，见 `agenticapp-tool-workflow` 的「新 SDK 应用」说明。

## 工具取样

要确认已有工具的真实返回和输入约定时，`otpe_tool_test(task_id, tool_group_id, tool_id, input=<最小合法参数>)` 真调一次，看 `structured_content` 是不是要的那个对象。**这会真实调用供应商接口**，取样前先按 [references/工具取样.md](references/工具取样.md)「哪些不取样」排除不能取样的工具。依赖项目上下文的工具、要读 `/workspace` 测试文件的工具怎么传参，取样能证明什么，也在这份 references。

## 分享来的工具组

分享来的工具组搜不到、看不到参数（`can_view_params=false`），或不能克隆时，读 [references/分享来的工具组.md](references/分享来的工具组.md)。

## 依赖变更后

工具组刷新（`register_and_refresh_tool_group` 会给出差异）、工具删除或参数变化后：

- 回头核对所有引用它的地方：工具集使用指南、FA 提示词、编排型 TPE 脚本、`apc_skill`、场景 Skill 文件。留着失效知识会让运行时 Agent 反复尝试不存在的能力，静态检查看不出来。
- 变更完成后重跑所有受影响的预览、运行验证和整包验收。

## 外部平台授权与充值

PRD 写了「外部平台授权」或充值，或者 ③ 建好应用、挂好路线（旧写法应用挂好场景包）后 `business_ui_manage(action="list_authorization_candidates")` 返回的候选不为空，就要做：保存开发者确认的选择、查充值开通状态；页面经 `sdk.authorization` / `sdk.payment` 接入；④ 交报告前再核一遍。做成：候选不为空时选择已保存、页面有授权入口；授权在预览里没真正打通的，报告里那几条记「未测」并写明要账户持有人在预览里授权一次。调用、页面规则、应用自管外部登录和交报告前核对见 [references/外部平台授权与充值.md](references/外部平台授权与充值.md)。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 跳过预览直接注册，不可用的连接被写成正式资产 | 先 `preview_tool_group` 成功再注册 |
| 预览时装过依赖，注册时漏传同一组安装步骤；运行时到真正调用工具才因缺依赖失败 | 注册带上预览时验证过的安装步骤 |
| 给预览工具传本地文件路径，它访问不到你的文件系统 | 私有包走 `file_to_url` 上传 |
| 私有包用了 `zoneinfo` 没声明 `tzdata`；本机能跑，平台上调用到时区的工具才失败 | 声明后在无时区环境里真调一次工具 |
| 配授权卡传了 `tool_group_id` | 传 `mcp_id` |
| 要使用者各自授权的工具没配授权卡，自测正常就交付；使用者调用失败 | 按凭证归属判断，每人一份的配授权卡并绑定；调用失败先查卡有没有配、有没有绑定 |
| 工具集还是离线就建编排型 TPE（建不了），或关联成功但运行时加载不到 | `online_toolsets` 后 `get_asset` 反读确认已上线 |
| 把 `can_view_params=false` 的分享工具组当成空资产 | 这是权限脱敏，按 [references/分享来的工具组.md](references/分享来的工具组.md)「看不到参数」做 |

外部平台授权与充值的常见错误见 [references/外部平台授权与充值.md](references/外部平台授权与充值.md)「授权与充值的常见错误」。
