# 编排报错对照

建 FA、写 TPE、保存路线、冒泡时工具返回错误或运行失败时读。先看返回里给的出口和提示，本表只补返回里没说清的部分。照这里处理后仍走不下去、又不是应用自己的问题，按入口「报错和平台问题」报。

改同一份对象、同一错误连续两次换思路、`recoverable=False` 不重试这三条通用做法，先按入口「报错和平台问题」。

## 对照表

| 现象 | 处理 |
|---|---|
| 工具或 action 不存在 | 回看当前工具定义，按实际 action 和字段改；工具确实不在列表里时如实告诉开发者该能力当前不可用 |
| 预览报字段、工具或路径错误 | 按报错精确修同一份草稿，再重跑预览 |
| `get_asset` 反读快速智能体时没有 `actual_tool_group_ids` 或 `model_selection_mode` | 平台还没返回这两项：不拿 `create_fast_agent` 的回执代替反读，按入口「报错和平台问题」报（已有同类反馈就追加）；这一项在 G4 记「平台未返回，待核」，读写应用库的路线照常靠 ④ 实际跑证明 |
| preview 报「无法解析到 preload_toolsets」 | `preload_toolset_ids` 里缺装了「query_business_app_dataset」的工具集，或工具集没上线 |
| `otpe_manage(verify)` 的 `static_contract` 失败 | 看 `errors[].where/msg`，多半是 `_output` 形状或事件契约；改脚本 |
| `otpe_manage(verify)` 的 `toolsets_online` / `tpe_online` 失败 | `online_toolsets` / `otpe_manage(action="online")` 上线后反读 |
| 冒泡没到终态 | 按 [冒泡与实际跑能证明什么.md](冒泡与实际跑能证明什么.md)「时限」续等 |
| 冒泡失败 | 看 `steps[].error`；同一错误连续两次换策略（入口「报错和平台问题」）；事实错误、引用错误或无产物反复出现时，按 [执行形态与模型档位.md](执行形态与模型档位.md)「FA 与脚本的职责边界」第 4 条处理 |
| 不确定 FA 用了哪个模型 | 回执顶层 `resolved_model` / `resolved_mode` 是这次验证运行（外层 SA）的模型和模式，不是 FA 的。FA 按资产配置运行：`required` 模式固定用该模型，`agent_selected` 模式用资产兜底模型，未配兜底用平台默认组；用 `get_asset(asset_type="fast_agent")` 查 `model_selection_mode` 与 `model_name` |
| FA 失败或 `FA_STEP_BUDGET_EXCEEDED`，不知道它每一轮做了什么 | 先看 `manage_goalfymax_project` 的 `wait` / `status` 返回的 `fast_agent_failures` 和下一步提示；再用 `get_project_execution_logs(action="detail", log_type="fast_agents", project_id=…)` 看逐轮的工具、参数和截断标记（`args_truncated_by_repeat_guard`）。冒泡回执里的 `project_id` 在冒泡发起后 2 小时内可读 |
| `FA_CONTEXT_BUDGET_EXCEEDED` / 预览提示「本次预览没有完整正文行」 | 见 [脚本骨架与失败出口.md](脚本骨架与失败出口.md)「失败出口怎么写」的上下文预算、[事件契约与文件产物.md](事件契约与文件产物.md)「交给 FA 读的数据走文件」 |
| 冒泡异常长跑或积分持续上涨 | 按 [冒泡与实际跑能证明什么.md](冒泡与实际跑能证明什么.md)「止损」cancel |
| `ORCH_NODE_FAILED` | 兜底错误码，不等于工具坏了，按排查信息里的失败类别归因：`business_gate` 是脚本按规则主动停止，查业务条件与输入；`contract_error` / `script_bug` / `shell_exit` 归制作侧，修同一份脚本或契约；`tool_error` 看上游工具与 `recoverable` / `attempts`；`fa_error` 是 FA 预算或异常退出；`timeout` 先查最慢的一步。信息是「结果为空」且判失败与上一条工具返回只隔几十毫秒，多半是没等分段返回收齐 |
| `Workflow business event requires persisted Runtime identity` | 运行身份只给了一部分，或内部调用链丢了降级标记，属于平台问题，按入口「报错和平台问题」报；单独派发带事件的 TPE 不会报这条，只会事件被抑制。冒泡时是服务端没分配验证身份，同样报平台问题。Runtime ID 只用平台生成的 |
| `WORKFLOW_RUNTIME_IDENTITY_INCONSISTENT` | 三元身份部分缺失，是调用链内部错误，不是业务输入问题；核对入口是否完整传递服务端生成的身份 |
| 路线保存被拒 | 按返回的节点、字段、路径错误修同一个对象；节点只能读直接依赖的上游输出；审阅动作不写 `label`；入口映射不直接写 `default` |
| 上游返回阻断后，下游缺必填入参报 `CONTRACT_VALIDATION_FAILED` | 返回阻断只结束本节点，下游照常派发并校验入参。要停整条路线按[多编排型TPE契约-入口映射交互与介入.md](多编排型TPE契约-入口映射交互与介入.md)「业务阻断怎么写」改，不放宽下游必填 |
| 路线保存或上线被拒，提示中途表单的跳过规则已不再支持 | 这条规则在运行时从来没有生效过。直接删掉，或按[多编排型TPE契约-入口映射交互与介入.md](多编排型TPE契约-入口映射交互与介入.md)「业务阻断怎么写」改写 |
| `WORKFLOW_FORM_PENDING` / `ORCH_INTERACTION_PENDING` | 项目里还有表单没答完，又在同一项目提交了入口表单。不是故障：让使用者回该项目答完，新业务新建项目；页面做法见 `agenticapp-tool-frontend` |
| `WORKSPACE_PATH_UNTRUSTED` | 节点返回的文件路径没有可信来源。把要返回的文件实际写入或复制到 `ctx.output_dir` 再返回真实路径；不能只改路径字符串、虚构文件或删掉文件声明（[事件契约与文件产物.md](事件契约与文件产物.md)「文件产物」） |
| `ORCH_DELIVERY_FILE_UNISOLATED` | 声明为文件的交付不在最终节点产物目录；先复制进 `ctx.output_dir` 再返回 |
| `ORCH_ARTIFACT_PUBLICATION_FAILED`，报 `s3_key does not match`，路径里有 `output//` | 脚本在 `ctx.output_dir` 后面多拼了一个 `/`，它自带结尾斜杠。改脚本重跑；回执可能把修复指向路线的交付配置，问题不在那里 |
| `ORCH_DELIVERY_FILE_UNVERIFIED`，或交付出现「内部资料：文件名」、该交付的文件没成为附件 | 未声明为文件的 workspace 路径不会成为附件。有意保留的出处引用属正常；本来要交付的文件，逐项核对真实文件、最终节点目录、文件声明和交付映射（[业务路线与assemble.md](业务路线与assemble.md)「交付与审阅」） |
| 交付审阅提交后回 `rejected`，`field_errors` 为 `ORCH_DELIVERY_ACTION_INVALID` 或 `DELIVERY_REVIEW_REPLY_INVALID` | 审阅应答缺 `action_key`、夹带了业务数据，或动作不在本次声明内；项目会停在 waiting-input 等使用者重选，最长 2 小时。审阅只提交 `{ action_key }`；要改数据用中途表单或带表单的审阅动作；页面展示被拒原因 |
| `get_project_execution_logs(action="download")` 报不存在或受保护目录 | 不存在：先 `outputs` 看清单，节点产物在 `/workspace/task_agent/<taskpoint>/output/`；受保护目录（`input/`、`skills/`、`.env` 等）本来就不提供下载 |
| 新 SDK 应用的 `EXECUTION_*`、`APP_VERSION_*` | [新SDK应用的路线.md](新SDK应用的路线.md)「冒泡和执行里可能遇到的错误码」 |

工具集加载不到、授权卡、外部工具参数格式、分享来的资产字段为空，见 `agenticapp-tool-integration`「常见错误」。
