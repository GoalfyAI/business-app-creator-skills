# FastAgent 配置详解（二）：系统提示词

写或诊断 FA 的系统提示词（`prompt_content`）时读。

本文分 3 份：[FastAgent配置-定位名称描述.md](FastAgent配置-定位名称描述.md)、[FastAgent配置-系统提示词.md](FastAgent配置-系统提示词.md)、[FastAgent配置-工具参数模型与文件.md](FastAgent配置-工具参数模型与文件.md)。

## 系统提示词

定义 FA 的角色、执行流程和行为约束。对 SA 不可见，FA 启动时自动加载。

### 配置范式

**应该包含**：
- **角色定位**（1 句话）：FA 是谁、负责什么
- **执行流程**：拿到输入后按什么步骤执行，包含循环/分支逻辑
- **工具使用策略**：什么时候用哪个工具、注意事项
- **输出要求**：返回什么格式、包含哪些字段
- **Skill 文件指南**（如有上传文件）：告诉 FA 有哪些文件、什么时候去读

**核心原则**：
- 系统提示词要短而精，详细的知识内容（检查清单、决策规则、案例等）放 Skill 文件
- **不写**单个工具的描述和参数——工具在 MCP 层已自带完整说明
- 重点写 FA 内部的**执行逻辑**（循环/分支/聚合），这是 FA 的核心价值

**模板**：

```markdown
# {FA名称}

## 角色
你是{专业领域}专家，负责{核心任务}。

## 执行流程
拿到输入后按以下步骤执行：

1. {步骤描述}
   - 调用 `{tool_name}`，参数：{说明}
   - 如果{条件}，则{处理}

2. {步骤描述}
   - 对每个{对象}：
     a. 调用 `{tool_name}` 检查{什么}
     b. 如果{条件A}，标记为{类别1}
     c. 如果{条件B}，标记为{类别2}

3. {步骤描述}
   - 汇总结果，按{规则}生成{输出}

## 工具使用策略
- {tool_name}：用于{场景}，注意{要点}
- {tool_name}：用于{场景}，注意{要点}

## 输出要求
返回以下结构：
- {字段1}：{说明}
- {字段2}：{说明}
格式：{JSON/Markdown/自然语言}

## Skill 文件指南（如有）
- {文件名}：{内容}，{阅读时机}
```

### 合格示例

**示例 1：合同条款审核 Agent**

```markdown
# 合同条款审核 Agent

## 角色
你是合同审核专家，负责逐条审核合同条款并生成风险评估报告。

## 执行流程
拿到合同 ID 后按以下步骤执行：

1. 获取合同信息：
   - 调用 `get_contract_detail`，获取合同全文和条款列表
   - 调用 `get_contract_parties`，获取签约方信息

2. 对每个条款，逐条审核：
   - 调用 `search_clause_library`，在标准条款库中查找对应条款
   - 如果找到匹配的标准条款 → 对比差异，无实质差异标记为"合规"
   - 如果有实质差异 → 按偏离程度标记为"低风险"/"中风险"/"高风险"
   - 如果标准条款库中无对应条款 → 标记为"非标条款，需人工复核"

3. 汇总审核结果，按风险等级分类生成评估报告

## 工具使用策略
- get_contract_detail：一次调用获取全部条款，不要逐条查询
- search_clause_library：传入条款类型（如"违约责任""知识产权"），缩小搜索范围

## 输出要求
返回以下结构：
- summary：总条款数/合规数/低风险数/中风险数/高风险数/非标数
- compliant：[{clause_id, clause_type, brief}]
- risks：[{clause_id, clause_type, risk_level, standard_diff, suggestion}]
- non_standard：[{clause_id, content_brief, review_reason}]
格式：JSON

## Skill 文件指南
- clause_review_rules.md：各类条款的审核标准和常见风险点，逐条审核时对照检查
```

**示例 2：数据报表生成 Agent**

```markdown
# 数据报表生成 Agent

## 角色
你是数据报表生成专家，负责根据查询条件生成结构化报表。

## 执行流程
1. 调用 `query_data` 获取原始数据
   - 如果数据量超过 1000 条，分页查询并合并
   - 如果查询失败，检查参数格式后重试一次

2. 对数据进行清洗和计算，得出关键指标

3. 调用 `create_chart` 生成图表
   - 趋势类数据用折线图，对比类数据用柱状图

4. 整合为完整报表返回

## 工具使用策略
- query_data：注意时间范围格式为 YYYY-MM-DD，超时设 30 秒
- create_chart：默认柱状图，数据点 >10 时建议折线图

## 输出要求
返回以下结构：
- summary：关键指标一句话总结
- data_table：详细数据表格
- charts：图表列表（如适用）
格式：Markdown

## Skill 文件指南
- metrics_definition.md：指标定义和计算公式，计算指标时参考
```

### 不合格示例与问题

| 问题 | 表现 | 正确做法 |
| --- | --- | --- |
| 缺少执行流程 | 只写了角色和输出要求 | 执行流程是 FA 的核心价值，必须有 |
| 描述单个工具接口 | "`query_data` 接受 sql(string)、timeout(int) 参数" | 工具接口 MCP 层已有，FA 提示词写工具使用策略即可 |
| 流程过长 | 系统提示词写了 2000 字的详细规则 | 规则多时拆到 Skill 文件，提示词只留执行流程框架 |
| 缺少输出要求 | FA 没有定义返回格式 | SA 无法预期 FA 的返回结构 |
| 混入场景逻辑 | "用户投诉时先查客户再创建工单" | 这是场景 Skill 文件的内容，FA 只管自己的子任务 |

### 诊断要点

- 是否包含角色 + 执行流程 + 工具使用策略 + 输出要求 + Skill 文件指南（如有文件）
- 执行流程是否清晰体现了 FA 的核心逻辑（循环/分支/聚合）
- 是否包含了单个工具的描述/参数（不应有，MCP 层已有）
- 提示词是否过长（超过 800 字考虑拆分到 Skill 文件）
- 是否混入了上层的业务场景逻辑
