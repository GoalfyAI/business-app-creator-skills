# 失败与降级正反例（一）：必需步骤与可选步骤

有真正可选的步骤、工具部分成功、可恢复失败或副作用调用时读。诊断关键词：success 含 failure step、无痕 fallback、`degraded`、`warnings`、`retryable`、非幂等重试。对应契约：`WF-SINGLE-06`。

本文分 2 份：[编排示例-失败-必需与可选.md](编排示例-失败-必需与可选.md)、[编排示例-失败-结果分类与副作用.md](编排示例-失败-结果分类与副作用.md)。

本页中的 `demo_required`、`demo_optional`、`demo_search` 和 `send_email` 只用于说明契约；除 Max 默认工具外，实际开发必须先用 `get_asset` 取得真实工具名和当前 Schema。

Max Runtime 对失败的边界很明确：工具步骤失败时先在 `step_results` 记录 failure，再向脚本抛异常；脚本没有捕获时，整条 run 为 failure；脚本捕获后正常返回时，Runtime 认为作者已经处理该失败，只要最终输出通过校验，整条 run 就可以是 success。因而，捕获异常不是普通的语法选择，而是在声明「该步骤可选，并且当前返回是可解释的降级结果」。

2026-08-08 的 QA 脱敏聚合中，18 条整体 success 的 run 仍包含 failure step，且最终输出顶层都没有 `degraded`、`warnings`、`errors` 或 `fallback` 标记。这不能证明 18 条都错误，但说明无痕兜底会让消费者无法区分真实空结果和执行失败。

## 1. 必需步骤失败：不要伪造成功

错误脚本：

```python
async def run(input, ctx):
    try:
        result = await tool(
            "demo_required",
            query=input.get("query", ""),
            _output={
                "type": "object",
                "required": ["items"],
                "properties": {"items": {"type": "array"}}
            },
            _rationale="读取生成最终结果必需的数据"
        )
    except Exception:
        result = {"items": []}
    return {"items": result["items"]}
```

实际诊断边界：preview 不一定报错，因为它无法判断业务上哪个步骤必需。真实运行时，工具错误会保留在 `step_results`；但异常被脚本吞掉，最终空数组又符合 Schema，整条 run 可以被记为 success。调用方无法知道 `items=[]` 是正常查无数据，还是工具根本没有执行成功。

修复后证据：工具失败会以 `WorkflowStepError` 冒泡，最终运行结果为 `Workflow execution failed: demo_required#1: <reason>`，不会提交伪造的业务数据。

所属契约：必需步骤失败 = 整条编排型 TPE 失败。

## 2. 可选步骤失败：显式返回降级状态

只有业务在缺少该步骤时仍能交付一个有意义、可识别的结果，才允许捕获异常：

```python
async def run(input, ctx):
    required = await tool(
        "demo_required",
        query=input.get("query", ""),
        _output={
            "type": "object",
            "required": ["items"],
            "properties": {"items": {"type": "array"}}
        },
        _rationale="读取生成最终结果必需的数据"
    )

    optional_items = []
    degraded = False
    warnings = []
    try:
        optional = await tool(
            "demo_optional",
            query=input.get("query", ""),
            _output={
                "type": "object",
                "required": ["items"],
                "properties": {"items": {"type": "array"}}
            },
            _rationale="补充不影响基础交付的可选资料"
        )
        optional_items = optional["items"]
    except Exception:
        degraded = True
        warnings = ["optional_source_unavailable"]

    return {
        "items": required["items"] + optional_items,
        "degraded": degraded,
        "warnings": warnings
    }
```

对应的编排型 TPE `output_schema` 至少声明：

```json
{
  "type": "object",
  "required": ["items", "degraded", "warnings"],
  "properties": {
    "items": {"type": "array"},
    "degraded": {"type": "boolean"},
    "warnings": {
      "type": "array",
      "items": {"type": "string"}
    }
  }
}
```

修复后证据：必需步骤仍会失败冒泡；只有可选步骤可降级。可选步骤失败时，`step_results` 保存真实错误供诊断，最终输出以稳定 warning code 告诉下游当前结果不完整。

不要把 `str(exc)` 直接写进最终输出。Provider 原始错误可能包含凭证、内部地址或实现细节；最终输出只返回稳定错误码，详细原因留在运行轨迹中。

所属契约：可选步骤失败 = 成功但 `degraded=true`，且输出 Schema 强制携带 `warnings`。
