# 执行形态、职责边界与模型档位

决定一步交给谁做、FA 和脚本各管什么、选哪个模型、想弄清一次运行里谁在做什么时读。

## 场景包由什么组成（旧应用）

场景包是能力容器，定义运行 Agent 在这个业务里能做什么、怎么做、用什么做：

| 组成 | 说明 |
|---|---|
| `apc_skill` | 始终注入，运行 Agent 每轮都能看到；写「能做哪几件事、各自什么时候用、发起前要收齐什么」，不写资产 ID |
| 场景 Skill 文件 | 按需读取的大段知识，启动时只看到文件名 |
| 任务点（TPE） | 同一类资产的两种类型：普通任务点、编排型 TPE；共用 `tpe_id`，查询时看类型标记区分，不当两套资产管理 |
| 业务路线 | 场景包字段 `workflow_orchestration`，`orchestrations[]` 每一项是一条路线，`orchestration_id` 是路线标识 |
| 工具集 | 装工具与 FastAgent，附使用指南；预加载或动态加载 |
| 长期数据集 | 已有数据集的引用，不拥有数据 |

- 智能应用的前端、后端、数据模板不在场景包里，它们消费场景包的公开契约。最小场景包 = 一份草稿（通常克隆官方基础包）+ 至少一个已上线的工具集 + `apc_skill`。
- 平台没有「包引用包」，跨包复用走共享资产（先克隆再改）；继承用 `create_derived_scene_package` 从已上线版本派生新家族（`clone` 或 `personalization`），血缘用 `get_scene_package_lineage` 看。
- 新 SDK 应用不挂场景包，路线与编排型 TPE 直接挂在应用版本上，见 [新SDK应用的路线.md](新SDK应用的路线.md)。

## 四种执行形态

| 形态 | 是什么 | 能和使用者交互 | 自带文件 / 命令 / 邮件 | 适合 |
|---|---|---|---|---|
| SystemAgent 直接执行 | 运行时对话的 Agent 自己调工具，不产生资产 | 能 | — | 次数确定、指令量小的动作；只在 `apc_skill` 写规则 |
| FastAgent | 可当工具调用的完整执行单元：挂上工具后在一次调用里多轮做完一个业务环节 | 不能 | 不自带，要用就单独配 | 需要模型判断、判断与工具调用交织的环节 |
| 普通任务点 | 派给 TaskAgent 的任务模板，步骤临场决定，独立上下文 | 能，可中途提问 | 自带 | 整条路径要临场规划，或必须和使用者自然语言往返 |
| 编排型 TPE | 确定性脚本，自己不推理；需要模型的环节调 FastAgent | 不能（中途要人用路线的节点级机制） | 自带 | 稳定、可复跑的执行管道 |

- **FastAgent 没有记忆**：每次调用是全新隔离会话，必要背景都要随参数传入，只传 ID 它读不到调用方的历史。
- 拆 FA 的唯一理由是职责边界不同（领域知识、产出契约、需要独立复用），不是步骤不同；一个环节拆成好几个 FA 串起来是错的。
- 文件读写、命令执行、邮件发送是普通任务点和编排型 TPE 自带的，不当成工具缺口去建工具集。

## FA 与脚本的职责边界

| 责任方 | 只负责 | 不负责 |
|---|---|---|
| FastAgent | 一个可独立复用的语义责任；在内部按结果自适应判断和调用工具 | 流程分发、跨环节汇合、固定收口 |
| 编排脚本 | 确定性准备、分发、汇合、幂等写入和固定收口 | 判断内容真假、用新增字段替代语义判断 |

「看结果再决定查什么」放进 FA，不写成脚本里 tool → FA → tool → FA 的长链。

`_output` 是脚本与 FA 之间的**控制面最小合同**，不是内容质量检查器。按这个顺序收口：

1. 默认软门禁是顶层字段不超过 8 个、对象嵌套不超过 2 层；超过时拆开语义责任，或把内容改成稳定载体引用，不继续扩 Schema。
2. 内容型大结果（长报告、完整证据集、批量明细）写入数据集或 `ctx.process_dir` 文件等稳定载体；`_output` 只返回 `status`、`note`、引用和脚本真正需要的计数。一篇草稿、几条诊断这类短内容照常以字段返回；节点最终返回里给使用者看的列表、正文、结论仍以业务字段出现，要交付的文件才写 `ctx.output_dir` 并声明交付（见 [事件契约与文件产物.md](事件契约与文件产物.md)「文件产物」）。
3. Schema 只校验形状，不能证明内容真实。输出分成事实区与推断区：事实保留来源和原文，推断明确标记且不得回填为事实；首版只承诺来源、原文和失败原因可追溯。
4. 同类事实错误、引用错误或无产物连续两轮出现时，停止加字段和原样重试，重判 FA、脚本与工具的职责（要改施工单的回 ②）；仍保留 `completed`、`partial`、`blocked` 等合法出口。不用增加角色、关系、否定条件或嵌套 ID 来修正事实错误。

## 模型档位

给开发者只说「快而便宜的一档」「强的一档」「写代码的一档」；具体模型名只写进 FA 配置和阶段文档。

| 档 | 当前可选的模型（以 `create_fast_agent` 的 `model_name` 当前可选值为准） | 适合 |
|---|---|---|
| 快而便宜 | `deepseek-v4.1-flash-thinking-ha` | 核实、抽取、分类、打标签、摘要、校验格式；也能看截图 |
| 强 | `deepseek-v4-pro-thinking-ha`（不看图）、`kimi-k2.6-thinking-ha`（要看截图或图片） | 写能直接对外的报告和文案、多步推理、复杂诊断 |
| 写代码 | `kimi-k2.7-code-ha` | 运行时要写或改代码的步骤 |

- 选定的档写进 FA：`model_name` 填所选模型，`model_selection_mode="required"`；不填时运行时按平台默认组解析，花费和效果都不受控制。
- **`max_turns`**：平台硬下限 5（小于 5 会被拒）。建议值按预估步数算：读输入 1 步 + 每次必需的工具调用各 1 步 + 每个落盘产出 1 步 + 提交 1 步，乘 1.5 向上取整，至少 8、至多 50；预估超过 30 步说明环节太大，先拆。
- 每次约多少积分以实测为准：FA 第一次实际跑后从 `get_project_execution_logs` 和 `cost_credits` 取这一步的花费（新 SDK 应用只能读到整次执行的，分不到单步，见入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)「积分」：整次执行只有这一个花钱的步骤时用整次执行的数，否则保留估算并注明分不到单步）；没测过的写「估算」。

## 一次运行里谁在做什么

- **项目**是一次运行的容器：对话、任务点、Runtime、交付物、日志都在里面。项目钉住场景包的具体物理行，包上线新版本后已运行的项目继续跑旧版。诊断以项目为单位，轮询、追问、读日志复用同一个 `project_id`。
- **业务路线 Runtime** 是确定性控制器：节点派发、字段映射、交付冻结都不经过模型；只有声明的中途表单、Agent 介入点和最终审阅会停下来。
- **时序**：入口表单提交 → 派发首批节点 → 节点 `stage_started` → 工具 / FA → `stage_result`（或 `stage_failed`）→ 全部节点完成 → 交付映射求值、文件登记（`artifact_ready`，平台自动）→ 冻结（`delivery_ready`，平台自动）→ 最终审阅。
- **失败是终态**：Runtime 不替脚本重试；重做、改稿、改路线都是开启新的运行实例并保留旧交付。写入步骤要经得起再执行一次（[脚本骨架与失败出口.md](脚本骨架与失败出口.md)）。
- **入口并存**：已发布路线在智能应用和聊天两个入口都能发起。聊天里由 SA 发起路线时业务事件照常记录；单独派发路线里的 TPE 时业务事件被抑制。制作侧不设计入口选择。
- **投影什么**：以使用者能回答「现在到哪了、出了什么、接下来会怎样」为准；阶段名用业务语言；要给使用者看的内容必须以业务字段出现在 `output` 里，界面读不到工作区文件正文。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 事实错误就扩 `_output`、加嵌套字段，或连续两轮原样重试 | 重判 FA、脚本、工具的职责，大结果改成文件或数据集引用 |
