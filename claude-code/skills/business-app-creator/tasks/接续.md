# 接续

## 识别信号

- 开发者说「继续」「接着做」「上次那个应用」，或当前目录已有 `app.json`、`WORKSPACE.md`、`workspace.json`。
- 开发者给了此前的 `task_id`、应用名或 `business_ui_id`。
- 开发者打开插件继续一个协作中的应用，或收到了提请属主上线、基线过期的站内信。

## 先读什么

1. 当前应用工程根的三件套：`WORKSPACE.md` 的 `current_stage` 与 `business_ui_id`（与 `app.json` 的 `id` 一个是数字、一个是带引号字符串时是同一个应用，见 [../reference/平台对象速查.md](../reference/平台对象速查.md#常见错误)），`workspace.json` 的阶段标记，`docs/stages/` 下当前阶段的阶段文档，以及交付物里的 PRD 与状态（方案页 `docs/proposal/index.html` 的 `status`；Studio 下用 `studio_read_creation` 读开发文档）。
2. 原工单：`task_manager(action="get", task_id=…)` 看已记的 checkpoint（资产 ID、版本、run_id）。原工单是只读或已结单时新建 write 工单并传 `continued_from_task_id`，`skill_version` 按 [../SKILL.md](../SKILL.md)「开工」建工单。
3. 协作状态：`business_ui_manage(action="get")` 看 `role`、待上线的提请和自己草稿的基线是否过期，处理完再接本轮改动：
   - 属主有待上线的提请：告诉开发者谁提请了哪份草稿、改了什么（用 `compare_asset_versions` 对比当前上线版，连同提请说明一起说），问他要不要上线；他看过并明确说「可以上线」后按 [../stages/5-上线.md](../stages/5-上线.md) 上线这份草稿（`draft_asset_id` 用协作者的草稿行），这一版成为属主自己的正式版，发不发布由属主决定。提请的草稿基线已过期时，告诉开发者要提请人先合并新版本。
   - 协作者草稿基线过期：先按 [修订.md](修订.md)「基线过期的合并」处理。
   - 协作者本地没有应用工程：用 `business_ui_bundle(action="download")` 取最新上线版（或自己要接着改的草稿）的源码包，解压到开发者中心分配的 `apps/<应用目录>/`，再按 [../SKILL.md](../SKILL.md)「开工」第 2、3 步核脚手架版本、补工作区文件。
   - 只读协作者：用 read 工单，按 [诊断.md](诊断.md) 做。
4. 本地缺失或换了机器：按 [../reference/开发者中心与工作区.md](../reference/开发者中心与工作区.md)「云端保存与换机」取回并合并，不默认用云端覆盖本地。
5. 脚手架版本：按 [../SKILL.md](../SKILL.md)「开工」核脚手架版本的做法核门槛，低于必须线先升级；缺失的工作区文件用 `npm run scaffold:repair -- --app-name "<应用名>"` 补，保留已有事实。
6. 本轮涉及文案或页面时，按 [../reference/前端页面.md](../reference/前端页面.md)「业务文案」只核受影响的场景；已有正确配置和定制保留，不用默认词覆盖，也不从零重做需求确认。

## 从哪一段进

- 做到哪一段按各段「交棒条件」判断：对照交付物的状态、`current_stage`、阶段文档和工单 checkpoint，从还没交棒的那一段接上；段内已 `passed` 的阶段不重做。阶段标记为 `not_started` 的，先读阶段文档里写的原因，再按交棒条件判断这次要不要做。
- 接上前核对它依赖的东西是否仍成立：PRD 已确认、当前整版方案已确认、资产还在、版本没被别人改、冒泡证据仍是当前合同下的；不成立就回到失效的那一段。
- 做到哪一段以 `workspace.json` 为准，没有工作区的从 ① 开始；工作区里的阶段名以已有的为准，按 G 键对应。
- 没有 PRD 的应用（Studio 下包括只有方案记录、没有 PRD 记录的）：已经上线的按 [修订.md](修订.md) 处理；还没上线的，先把已有材料补成 PRD 差异版（补上谁来用、每一步谁来做、花费上限和用量），Studio 下按 PRD（`documentType=prd`）交，请开发者确认一次，再从对应的段接上。已有的方案记录不当作 ② 已确认的方案，不凭它跳过 ① ②，也不改写它；工作区已有的方案页不删除、不改写。
- G6 既没有 ④ 验收报告、也没有开发者确认上线或确认预览的原话 checkpoint（「可以上线」或「确认预览没问题」这类等价说法都算）的，算 ④ 未验收，接到 ④ 或 ⑤ 时按 ④ 验收；开发者此前在在线预览里确认过的 G6 结论照旧保留，不重测。开发者说「可以上线」后才上线。
- 接上后先发一条交接消息，告诉开发者现在在哪一段、下一步、要他做什么。
- 开发者要看本地页面而「演示预览」是空的，按 [../reference/开发者中心与工作区.md](../reference/开发者中心与工作区.md)「演示预览与在线预览」判断。
