# 修订

## 识别信号

- 开发者要改已上线应用的页面、接口、表结构、路线、提示词或能力。
- 开发者按用户反馈报告要求改应用（先按 [../reference/用户反馈.md](../reference/用户反馈.md) 校验决定）。

## 先读什么

1. 建 write 工单，同样按 SKILL.md「开工」第 1 步带 `skill_version`；定位应用工程并按 [接续.md](接续.md) 核对本地与云端。
2. 看版本与角色：先 `business_ui_manage(action="get")` 看 `role`。属主用 `list_asset_versions` 看场景包、应用、模板各自的现役版本和有没有搁浅草稿。`viewer` 不能修订，转 [诊断.md](诊断.md)；`editor` 按 [../reference/多人协作.md](../reference/多人协作.md)「编辑协作者：修订路线」只改自己的草稿：应用的版本和草稿看 `get` 的返回，场景包、工具集、FA 等资产用 `get_asset` 和 `ensure_editable_asset_draft` 的返回看版本，不调 `list_asset_versions`（它对智能应用以外的资产只给资产属主）；新建或克隆资产时显式带 `collaboration_business_ui_id=<应用家族 ID>`，下面第 3 步起照做。
3. 取可编辑草稿：场景包 `scene_package_manage(action="ensure_draft")`，应用 `business_ui_manage(action="ensure_draft", change_note=…)`，其他资产 `ensure_editable_asset_draft`。应用建草稿必须带 `change_note` 写这次改了什么。对上线行直接 update 会自动派生草稿，之后一律用返回的 `draft_asset_id`。规则见 [../reference/部署与版本.md](../reference/部署与版本.md)。
4. 评估影响：共享资产用 `get_asset_usage_impact` 看谁在用；改表结构先看 [../reference/数据模板.md](../reference/数据模板.md) 的迁移规则；改 TPE 的输入输出会波及路线映射和页面。
5. 把改动写成 PRD 的差异版（只列这次改什么、影响哪些功能、谁来用和每一步谁来做有没有变、费用与用量有没有变、正在用的人会看到什么变化），用 `pv-changed` 标出，发开发者确认一次；只改文案、样式时在对话里说清改什么、确认一句即可。
6. 涉及文案、入口或产物时，按 [../reference/前端页面.md](../reference/前端页面.md)「业务文案」对照原配置、实际页面消费与真实业务事实。只改受影响部分，保留正确的显式覆盖；上传/发起/补充、受理/完成及有无产物分别核，不因模板兜底可运行就记业务通过。

## 从哪一段进

修订也走五段，每段只做和这次改动有关的部分：

| 改什么 | 从哪一段开始 |
|---|---|
| 业务规则、功能范围、谁来用、每一步谁来做 | ① 需求确认 |
| 换工具或模型、接新能力 | ① 需求确认（只核实受影响的步骤，PRD 差异版写清后果） |
| 做法变了，要开发者重新判断 | ② 方案（只重答受影响的判断题） |
| 脚本、提示词、路线、表结构、页面、后端接口，PRD 和方案都不变 | ③ 制作 |
| 只改文案或样式 | ③ 制作（本地 verify 后直接 ④） |

要上线的修订，④ 和 ⑤ 每次都要做，不存在「小改免验」：④ 的验收报告只验受影响的条目加一条完整主流程。编辑协作者在 ⑤ 提请属主上线，不自己上线应用。修订前后用 `compare_asset_versions` 取配置差异，写进上线结果给后续 Agent 的部分（见 [../stages/5-上线.md](../stages/5-上线.md) 第 3 节）；上线消息里写「正在用的人会看到什么变化，已有数据怎么处理」。

Studio 宿主：先用 `studio_read_creation` 分别按 `documentType="prd"`、`"proposal"` 核对当前 PRD 和方案的确认状态。改动在已确认范围内的，以宿主返回的当前确认状态为准，不自行增加确认步骤；要改 PRD 或方案的，按 ① 或 ② 照 `design/开发文档/` 的模板保存新的一版并请开发者重新确认；制作进度和验收报告照常按 ③ ④ 更新，④ ⑤ 照上面每次都做（[../reference/开发者中心与工作区.md](../reference/开发者中心与工作区.md)「Studio 宿主」）。
