# G5 后端业务闭环验证：确定"部件组合后能完成业务并留下正确事实"

> 阶段层文件。两个可辨认的子闭环：**G5a 执行闭环**（能力容器内的业务路线真跑）与 **G5b 应用数据闭环**（数据模板、后端、验证实例）。方法在 [P3](../modules/P3-执行形态与路线制作.md)（路线组装）、[P6](../modules/P6-验证与证据裁决.md)（全真）、[P4](../modules/P4-数据建模与回流.md)（数据）、[P5](../modules/P5-应用脚手架与页面实现.md)（后端）、[P7](../modules/P7-版本部署与上线.md)（能力容器定稿上线）。

## 1. 进入依据

所用单元已通过适用验收；数据与交互契约与 G3 一致。

## 2. 本阶段建设

**G5a 执行闭环**
1. 将已验单元装入业务路线；保存、反读、检查映射与依赖（P3 的 S3 §7；静态接缝检查）。
2. 路线 Bubble（P6 的 S4 §2.4）后，在获授权的真实项目中验证路线控制、真实模型 / 工具、业务表单、交付冻结与审阅（P6 的 S4 §3 真跑四步：建项目、绑数据、看运行、拿结果；身份口径：`orchestration_id` 取自路线定义、`business_id` 调用方生成且业务实例内不变、`workflow_runtime_id` 只由服务端生成）。
3. 达到能力容器自身标准并获授权后执行定稿上线（P7 的 S5）；场景包上线**不等于**应用已交付。

**G5b 应用数据闭环**
4. 建数据工作集、`create_table` 逐列 `[editable]` 注释、`inspect` 反读、`extract` 模板版本（P4 的 A2）。
5. 实现后端服务（P5 的 A3 §3：CRUD / 统计 / 回流；`buiTable`、幂等键、写权 `canWrite`、来源标记、`row_version`）。
6. 按平台前置条件准备 `business_ui` 草稿与最小验证部署物（P6 的 A4 §2–3），在真实应用实例验证：发起时带入 → 执行中取数 → 结果回流 → 编辑 → 再次读取。此时不要求完整界面，但不能缺实例与数据通道证据。

两条线可穿插，依赖次序由真实契约定。**能力容器在"无应用数据"的项目里跑通只证明该输入与回退路径，不能判 G5b 通过。**平台不允许提前提供测试实例时，记录 `platform_blocked` 并补能力，不把必需项豁免掉上线。

另须实现：异步任务定位、输入 / 产物 / 版本关联、幂等与冲突、部分失败恢复策略、错误归因、引用旧产物的权限与有效性。当前 Runtime 的重入方式优先使用；不承诺平台未验证的任意节点断点续跑。

## 3. 给开发者看什么

按业务节点排列的真实运行时间线；预期 / 实际路线对照；数据读入 / 写回前后对照；停止、恢复、部分失败记录。每个显示"完成"的节点都能指出实际成立的事实。

## 4. 要确认哪些边界

未取到必要数据时补充还是拒绝；部分成果是否可交付；哪些修改重用旧结果、哪些重算；历史结果与运行实例如何保留；后台持续执行与费用上限；越界临时请求如何转为新决策。

## 5. 门禁 Checklist（G5）

- `G5-01` U3 适用项逐条验证：齐备时连续执行、必要暂停有原因、补充后继续正确任务；核对真实路线的映射、介入、交付与审阅，不拼接单元日志。
- `G5-02` 从 U2-06 / U6-01 的实例记录能反查一次任务实际消费了哪份资料、哪个对象 / 周期，产物回到哪个实例 / 任务 / 版本；库里"有资料"不算已用上。
- `G5-03` 重复请求 / 回调、后端写权拒绝、并发版本冲突三类用例分别有结论；不只验前端禁用（U4-05/U6-01）。
- `G5-04` U4 离开、补充、结果未知、部分失败、重复请求、取消各有处理记录；关闭页面不取消任务；结果未知不盲重试。
- `G5-05` 交付完整性、文件可取用、业务审阅、外部动作回执分别核验（U5-01/U5-06）；无可靠回执的动作保持未知。
- `G5-06` U5 修改 / 版本保护与 U6 事实 / 偏好复用分别取证；可追溯 ≠ 会复用，保存偏好 ≠ 下次生效。
- `G5-07` 路线证据与应用数据证据分别闭合；实例缺失、数据通道未测明确阻断对应承诺。

## 6. 证据与结论

产出：路线真实日志、应用实例测试记录、数据库前后状态、版本关系、恢复与权限案例；按 [场景包验收检查清单](../checklists/场景包验收检查清单.md)（能力容器部分）与 [应用验收检查清单](../checklists/应用验收检查清单.md) 后端 / 数据面部分裁决；工单 `orchestration_runtime_verified`、`data_loop_verified`。

## 7. 失败回退

单元问题 → G4；路线 / 数据语义问题 → G3；真实能力不可用 → G2。

## 继承与调整

S3 路线 + S4 全真 + S5 容器上线 + A2 数据 + A3 后端 + A4 环境准备；把原来集中到最后的数据风险提前暴露。主责 P3 / P4 / P5 / P6 / P7。
