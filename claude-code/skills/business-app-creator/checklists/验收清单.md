# 验收清单（人判项）

机器能判的交给 `otpe_manage(action="verify")`、`npm run verify` / `npm run verify:release`、路线冒泡和结单门，这里不重复。下面是只能由你判断的项，④ 逐条写「通过 / 不适用」加一句依据，写进阶段文档 G6 与工单 checkpoint。页面上的项由你在本机版上用无头浏览器看，做法见 [../reference/开发者中心与工作区.md](../reference/开发者中心与工作区.md)「④ 本机版页面验收」；只有线上才能验证的和本机版起不来修不好的写「未测」和原因，**禁止**请开发者代测。

| 查什么 | 证据 | 不过怎么办 |
|---|---|---|
| 1. PRD「每一步谁来做」每一行都能在资产里找到：脚本步骤有脚本，模型步骤有 FA 且模型是 PRD 定的那一档，人的步骤有页面或表单 | 施工单与实际资产 ID、FA 模型配置对照 | 回 ③ 补 |
| 2. 使用者能走完每条路线：从入口到看到结果，中途要补的信息有地方补 | 真跑到终态的 `project_id`，加本机版上从入口操作到结果页的步骤和截图 | 回 ③ 修页面或路线 |
| 3. 每种人都能完成自己的事、看到 PRD「谁来用」写的东西 | 按每种人的验收条目的结论；要另一种人的账号才能看的部分写「未测」，原因写「只有线上才能验证：平台登录身份」 | 回 ③；少了一种人回 ① |
| 4. 结果看得懂：没有路线 ID、项目 ID、`PRJ-…` 任务标题、Runtime/编排等内部术语、字段名、原始 JSON 和原始时间串直接给使用者看；`npm --prefix frontend run check` 无「界面直接显示」警告 | 本机版截图、页面描述或本地布局回归截图 | 回 ③ 改展示 |
| 5. 「会停下的情况」真的按 PRD 发生：至少人为制造一次失败看表现 | 失败那次的 `run_id` 或 `project_id` 与页面表现 | 回 ③ 改失败出口 |
| 6. 模型步骤的输出用真实样例逐条读过一次，不只看形状；要人判断的条目已把实际结果附进验收报告「好不好你说了算」 | 真跑或 `full_run` 冒泡的输出摘录 | 回 ③ 改提示词、模型档位或输出字段 |
| 7. 数据管理页只开放使用者该改的列；系统和路线写的列只读并标来源 | 页面与列注释对照 | 回 ③ |
| 8. 只读权限下发起和写入入口都置灰并说明原因 | 用只读身份或 `permission='view'` 看一次 | 回 ③ |
| 9. 费用与副作用和 PRD 一致：没有多调工具、多发消息、多写正式数据；每个按钮实际花费和估算差得不多，差得多的已告诉开发者 | 真跑日志里的工具调用清单与 `cost_credits` | 回 ③，或回 ① 补确认 |
| 10. 用量：按 PRD 的用量上限（一次最多多少条）跑得完，超出时有提示 | 用接近上限的样例在 `workspace` 真跑一次的结果 | 回 ③ 改分批；做不到回 ① |
| 11. 离开再回来：关掉页面、换设备后任务和结果能找回，从正确位置继续 | 本机版里刷新、重新打开后的状态 | 回 ③ |
| 12. 验收报告和上线结果里每一句「通过」「已验证」都能指到证据，没验证的明确列出 | 报告与工单 checkpoint 对照 | 改报告 |
| 13. 空库也能用：没有数据时页面有引导或首次设置入口；上线后必须存在的设定不依赖预览数据 | 清空或换新工作集后的页面表现 | 回 ③ |
| 14. 按验收条目逐条验收：你按 ④ 2.3 照每条「照着做」做一遍，每条有「通过 / 没通过 / 好不好你说了算 / 未测」结论和怎么测的（「未测」只用于 ④ 写明的几种情况：只有线上才能验证的、本机版起不来修不好的、开发者还没同意部署而依赖已部署版本的，以及到点真触发、从目录或分享打开这两类要先发布才看得到的条目，都写原因）；看实际产出，不只看页面能打开、状态显示完成；页面条目的「通过」附本机版操作步骤和截图文件路径（或断言原文），没有就不算通过；读写应用库的条目只有冒泡证据的记「冒泡无法验证真实读写」，`workspace` 真跑并在开发工作集查到写入的行才算通过，判法见「④ 本机版页面验收」的「怎么判结论」 | 每条的结论、证据与部署编号 | 没过的回 ③ 改，改完重测这条和受影响的条目 |
| 15. 首屏与导航按使用者的业务任务组织：首页直接给目标、依据和下一步；导航顺序与完成业务的顺序一致；界面上没有 mock、运行状态、日志等平台信息 | 本机版首页与导航的截图，或开发者给的截图、本地布局回归截图 | 回 ③ |
| 16. 页面样子与 PRD「界面」一致：开发者给的参考网站、截图、原型都做到了，不是只换了品牌色和圆角的起始应用 | 参考图与本机版对应页面的并排截图，或逐条对照 | 回 ③ |

按应用类型追加：

- 有中途表单：挂着表单时再提交入口表单，界面给出「上一张表单还没完成」而不是改走新项目。
- 有写库路线：同一业务重复发起不产生重复行。
- 有文件交付：附件能在交付审阅页下载，内容是本次运行的产物。
- 有自动化：④ 用 `business_ui_automation(action="bubble")` 在开发工作集里跑一次，处理逻辑符合 PRD；到点真触发记「未测」，原因写「到点触发要等真实时间，且要发布后在正式入口开规则」，上线结果单列它，告诉开发者发布后在自动化面板开规则自己看。
- 有授权或充值：在本机版里走到付款或授权窗口出现为止，取消、关闭窗口后的页面表现照条目核对；真实授权和真实支付只有线上才有，记「未测」，原因写「只有线上才能验证：真实宿主桥接」。
