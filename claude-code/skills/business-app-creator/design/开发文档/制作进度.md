# 制作进度版式

③ 的进度在 Studio 里写成这一份 HTML，制作中反复更新。内容按 [../../stages/3-制作.md](../../stages/3-制作.md) 2.3 写：进度表、我先跑了一遍、页面说明、没做成的。页面开头用 [样式.md](样式.md)，写完按 [检查清单.md](检查清单.md) 自查。

## 各部分放什么

| 部分 | 放什么 | 组件 |
|---|---|---|
| 开头 | 应用名、一句话说明 | `.eyebrow`、`h1`、`.lead` |
| 本次更新 | 更新时间；这次变了什么，真实结果照实写（失败、受阻、没验证的不写成完成） | `.callout` |
| 完成数 | 做好的格数 / 总格数，右侧一句还剩什么；下面的进度条 | `.statline`、`.progress` |
| 进度表 | 每个功能一行：后台、页面、存数据 | `<table>`，格子按状态加类 |
| 我先跑了一遍 | 每个跑过的例子一个折叠：例子、为什么挑、用了什么、每一步、结果、花了多少用了多久 | `.sectiontitle`、`details.trial`、`.trialbody`、`.flow` |
| 页面说明 | 页面做完后，每个页面给哪种人用、显示什么、有哪些按钮 | `.sectiontitle`、`details.trial` |
| 当前遇到的问题 | 没做成的、卡住的：哪件事、原因、影响哪个功能、谁在处理 | `.callout.warn`；没有问题时整块删掉 |
| 页脚 | 下一步；更新时间 | `.footerline` |

### 格子怎么写

| 格子文字 | 类名 |
|---|---|
| 做好了，真跑过 / 做好了，只用模拟数据试过 / 做好了，等部署后真跑 / 做好了 | `good` |
| 在做 | `doing` |
| 没开始 / 不需要 | 不加类 |

- 「后台」一格只用上面三种「做好了，……」之一或「在做」「没开始」「不需要」；页面、存数据用「做好了」「在做」「没开始」「不需要」。
- **完成数**：总格数 = 表里所有格子减去「不需要」的；做好的 = 以「做好了」开头的格子数。`.statline` 写「做好的 / 总格数 项完成」，进度条 `--done` 写「做好的 ÷ 总格数」的百分数，四舍五入到一位小数。三处的数必须一致。
- 「我先跑了一遍」只放后台「做好了，真跑过」的功能（读写应用库的路线 ④ 真跑后补）。`.flow` 里一步一个 `<span>`：脚本步骤不加类，模型步骤加 `model`，停下等使用者的那一步加 `human`。
- 正文只写业务话；原始输出、日志、工具名放阶段文档 G4，不放这里。

## 什么时候更新

- ③ 开始时写第一份：列出方案里的全部功能，格子按实际状态写（多数是「没开始」）。
- 之后每个有实质进展的步骤完成、失败或受阻时更新一次（做好一个功能、跑完一次「我先跑了一遍」、出现或解决一个问题），同时发交接消息；不必每调一次工具就更新。
- 更新时在上一份 HTML 上**只改变化的部分**：变了的格子、完成数和进度条、新增的「我先跑了一遍」、问题区，以及「本次更新」和页脚的时间。其余内容原样保留，不重写整页、不改结构。
- 「本次更新」写更新时间（月-日 时:分）和这次变了什么；页脚右侧写同一个时间。不写「第几次更新」，版本以 Studio 保存的为准。
- 只更新制作进度，不顺带重写另外三份文档。交给 Studio 时 `documentType` 用 `progress`，见 [README.md](README.md)。

## 骨架

照抄下面的结构，把每个【填：…】换成真实内容。标着「重复」的块按实际数量复制，多余的删掉；`<!-- -->` 注释写完后全部删掉。

```html
<article class="sheet">
<div class="eyebrow"><span></span>【填：应用名】 · 制作记录</div>
<h1>制作进度</h1>
<p class="lead">各个功能做到哪了，以及我先跑出的结果。</p>
<div class="callout"><strong>更新于 【填：月-日 时:分】</strong>本次：【填：这次变了什么，例如「确认门店的页面做好了」；第一份写「开始制作，列出全部功能」】</div>
<div class="statline"><strong>【填：做好的】<span>/ 【填：总格数】 项完成</span></strong><span>【填：还剩什么，例如「还有 4 个页面在做」】</span></div>
<div class="progress"><div style="--done:【填】%"></div></div>
<table><thead><tr><th>功能</th><th>后台</th><th>页面</th><th>存数据</th></tr></thead><tbody>
<tr><td>【填：功能名】</td><td class="【填：good / doing / 不加类就删掉 class】">【填】</td><td class="【填】">【填】</td><td class="【填】">【填】</td></tr><!-- 重复：每个功能一行 -->
</tbody></table>
<p class="tiny">【填：和方案不一样的地方，一处一句；没有就写「和方案一致」】</p>

<div class="sectiontitle"><h2>我先跑了一遍</h2><span class="evidence">【填：一句总的，例如「跑了 3 个例子，都和方案说的一样」】</span></div>
<!-- 重复：每个例子一个 details.trial；还没有跑过的功能时，这里写一行 <p class="bodytext">后台做好并真跑后，在这里放结果。</p> -->
<details class="trial"><summary><span>【填：例子】<small>【填：为什么挑这个】</small></span></summary>
<div class="trialbody"><p>用了什么：【填：入口填了哪些、哪些空着】</p>
<div class="flow"><span>【填：步骤】</span><i>→</i><span class="model">【填：模型步骤】</span><i>→</i><span class="human">【填：停下等使用者的步骤】</span></div>
<p>每一步：【填：逐步一句结果】</p><p>结果：【填：拿出来的东西摘要；和方案的预期一样不一样】</p><p>花了多少、用了多久：【填：实测】</p></div></details>

<div class="sectiontitle"><h2>页面说明</h2></div>
<!-- 页面还没做完时，这里写一行 <p class="bodytext">页面做好后在这里说明。</p> -->
<details class="trial"><summary><span>【填：页面名】<small>【填：给哪种人用】</small></span></summary><div class="trialbody"><p>【填：显示什么、有哪些按钮】</p></div></details><!-- 重复 -->

<div class="sectiontitle"><h2>当前遇到的问题</h2></div>
<div class="callout warn"><strong>【填：哪件事没做成或卡住了】</strong>【填：原因、影响哪个功能、谁在处理、什么时候能继续】</div><!-- 重复；没有问题时删掉这个标题和这一块 -->

<div class="footerline"><span>下一步：【填】</span><span>更新于 【填：和「本次更新」同一个时间】</span></div>
</article>
```
