# 定性边界：平台能不能

拆完步骤、逐步对照「能不能」时读。每一行写边界本身、需求撞上它时常见的变形，和细则在哪个 Skill。这里只汇集，不另立规则；细则以右列 Skill 为准。

## 使用者与数据

| 边界 | 撞上时常见的变形 | 细则 |
|---|---|---|
| 平台没有组织和团队；一个应用里没有提交、审核、复核这类多人分工 | 能由使用者本人做的写成他自己的一步（「自己确认后再生成」）；另一个人的动作是刚需时出选择题（由其中一人用 / 这一步这次不做），不设计成多人流程、不承诺权限 | `agenticapp-stage-1-requirements` |
| 每个使用者安装后用自己的一份，从空库开始，数据互不相通，不能把一条记录交给别人接着做 | 「谁来用」只写一种使用者；空库首次打开做引导或首次设置 | 入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md) |
| 预览里产生的数据不进正式版，平台没有迁移数据的机制 | 上线后必须存在的设定写成代码默认值、场景包配置或首次设置入口 | `agenticapp-tool-data-template` |
| 每列恰好一个写入方（使用者 / 路线 / 系统） | 使用者和路线都要写的信息拆成两列（使用者填的 + AI 建议的） | `agenticapp-tool-data-template` |
| 表结构只走数据模板，应用代码不建表改表；每个应用挂且只挂一份模板，至少一张业务表；换绑到另一个模板家族等于换库，不允许；模板没有降级 | 需要新库就新建应用；回到旧结构要重新抽成新版本 | `agenticapp-tool-data-template` |
| 写连接经数据集代理，事务语句、`SET ROLE`、`SET search_path` 都会被拒 | 要原子性就压进一条 SQL | `agenticapp-tool-workflow` |
| 场景包单独运行时没有应用库 | 读库的地方按「没有数据」收口 | `agenticapp-tool-workflow` |

## 长期数据集

| 边界 | 撞上时常见的变形 | 细则 |
|---|---|---|
| 编排里的 FA 读不到长期数据集，只看得到名字 | 由脚本用 `shell` 的 `ds-cli` 读出来，再交给 FA | `agenticapp-tool-workflow` |
| 读权限按运行应用的使用者算，没被分享的人读不到 | PRD 写明所有者要先把数据集分享给使用者 | `agenticapp-tool-workflow` |
| 新 SDK 应用不能依赖开发者个人的普通数据集 | 只用应用自身的实例数据和官方、公开数据集 | `agenticapp-tool-workflow` |

## 页面与应用后端

| 边界 | 撞上时常见的变形 | 细则 |
|---|---|---|
| 页面只经 SDK 和平台交互，调后端走 `sdk.api.request`；失败不静默、不自动重试 | 页面给使用者反馈并留重试入口 | `agenticapp-tool-frontend` |
| 专属后端是 Express + PG，直连这个使用者自己的库；无人访问时会休眠（可能缩容到 0），冷启动会拖慢执行 | 执行路径优先读写数据集、少调后端；自动化不指望到点时后端在线，路线自给 | `agenticapp-tool-workflow`、`agenticapp-tool-automation` |

## 路线怎么运行

| 边界 | 撞上时常见的变形 | 细则 |
|---|---|---|
| 模型步骤（FA）不能和使用者来回对话 | 能预知的输入放入口表单；上游成功后才知道的用中途表单；结果用审阅确认 | `agenticapp-tool-workflow` |
| 平台不会自动重试，失败是终态 | 「做不成怎么办」写成停下告诉使用者 / 标记状态继续 / 重试一次；新 SDK 应用由使用者点重试，会重跑失败节点全部步骤，外发步骤要防重复 | `agenticapp-tool-workflow` |
| 新写和修订的路线都不能转交 Agent（`agent_gate`、`sa_handoff`）：新 SDK 应用没有运行 Agent，旧应用审阅里的「转交 Agent」之后也会被平台拒绝 | 能用规则判断的写进脚本；好不好由使用者审阅；存量旧路线里的转交，修订时一并改掉 | `agenticapp-tool-workflow` |
| 改稿、重做、换路线是开启新的运行实例，旧交付保留 | 审阅加跳转动作或修正路线，不画回边 | `agenticapp-tool-workflow` |
| 同一使用者的多次执行可能同时改同一条数据，平台只保证同一执行内部串行（新 SDK 应用） | 会冲突的写库用唯一约束或幂等键兜住 | `agenticapp-tool-workflow` |
| 运行中的执行数、单次执行的状态记录数都有上限（新 SDK 应用报 `EXECUTION_LIMIT_REACHED`、`EXECUTION_STATE_LIMIT`），具体数字没有写 | 减少同一执行里的重试、修正次数，改成新开执行；批量放进一条路线 | `agenticapp-tool-workflow` |
| 单次运行有时长上限，只有冒泡有数字 | 见 [还没有数字的项.md](还没有数字的项.md) | `agenticapp-tool-workflow` |
| 已发布路线在应用和聊天两个入口都能发起；聊天里发起路线时业务事件照常记录，单独派发路线里的 TPE 时被抑制 | 制作侧不设计入口选择 | `agenticapp-tool-workflow` |
| 文件读写、命令执行、邮件发送是任务点和编排型 TPE 自带的 | 不当成工具缺口去建工具集 | `agenticapp-tool-workflow` |

## 自动化

| 边界 | 撞上时常见的变形 | 细则 |
|---|---|---|
| 只在应用发布后可用（开发者本人也一样）；到点真触发要发布后在面板开规则，MCP 不提供规则的创建与暂停 | ④ 用 `validate` / `bubble` 验处理逻辑，到点真触发记「未测」 | `agenticapp-tool-automation` |
| 自动发起时没人答题：入口必填字段都要有来源，不能有文件字段，路线里不能有中途表单和 `sa_handoff` | 路线第一个节点自己取数、建记录；中途判断改成规则或 FA 判断；做不到的只能人工发起 | `agenticapp-tool-automation` |
| 事件触发只看使用者实例库，开发工作集里的写入不触发；有每小时上限和排队上限，一条语句批量改很多行时只有前面一部分逐条触发；暂停期间的变化不补跑；触发记录过大时不带内容 | 批量导入改成定时触发；单次运行要短；大字段改成按主键查库 | `agenticapp-tool-automation` |

## 外部平台

| 边界 | 撞上时常见的变形 | 细则 |
|---|---|---|
| 每个使用者用自己的第三方账号授权；授权只对本应用及其项目生效，预览和正式不共用 | 配授权卡；上线结果写明使用者要授权哪些平台 | `agenticapp-tool-integration` |
| 有些工具不能取样（哪些见 `agenticapp-tool-integration`「哪些不取样」），只能按参数说明判断 | PRD 写「能做，没真发过」，④ 只发给开发者自己试一次 | `agenticapp-stage-1-requirements` |
| 充值要平台开通（`get_recharge_config` 返回启用）；协作者的预览不能用充值 | 没开通就写「充值暂不可用」 | `agenticapp-tool-integration` |
| 分享来的资产，分享人收回或改动后用到它的步骤会停；看不到参数的是权限脱敏 | PRD 写明这个风险；第一次实际跑时核实 | `agenticapp-tool-integration` |

## 复用与发布

| 边界 | 撞上时常见的变形 | 细则 |
|---|---|---|
| 平台没有「包引用包」；官方或他人的资产要先克隆再改 | 跨包复用走共享资产 | `agenticapp-tool-workflow` |
| 正式使用、到点自动运行、使用者打开，都要先上线再由开发者发布；发不发布由开发者决定 | 制作和验收只用在线预览和 `workspace` 实际跑 | `agenticapp-tool-deploy` |
