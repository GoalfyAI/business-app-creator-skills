# 制作进度：数据说明与完整样例

写 `docs/studio/progress/data.json` 时照这里写，生成用 `build_studio_doc.mjs progress`。**写什么**按 `agenticapp-stage-3-build` 的[制作进度怎么写](../../agenticapp-stage-3-build/references/制作进度怎么写.md)；进度消息照常在聊天里发，这份文档和消息在同一条回复里更新，格子状态和完成数一致。进度表、「我先跑了一遍」、页面说明、没做成的说明只在消息里写，文档里不放。

页面只有三块：当前在做什么（完成数和进度条由脚本按功能格子算）→ 制作时间轴（可回放）→ 时间轴下面折叠的「交付范围与待明确条件」（每个功能的三格、和方案不一样的地方、还要明确的条件）。

**时间轴只写真实发生过的事**：时间从工作记录（阶段文档、checkpoint）里取，不估、不补；还没做的写 `todo`、不写时间。回放只是把已有记录按顺序亮一遍。

## 字段

| 字段 | 必填 | 写什么 |
|---|---|---|
| `app`、`version`、`updated`、`changes` | 是 | 同需求说明；`changes` 写这次更新变了什么 |
| `state` | 是 | `working` 在做 / `done` 方案里的功能都做好了 / `blocked` 卡住了（时间轴上要有一条 `blocked` 事件） |
| `now.title / detail` | 是 | 现在在做什么，一句标题加一句说明 |
| `next.title / detail` | 否 | 下一步 |
| `features[]` | 是 | 方案里的全部功能，一个不漏：`name`；`backend` 只写 `做好了，实际跑过` / `做好了，只用模拟数据试过` / `做好了，等在线预览时实际跑` / `在做` / `没开始` / `不需要`；`page`、`data` 只写 `做好了` / `在做` / `没开始` / `不需要`。判定按「制作进度怎么写」的进度表规则 |
| `events[]` | 是 | 时间轴：`time`（`14:20` 或 `11-05 14:20`）、`title`、`detail`、`status`（`done` / `doing` / `todo` / `blocked` 受阻）、`steps[]`（小步骤，同样三个字段）。受阻的 `detail` 写卡在哪、影响哪个功能、谁在处理、什么时候能继续；整份卡住时 `state` 再写 `blocked`。跑过一次「我先跑了一遍」就记一条，`detail` 一句话写跑了什么、结果和预期一样不一样 |
| `diffs` | 否 | 和方案不一样的地方，一条一句 |
| `pending[]` | 否 | 还要明确的条件：`what` `affects`（影响什么） |

## 完整样例

```json
{
  "app": "库存预警",
  "version": 4,
  "updated": "2026-11-05 14:20",
  "changes": ["「每天出清单」后台做好了，用测试数据跑了 4 次", "首页正在做"],
  "state": "working",
  "now": {"title": "正在做首页「今天的清单」", "detail": "三个数字和快过期列表已经出来，正在做按供应商分组。"},
  "next": {"title": "食材页", "detail": "做完首页接着做。"},
  "features": [
    {"name": "录入进货批次", "backend": "不需要", "page": "做好了", "data": "做好了"},
    {"name": "每天出清单", "backend": "做好了，实际跑过", "page": "不需要", "data": "做好了"},
    {"name": "看今天的清单", "backend": "不需要", "page": "在做", "data": "做好了"},
    {"name": "管理食材", "backend": "不需要", "page": "没开始", "data": "做好了"}
  ],
  "events": [
    {"time": "11:32", "title": "开始制作", "detail": "列出 4 个功能，存下数据表。", "status": "done",
     "steps": [{"time": "11:32", "title": "建好 5 张表", "status": "done"}]},
    {"time": "12:10", "title": "每天出清单做好了", "detail": "按规则算三组结果，用测试数据跑了 4 次，和手算一致。", "status": "done"},
    {"time": "12:25", "title": "先跑了一遍每天出清单", "detail": "用 11 月 5 日的测试数据：快过期 1、该补货 2、缺货 1，和预期一样；每次 0 积分，约 2 秒。", "status": "done"},
    {"time": "14:20", "title": "正在做首页", "detail": "三个数字和快过期列表已经出来。", "status": "doing",
     "steps": [{"time": "14:05", "title": "三个数字和快过期列表", "status": "done"}, {"time": "14:20", "title": "按供应商分组", "status": "doing"}]},
    {"time": "", "title": "食材页", "detail": "做完首页接着做。", "status": "todo"}
  ],
  "diffs": ["清单保留 90 天（需求说明没写保留多久，按默认定的）"],
  "pending": [{"what": "后厨是否共用一个账号", "affects": "验收时按一个人用还是几个人共用来测"}]
}
```

## 容易写错的

- 第一份就写成「做好了」：③ 开始时第一份多数格子是「没开始」，这一份在建任何东西之前保存。
- 只在 ③ 结束时写一份：每做好一个功能、跑完一次「我先跑了一遍」、出现或解决一个问题就更新一次。
- 照旧写 `trials`、`pages`、`problems`：脚本会拦，并告诉你改写到哪；这些内容在聊天的进度消息里照常写。
- `state` 写 `done` 但还有格子没做好：脚本会拦；`done` 也不等于验收通过。
