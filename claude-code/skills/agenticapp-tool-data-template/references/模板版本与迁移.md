# 模板版本与迁移

改已上线应用的表结构、出模板新版本、写迁移脚本、处理 `extract` 和部署里与模板有关的错误时读。

## 规矩

改结构的流程（缺列加列、新增优先、不换模板家族）见 SKILL.md「改已上线的模板」，工作集为什么一直绑定见 SKILL.md「开发工作集」。这里补两条做法：

- **就在绑定到应用的那个工作集上改**：用 `connect` 取写连接，`CREATE TABLE IF NOT EXISTS` / `ALTER TABLE … ADD COLUMN IF NOT EXISTS`（幂等），再从它 `extract`。开发者的预览容器直连这个工作集，里面有开发期数据，平台不会替它迁移结构。
- 应用有协作者时，改结构前先核对模板基线并和其他人协调，见 `agenticapp-role-collab`；修订流程见 `agenticapp-task-revise`。

## 出新版本时的基线

给已有模板出新版本时 `extract` 传 `template_id`，并带 `expected_base_version`：开始改结构前先从 `inspect`（或 `open`、`connect` 的返回）读出模板当前的 `template_version`，原样填入。

## 默认值变更与破坏性变更

| 变更 | `extract` 怎么带 | 存量实例怎么升 |
|---|---|---|
| 只改默认值（`ALTER COLUMN … SET DEFAULT`） | 增量，`extract` 不收脚本；响应 `diff.defaults_changed` 逐列列出旧值 → 新值 | 平台自动 `SET DEFAULT` |
| 删列、改类型等破坏性变更 | 必须带 `migration_script`：幂等、单事务、只动本 schema、不建外键 | 开发者发布时平台在临时库彩排，上线不彩排；只往前升，没有降级 |

迁移脚本怎么写由你定。会改变使用者已有数据或页面行为的（例如删掉一列使用者填过的内容、改了类型后旧值显示不同），是破坏性改动，开工前按 `agenticapp-task-revise` 列差异请开发者定。

## 错误码

| 错误码 | 含义 | 处置 |
|---|---|---|
| `TEMPLATE_WORKSPACE_EMPTY`（`extract`） | 工作集里没有业务表：零张表，或只有平台维护的系统表 `app_write_requests` | 回 PRD「会记下来的东西」和开发者定下要存的表，`create_table` 建好再 `extract` |
| `TEMPLATE_BASELINE_REQUIRED`（`extract`） | 给已有模板出新版本没带 `expected_base_version` | `inspect` 读出当前 `template_version`，确认它就是这次改结构的起点后填入重调；仍在原模板上出新版本 |
| `TEMPLATE_BASELINE_CHANGED`（`extract`） | 从你开始改结构到抽取之间，别人已抽出更新的版本 | 重新 `inspect`，核对对方加的表列和你的改动都在工作集里（缺了先补，对方的结构保留），用新的 `template_version` 作 `expected_base_version` 重新 `extract` |
| `create_table` / `extract` 被拒（不带码） | 看返回的列与 diff | 破坏性变更要带迁移脚本 |
| `BUSINESS_UI_WORKSPACE_BEHIND_TEMPLATE`（`ship`） | 绑定的工作集缺草稿钉定模板版本的表或列；`metadata.missing` 逐表点名，`metadata.data_uid` 是这个工作集 | 按 `metadata.next_action`：对这个 `data_uid` `connect` 取写连接，用幂等 DDL 补齐缺的表和列（列注释带 `[editable:…]`），`inspect` 核对后重新 `ship`；工作集保持绑定 |
| `BUSINESS_UI_PREVIEW_DATA_UNBOUND`（`ship`） | 开发工作集被解绑了 | 重新 `bind` 回原工作集再部署；应用的上线、下线状态不动（不为此上线派生草稿、下线或删除应用） |
| `TEMPLATE_WORKSPACE_IN_USE_BY_DEPLOYMENT`（`close`） | 还有部署跑在这个工作集上，`metadata.holders` 点名 | 开发工作集本来就不 close；保持绑定，接着做原来的事 |
| `BUSINESS_UI_TEMPLATE_REQUIRED`（发布） | 带代码包的应用发布时没挂数据模板 | 回 ③ 建表并 `extract` → 挂模板并绑工作集 → 重新部署（模板进指纹）→ 上线 → 开发者再发布 |
| `BUSINESS_UI_TEMPLATE_SWITCHED` | 换绑到另一个模板家族（等于换库） | 不允许；需要新库就新建应用 |
| `BUSINESS_UI_TEMPLATE_UPGRADE_PATH_BROKEN`（发布） | 模板升级链缺迁移脚本 | 回 ③：破坏性变更的 `extract` 带上 `migration_script` |
| `BUSINESS_UI_TEMPLATE_REGRESSION` | 回滚钉回了更老的模板版本 | 没有降级：把旧结构重新抽成一个新版本再挂 |
| `BUSINESS_UI_UPGRADE_REHEARSAL_FAILED`（发布） | 迁移脚本在临时库彩排失败 | 按返回的错误修脚本，重新 `extract`，改挂后重新部署并上线，开发者再发布 |

`BEHIND_TEMPLATE` 起因是另开了空工作集抽新版本的，见 SKILL.md「常见错误」。
