# 表与列的设计

② 列表清单、③ 建表前读：数据放哪、入口字段放哪、每张表回答的五问、列注释和默认值怎么写。

## 数据放哪

| 类别 | 例子 | 放哪 |
|---|---|---|
| 使用者自己的数据 | 门店档案、账号绑定、禁用表达、偏好 | 模板表，列 `editable:user` |
| 路线读写的字段 | 每次运行的结果、效果指标、回写的统计 | 模板表，列 `editable:agent` |
| 系统字段 | 主键、关联 id、审计列 | 模板表，列 `editable:system` |
| 界面意图 | 草稿、筛选条件、已读态 | `sdk.storage`，不进库 |
| 文案、开关 | — | 代码 |

- 该进库的数据都进模板表，不写成前端 mock 数组、静态 JSON 或后端常量。文件只存路径、文件名、时间，不存文件体。
- 新 SDK 应用的数据能从哪来，见 `agenticapp-tool-workflow`「编排脚本的额外约定」；旧应用读开发者的长期数据集要先分享给使用者，见 `agenticapp-tool-workflow`「读长期数据集」。
- 「××档案场景包」是目录里的另一条产品线，不是应用库；存使用者数据不去挂它。

## 入口字段放哪

② 编施工单时，路线的每个业务输入按下表判断，同一个值只走一边：

| 这个值 | 放哪 |
|---|---|
| 使用者这次发起时才给的（新店名、这次的要求、上传的文件） | 入口表单字段 |
| 应用库里已经有的（前一条路线存下的、使用者在页面上确认或改过的、首次设置里填的） | 入口只放业务键，脚本按键读库（写法见 `agenticapp-tool-workflow`「读写应用库」） |
| 所有人一样、不随每次变的设定 | 代码默认值或场景包配置，不进入口 |

同一个值不既放入口又读库（不写「入口传了就用、没传再查库」）。库里已有的信息不由应用后端拼进发起报文。③ 反读自查的第四项按这张表核。

## 每张表回答五问

1. **存什么**：看板要算的指标所需字段现在就要有。
2. **逐列可编辑性**：每列 `comment` 以 `[editable:user|agent|system] ` 开头再写中文名，选项列加 `{options:a|b|c}`。每列恰好一个写入方：使用者和路线都要写的信息拆成两列（使用者填的 + AI 建议的），不靠运行时仲裁。漏写注释的列按最保守的 user 处理，路线写不进去。
3. **审计**：有写入的表带审计列，都是 `system`，按下表声明。脚手架 `createCrudService` 建行只填业务列和 `updated_by`，更新只改业务列并自动带 `updated_at`、`row_version + 1`，所以 NOT NULL 的审计列必须在库里有默认值；平台不替你补，`gen:pages` 会在生成前检查并拒绝缺默认值的表。

   | 列 | `type` | `nullable` | `default` |
   |---|---|---|---|
   | `created_at` | `timestamptz` | `false` | `CURRENT_TIMESTAMP` |
   | `updated_at` | `timestamptz` | `false` | `CURRENT_TIMESTAMP` |
   | `updated_by` | `varchar(16)` | `false` | `'system'` |
   | `last_run_id` | `varchar(128)` | `true` | 无 |
   | `row_version` | `integer` | `false` | `1` |
   | `deleted_at` | `timestamptz` | `true` | 无 |

4. **冲突**：使用者和路线同时改一行靠 `row_version` 乐观锁，后写方重读重试；没有静默覆盖。
5. **回流**：路线产出直接入库，还是先作草稿等使用者确认后入库，按业务风险定，写进 PRD。

## 建表时的列规则

- 每表至少一列 `primary_key=true`，代理主键用 `bigserial`；类型写 PG 精确类型。
- 列的 `default` 原样写成 PG DEFAULT 并进模板，只接受字面量、`true/false`、`NULL`、数字、`CURRENT_TIMESTAMP`、`now()`、`gen_random_uuid()`。
- 同一业务要「更新原记录」的，业务键在模板里建唯一约束：`INSERT … ON CONFLICT` 的冲突目标必须是模板里已有的唯一约束，否则直接报错。
- 多个执行可能同时改同一条业务数据（新 SDK 应用里平台只保证同一执行内部串行），会冲突的写库用唯一约束或幂等键兜住。
- 每个应用至少一张业务表，只展示的应用也要存数据快照、收藏或查看记录等；表都要有业务用途。
