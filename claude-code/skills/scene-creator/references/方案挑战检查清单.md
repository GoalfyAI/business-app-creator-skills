# 方案挑战检查清单

> 本文是 `SKILL.md` 的方案审查指南。业务蓝图形成、任何资产创建之前读取；没有真实资产证据时不得礼貌性判定通过。

---

本清单承接 Max `csp_battle_reviewer` 的职责。外部 Agent 在创建资产前直接执行，不调用 FastAgent。

## 证据

先用 `list_assets`、`get_asset` 和按需的 `dataset_read` 核对真实资产，再判断方案。输入至少包括用户目标、使用角色、业务里程碑、拟复用或新建的场景包、Workflow、FA、Toolset、Tool Group、数据集和业务档案。禁止凭名称、历史对话或记忆推断资产能力。

## 必查项

### 业务完整性

- 解决的是稳定、可复用的业务问题，而不是固化一次性项目。
- 主流程、异常路径和最终交付完整；每个阶段有明确输入、输出和责任方。
- 授权、外部写入、通知、邮件、发布和收费等高风险动作有用户确认与 `ctx.dry_run` 护栏。

### 工具、数据和资产闭包

- 每个里程碑都有真实工具或 FA 支撑，参数和能力匹配。
- 所需 Toolset、Tool Group、FA、Workflow、数据集和业务档案会实际挂载；不能假设用户可能拥有。
- 数据源名称与绑定资产一致，不存在引用缺失或无用途的冗余绑定。
- 不依赖创建者本地路径、外部 Agent 沙箱或其他 Max 项目的临时文件。

### Workflow、普通 TPE 和 FA 选型

- 稳定、重复、无需临场判断的多步流程优先 Workflow。
- 只有内容判断、归纳和写作等确需大模型的步骤才使用 FA；确定性搜索、取数、转换和发送直接调用工具。
- 只调用一个 FA 后原样返回的是空壳 Workflow，应直接使用该 FA。
- Workflow 输入能由用户、业务档案或上游 Workflow 提供，输出是用户或下游真正需要的稳定对象。
- 只有依赖顺序固定时才配置多 Workflow DAG；路线需要临场规划时交给 Agent。

### 鲁棒性和运行时 Skill

- 数据缺失、格式变化、工具失败和外部系统变化有明确失败或降级规则。
- `apc_skill` 包含业务里程碑、权限边界、操作策略和必要系统认知，不含数字资产 ID、制作说明或第二份 DAG。
- Toolset Skill、FA Prompt 与真实工具一致，不使用会让 Agent 自由发挥的泛化描述。

## 输出

输出并写入工单简洁检查点：

- `关键问题`：位置、后果、精确修改办法；未解决前不得创建。
- `改进建议`：不阻断但会影响稳定性或质量的问题。
- `确认项`：证据不足或属于业务取舍的问题，由用户决定。
- `证据`：审查视角和实际读取的资产 ID。

不得把方案挑战写成运行验证，也不得礼貌性判定通过。
