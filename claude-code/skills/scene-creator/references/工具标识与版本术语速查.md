# 工具标识与版本术语速查

（自路由器 8.1 / 8.2 搬入；路由器只留一段总述。）工具名、action、参数名与必填项**以你看到的工具定义为准**，本文只解决“这个标识指向什么”和“这四个版本术语怎么用”。

## 一、出现在工具调用里的标识

这些是工具真实接受的参数名和标识，**以你看到的工具定义为准**：

- 工具名、action 名、参数名和必填项
- 业务路线对象的结构、节点引用、字段映射、路径与类型
- 工单模式与 Skill 版本
- 各类标识，注意不要混用：

| 标识 | 指向 |
|---|---|
| `task_id` | 工单审计范围，**不是**资产 |
| `scene_package_id` | 场景包 |
| `tpe_id` | 任务点，普通任务点和编排型 TPE 共用同一套编号 |
| `toolset_id` / `tool_group_id` / `tool_id` | 依赖资产 |
| `mcp_id` | 授权卡绑定用，**不是** `tool_group_id` |
| `run_id` | 运行验证实例，轮询时复用 |
| `project_id` | 真实项目，查询、追问、读日志时复用 |
| `deployment_id` | 界面构建发布任务 |
| 编排型 TPE 脚本里的工具名 | 用线上真实名称，**不用**资产数字标识 |

写错了调用会失败并返回结构化错误。此时**必须**按报错更正参数或条件后重试，**禁止**自行发明兼容字段（见 `stages/SD-诊断与维护.md`）。

## 二、版本体系的四个术语

场景包与各类资产进入统一版本体系后，以下概念**必须**区分（详见 [场景包版本体系与发布逻辑](references/场景包版本体系与发布逻辑.md)）：

| 概念 | 含义 |
|---|---|
| 家族 | 同一个"场景包"对外的稳定身份；家族内每个版本是独立物理行（独立 ID） |
| 物理行 | 一个具体版本对应的资产行；版本引用指向具体物理行 |
| 草稿态 | `testing` 状态的物理行，未上线；制作、修改与全部验证在草稿行上进行 |
| 上线 | 定稿并真正上线（`testing → live` 且对最终用户可运行）；全真验证通过是其前置 |

本文与各阶段文件**禁止**用"发布"指代上线动作；面向外部市场的发布链路不属于制作工具面，不在本 Skill 表述范围内。

## 补充：TPE 两型与业务路线（2026-09-05）

| 说法 | 指什么 | 标识符里怎么写 |
|---|---|---|
| 普通 TPE / 任务点 | 派给 TaskAgent 临场执行的任务模板 | `tpe_type` 为 `custom` / `predefined` |
| 编排型 TPE（O-TPE） | 确定性脚本型任务点，旧称 Workflow | `tpe_type=workflow`；工具 `otpe_manage`；事件 `WORKFLOW_*` |
| 业务路线 | 把多条编排型 TPE 串成客户能发起的一件事，旧称"业务路线编排" | 场景包字段 `workflow_orchestration`，契约区 `schema/orchestrations/`，一条路线 = `orchestrations[]` 的一项 |
