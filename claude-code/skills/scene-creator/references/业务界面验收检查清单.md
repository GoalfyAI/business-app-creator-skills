# 业务界面验收检查清单

> 仅在用户已选择制作业务界面，且界面完成本地交互检查并取得部署终态后读取。用户未选择制作时不读取本文，也不把缺少界面列为场景包问题。验收依据是当前场景包和 Workflow 资产、实际源码包、模板检查结果与部署终态；**页面能打开、请求已受理，都不能代替这里要求的证据**。

- Workflow 制作前已形成 `ui_predesign_brief`，覆盖用户旅程、模块决策、状态—行动矩阵和业务节点—事件—界面响应；最终实现使用的是 Workflow、Schema、事件和顶层编排稳定后冻结的 `ui_design_brief`，没有边写 Workflow 边编码界面。

---

## 绑定与契约

- `goalfy-app.json.scenario_pack_id` 等于本工单的真实场景包 ID。
- 当前场景包至少挂载一个真实 Workflow；纯 SA 或只有普通任务点的场景包没有绕过当前 UI 工具门槛。
- 已形成 `ui_design_brief`：场景—界面映射表、页面地图、模块决策账本、状态—行动矩阵和关键交互样例；每个核心模块都能追溯到场景事实。
- 界面涉及的 Workflow 输入输出、业务事件契约、公开业务语义、orchestration/form 定义来自当前线上资产和已确认方案，不来自 Demo、历史文档或记忆。
- 单路线和多路线都使用宿主公开的 Business/Runtime 启动、状态、交互和 Delivery Review 能力；页面不直接运行 Workflow。
- 编排形状来自实时 Schema 和版本化服务端契约，没有混入设计稿、集成分支或旧资产中的未来字段。
- `schema/orchestrations/` 和 `schema/forms/` 只包含本场景包真实公开契约，文件名分别与 orchestration/form ID 一致；不存在演示契约或 v1 遗留 Workflow 快照。
- 记录的 `ui_contract_snapshot` 与部署时场景包、Workflow、业务事件和 orchestration 版本一致。
- 开发前和本次部署前均已反读当前 TPE 的输入/输出 Schema、业务事件契约、Workflow 脚本版本/摘要和顶层编排契约，并与 `schema/orchestrations/`、`schema/forms/`、业务事件契约快照、页面渲染逻辑及 `ui_contract_snapshot` 逐项比较。
- 若输入、输出、业务事件、路线、用户/Agent 介入、里程碑或交付语义有变化，已更新业务界面契约和实现并重新验收；仅脚本实现变化时，也已更新快照并回归主路径。
- 无法证明新旧契约兼容时已停止发布；界面不使用旧 Schema 迁就新 TPE/编排，也不复制、执行或展示编排脚本。
- 页面发现契约缺失、编排版本或公开 ID 漂移、不兼容时停止结构化提交并回落聊天，不自行补字段。

## 源码与 SDK 边界

- 开发起点有本工单 `download_template` 的成功响应；模板实际字节数与响应一致，且安全解压到新的独立目录。
- 唯一开发目录由 `goalfy-app.json` 定位，不是其他脚手架、代码仓库克隆、历史模板或手工空目录。
- 根 `AGENTS.md`、`README.md`、`schema/README.md` 和 `src/sdk/docs/README.md` 已完整读取；`template_identity` 不含下载短链。
- 业务代码只修改模板允许的页面和组件；固定 SDK、启动、桥协议和错误边界未被绕过。
- 平台能力只通过当前模板 SDK 使用，不存在直接平台 `fetch`、存储凭证、访问父窗口或自造 postMessage。
- 业务界面没有暴露 MCP 工具、Toolset、FastAgent、提示词、脚本、DAG 或内部控制动作。
- manifest 声明的 capabilities 覆盖源码实际使用能力，未申请无关能力。
- 源码不含用户身份、密钥、Cookie、临时上传地址、构建机路径、写死的运行时输入路径或测试场景包 ID。

## 交互和业务完成度

- 业务终点、候选路线、档案规则、里程碑、运行中交互和最终交付在界面中都有对应承载；页面没有暴露内部节点或技术名词。
- 路线选择、推荐、向导、档案摘要、历史、聊天、看板等条件模块都有明确 include/exclude 理由，没有按 SDK 能力清单堆模块。
- 必填、枚举、数值、日期、文件、图片、数组和对象字段按真实 Schema 提供可用控件；复杂结构**禁止**降级为不可用的文本框。
- 文件上传后提交 SDK 返回的当前项目 Workspace 路径，不提交文件名、本地路径或 URL。
- 只读协作者、项目执行中、等待用户、失败和完成状态有清晰反馈和正确禁用策略。
- 提交成功只显示“已受理”，不会误报“执行完成”；最终状态和结果来自已声明的 Workflow 业务事件与宿主权威快照。
- 档案推荐与默认值有依据、可解释、可修改；档案缺失或冲突时能降级为普通输入，不替用户做高风险决定。
- 运行进度使用用户可理解的业务里程碑；页面只消费已声明的业务事件，不从任务点、工具调用或技术状态反推业务含义。结果按结论、影响、证据、交付物和下一步组织，不直接展示原始 JSON。
- 每条 Workflow 的开始、正常结束、可控业务失败、文件交付物和路线最终交付均按适用条件拥有对应硬门事件；细分阶段、客观进度、中间结果和非表单提醒的可选事件都有明确的界面消费理由。
- `artifact_ready` 不暴露 Workspace 路径或临时 URL；`delivery_ready` 只进入待审阅/可交付状态，不冒充用户已接受；`attention_required` 不复制运行中表单。
- 页面刷新、主题切换、空数据、错误和回落聊天路径可用。

## 视觉、语言和信息边界

- `ui_design_brief` 已记录使用场景、明确风格取向、具体参考点、唯一识别点、字体层级和取舍清单，不是“简洁、专业、科技感”等空泛形容词。
- 主色、强调色、密度、留白、字体、背景和动效服务于业务层级；不存在无场景理由的蓝紫渐变、装饰光斑、等权彩色卡片或无决策价值的大数字。
- 用户可见的标题、导航、按钮、标签、占位语、状态、空态、错误、提示和无障碍文案默认全部为简体中文；保留的英文均属于明确例外。
- 不存在 `Dashboard`、`Submit`、`Loading`、`Pending`、`Retry`、`Workflow`、`Runtime`、`Schema`、`Success`、`Error` 等开发术语直出，服务端枚举已翻译为稳定业务文案。
- 页面、提示、错误、表格、可复制文本、下载文件名和用户可见网址不含场景包、Workflow、任务点、编排、表单、运行、业务、项目、工具、部署、跟踪或存储的内部 ID/slug。
- 不显示 RPC 名称、错误码、堆栈、Workspace 路径、预签名 URL、存储 key、原始 JSON或 `[object Object]`；只在服务端明确提供可公开问题参考号时显示该参考号。
- 真正有业务意义的订单号、门店编码或合同号按需展示、使用业务名称并按权限脱敏，不统称为“ID”。
- 已以长中文、空/零/未知值、窄屏、放大文字、明暗主题、减少动效和宿主保留区完成显示验收。
- 已覆盖权限中途变化、重复提交、断线重连、事件迟到/重复/乱序、契约漂移、部分交付和下载失败；界面最终以宿主快照收敛。
- 手机号、证件、地址、金额、内部备注等敏感值遵循最小展示和按权限脱敏，不写入错误、日志或网址。

## 构建和发布证据

- 模板要求的类型检查、lint、测试和 build 全部通过。
- mock 交互至少覆盖真实主路径：输入、上传（如有）、提交、运行中状态和结果展示。
- 正式源码包已删除 Demo 页面、演示路由、演示契约、占位文案、`node_modules`、`dist`、`.git` 和 `.env*`。
- `size_bytes` 与实际压缩包一致，`source_sha256` 是实际压缩包字节的 64 位小写 SHA256。
- `prepare_upload → PUT → complete_upload → deploy/status` 使用同一工单和场景包；部署到达明确终态。
- `scene_package_ui_bundle(get)` 反读到当前源码包及成功激活地址。

## 裁决和输出

- 任一绑定错误、契约漂移、SDK 越界、Demo 残留、构建失败或部署非成功终态都裁决为 `blocked`。
- 模板缺少当前编排版本所需顶层运行能力时裁决为 `platform_blocked`，**不得**直接运行某条 Workflow 假装执行整包编排。
- 通过时输出并写入工单：`passed`、场景包 ID、契约摘要、源码 SHA256、deployment_id、激活地址和已覆盖交互。
- 同时列出模板身份、未做真实全链路运行、未覆盖复杂控件或宿主能力等剩余盲区。
