## 1. 定位与生命周期

业务界面是场景包面向用户的专属操作层，不是独立于场景包存在的普通网站。一个业务界面必须：

- 绑定唯一 `scene_package_id`；
- 在同一个场景包制作工单中创建、验证、部署和留痕；
- 消费该场景包公开的输入、状态和交付契约，不读取内部脚本、提示词、DAG 或工具配置；
- 场景包相关运行契约变化后重新验证和部署。

场景包仍允许没有专属业务界面并回落现有对话界面。创建或更新场景包时必须显式记录 `business_ui=required` 或 `business_ui=not_required`；一旦选择 `required`，未完成界面验收和部署就不能宣称整包完成。

## 2. 事实源和模式门

按以下优先级判断当前真实能力，低层资料不得覆盖高层事实：

1. 当前外部 MCP `tools/list` 中 `scene_package_ui_bundle` 的实时 action 和参数 Schema；
2. 本工单通过 `download_template` 下载的官方模板、SDK 类型和模板内文档；
3. `get_asset` 反读的当前场景包、Workflow 和 `workflow_orchestration`；
4. 服务端 Preview、Bubble、部署校验和 Max Runtime 的真实结果；
5. 历史仓库分支、示例和本文的流程说明。

不得把历史脚手架分支固定写入交付物。每次制作都下载当前官方模板，记录模板返回的可验证版本信息；若响应没有版本或 SHA256，只记录实际文件名、大小和下载时间，并把“模板身份不可复现”列为平台盲区。

### 新编排与旧单 Workflow 分流

- **新 `workflow_orchestration` 场景包**：业务界面必须通过宿主提供的顶层 Runtime Manifest、Submit 和 State 契约收集整轮输入、启动编排和展示状态。只提交顶层 `workflow_input`，不自行选择 `tpe_id/node_id`，不执行或解释 DAG。
- **旧版单 Workflow 场景包**：只有宿主明确提供兼容能力时，才可以使用模板中的 `workflow.list/run` 入口，并按当前场景包的真实 slug 过滤。
- **没有业务界面或契约不兼容**：回落现有 Agent 对话界面。

如果当前下载模板只提供单 Workflow `workflow.run(slug, input)`，却要制作新多 Workflow 编排界面，必须停止发布并报告宿主 SDK 能力缺口。禁止选择第一条 Workflow、直接运行入口 Workflow 或在前端手工推进节点来伪装整包编排。

## 3. 冻结业务界面契约

只在全部受影响 Workflow 完成 Preview、bubble 和单体验收后生成业务界面契约：

1. 用 `get_asset(asset_type="scenario_package")` 反读场景包 ID、名称、TPE 列表和完整 `workflow_orchestration`。
2. 对每条业务界面涉及的 Workflow 调用 `get_asset(asset_type="tpe")`，取得真实 `slash_command`、`input_schema` 和 `output_schema`。
3. 新编排场景包以顶层 `workflow_orchestration.input_schema` 为整轮输入契约，以 delivery 映射后的结构为最终结果契约；单条 Workflow Schema 只描述节点自身。
4. 旧单 Workflow 兼容模式只允许唯一 Workflow 成为界面入口。
5. 把每条真实 Workflow 编码期快照写入模板规定的 `schema/workflows/<slug>.json`，文件名与 slug 一致，不保留模板演示契约。
6. 记录场景包 ID、Workflow ID/slug、Schema 摘要和可用的 revision/hash，形成 `ui_contract_snapshot` 检查点。

`schema/workflows/` 是编码期快照，不是运行期真相。页面加载时仍以宿主下发的当前契约为准；发现 revision、slug 或 Schema 不兼容时停止结构化提交并引导用户回到聊天，不在浏览器本地猜测或修补。

以下任一变化都会使既有界面验收失效：

- Workflow slug、input/output Schema 或是否上线发生变化；
- 顶层 `workflow_orchestration.input_schema`、节点映射或 delivery 发生变化；
- App 使用的 SDK capability 或最低 SDK 版本发生变化；
- 场景包绑定关系发生变化。

## 4. 使用官方脚手架开发

参考线上 deploy 工具集“初始化工具是强制第一步、使用返回目录、先读模板说明再开发”的约束，业务界面必须执行以下初始化闭环：

1. 冻结界面契约后，首先调用 `scene_package_ui_bundle(action="download_template", task_id=<task_id>)`。业务界面开发不能从空目录、通用 `init_project`、Git 克隆或旧源码副本开始。
2. 只有响应 `success=true` 且 `data` 同时提供非空 `file_name`、正整数 `size_bytes`、非空 `download_url` 和正数 `expires_in` 时才继续。短链是临时凭证，只用于本次下载，不向用户展示，也不写入工单、源码、日志或记忆文件。
3. 在短链有效期内，用支持 HTTPS、重定向和非 2xx 失败退出的下载能力，把文件写入当前可写工作区的独立过程目录。不得把短链当成本地路径交给文件读取工具，也不得假定工具已自动解压。
4. 下载后检查文件真实存在且非空，实际字节数必须等于 `data.size_bytes`；文件名和实际归档均须为 `.tar.gz` 或 `.tgz`。不一致时停止开发并重新取得当前模板，禁止继续使用残缺包。
5. 解压前先检查归档成员，拒绝绝对路径、`..` 路径穿越、逃逸目标目录的链接或设备文件；解压到新的空目录，禁止覆盖已有项目。
6. 解压后定位唯一包含 `goalfy-app.json` 的模板根目录，并把它记录为本次业务界面的唯一开发目录。不存在或存在多个候选根目录时停止，不得猜选。
7. 完整阅读模板根目录的 `AGENTS.md`、`README.md`、`schema/README.md` 和 `src/sdk/docs/README.md`。缺失任一模板声明的必读文件，或其指令相互冲突时，停止编码并报告模板问题。
8. 记录不含短链的 `template_identity`：返回文件名、声明字节数、实际字节数、下载时间，以及模板响应实际提供的版本或校验值。响应未提供版本或 SHA256 时明确记录该盲区，不自行计算模板内容哈希并冒充官方版本。

这个入口与 deploy 工具集的 `init_project` 具有相同的生命周期地位，但二者不能互换：`init_project` 初始化的是通用 Web 应用和独立部署记录；`download_template` 初始化的是与场景包同工单、随后由 `scene_package_ui_bundle` 上传和发布的业务界面源码。调用前者不能证明取得了当前场景包 UI 模板。

遵守以下开发边界：

- 业务代码只写入模板声明的业务页面和组件目录；
- SDK、启动入口、错误边界、桥协议等固定层未经用户确认不得修改；
- 使用模板既有框架、路由和样式方案，不另起一个前端工程；
- `goalfy-app.json.scenario_pack_id` 必须等于本工单真实场景包 ID；
- `name/version/default_route/min_sdk/capabilities` 与实际页面和 SDK 调用一致；
- 文件字段使用 JSON Schema 的 `format:file/image` 渲染上传，提交 `sdk.upload` 返回的当前项目 `/workspace/...` 路径；
- 复杂数组、对象、日期、表格、时间线或画布使用专属业务控件，不把 JSON 文本框当成默认完成态；
- 提交成功只代表请求被接受，不代表 Workflow 完成；进度和结果必须使用宿主状态和消息能力。

开发阶段保留模板 Demo 作为调用示例，但正式打包前必须删除 Demo 页面、演示路由、演示 Workflow 契约和首页占位文案。不得把演示场景包 ID、Workflow slug、测试文件路径、用户身份或构建机路径写入源码。

## 5. SDK 与安全边界

业务代码只使用当前模板公开的 SDK。Skill 中不复制完整 SDK 类型；开发时以模板的类型定义和文档为准。

典型能力域包括：

- 会话、语言和初始路由；
- Workflow/整轮编排的公开运行入口；
- 项目状态和协作者权限；
- 历史消息与实时消息；
- 文件上传；
- 打开宿主聊天；
- 主题同步。

禁止：

- 直接使用 `fetch/XMLHttpRequest/axios` 访问平台内部 API；
- 读取或写入 `localStorage/sessionStorage/document.cookie`；
- 访问 `window.parent/window.top` 或自行定义 postMessage 协议；
- 向 iframe 下发登录 token、Cookie、预签名 URL、Workspace 挂载信息或数据库身份；
- 在业务界面公开 MCP 工具清单、Toolset、FA、提示词、脚本、`input_mapping` 或 `sa_handoff` 内部指令；
- 在前端执行 DAG、选择下一节点、决定 Agent `resume/stop/take_over` 或直接重试失败节点。

MCP 工具清单只服务制作 Agent。浏览器业务界面只看到宿主 SDK 和公开运行契约。

## 6. 打包、上传和部署

交付前执行模板要求的完整静态检查、测试、构建和 mock 交互验证。只有“命令通过”但没有走通关键输入、上传、提交、等待和结果展示，不算界面验收。

打包源码而不是构建产物：

1. 删除 `node_modules`、`dist`、`.git`、`.env*`、系统元数据和模板 Demo。
2. 创建 `.tar.gz` 或 `.tgz`，使用稳定相对路径，避免把外层临时目录多包一层。
3. 对实际压缩包字节计算 `size_bytes` 和 64 位小写 SHA256。
4. 调用 `scene_package_ui_bundle(action="prepare_upload", ...)`。
5. 严格按返回的 method、headers 和 URL 执行 HTTP PUT，不把预签名 URL写入工单。
6. 调用 `complete_upload` 绑定当前源码包。
7. 调用 `deploy`，传入实际压缩包 SHA256。
8. 若未返回终态，使用同一 `deployment_id` 调用 `status`，直到成功、失败或平台明确超时。
9. 成功后调用 `get` 反读当前包和激活地址。

部署是外部发布动作。开始 `deploy` 前向用户说明会发布业务界面；如果当前任务上下文已经明确授权创建并发布整个场景包及其业务界面，则不重复确认同一动作。上传源码包本身不等于发布成功。

## 7. 更新、诊断和失败恢复

- **界面代码问题**：修复同一源码目录，重新检查、打包、上传和部署。
- **Workflow 契约变化**：先更新并重新验收 Workflow，再重新生成界面契约和部署；不得只改前端适配旧快照。
- **部署超时**：保存 `deployment_id`，使用 `status` 续查；不要重复 `deploy` 创建并行任务。
- **部署失败**：依据结构化 stage/error 修复根因，禁止只改错误文案或跳过失败检查。
- **模板下载失败**：区分短链过期、HTTP 失败、大小不一致和归档不安全；重新获取当前短链后从下载校验开始，不在旧文件上续写或手工补齐缺失内容。
- **模板根目录不唯一或必读说明缺失**：裁决为模板交付问题并停止编码；不得自行挑选目录或从历史仓库补文件。
- **模板能力不足**：记录缺失的 SDK 能力和受影响场景，停止该界面发布；不得修改固定桥协议自造平台能力。
- **诊断已有界面**：先 `get` 读取当前元数据，必要时 `download` 当前源码，再与场景包和 Workflow 当前契约比较；下载短链仅用于本次读取。

最终工单检查点记录：业务界面决策、场景包 ID、契约摘要、源码 SHA256、deployment_id、激活地址、验收裁决和剩余盲区。不得记录上传/下载短链、密钥、Cookie 或内部挂载信息。
