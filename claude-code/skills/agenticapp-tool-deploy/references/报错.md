# 部署、实际跑、上线、结单的报错

工具返回下面的错误码或现象时读。表里没有的，按入口「报错和平台问题」处理。

## 部署与在线预览

| 错误码或现象 | 含义 | 怎么做 |
|---|---|---|
| 部署 `status` 失败 | 构建或启动失败 | 看返回里的构建日志尾部；在工作区跑 `npm run verify:release` 复现，修好后重新部署 |
| `BUSINESS_UI_NO_SCENARIO_PACK` | 新 SDK 应用的占位草稿既没挂场景包也没挂编排，上传或部署被拒 | 先 `business_ui_manage(action="update")` 挂编排与 `tpe_ids`，再部署 |
| 被脚手架闸门拒绝 | 脚手架低于必须线 | 按 `agenticapp-tool-workspace`「脚手架升级」迁移后重新打包 |
| `BUSINESS_UI_DEPLOYMENT_QUOTA_EXCEEDED` | 部署占用到了上限 | 把返回里的占用明细和每个释放选项的影响用业务话给开发者看，等他指明释放哪个、怎么释放。下线、删除由他决定，你不自己做，也不原样重试（下线让那个应用的使用者失去入口，删除永久删掉它的所有版本、实例和库，不能恢复）；他释放后用同样参数重新部署。明细为 0 或没有可释放项时是平台计数出错：按平台问题报反馈、交「卡住了」，不请他下线别的应用，也不再试跑 |
| `BUSINESS_UI_CONTRACT_OUTDATED` | 挂载场景包的编排契约和部署时不一致 | 草稿刚部署成功、之后没换挂也没改场景包时出现，是平台对草稿的误报，不再重复部署，照常往下走。换挂或改了场景包后出现，重新部署一次；契约变化波及页面时先按 `agenticapp-task-revise` 评估影响 |
| 同一张工单上线后再部署被拒（`PERSONAL_VERSION_OPERATION_ALREADY_FINALIZED`、`PERSONAL_VERSION_OPERATION_CONFLICT`，或指向已上线版本的其他拒绝） | 这一次部署没有落到新草稿 | 留下原始错误和请求参数，如实告诉开发者卡住了，按入口「报错和平台问题」报。不另开工单绕过，开发者可以等；验收先做不受影响的条目 |
| `BUSINESS_UI_WORKSPACE_BEHIND_TEMPLATE`、`BUSINESS_UI_PREVIEW_DATA_UNBOUND`、`close` 时的 `TEMPLATE_WORKSPACE_IN_USE_BY_DEPLOYMENT` | 开发工作集缺模板版本里的表列、被解绑了，或还有部署跑在上面 | 见 `agenticapp-tool-data-template`「错误码」 |
| 报错带 `metadata.asset_state=draft` | 出在挂本人场景包草稿的部署、预览或上线上 | 按原错误码处理，报平台问题时注明是草稿态 |
| 在线预览报 `PREVIEW_NOT_READY` | 当前草稿没有部署成功，或部署后又派生了新草稿 | 在当前草稿上重新部署到 `success` 再请开发者打开；部署已成功仍报，才按平台问题报 |
| 部署 `status=success`，但 `stage=preview_failed`、`PREVIEW_HOST_UNAVAILABLE` 或 `PREVIEW_HOST_HANDSHAKE_FAILED` | 容器起来了，平台没拍成首屏截图。它既不说明页面能打开，也不说明打不开 | 照常往下走。对开发者只说「首屏截图没拍成，线上页面能不能打开我还不知道」，不说「不影响使用」「只影响缩略图」；报告里线上打开记「未测」，写明首屏截图没拍成，按平台问题报 |
| 刚重新部署后，开发者说保存失败、提示后端没部署 | 先对照部署完成时间，多半是更新窗口内的提示 | 他的话只用来定位问题。说清不是他配错了，页面正在更新，更新好后再试；部署完成足够久仍出现，才按平台问题报，一句没有复现的回报不把状态改成「卡住了」 |
| 开发者说在线预览显示「Agentic APP 不存在或加载失败」（3024） | 当前草稿没部署成功，或他的账号无权访问；不表示应用被下线 | `business_ui_manage(action="get")` 核对，没部署成功就重新部署再请他重开；部署成功仍打不开才按平台问题报。不为此下线，下线会让使用者失去入口 |

## 实际跑

| 错误码或现象 | 含义 | 怎么做 |
|---|---|---|
| `BUSINESS_UI_NOT_ONLINE` | 带 `business_ui_id` 实际跑没传 `business_ui_data_space="workspace"` | 补传 `workspace` 重跑；不需要上线，不是平台问题 |
| `BUSINESS_UI_NOT_DEPLOYED` | 还没有你部署成功的版本 | 先部署到 `success` 再跑 |
| `BUSINESS_UI_NOT_FOUND` | 把版本行 ID 当成了应用 ID，或 ID 被改写 | 用 `WORKSPACE.md` 或平台返回的应用 ID 原值重试；不为此新建应用或重新 `setup` |
| `SCAFFOLD_BUSINESS_UI_ID_INVALID` | 工作区里的脚手架不认平台返回的应用 ID | 见 `agenticapp-tool-workspace`「版本错误」 |
| `BUSINESS_UI_NOT_RELEASED` | 上线了但从没发布；正式实例的运行要已发布版本 | 制作和验收用 `workspace` 实际跑，不需要它；发不发布由开发者定 |
| 卡在 `waiting-input` | 中途表单或审阅在等回答 | 用 `reply` 回；没人答就是正常挂起 |
| 上线前 `resolve` 报「还没有上线版本」 | `resolve` 只认上线版本 | 正常结果，不是平台问题 |
| 换了场景包或模板版本后结果没变 | 跑的不是要验的版本，或改了代码没重新部署 | 按 SKILL.md「实际跑」里「跑的是哪一版」核对 |

## 上线与下线

| 错误码或现象 | 怎么做 |
|---|---|
| `BUSINESS_UI_NO_BUNDLE` | 还没有源码包：部署成功后再上线 |
| `BUSINESS_UI_NOT_DEPLOYED`（finalize 时） | 源码包没有成功部署：部署到 `success` 再上线 |
| finalize 只传 `business_ui_id` 被拒 | 家族里有多份草稿，平台不替你挑：显式传 `draft_asset_id` |
| `PERSONAL_VERSION_STALE_SOURCE`（finalize 时） | 这份草稿所依据的版本已不是最新上线版。告诉开发者「已放到在线预览，上线没成功」和原因，验收接着做；按 `agenticapp-role-collab`「基线过期的合并」合并最新版，重新部署再上线，在此之前不说已上线 |
| 上线结果不明（网络中断、超时） | 先 `resolve` 读回：已上线就按已上线继续，没上线再用相同参数重试，不换标识重复操作 |
| `BUSINESS_UI_RELEASED_CANNOT_OFFLINE` | 已发布到目录的应用不能直接下线：请开发者先在发布管理页取消发布 |
| `CHANGE_NOTE_REQUIRED` | 建应用草稿没带变更说明：写清这次改了什么，带 `change_note` 重调 |

## 开发者发布时

发布被拒是开发者把报错告诉你时才知道的。要改的按 `agenticapp-task-revise` 开修订修好，重新放好并上线，他再发布；你不替他发布。

| 错误码或现象 | 怎么做 |
|---|---|
| `BUSINESS_UI_CONTRACT_OUTDATED` | 这一版绑定的部署对着旧契约：重新部署一次再上线；契约变化波及页面时先按 `agenticapp-task-revise` 评估影响 |
| `BUSINESS_UI_INVALID_SCENARIO_PACK_REFS` | 新 SDK 应用的版本没挂编排：先 `business_ui_manage(action="update")` 挂编排与 `tpe_ids`，重新部署并上线 |
| `BUSINESS_UI_TEMPLATE_REQUIRED` 等模板相关的拒绝、迁移彩排失败 | 按 `agenticapp-tool-data-template`「错误码」处理后重新部署再上线 |

## 版本与结单

| 错误码或现象 | 怎么做 |
|---|---|
| 版本闸门拒绝（如 `PERSONAL_VERSION_FINALIZE_REQUIRED`） | 改内容撞了上线行：先取可编辑草稿；上线动作撞了没上线的草稿：走上线。状态字段只由平台改 |
| `WORKFLOW_TASK_ROUTE_BUBBLE_EVIDENCE_REQUIRED` | 有路线没有对得上的运行证据（没跑、跑失败、`run_id` 属于别的路线、证据早于最后一次路线修改）。按 `agenticapp-tool-deploy`「结单」补运行证据，或按 `agenticapp-stage-5-launch`「等他选」处理（读写应用库的路线不能豁免）；在同一张工单上按返回逐条处理，不反复重试 |
| `task_manager(insert)` 带 `format_warning` | 记录已写入但多条路线合在一条里；补成每条路线一条，各带自己的 `run_id` |
