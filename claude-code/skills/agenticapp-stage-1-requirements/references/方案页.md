# 方案页

非 Studio 宿主都写方案页 `docs/proposal/index.html`：工作台里开发者在右栏「方案」看到它，命令行宿主没有右栏（`agenticapp-tool-workspace`「命令行宿主」）。① 第一次写 PRD 时照这里写，之后各段只更新自己那几块。这里写给开发者看的内容和版式；文件放在哪、缺样式文件怎么补、改动高亮和历史版本怎么存，见 `agenticapp-tool-workspace`「方案页」。Studio 宿主没有方案页，写开发文档，按 `agenticapp-host-studio`。

## 版式

`doctor` 按这套版式校验。只写内容和类名，不写 `<style>`、`style=` 属性，样式全部来自脚手架维护的 `proposal.css`。页面按顺序只有这几块：

```html
<main data-proposal="2" data-version="3">            <!-- 方案每次改动后 data-version 加一 -->
  <header>
    <div class="pv-eyebrow">智能应用方案 · 第 3 版</div>
    <h1>应用名</h1>
    <p class="pv-goal">一句话：它帮使用者做什么。</p>
  </header>
  <section id="status" data-state="blocked" data-stage="G6">
    <div class="pv-state">④ 试用验收</div>
    <p class="pv-summary">一句话现状。</p>
    <p class="pv-you">开发者要做什么；不用做也写「现在不用做」。</p>
    <p class="pv-owner">谁在处理（卡住时必填）。</p>
    <details class="pv-raw"><summary>查看原始原因</summary><pre>报错原文、编号</pre></details>
  </section>
  <section id="needs">                               <!-- 没有要开发者准备的东西时整节省略 -->
    <h2>需要你准备的</h2>
    <ul class="pv-needs">
      <li data-ready="no">聚光广告账号授权<small>用在第 2 步拉取投放数据；没有它第 2 步起都跑不了</small></li>
      <li data-ready="yes">一份持仓示例表<small>用在导入功能的验收</small></li>
    </ul>
  </section>
  <section id="business-process">
    <h2>业务过程</h2>
    <ol class="pv-steps">
      <li data-kind="rule">固定规则做的一步</li>
      <li data-kind="model">要模型判断的一步（会花钱）</li>
      <li data-kind="human">人① 使用者：要使用者决定的一步</li>
    </ol>
    <p class="pv-fallback">做不成时使用者会看到什么。</p>
  </section>
  <section id="development-content"><h2>开发内容</h2>① 流程图的节点详情；② 补运行条件、功能与页面</section>
  <section id="verification">
    <h2>验证情况</h2>
    <ul class="pv-verified"><li data-evidence="部署 p2s-3316">已经真实验证过的事</li></ul>
    <ul class="pv-unverified"><li>还没验证的事，写明原因</li></ul>
  </section>
  <p class="pv-meta">本版改动：… · 历史版本：<a href="history/v2.html">第 2 版</a></p>
</main>
```

## 各块怎么写

| 块 | 规则 |
|---|---|
| `status` 的 `data-state` | `working` 在做、`waiting` 等开发者、`blocked` 卡住、`done` 已完成，颜色由它决定。和交接消息开头的状态一致：等你确认 = `waiting`，正在做 = `working`，卡住了 = `blocked`，已完成 = `done`。平台问题、权限、部署失败等你推进不了的一律 `blocked`。`data-stage` 写当前工作区阶段（G1–G7） |
| `status` 内容 | `.pv-state` 写当前段名（① 需求确认、② 方案、③ 制作、④ 试用验收、⑤ 上线），不写 G1–G7；脚手架初始生成的「G1 需求确认」第一次更新状态时就改掉。`.pv-summary` 写「刚做完」，`.pv-you` 写「要你做的」；`waiting`、`blocked` 必须有 `.pv-you`；`blocked` 必须有 `.pv-owner`；报错原文与编号只放进 `.pv-raw` 折叠 |
| `needs` | 开发者要提供、别人替不了的东西：第三方账号授权、密钥、示例数据、机器人或群、要开通的平台能力。每项写用在哪一步、缺了影响什么，`data-ready` 标 `yes` / `no`，备好一项改一项。① 核实时查清，② 写运行条件时列出。有 `no` 且挡住当前进度时，`.pv-you` 写「准备下面 N 项」 |
| `pv-steps` | 来自 PRD 流程图，按环节顺序每个节点一条，标 `data-kind`：脚本 `rule`、模型 `model`、人 `human`，图例说法是「脚本 / 模型 / 使用者」。模型步骤写哪一档、每次约多少积分；人的步骤以「人① 使用者：」开头 |
| `development-content` | ① 写概览和每个节点的输入、输出、重要信息；② 补运行条件、功能与页面，见 `agenticapp-stage-2-plan` 的方案模板 |
| `verification` | 「已验证」每条用 `data-evidence` 写证据（部署编号、真跑的项目编号、「演示版」或在工作区跑的命令）；桩运行、只在演示版上看过、没真跑过的一律放「未验证」并写原因 |
| 用词 | 正文用业务话（入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)）；编号只放在 `data-evidence` 或 `.pv-raw` 里 |

开发者确认过这一版后，`status` 要跟着改成当前实际状态，不留「请确认」这类过期的话。
