# 上线前自查

认定上线哪一份、上线之前逐条核时读。

## 没部署过时

④ 因为开发者说先别放而没有部署过的，如实说「还没放到在线预览，上不了线」，问他现在放不放。

- **同意**：加载 `agenticapp-tool-deploy` 部署到 `success`，按 `agenticapp-stage-4-acceptance` 的工作集真跑和逐条判定，补测依赖已部署版本的条目，结果更新进验收报告。
  - 补测没通过、原因在你能改的东西里（应用代码、场景包配置、数据）：不问开发者，按 ④「按反馈改」改好、重新部署、重测，补测最多 3 轮。
  - 原因你改不了（平台故障、外部数据源、要开发者授权或付费），或 3 轮后仍没通过：把这几条逐条做成「接受，先上线 / 等改好再上线」选择题，写清原因和上线后使用者会遇到什么。选「接受」的记「没通过，开发者选了接受」，照常上线；选「等改好」的不上线。
  - 有「好不好你说了算」的，把实际结果给他看，请他看过后再说一次「可以上线」。
  - 补测的条目都是通过、他选了接受，或判断类他再说过「可以上线」，才上线。
- **不同意**：停在这里，告诉他这一版还没放到在线预览，所以没有上线。

## 上线前自查

| 查什么 | 没满足时 |
|---|---|
| ④ 里确认过、上线后还要用的设定，是不是只存在开发工作集里（使用者从空库开始，看不到它） | 搬到代码默认值、场景包配置或首次设置入口（放哪按 `agenticapp-tool-data-template`），重新部署后再上线 |
| 有外部平台授权或充值的 | 加载 `agenticapp-tool-integration`，按它的「上线前核对」核一遍，结论写进上线结果的使用说明 |
| 新 SDK 应用：部署之后又改过编排 | 重新部署一次再上线；部署记录对着旧契约时，开发者之后发布会被拒（`BUSINESS_UI_CONTRACT_OUTDATED`） |
