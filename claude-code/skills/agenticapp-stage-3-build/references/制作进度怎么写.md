# 制作进度怎么写

发 ③ 的进度消息时读。消息的通用格式（四件事、花费三个数）见入口的「交接」；这里只写 ③ 特有的部分。

## 什么时候发

- ③ 开始时保存第一版进度，之后什么时候发见 `agenticapp-stage-3-build` 第 4 步。不必每调一次工具就发；每条发完都在同一条回复里接着做。
- 页面做好、在演示版上测过时，在这条进度里说：「页面做好了，演示预览里能看，想改样子直接在上面改或告诉我，我接着往下做。」只是让他知道能看了，不是请他验收，也不等他回话。他在演示预览里改过文字或样式的，改动已在工作区里的工程里，接着做之前重新读相关文件。命令行宿主没有演示预览，不发这句。
- 进度在做的过程中发，不攒到 ④，也不和 ② 的确认回复合成一条。③ 的最后一条进度什么时候发见 `agenticapp-stage-4-acceptance` 第 6 步。
- ④ 里要返工时同样发：第一个改动之前，受影响的功能改回「在做」（`agenticapp-stage-4-acceptance`「按反馈改」）。
- 开头写「【③ 制作 → 正在做】」；推进不下去时按入口「交接」写「卡住了」。

## 进度表

每条进度都带这张表。每个功能一行，三格「后台 / 页面 / 存数据」。

| 格 | 只能写 |
|---|---|
| 页面、存数据 | 做好了 / 在做 / 没开始 / 不需要 |
| 后台 | 指这个功能用到的路线，写下面四种之一；没有路线的写「不需要」 |

后台的四种：

- **做好了，实际跑过**：实际跑，或冒泡到终态且没有桩（有模型步骤要带 `full_run`，纯脚本路线没有桩），并已发「我先跑了一遍」；
- **做好了，只用模拟数据试过**：有模型步骤的路线只有桩跑通（冒泡没加 `full_run`）；
- **做好了，等在线预览时实际跑**：读写应用库的路线，静态 verify 只差运行证据，④ 放好后实际跑；
- **在做 / 没开始**。

## 表下面写什么

- 一句总数，三格都好才算做好一个，例如「19 个功能里做好 15 个」。
- 和方案不一样的地方各写一句：换了什么、对使用者有什么不同。
- 读写应用库的功能「后台」标「做好了」时，写一句「存数据自查：<功能名> 四项都有」。写得出这句才能标「做好了」。
- **我先跑了一遍**：发给每个后台「做好了，实际跑过」的功能，写法见 [我先跑了一遍怎么写.md](我先跑了一遍怎么写.md)。
- **页面说明**：页面做完后写每个页面做什么用、显示什么、有哪些按钮；可以附布局回归的截图（只连演示版 Mock，不是线上页面），写明「示意，演示预览里的模拟数据」。
- **没做成的**：哪件事没做成、原因、影响哪个功能。

## 别处的同步

- 非 Studio 宿主发消息的同时更新方案页的状态块（按 `agenticapp-tool-workspace` 的「方案页」）。
- Studio 宿主下进度写成「制作进度」开发文档，什么时候写、什么时候更新和进度消息相同，格子状态与这里的进度表一致，版式按 `agenticapp-host-studio`。
