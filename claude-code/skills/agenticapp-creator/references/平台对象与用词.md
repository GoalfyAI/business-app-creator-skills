# 平台对象与用词

分不清某个对象、某个 ID 指什么，或者要把平台的词转述给开发者时读。

## 智能应用由什么组成

| 组成 | 是什么 | 使用者感受到的 |
|---|---|---|
| 前端应用 | 脚手架上的页面，只经 SDK 和平台交互 | 看现状、发起一件事、拿结果、改结果、离开再回来 |
| 专属后端 | Express + PG，直连这个使用者自己的库 | 编辑自己的数据、看板统计、产出回流入库 |
| 数据模板 | 表、字段、每一列由谁写；使用者第一次打开时照模板建一份自己的库 | 不用重复交代，能查看和纠正 |
| 业务路线与编排 | 编排型 TPE、FastAgent、工具集；旧应用装在场景包里，新 SDK 应用直接挂在应用版本上 | 在必要节点补信息、做选择、审阅结果 |

应用里每一步由三类之一来做：**脚本**（结果固定、不花模型费）、**模型**（要判断或要写作，按模型计费）、**人**（使用者补信息、选择、确认、审阅）。

**新 SDK 应用**：应用工程 `frontend/goalfy-app.json` 写了 `"executor": "launch_agent"` 的是新 SDK 应用，不挂场景包，一次运行是一个「执行」，执行里没有运行 Agent。没写 `executor` 的是旧应用，挂场景包。各 Skill 里新旧不同的地方都单独写了。

## 角色

| 角色 | 是谁 |
|---|---|
| 开发者 | 用本 Skill 制作、维护应用的人；懂业务，一般不懂代码；应用属主 |
| 需求方 | 提需求但不操作 AI 的人，可以就是开发者本人 |
| 使用者 | 应用发布后用它的人。每人安装后用自己的一份，从空库开始，数据互不相通。平台没有组织和团队，一个应用里没有提交、审核、复核这类多人分工 |
| 你 | 执行本 Skill 的 Agent：调查、核实、制作、验证；准备选择题和推荐答案，不替开发者决定 |

开发期的确认、授权写「开发者」；运行期每一步写「使用者」或「运行 Agent」。不单独写「用户」。

## 部署、上线、发布

内部只用这三个词，各指一件事（详见 `agenticapp-tool-deploy`）。对开发者按右列说：

| 内部的词 | 指什么 | 要不要他同意 | 对开发者怎么说 |
|---|---|---|---|
| 演示版（Studio 里叫演示预览） | 在工作区里跑起来的应用，平台能力是模拟的 | 不用，做完直接跑 | 在演示版上跑的过程不提，要提时说「演示版」，不说本机版、本地。③ 页面做好时告诉他演示预览能看了，不等他回话，他看了也不算验收 |
| 部署 | 把草稿放到开发者的在线预览，用真实链路跑 | 方案确认后直接做，不再问 | 「放到在线预览」「更新在线预览」，名额说「在线预览的名额」，不说部署 |
| 上线 | 把部署成功的那一版放到 Max，成为开发者自己的正式版，使用者还看不到 | 不用，部署成功后直接做；他说「这版先别上线」才不做 | 「上线」 |
| 发布 | 开发者在发布管理页发给使用者 | 他自己定 | 「发布」 |

对开发者说上线时补一句：「这一版上线到 Max，成为你自己的正式版；要自己正式使用或给别人用，需要你在发布管理页发布，发不发布由你决定」。

## 平台的词怎么转述

| 工具说明或返回里的词 | 对开发者说 |
|---|---|
| 定版、提请属主定版、等属主定版 | 上线、提请属主上线、等属主上线 |
| `business_ui`、业务应用 | 智能应用 |
| 确认页、PRD | 需求文档 |
| 分工表 | 需求文档的「每一步谁来做」 |
| 用户、最终用户、终端用户 | 使用者；指做应用的人时是开发者 |
| 创建者 | 开发者（应用属主） |
| G1–G7 | 不说，说成「需求确认」「方案」等段名 |

转述给开发者时不照搬工具说明里的「定版」等旧词，按上表改说。

## 不对开发者说的词

- 技术词：FA、TPE、schema、工具名、模型名、资产编号、原始日志和报错原文。
- 流程词：本 Skill、SKILL.md、段文件、规则出处，以及「交棒」「阶段标记」「G1–G7」「checkpoint」「施工单」「阶段文档」「full_run」，还有入口「跟开发者说话」列出的那些词，也不自造词代替（「空跑」「替身」）。各 Skill 自己用这些词组织步骤，不代表可以照搬给开发者。
- 过程话：调用工具之间的一句话开发者也看得到，用他的语言、只说进展，例如「需求文档在写了」「页面做好了，在补后台的计算」。
- 没依据的结论：测试里说过、事后证明不对的话——「能跑，不花积分」（查询刚返回无权限）、「这个问题不影响你正常使用」（那条路一次没跑通）、「读不出文字的文件也测过了」（实际传的是不存在的路径）、「是我们当时没对齐」（记录里写得清楚）。改说「还不知道，要等 X 跑完才能确定」「这条没测通，原因是 Y」。
- 要他做的事直接说成动作：看哪份文档、确认什么、确认后你接着做什么，例如「请看右侧的需求文档，没问题回『确认这一版』。确认后我开始写制作方案。」

## 标识

| 标识 | 指向 |
|---|---|
| `task_id` | 工单，不是资产 |
| `business_ui_id` | 智能应用的对外 ID，指整个应用家族。旧应用是数字串（如 `"84"`），新应用是 8 位小写字母数字短码（如 `"k3m9x2ab"`）；只能原样取自平台返回或工作区文件，不按形状猜 |
| `business_ui_version_id` / `draft_asset_id` | 应用的某个版本行（数字） |
| `scene_package_id` | 场景包，家族或某个版本行要看上下文，先反读 |
| `tpe_id` | 任务点，普通任务点和编排型 TPE 共用编号 |
| `run_id` | 一次冒泡验证，续等时复用 |
| `project_id` | 一次实际跑，查询、追问、读日志都复用 |
| `deployment_id` | 一次部署 |
| `mcp_id` | 授权卡绑定用，不是 `tool_group_id` |

版本相关的四个词：**家族**是对外的稳定身份；**物理行**是一个具体版本的行；**草稿**是 `testing` 状态的物理行，制作和验证都在草稿上做，一个家族同时只有一份草稿；**上线**是草稿变成 `live`，旧上线版本保持不变。`get_asset` 传家族 ID 会解析到最新上线行，要看某个旧版本必须传那一行的 ID。

## 积分

只按积分计费，1 元 = 100 积分。一个项目的花费 = 模型调用 + 付费工具 + 云端沙盒（存活期间持续计费）+ 平台资产费用。冒泡（工具和沙盒照常真实执行）、`full_run`、实际跑、在线预览里的操作、自动化运行都花开发者的积分；你和开发者之间的对话不花。

实际花费读结果里的 `cost_credits`，先分清读到的是哪一份：

- **新 SDK 应用**（执行编号 `BIZ-` 开头）：路线冒泡结果和 `manage_goalfymax_project` 带 `business_id` 的 `status` / `wait` 返回本次执行的 `cost_credits`，是这一次执行截至此刻已入账的积分，运行中也有；`cost_excludes` 列出没计入的来源，固定含 `sandbox`，环境未接线的来源也会列入（例如资产计费没接线时多出 `asset_billing`）。对开发者说来源用中文：`sandbox` 沙盒、`asset_billing` 平台资产计费、`token` 模型调用、`mcp` 付费工具，其他名字原样写。只能读到整次执行的，分不到单步。按项目查到的是该使用者实例隐藏项目的累计，隐藏项目可能被多张工单、在线预览和自动化共用，**禁止**当本次花费，也**禁止**当工单花费。
- **旧应用**：`manage_goalfymax_project` 的 `status` / `wait` 与冒泡终态的 `cost_credits` 是该项目截至此刻已花的积分。沙盒按周期记账，运行刚结束读到的可能还没算上沙盒部分。

汇总累计花费时对记下的每个运行重新读一次再相加：旧应用同一项目编号只算一次；新 SDK 应用按执行编号逐次读本次执行的数，同一执行只算一次。重读不到的运行（例如旧应用冒泡的隐藏验证项目 2 小时后被回收）用当时记下的读数；当时也没读到的才算「没读到」，不算 0。累计 N 只加读到的数，和上限比（含 80% 停）也用这个 N；新 SDK 应用的 N 不含沙盒，沙盒用得多的应用同时看步数和运行时长止损。读数和合计怎么写见 [提问与交接.md](提问与交接.md)「交接消息」。

拿不到实测时按顺序估：用 ① 试用过的同类实测；没有就按模型档位单次花费 × 次数 + 付费工具单价 × 次数，量级参考 `agenticapp-ref-platform-limits`「怎么用这些数字估算」；每个数都标「估算」并写出算法。开发者问多少钱、要多久时给范围和算法，说明什么时候能更准，不回「给不出」。上限题的推荐值也这样算，算不出单价时先跑一次最小的例子（花钱先问），不拍一个大数。
