# 提问与交接消息

出选择题、发交接消息时读。

## 选择题

```text
❓ Q2 从哪开始：使用者要先填什么才能开始？地图工具按店名能查到候选门店，海外店要多一步网页核实。
   A 只填店名，城市选填：门店由应用去查，查到几家时让使用者选
   B 店名、城市、官网都填：查得更准，但使用者要先准备好这些
   C 其他，说说你的想法
➡️ 推荐 A，只填店名
```

- 一题一个标题、一段说明、一个推荐答案；写成开发者回「是」就是采纳推荐。
- 说明先写为什么要问，再给查到的事实（实测花了多少、多久、查到什么）。
- 2–4 个选项，每个写清选了会怎样（多花多少、少什么、慢多少）；最后固定加「其他，说说你的想法」。
- 要花钱的题（试跑、真调），题干写清份数和约多少积分；没有准数时按同类实测和份数、页数、字数推一个范围并写出算法，不写「估不准」。
- **事实题**：只有开发者知道的事（站点、账号、现在记在哪、多久用一次）照样出题，但不给选项和推荐，写明「这题只有你知道，没有推荐答案」。回「是」不算答了。
- 需求方和开发者不是同一人时，题号后写「请需求方答」；开发者可以代答。
- 答案记进 PRD 或方案对应的题下面，写清谁答的：「开发者答：A」。

## 交接消息

```text
【① 需求确认 → 等你确认】
刚做完：需求文档第 2 版：4 个刚需、2 个非刚需，每个都写了放进去什么、拿出来什么；识别、报告都用真实商家试过一次。
下一步：你确认后，我先问清还没定的做法和验收要求，再整理成制作方案请你整份看一次。
要你做的：① 看右侧的需求文档，不对的直接说哪一条；② 答 8 道选择题；③ 没问题就回「确认这一版」。
花了多少：这一阶段 760 积分（第 5 题同意后试跑的一份报告）；一共 760；上限 15,000。
```

| 项 | 写什么 | 不写什么 |
|---|---|---|
| 开头 | 【段名 → 状态】，状态只有四种：等你确认 / 正在做 / 卡住了 / 已完成。「正在做」只用于发完你在同一条回复里还接着做的消息；最后一条用哪种见入口「每条回复都是一条交接」。只回答问题时也由这一行打头，答案写在它下面的「刚做完」里，不先答完再在末尾补这一行 | G1–G7 这类编号 |
| 刚做完 | 这次交出的东西，用业务话；有真实结果就带一句；你替他定的技术事用一两句说后果 | 建了几个资产、跑了几次验证、改了哪些文件 |
| 下一步 | 你接下来做什么；要等他的写「等你……后我……」；提问时写还剩几轮，上一轮没答再问的也写 | 内部步骤清单 |
| 要你做的 | 编号列出，每项是他能做的动作；没有就写「没有」 | 他判断不了的技术事 |
| 花了多少 | 「这一阶段 N；一共 N；上限 N」 | token、美元 |

带【段名 → 状态】开头的每一条都写齐四项，③ ④ 的进度和「卡住了」也一样，少一项开发者就不知道做到哪、接下来等谁。

- **这一阶段** = 当前这一段到现在所有运行的积分和；**一共** = 这张工单所有段之和；**上限** = 入口「花费」定的数，后来改过按最新的。前两个数怎么加见 [平台对象与用词.md](平台对象与用词.md)「积分」。
- 实测读运行结果的 `cost_credits`（读哪一份见 [平台对象与用词.md](平台对象与用词.md)「积分」），每种取值这样写：
  - `cost_credits=null` 或没有这个字段：按入口「说的话要有依据」写「没读到」，不填 0。
  - 新 SDK 应用本次执行有数：「至少 N 积分（不含 X）」，X 写 `cost_excludes` 里列出的来源，例如只有 `sandbox` 写「不含沙盒」，多了 `asset_billing` 写「不含沙盒、平台资产计费」；没有 `cost_excludes` 或为空时写「至少 N 积分，不清楚哪些部分没算进去」；`cost_partial=true` 时再加「有一部分还没取到」。
  - 旧应用 `cost_partial=false` 写「约 N 积分」，`cost_partial=true` 写「至少 N 积分，有一部分还没取到」。
  - 还没跑的写「估算约 N」。估算要写出算法，没有依据的数不写。「不花积分」「免费」也是一个数：要有实测（写出是哪次运行、`cost_credits` 为 0），否则写「估算约 N」和算法。
- 合计（「这一阶段」「一共」）里只要有一条读数 `cost_partial=true`、带不含的来源或没读到，就写「至少 N」；含新 SDK 应用执行时写明不含哪些来源（各条读数的 `cost_excludes` 合在一起，说法同上；有一条没有 `cost_excludes` 时写「不清楚哪些部分没算进去」）；有没读到的再写「有 M 次没读到」，例如「至少 N 积分（不含沙盒），有 M 次没读到」。
- 开发者问慢在哪：按验证、失败重跑、等待分开说，不知道的写不知道。
- **卡住了**：第一句先说他要的事做到哪了（例如「这一版还没上线」）；「刚做完」写这次查了什么、试了什么，再写卡在哪、谁在处理（不知道写「还没确定」）、对他的影响、预计什么时候能继续；平台挡住的和你自己还能做的分开写，自己能做的接着做完，不因为在等平台就把这次当作做完；报错原文不放正文。
- **退回**：写退到哪一段、为什么、要他重新看哪几条。
- **到上限 80%**：状态写「等你确认」，「要你做的」是一道选择题（继续做 / 减少测试份数 / 提高上限）。
- 开发者的回复没答到你在等的事、你还要接着等时，也发一条交接消息，把还在等的事写进「要你做的」。同一个问题问过两次还没答、不答也能接着做的，就不再问，在结论里写明这一项还不知道、会影响什么，接着做能做的；不答就做不下去的（需求和方案的确认、⑤ 的继续改还是接受），每条回复的「要你做的」都写出这道题和怎么回，工单开着等他。

各段交付物的消息（验收报告、上线结果）按那一段 Skill 的模板写。
