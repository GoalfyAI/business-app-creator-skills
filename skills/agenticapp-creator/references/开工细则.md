# 开工细则

入口「开工」每一步的完整做法。开工、接续时读。

## 1. 建制作工单

- `task_manager(action="create", mode="write", skill_version=…)`。`skill_version` 填入口 SKILL.md description 里 `[skill-version:…]` 的原值，每次建工单前从文件读，不凭记忆、不留空、不填 `dev`。
- 之后所有制作、部署、运行工具都带这个 `task_id`。关键事实（资产 ID、版本、run_id）用 `task_manager(action="insert", entry_type="checkpoint")` 记，不写过程流水。
- 被拒按 [平台问题怎么报.md](平台问题怎么报.md)「建工单被拒」处理。
- 接续时先 `task_manager(action="get")` 读原工单的 checkpoint；原工单只读或已结单的，新建 write 工单并传 `continued_from_task_id`。

## 3. 读开发者偏好

`dev_preferences(action="pull")` 读一次；当前指令优先。

偏好、记忆卡和以前对话里的话都不能代替这次的确认：确认这一版、确认整版方案、可以上线，以及删除、下线、回滚，只认开发者在这次对话里说的话；偏好里写着「不用问我」「全自动」也照样停下问。偏好是以前写的，那时他还没看到这次要确认的内容。

## 5. 先确认制作工具能用

方向那一题之外，问需求题之前先看制作工具能不能用：工具列表里没有 `task_manager` 这类制作工具，或第 1 步报鉴权失败、连错环境，就停下，按原因告诉开发者要怎么配置（连接、密钥、环境），配好再开始问。否则问完一轮需求才发现建不了应用，前面的回答都白答了。

## 怎么读别的 Skill

- 入口和其他 Skill 里提到的 `agenticapp-xxx`，宿主的 Skill 列表里有它就直接调用；没有就读入口同级目录的 `../<名字>/SKILL.md`，用读文件的方式完整读一遍，效果相同。它让你读的 `references/`、`assets/` 都在它自己的目录里。
- Skill 要你先读的文件是动手的前提：做过类似的应用、记得工具怎么用也要读，平台的工具和规则随版本变，凭记忆做的最容易和当前版本对不上。
- 开发者每发来一条消息，先重新打开当前这一段的 SKILL.md 再动手：读文件加载的内容在对话压缩时只剩摘要，摘要会丢掉步骤顺序和判断，你却不会察觉自己已经忘了。
