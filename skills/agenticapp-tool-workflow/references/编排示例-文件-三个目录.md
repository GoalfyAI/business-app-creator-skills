# 文件路径与产物正反例（一）：来源与三个目录

编排型 TPE 要读用户文件、随资产文件，或生成中间 / 最终产物时读。诊断关键词：`file_path_contract`、`WORKSPACE_PATH_UNTRUSTED`、`WORKSPACE_FILE_NOT_FOUND`、URL、`/tmp`、`ctx.skill_dir/process_dir/output_dir`。对应契约：`WF-SINGLE-05`。

本文分 2 份：[编排示例-文件-三个目录.md](编排示例-文件-三个目录.md)、[编排示例-文件-返回路径与失败.md](编排示例-文件-返回路径与失败.md)。

编排型 TPE 中的文件有四种来源和用途：

| 类型 | 路径来源 | 用途 |
|---|---|---|
| 用户上传文件 | `input` 中声明 `format: "file"` 或 `format: "image"` 的字段 | 本轮外部输入 |
| 随资产交付的文件 | `skill_file_urls` 上传，脚本通过 `ctx.skill_dir` 引用 | 模板、辅助脚本、合成样例 |
| 本轮过程文件 | `ctx.process_dir` | 转换结果、缓存、中间 JSON |
| 本轮候选交付物 | `ctx.output_dir` | 报告、表格、图片等最终文件 |

把 `/workspace` 文件交给只收 URL 的外部工具（生图、识图、第三方 MCP）时，用**运行期沙箱工具** `file_to_url`（与制作期 External MCP 的同名工具不是一回事）：

```python
r = tool("file_to_url", file_paths=[cover, detail], url_ttl="1d",
         _output={"results": [{"workspace_path": "", "url": ""}]},
         _rationale="把实拍图换成外部生图工具能访问的限时 URL")
url_by_path = {x["workspace_path"]: x["url"] for x in r["results"] if x.get("url")}
```

入参 `file_paths` 是 `/workspace` 绝对路径列表；返回 `results[]` 每项是 `{"workspace_path", "url", "error"?}`——**键名是 `workspace_path`，不是 `file_path`**，按它建映射；`url` 为 null 的项是失败项，必须单独处理，不能拿别的文件或上一轮的 URL 顶上；URL 限时（`url_validity`），用完即弃，不写进 `output`、不落库。真实返回结构以取样为准。

两层要求分开记，别混成一句：

- **节点输出里的文件路径**（`output_schema` 标 `format: "workspace-file-path"` 的字段）：收尾时先做**来源信任**校验，再由 File Service 确认文件在当前用户和项目下真实存在。来源信任只认三类，满足其一即可：
  1. 位于本次 `ctx.output_dir` 下；
  2. 来自本编排型 TPE input 里声明为 `workspace-file-path` 的字段（入口表单上传、上游节点传来的路径走这一类）；
  3. 本次某个工具或 FastAgent 步骤的**返回值里以结构化形式出现**：返回值本身就是 `/workspace/...` 路径字符串，或返回的 JSON / 对象里某个字段的值就是这个路径。

  说明文字里夹带的路径**不算**：`file` 工具写文件的回执是 `File written successfully: <路径>`，shell 的终端回显同理，平台不从这类文字里解析路径。三类都不满足就是 `WORKSPACE_PATH_UNTRUSTED`（报错文案 `workspace output path(s) are not produced by this run or its inputs/tools`），即使文件确实是本次运行写出来的。所以脚本用 `file` / `shell` 写到 `ctx.process_dir` 的文件**不能**作为输出返回；要返回的文件（包括诊断、排查用的文件）直接写进或复制进 `ctx.output_dir`。
- **进 `delivery.mapping` 要交付给用户的文件**：除了上面那条，还必须位于本节点产物目录 `/workspace/task_agent/<taskpoint>/output/` 内，否则 `ORCH_DELIVERY_FILE_UNISOLATED`。来源可信不豁免：入口上传的图片、上游节点的产物、FastAgent 会话目录里的文件，要交付就先复制进 `ctx.output_dir` 再映射；只是输入或参考、不是本次产出的，不进交付文件字段，需要说明就写进 `output` 的普通业务字段。修法不是补 schema 声明——守卫查的是目录。

## 1. `ctx.skill_dir`：不要依赖构建期绝对路径

错误脚本：

```python
async def run(input, ctx):
    result = await tool(
        "shell",
        action="shell_exec",
        command='python3 "/workspace/pre_skills/parse_csv.py"',
        _text=True,
        _rationale="运行随编排型 TPE 使用的 CSV 解析脚本"
    )
    return {"result": result}
```

实际 preview 诊断：

```text
shell 命令里执行了脚本文件 "/workspace/pre_skills/parse_csv.py"，但本编排型 TPE 从没写出过它，也不是随资产交付的。
```

构建会话里临时创建的 `/workspace` 文件不会自动进入用户的真实 Max 项目；固定写入 TPE ID、项目 ID 或个人目录也会在克隆后失效。

最小修复：

```diff
-        command='python3 "/workspace/pre_skills/parse_csv.py"',
+        command=f'python3 "{ctx.skill_dir}parse_csv.py"',
```

先通过 External MCP 的 `file_to_url(purpose="skill_file")` 执行 `prepare → 客户端 PUT → complete`（已有 HTTPS 文件也可用 `from_url`），再把返回的 `data.skill_file` 在同一次 create/update 中提交：

```text
skill_file_urls=[<file_to_url 返回的 data.skill_file>]
```

修复后证据：脚本不再包含构建期路径；Scene create 会确认编排型 TPE 已有或本次上传了 skill 文件，Max 运行时按当前 TPE 注入并挂载真实 `ctx.skill_dir`。

所属契约：随资产交付的辅助文件通过 `skill_file_urls + ctx.skill_dir` 延迟绑定。

## 2. `ctx.process_dir`：中间文件不是默认交付物

目录角色反例：

```python
async def run(input, ctx):
    normalized_path = f"{ctx.process_dir}normalized.json"
    await tool(
        "file",
        action="file_write_text",
        abs_path=normalized_path,
        text=json.dumps(input.get("records", []), ensure_ascii=False),
        _rationale="保存后续步骤使用的标准化中间数据"
    )
    return {"report_path": normalized_path}
```

实际 Runtime 诊断（preview 不一定报错）：

```text
WORKSPACE_PATH_UNTRUSTED: workspace output path(s) are not produced by this run or its inputs/tools
```

文件确实由本次 `file` 步骤写出，但 `file` 工具只返回说明文字 `File written successfully: <路径>`，不属于来源信任认可的结构化返回；路径又不在 `ctx.output_dir` 下，所以收尾被拒，成功输出不会提交。即使来源校验能过，它也把中间 JSON 冒充成最终报告，破坏了目录角色和交付语义——`process_dir` 是否存在文件，不能证明它是用户应收到的产物。

最小修复：过程文件继续放 `process_dir`，真正的候选交付物另写入 `output_dir`。

```diff
     normalized_path = f"{ctx.process_dir}normalized.json"
+    report_path = f"{ctx.output_dir}report.md"
     await tool(
         "file",
         action="file_write_text",
         abs_path=normalized_path,
         text=json.dumps(input.get("records", []), ensure_ascii=False),
         _rationale="保存后续步骤使用的标准化中间数据"
     )
-    return {"report_path": normalized_path}
+    await tool(
+        "file",
+        action="file_write_text",
+        abs_path=report_path,
+        text=input.get("report", ""),
+        _rationale="保存本轮最终候选报告"
+    )
+    return {"report_path": report_path}
```

修复后证据：中间数据和候选交付物有不同路径；最终返回字段指向 `ctx.output_dir`。

所属契约：`process_dir` 存中间状态，`output_dir` 存候选交付物。

## 3. `ctx.output_dir`：不要猜固定 `/workspace/output`

错误脚本：

```python
async def run(input, ctx):
    report_path = "/workspace/output/report.md"
    await tool(
        "shell",
        action="shell_exec",
        command=f'mkdir -p "/workspace/output" && printf "%s" "report" > "{report_path}"',
        _rationale="生成最终报告"
    )
    return {"report_path": report_path}
```

实际诊断边界：静态 preview 可能只看到“脚本确实写了这个文件”而通过；Max 收尾时会按本次 TaskPoint 注入的真实 `ctx.output_dir` 判断来源。固定 `/workspace/output/report.md` 不属于本次 output 目录，也不是可信输入，最终会以 `WORKSPACE_PATH_UNTRUSTED` 拒绝成功收口。

最小修复：

```diff
-    report_path = "/workspace/output/report.md"
+    report_path = f"{ctx.output_dir}report.md"
     await tool(
         "shell",
         action="shell_exec",
-        command=f'mkdir -p "/workspace/output" && printf "%s" "report" > "{report_path}"',
+        command=f'mkdir -p "{ctx.output_dir}" && printf "%s" "report" > "{report_path}"',
```

修复后证据：路径随 TaskPoint 隔离目录动态生成，克隆、换项目和换用户时不携带构建环境信息。

所属契约：本轮新候选产物使用运行时注入的 `ctx.output_dir`。
