# 场景包配置详解（一）：名称、描述、工具集

写或诊断场景包（旧应用）的名称、描述、工具集加载模式时读。

本文分 4 份：[场景包配置-名称描述工具集.md](场景包配置-名称描述工具集.md)、[场景包配置-Skill文本.md](场景包配置-Skill文本.md)、[场景包配置-场景文件.md](场景包配置-场景文件.md)、[场景包配置-知识文件与分工.md](场景包配置-知识文件与分工.md)。

场景包定义一个完整业务场景下 Agent 的能力边界和行为规范。项目启动时选择场景包，Agent 即具备该场景的全部能力。

> 建议先复制官方场景包，再根据业务需求定制。官方场景包已具备完整的基础能力，你只需在此基础上调整工具集组合、新增业务工具集、注入领域知识与流程规范。

---

## 名称

场景包的名称。

### 配置范式

> 名称清晰传达业务定位和能力范围，让用户一眼看懂这个场景包做什么。

**合格示例**：
```
腾讯广告智能投放
跨境电商运营助手
企业客服管理
供应链监控与补货
```

**不合格示例**：
```
我的场景包          ← 没有业务信息
工具测试            ← 看不出业务定位
场景包v2            ← 没有业务含义
```

### 诊断要点

- 名称是否体现了明确的业务领域
- 用户能否仅凭名称判断该场景包的用途

---

## 描述

场景包的功能说明。

### 配置范式

> 2-3 句话：覆盖的平台/系统 + 核心能力 + 适用角色。

**合格示例**：
```
为企业客服团队提供工单管理、客户信息查询、退款处理、满意度跟踪等全流程客户服务能力，支持对接 Zendesk 和企业微信
```

```
提供供应链数据监控、库存预警、自动补货建议和供应商管理能力，适合供应链运营人员使用
```

**不合格示例**：
```
一个很厉害的场景包     ← 没有实质信息
管理各种东西           ← 太模糊
```

### 诊断要点

- 描述是否覆盖了核心能力范围
- 目标用户能否从描述判断这个场景包是否适合自己

## 工具集

选择该场景包可使用的工具集，并设置每个工具集的加载模式（预加载或挂载）。

### 配置范式

| 模式 | 启动时 SA 能看到什么 | 适用场景 |
| --- | --- | --- |
| **预加载** | 工具集的全部信息（描述、技能、Skill 文件路径列表、包含的 FA 和工具） | 工具集的详细能力会影响 SA 的任务规划 |
| **挂载** | 仅工具集的描述，使用时 SA 调用 load_toolset 才加载详细信息 | SA 根据描述即可判断是否需要，使用时再加载 |

**原则**：能挂载就挂载，减少初始上下文长度。

**合格示例**：

假设场景包"企业客服管理"包含以下工具集：

| 工具集 | 加载模式 | 理由 |
| --- | --- | --- |
| project_plan（项目计划管理） | 预加载 | 每次对话都需要分析意图和管理任务 |
| tool_advisor（工具顾问） | 预加载 | 规划阶段需要知道有这个顾问能力 |
| 工单管理工具集 | 挂载 | SA 根据"工单管理"描述即可判断何时需要 |
| 客户信息工具集 | 挂载 | 需要查询客户时再加载 |
| 退款处理工具集 | 挂载 | 涉及退款时再加载 |

**不合格示例**：
- 所有工具集都设为预加载 ← 启动时上下文过长，影响 SA 判断
- 高频使用的核心工具集设为挂载 ← SA 每次都要额外加载，增加延迟

### 诊断要点

- 是否有工具集应该挂载但被设为了预加载（浪费上下文）
- 是否有核心工具集被设为挂载但几乎每次都需要加载（应改为预加载）
- 挂载模式下，工具集的描述是否足够让 SA 判断何时需要加载
