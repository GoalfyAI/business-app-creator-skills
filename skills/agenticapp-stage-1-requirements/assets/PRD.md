# 需求文档（PRD）模板

PRD 只有两块：**概览四行**和**一张业务流程图**。开发者读完要能指着某一步说「这里不对」，所以细节都放进流程图的节点里，不另起章节。花多少、副作用、外部数据、要他提供的、页面长什么样，在 ② 的方案里写（`agenticapp-stage-2-plan` 的方案模板）；选择题在聊天里问，不进文档。

Studio 宿主按 `agenticapp-host-studio` 的需求说明数据写；其他宿主写进方案页（[../references/方案页.md](../references/方案页.md)）：概览进 `.pv-goal` 和「开发内容」开头，流程图进 `#business-process`，节点详情进「开发内容」。

## 概览

| 行 | 写什么（各一行，≤60 字） |
|---|---|
| 服务对象 | 给谁用、多久用一次（[../references/谁来做.md](../references/谁来做.md)「谁来用」） |
| 业务问题 | 现在哪里不方便，用开发者的话 |
| 建设目标 | 做成后有什么不一样；这一轮做到哪一步 |
| 设计思路 | 大致怎么做，一两句 |

## 业务流程图

一个刚需是一个**环节**，按使用顺序排。环节标题旁标核实结论：「已试过，能做」「能做」「要新做，没试过」「做不到，见替代」。

环节里的**节点**是使用者看得懂的一步（「校验并保存」，不是函数），一个环节一般 2–5 个。每个节点标谁做：使用者、应用（脚本）、AI（模型，写档位的说法和每次约多少积分，按 [../references/谁来做.md](../references/谁来做.md)）。点开节点看到：

| 栏 | 写什么 |
|---|---|
| 输入 | 这一步用到的东西，用业务话：使用者填的、上传的，前一步的结果，从外部拿的，读了哪些记录 |
| 输出 | 这一步得到什么。环节最后一步带一个样例：① 里真拿到的写真实数据，还没做出来的标「预期」 |
| 重要信息 | 这一步的规则和标准，见下表 |
| 做不成时 | 这一步做不成时使用者看到什么；没有就不写 |

原来要单独写的内容，写进重要信息：

| 内容 | 写在哪一步 |
|---|---|
| 这样算对、这样不行、怎样算做成 | 环节最后一步。「怎样算做成」写照着做应该看到什么，不写「效果好」；② 照它写验收条目 |
| 会记下来的东西：存什么、有哪些内容、谁写进去、谁能改 | 保存它的那一步。选项列写全部取值和默认值，照抄开发者原话；至少一张业务表；先作草稿还是直接入库按业务风险定 |
| 做不到的替代：替代做法、比原来少了什么 | 被替代的那一步，环节标「做不到，见替代」 |
| 按默认定下的 | 原处标「按默认」（什么算按默认见 [../references/按轮问.md](../references/按轮问.md)「什么算定了」） |

到点或有新记录时自动开始的，画一个「到点开始」的应用节点；返回或复用的线画虚线，写一句为什么回去。只有脚本步骤的应用，加一句「平台要求挂一条最小路线，应用界面可以不发起它」。

```text
环节 2 每天出清单　[已试过，能做]
  到点开始（应用）
    输入：每天 7:00。输出：开始算今天的清单。
    重要信息：一天只出一份，重复触发只更新这一份。
  按规则算清单（应用）
    输入：全部食材和还没用完的批次。输出：快过期 1 项、该补货 2 项（11-05 测试数据实算）。
    重要信息：2 天内到期进「快过期」，低于安全库存进「该补货」；已用完的批次不算。
      怎样算做成：到 7 点清单自动出来，数字和手算一致。存进清单表（日期、三组数字），应用写，不能改。
    做不成时：这一天标「没算完」，下次到点重算。
```

## 不写进 PRD 的

| 内容 | 去哪 |
|---|---|
| 花费上限 | ① 在聊天里问，定成具体积分数，记工单 checkpoint 和阶段文档 G1 |
| 花多少、费用与副作用、要从外面拿的数据、要你提供的 | ① 核实时查清记进 G2；② 写进方案「运行条件」，随方案一起确认 |
| 界面（参考、第一眼看到什么、整体感觉） | ① 照样问，答案记 G1；② 写成方案「制作范围」的信息架构和「功能与页面」 |
| 这次不做的、非刚需 | ② 方案「制作范围」 |
| 选择题 | 聊天 |
