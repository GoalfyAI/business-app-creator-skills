# 制作步骤细则

做 ③「按这个顺序做」第 1–3 步时读。SKILL.md 列顺序、要加载的工具 Skill 和每步的「做成」；这里只补 SKILL.md 没写的做法，编号与 SKILL.md 对应。

## 接续时

接上前核对 PRD 与方案仍是确认过的那一版、资产还在、版本没被别人改、冒泡证据仍是当前合同下的，不成立就回到失效的那一段。

## 第 1 步：先保存第一版制作进度

非 Studio 宿主把方案页 `status` 改成 `data-stage="G4"`、`data-state="working"`，`.pv-state` 写「③ 制作」，`.pv-summary` 写全部功能和各自状态（方案页见 `agenticapp-tool-workspace`）；Studio 宿主下按 `agenticapp-host-studio` 保存制作进度并读回成功。

## 第 2 步：后台能力（G4）

1. 场景包草稿：按 `agenticapp-tool-workflow`「场景包草稿（旧应用）」。
2. 接入缺的工具：需要使用者各自授权的配授权卡。
3. FA：要按情况查应用库的，建时就挂应用库只读工具并反读确认。
4. 工具集：装进核实过的工具组和 FA（脚本要读写应用库时再加 `query_business_app_dataset`）。
5. 编排型 TPE：写第一条前先读 `agenticapp-tool-workflow` 的编排型 TPE 总契约和单编排型 TPE 契约，从三种模板之一复制改业务词，preview 前逐项自查，再 preview → create → online。新 SDK 应用的编排不能用需要运行 Agent 的写法。
6. 反读自查：每条读写应用库的路线 online 后反读，四项各记「有 / 没有」进阶段文档 G4（四项定义在 `agenticapp-tool-workflow`）。任一项「没有」回第 5 小步改；四项都有，这条路线才能标「做好了」。
7. verify：怎么调、各种证据能证明什么按 `agenticapp-tool-workflow`。
8. 路线：`assemble` 出的草稿先处理 `unresolved` 与 `notes`；分支、并行、中途表单、Agent 接管手写接缝。新 SDK 应用把编排和 `tpe_ids` 保存到应用草稿，冒泡传 `business_ui_id`。
9. 拿真实结果：`full_run` 和冒泡的费用方案「运行条件」列过的直接跑，没列过的按入口「红线」的「花钱和对外动作」先问，跑完把实际花费补进交付物；新 SDK 应用读冒泡结果里本次执行的 `cost_credits`，口径见入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)「积分」。

## 第 3 步：数据和页面（G5）

只改表、页面或后端、不碰路线时不用重做第 2 步。下面只列有补充做法的小步。

- 数据模板：开工作集、建表、反读核对施工单的表清单、抽出模板版本、挂到应用并绑工作集。按 `agenticapp-tool-data-template`。
- 前端页面：场景包契约进前端、业务页、业务文案接到实际页面和动作、清起始件并对齐路由。方案的信息架构和「功能与页面」是页面的最高依据，先按信息架构定导航、主工作区和信息优先级，再选预置件，空库要有引导；上线后必须存在的设定放哪按 `agenticapp-tool-data-template`。演示和示例要放真实成果的，先放 ① 真拿到的数据；模型要写的内容还没实际跑出来时放一份标明「示例」的占位，阶段文档 G5 记「待 ④ 回写」和位置。
- 在演示版上跑：命令见 `agenticapp-tool-workspace`。在线预览到 ④ 部署后才有；两个预览的区别见 `agenticapp-tool-workspace`「演示预览与在线预览」，Studio 宿主下的演示按 `agenticapp-host-studio`。
