# 演示版页面验收

④ 逐条验页面条目、演示版或无头浏览器起不来时读。条目怎么判结论、哪些能记「未测」见 `agenticapp-stage-4-acceptance`；浏览器边界的红线见入口「红线」，这里写具体做法。

## 只访问演示版地址

- 浏览器（Playwright 无头 Chromium）只打开演示版输出里的地址（`127.0.0.1` 或 `localhost`）。GoalfyMax 正式入口、登录页、在线预览或演示预览的地址、容器地址要走平台登录和身份注入，不在你要访问的范围里；开发者已登录的会话也不借用。
- 访问被工具审批拒绝时到此为止：不重试、不绕过，也不请开发者放开授权。它是工具限制，不当作平台或应用故障上报。

## 做法

顺序：`npm run dev:restart` 起演示版 → 等 `Bridge ready` 后照条目操作 → 记步骤、截图路径、演示版路由 → 同一份代码跑 `npm --prefix frontend run check` 与 `test:e2e:layout` → 关浏览器、`npm run dev:stop`。

1. **起演示版**：在应用根 `npm run dev:restart` 后台起演示版（工作区里起的后端加 Dev Host，SDK 的平台能力由内置 Mock 提供），从输出读 Dev Host 地址（默认 `http://127.0.0.1:5176/`），`npm run dev:status` 看是否在跑。命令、端口和首次安装 Chromium 见应用里的 `frontend/docs/dev-host-testing.md`。Studio 宿主下桌面入口已在跑当前工程的开发服务时直接用它，不另起、不停掉（见 `agenticapp-host-studio`）。
2. **无头操作**：用 Playwright 无头 Chromium 打开 Dev Host 地址，等页面顶部出现 `Bridge ready`、应用内容出现后再操作和截图；内容区空白的截图不作证据。只做验收条目里的点击和输入；条目里有付款或授权的，做到付款或授权窗口出现为止，演示版里的结果是 Mock。
3. **记证据**：每条记操作步骤、截图文件路径（写进阶段文档 G6；不截图的写断言原文）和打开过的演示版路由。
4. **在工作区跑检查**：同一份代码跑 `npm --prefix frontend run check` 与布局回归 `test:e2e:layout`，结果写进验收报告。
5. **收尾**：关闭浏览器；演示版是你起的，用 `npm run dev:stop` 停掉。做成：`npm run dev:status` 显示演示版已不在跑。

演示版里的平台能力是 Mock：依赖平台登录身份、真实宿主桥接的部分，演示版上看到的不作证据，按 `agenticapp-stage-4-acceptance` 的「未测」表记，只读置灰怎么验也见它的「证据与未测」；要看空库时页面怎么显示，清空演示版的 Mock 数据看。

## 演示版起不来

`npm run dev:restart` 失败、缺 Chromium 或系统库时你自己修：按输出补依赖，按 `frontend/docs/dev-host-testing.md` 装 Playwright Chromium（例如 `npx playwright install chromium`）。端口被占时换端口，只停你自己这次启动的进程，不按名字批量杀：同一台机器上可能有别人的服务。工程本身的问题回 ③ 修。修好后再测这几条；仍起不来的记「未测」，原因写「演示版跑不起来」，加做过的处理和错误原文。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 把演示版里 Mock 出来的身份、授权、付款当成线上验证通过 | 这些记「未测」 |
