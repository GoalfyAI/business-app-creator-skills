# 还没有数字的项

需求的量级可能撞上、但还没有数字的边界。遇到时按 SKILL.md「还没有数字时」处理：真调一次、问开发者分批，或报 `platform_limit`。**不要编数字**，也不要从别的应用、别的环境的经验推一个数写进 PRD。

## 运行时长与并发

| 项 | 已知的 | 需求什么样会撞上 |
|---|---|---|
| 正式运行（`workspace` 真跑、在线预览、使用者发起）的单次时长上限 | 只有冒泡的 30 分钟；自动化可以声明 `timeout_minutes`，超过平台停掉项目记「超时」 | 一次处理很多条、要等外部平台出结果、模型要写很长的内容 |
| 同一使用者同时运行的路线（项目、执行）数 | 新 SDK 应用运行中的执行有上限（`EXECUTION_LIMIT_REACHED`），数字没写 | 使用者一次发起很多份、页面上批量点「开始」 |
| 同一应用所有使用者同时运行的总数 | 没有 | 很多使用者在同一时间段用 |
| 一条路线内并行节点数、扇出个数 | 路线支持并行、扇出，数字没写 | 「每个门店 / 每个计划各跑一份」这类扇出 |
| 一个 TPE 内并行工具调用数 | 没有 | 脚本里同时调很多次外部工具 |
| 模型调用的并发与速率 | 异常 `recoverable=True` 包含限流，可换时机重发 | 一次让很多 FA 同时判断 |
| 一次执行里状态记录的上限 | 有上限（`EXECUTION_STATE_LIMIT`），数字没写 | 同一执行里反复重试、反复修正 |

## 自动化

| 项 | 已知的 | 需求什么样会撞上 |
|---|---|---|
| 事件触发的每小时上限 | `max_runs_per_hour` 必填，取值范围以 `validate` 返回为准 | 数据变化很频繁 |
| 排队上限、批量改动时逐条触发的行数、连续失败几次自动暂停、变化后多久发起 | 这些数值归平台管理、会随平台调整，制作时不按固定数值设计，以 `validate` 返回和平台当前配置为准 | 批量导入后想逐条自动处理；要求「改完立刻处理」 |

## 数据量与资源

| 项 | 已知的 | 需求什么样会撞上 |
|---|---|---|
| 应用库单表行数、查询耗时 | 没有 | 长期累积的历史记录、明细表 |
| 应用库连接数、写入吞吐 | 没有 | 一次写入很多行、很多执行同时写 |
| 文件产物（`ctx.process_dir`、`ctx.output_dir`）单文件与总量 | 没有 | 生成大文件、很多附件 |
| 页面上传文件的大小 | 没有；载荷上限只知道 `sdk.api.request` 的 256 KiB | 上传大表格、大图、视频 |
| 专属后端的容器资源和并发请求能力 | 没有 | 后端做重计算、很多人同时访问 |
| 部署占用上限 | 有上限（`BUSINESS_UI_DEPLOYMENT_QUOTA_EXCEEDED`），数字没写；超限时由开发者决定释放哪个 | 同时有很多应用部署着 |

## 页面

| 项 | 已知的 | 需求什么样会撞上 |
|---|---|---|
| 页面加载时限 | 没有 | 首屏要等大量数据或慢接口 |
| 正式页打开时宿主回查的时限 | 没有 | — |
| 宿主转发 `sdk.api.request` 的超时 | 没有 | 后端接口要处理很久才返回 |

## 费用

| 项 | 已知的 | 需求什么样会撞上 |
|---|---|---|
| 各档模型每次花多少积分 | 以实测为准：第一次真跑后读 `cost_credits`；没测过的写「估算」（入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)「积分」） | 天天跑、每次跑很多条 |
| 外部工具的限流和单价 | 因工具而异，看工具说明或安全取样一次（取样方法见 `agenticapp-tool-integration`） | 高频调用付费工具 |
