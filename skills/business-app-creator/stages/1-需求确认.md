# ① 需求确认（工作区阶段 G1、G2）

交给开发者一份确认过的 PRD：要什么、不要什么、谁来用、每一步谁来做、能不能做、做不到的怎么替代、花多少、用多少。「能不能做」建立在平台上真查过、真调过的基础上，所以和开发者沟通的同时就去核实，PRD 交出去时已经带着核实结论。这一段只交 PRD 这一份文档（Studio 下是开发文档 PRD）。

这一段要让开发者看明白两件事：这个应用能不能满足自己的业务需求；每件事会怎么走。看明白了，开发者才能指出哪里不对。

## 1. 进入条件

- 开工已完成（[../SKILL.md](../SKILL.md)「开工」）：有 write 工单、应用工程已初始化或接续、交付物已有最小草案（Studio 下记在阶段文档 G1）。开发者只给一句话、方向还不清楚时，方向那一轮在开工前发，方向定了再开工（同一节）。要问开发站点时，站点题和 ① 第一轮的题一起发，初始化在收到答案后做，最小草案在下一条消息前写好。
- 开发者给了任一材料：一句话目的、需求文档或 PRD、SOP、会议纪要、原型、截图、草图、参考项目、已有应用的问题。
- 从修订进来时，只确认这次要改的部分；只改文案、样式的不进这一段。两者都按 [../tasks/修订.md](../tasks/修订.md) 的改动起点表。

## 2. 段里怎么做

### 2.1 读材料

按 [../design/按轮问.md](../design/按轮问.md)「从开发者给的东西开始」读开发者给的全部材料，不加推测，把写明的事记成「已定的事」，缺的留给 2.2 去问：

- 谁来用、使用者做什么；材料里提到的别人参与（审核、复核、领导看汇总），按 [../design/谁来做.md](../design/谁来做.md)「谁来用」处理；
- 判断点、交付物、要存下来的东西、开发者提到的数量（一天几次、一次多少条）；
- 一次记录代表的整体业务对象、每个入口实际做什么、什么时候只算提交或受理、实际会产生什么结果（没有产物也记明），命名按 [../reference/前端页面.md](../reference/前端页面.md)「业务文案」；这些和其他业务事实一起在 PRD 里确认，不另加文案确认轮次；
- 截图、原型、参考应用、草图，或对话里说过的页面样子（有哪些页、每页放什么、怎么排），记进 PRD「界面」。

需求方和开发者不是同一人时，记下需求方是谁；需求方的原话、文档、会议结论和开发者的话同等对待，冲突的做成选择题（请谁答见 [../design/选择题与判断题.md](../design/选择题与判断题.md)「选择题」）。开发者明确要求先理一理业务时，按 [../design/咨询模式.md](../design/咨询模式.md) 做。

### 2.2 按轮问

按 [../design/按轮问.md](../design/按轮问.md) 一轮一轮问：从 ① 的起步方向排树，「每个应用都要问的题」（含界面三问（参考、第一眼看到什么、整体感觉））开发者没说过的都要问到。第一轮看完材料马上发，不等核实做完；之后每轮按上一轮的答案和 2.3 查到的结果，问新变成「现在就能问」的题，问到树上没有空着的节点为止。

问完发「我理解的是这些」，开发者回「对」再写 PRD。每轮都是一条交接消息，开头「【① 需求确认 → 等你确认】」，「下一步」写这轮答完后接着问什么或开始写 PRD。

### 2.3 同时核实

和开发者沟通的同时，对 PRD 里的每一步做下面几件事。这是你内部的工作：结论用业务话写进 PRD，资产 ID 和试调细节只写进 G2。这一段只查不建（[../SKILL.md](../SKILL.md)「红线」）：开发者回「确认这一版」之前，工作区最多标到 G2，不建业务资产、不写编排脚本、不建表、不部署；开工建的工单和工作区、第 3 步的能力试用包不算「建」。

1. **逐项查**：按步骤找平台上现成的东西，工具调用写法见 [../reference/平台对象速查.md](../reference/平台对象速查.md)「工具速查」。

   | 要做的步骤 | 去查 |
   |---|---|
   | 脚本要调的外部能力（拉数、发送、查询） | 工具组 / 工具集：工具名、参数、是否要授权卡 |
   | 模型步骤 | FastAgent：输入字段、输出形状、模型配置 |
   | 整条路线像已有应用 | 场景包：路线与编排型 TPE |
   | 要存的表 | 数据模板：已有表与列的可编辑性 |
   | 页面 | 应用工程的脚手架预置件清单 |

   别人分享来的工具组搜不到或看不到参数时，按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md)「分享来的工具组」处理；仍没取到真实返回的，核实结论写「能用，没取到样」，PRD「能不能做」那一行写「已有现成工具，还没真试过，制作时第一次真跑核实；分享人收回或改动后这一步会停」。

2. **真调一次**：名字对上不算。安全只读的工具按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md)「工具取样」取样，看返回是不是 PRD 要的那个对象。要外部数据的，用开发者的账号或开发者给的样例真拿一次；拿回来的真实数据放进 PRD 当样例，客户姓名、电话、证件号这类个人信息打码后再放。不能取样的工具只看参数说明，判定见第 4 步。取样要花钱时按 [../SKILL.md](../SKILL.md)「花费」先问。
3. **模型步骤拿不准时试一次**：关键的模型步骤（报告、方案、诊断这类直接交给使用者的内容）效果或用时拿不准，或拿不准用哪一档（[../design/谁来做.md](../design/谁来做.md)「模型选哪一档」）时，按 [../tasks/能力试用.md](../tasks/能力试用.md) 建一个极简试用包，用开发者的一两条真实样例跑，记下输出、用时和花费。试跑会花钱：先在题里说清份数和约多少积分，开发者同意后再跑；单价还没查到时等查到再出这道题（[../SKILL.md](../SKILL.md)「花费」）。
4. **判定能不能做**：

   | 情况 | 写进 PRD「能不能做」 | G2 记下 |
   |---|---|---|
   | 工具返回覆盖需要 | 能做，用平台现成的；要授权的确认已有授权卡，没有的写进「要你提供的」 | 复用 |
   | 发信、发布这类不能取样的工具，参数说明覆盖需要（发给谁、发什么） | 能做，用平台现成的，没真发过；④ 只发给开发者自己试一次。发到应用自己的消息中心不算向外发送 | 复用，未取样 |
   | 已有 FA 输出能覆盖「拿出来」 | 能做，用平台现成的 | 直接复用；差一两个字段时复制后改提示词 |
   | 官方或他人的场景包像这条路线 | 能做，用平台现成的 | 复制后改；自己的草稿接着改 |
   | 已有模板缺列 | 能做 | 加列出新版本（[../reference/数据模板.md](../reference/数据模板.md)），不另建同义表 |
   | 平台上没有，外部有现成 MCP 或 Skill 包（确认现有工具换更好的指引或组合也做不到，才接入） | 能做，要接入 | 按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md) 接入 |
   | 确定性的计算、存取 | 能做，要新做（脚本） | 新做 |
   | 要模型、平台上没有 | 能做，要新做（模型）；试过的写「已试过」 | 新做 |
   | 都不行、授权接不上、时间或费用达不到 | **做不到**：写原因、影响哪个功能，当轮给替代选择题（换做法 / 改范围 / 等平台） | 要平台补的能力记一条开发需求；开发者选「等平台」时该功能本次不做，按 [../SKILL.md](../SKILL.md)「平台问题」汇总 |

5. **算花费**：付费工具按单价算；模型步骤按 [../design/谁来做.md](../design/谁来做.md)「模型选哪一档」定档，有试跑的用实测，没有的写估算（口径见 [../reference/平台对象速查.md](../reference/平台对象速查.md)「积分怎么算」）。算出：做这个应用（开发和测试，① 到 ⑤）预计多少；上线后每用一次约多少；按用量题的答案算每周约多少。

### 2.4 写 PRD

开发者对「我理解的是这些」回了「对」之后，按 [../design/PRD.md](../design/PRD.md) 写；「谁来用」「每一步谁来做」按 [../design/谁来做.md](../design/谁来做.md) 写。Studio 下写成开发文档 PRD（[../design/开发文档/README.md](../design/开发文档/README.md)）。

### 2.5 发出与批注

写好交付物（方案页；Studio 下是开发文档 PRD），发交接消息（[../design/交接消息.md](../design/交接消息.md)），开头「【① 需求确认 → 等你确认】」，「要你做的」列：读 PRD 哪里不对就说、答选择题、提供材料和授权、都没问题回「确认这一版」。需求方和开发者不是同一人时，加一项「把 PRD 转给需求方看，或让需求方直接答第 N 题」。

开发者批注后按 [../design/PRD.md](../design/PRD.md)「版本、批注和确认」出新一版，直到开发者确认当前这一版；批注里引出的新问题照 2.2 的问法问。

## 3. 开发者要看、要做的

- 读 PRD，看每个刚需放进去的是不是自己有的、拿出来的是不是自己要的，哪里不对就指出来。
- 确认谁来用、看到什么；确认刚需和非刚需的划分、反向案例、怎样算做成。
- 看真实拿回来的数据，确认是自己的、是要的。
- 对做不到的事选替代做法；定花费上限和上线后的用量；答选择题；同意或不同意试跑。
- 提供材料、账号、授权、数据分享（有操作步骤就带着做）；分享来的工具组搜不到时给工具组 ID 或请分享人再分享。
- 回「确认这一版」。

## 4. 产出与落盘

- 交付物：PRD 全文按 [../design/PRD.md](../design/PRD.md)「有哪些节」写进方案页（版式与状态块见 [../design/方案页.md](../design/方案页.md)）；Studio 下写成开发文档 PRD。
- 阶段文档 G1：「已定的事」（每条写是什么、谁说的或按默认、哪一轮定的）、开发者和需求方原话里的关键事实、确认版 PRD 全文（只在这里存一次）、每一版 PRD 的改动、选择题及谁答的、确认时间与原话。
- 「要你提供的」（方案页 `needs`，版式见 [../design/方案页.md](../design/方案页.md)）：G1 列出，G2 核实资产时补全。
- 阶段文档 G2：核实对照表：

  | PRD 里的步骤 | 复用什么（资产 ID） | 取样结论（真调返回摘要、花费） | 缺什么 / 怎么处置 |
  |---|---|---|---|

  「缺什么」那一列就是 ② 编施工单、③ 要造的清单。
- 工单 checkpoint：`PRD 已确认`，附应用名、刚需列表、路线名、表名、花费上限、用量；核实对照表摘要。
- 出口标记：G1、G2 `passed`，用 `business_ui_stage` 写 G1、G2 各一条（写法见 [../reference/开发者中心与工作区.md](../reference/开发者中心与工作区.md)「三件套与阶段标记」）。

## 5. 交棒条件

- 写 PRD 前开发者对「我理解的是这些」回了「对」；
- 开发者确认了当前这一版 PRD（什么算确认见 [../design/PRD.md](../design/PRD.md)「版本、批注和确认」；Studio 下读到这一版的确认）；
- 每个刚需都有放进去 → 拿出来、这样算对、这样不行、怎样算做成；
- 每一步都标了脚本、模型或人，并有核实结论；做不到的都有开发者选过的替代；
- 选择题都有答案（开发者答的、需求方答的或标「按默认」），用量有；花费上限是一个具体的积分数，写在 PRD 和工单 checkpoint 里，「待定」「看情况」不算；
- 交付物里没有开发者看不懂的词，没有模板占位文案；
- 出口标记已写。

## 6. 出问题怎么办

| 现象 | 怎么做 |
|---|---|
| 开发者说不清要什么 | 按 [../design/按轮问.md](../design/按轮问.md)「从开发者给的东西开始」先探讨方向，给两三个具体做法让他选；开发者明确说「帮我先理一理业务」「不确定该做什么」时才进 [../design/咨询模式.md](../design/咨询模式.md) |
| 需求里有红线内容 | 按 [../SKILL.md](../SKILL.md)「红线」停止 |
| 取样报参数错、路径不存在 | 按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md)「工具取样」核对文件参数收 URL 还是 `/workspace` 路径，再取一次 |
| 工具要使用者各自授权 | 按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md)「授权卡」，写进 PRD「要从外面拿的数据」 |
| 资产受限或脱敏 | 按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md)「分享来的工具组」处理，结论写进 PRD，开发者确认 PRD 时一并确认 |
| 核实发现关键功能做不到 | 当轮写进 PRD「能不能做」并出替代选择题（2.3 第 4 步） |
| 开发者只想讨论、暂不开发 | 按 [../tasks/仅讨论.md](../tasks/仅讨论.md)；讨论落到具体应用时仍写交付物 |
