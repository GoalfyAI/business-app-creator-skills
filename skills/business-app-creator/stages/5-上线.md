# ⑤ 上线（工作区阶段 G7）

开发者说「可以上线」后，定版验收过的那一版，交一份开发者读完就能自测、发布、教使用者用的交付报告。发布到目录由开发者自己在发布管理页操作。

## 1. 进入条件

- ④ 交棒：每条验收条目都有结论，开发者（和需求方）说了「可以上线」。
- 上线是外部状态变更：只有开发者这次明确说了「可以上线」或等价表述才执行。

## 2. 段里怎么做

1. **场景包版本核对**：④ 之后改过场景包的，重新部署应用，让试用跑的是最新草稿。场景包不用单独上线，下一步定版应用时会先校验、再把挂着的本人场景包草稿一起定版上线。
2. **定版前自查试用数据**：试用里确认过、上线后还要用的设定是否只存在开发工作集里；是的话先按 ③ 2.2 第 5 步搬到代码默认值、场景包配置或首次设置入口，重新部署后再定版。
3. **定版应用**：`business_ui_manage(action="finalize", draft_asset_id=…, task_id)`；场景包草稿随它一起上线，定版后反读两者的版本号记进工单。被拒按 [../reference/部署与版本.md](../reference/部署与版本.md) 的定版错误码处理。
4. **反读**：`business_ui_manage(action="resolve")` 核对上线版本与挂载的场景包版本，`entry_url` 非空说明入口已写进版本；resolve 报没有上线版本说明定版没生效，**禁止**宣称已上线。`entry_url` 是开发者容器地址，**禁止**写进交付报告或发给任何人当入口。
5. **发布提示**：告诉开发者在发布管理页发布；上线只影响开发者自测，没发布时使用者打不开（`BUSINESS_UI_NOT_RELEASED`）。上线后开发者本人已能从「我的资产」进正式入口正式使用；有自动化的应用（到点或数据变化时自动开始），真实规则在这里开，见 [../reference/自动化.md](../reference/自动化.md)「验证」。
6. **结单门**：每条路线要以当前合同下最近一次到终态的运行通过，路线冒泡和真跑都算（真跑以 `route_runs` 里该路线 `succeeded` 为通过）。最近一次失败或没法验证时，先问开发者是否接受，再写（真跑失败时 `run_id` 填那次的 `project_id`）：

   ```text
   task_manager(action="insert", entry_type="checkpoint", metadata={"evidence_type": "route_verification_waived", "scene_package_id": …, "orchestration_id": …, "reason": "<至少 5 个字>", "run_id": <失败那次；没跑过就不带>})
   ```

   一条路线一条。`complete` 被拒（如 `WORKFLOW_TASK_ROUTE_BUBBLE_EVIDENCE_REQUIRED`）时按返回里逐条给的出口做，**禁止**删标签、改文字或另开工单绕过，也不要反复重试。
7. **算总花费**：对工单里记下的每个冒泡、真跑项目重新读一次 `cost_credits`（沙盒按周期记账，刚结束时可能没算全），汇总开发期累计，和 ① 的上限比。
8. **交付报告**：按下面第 3 节写，写进工单 `task_manager(action="insert", entry_type="result")`、方案页和发给开发者，然后 `task_manager(action="complete")`；结单响应里的 `delivery_note` 原样补进报告。本轮记下的已绕过平台问题和功能诉求，此时汇总成一条 `submit_dev_feedback`（`blocking` 按主要情况选 `worked_around` 或 `request`），没有就不提。
9. **阶段评分**（仅 Codex）：交付报告发出后，按 [../design/阶段评分.md](../design/阶段评分.md) 单独发一条「G7 正式上线」评分；G6 的评分还没回时，这条**必须**先列 G6 的三项、再列 G7 的三项；它和上一步的问题反馈是两条，**禁止**合并。
10. **开发工作集保留**：上线后开发工作集继续绑定在应用上，**不要**解绑、不要为它重新 `deploy`、不要 `close`。开发版（在线试用）只能连工作集，下次修订改表结构也在这个工作集上改（见 [../reference/数据模板.md](../reference/数据模板.md)「改已上线的模板」）；它只给开发者用，改它不影响使用者各自的实例库。解绑后 `deploy` 会报 `BUSINESS_UI_PREVIEW_DATA_UNBOUND`，`close` 会被 `TEMPLATE_WORKSPACE_IN_USE_BY_DEPLOYMENT` 拒绝，遇到说明走错了，重新 `bind` 回原工作集即可；**禁止**为此 finalize 派生出来的草稿、下线或删除应用。工作区用 `workspace_push` 保存到云端。

## 3. 交付报告

给开发者的部分用业务话写，结论先行，每一句「已验证」都能指到证据：

| 项 | 写什么 |
|---|---|
| 怎么打开 | 开发者：GoalfyMax → 我的资产 → 智能应用 → <应用名> → 打开（正式入口 `/business-ui/<家族 ID>`，不需要发布；不要把开发者中心的「预览」按钮当成上线后的自测入口）。使用者：等开发者在发布管理页发布后，从目录打开或用分享点「立即使用」。不写容器地址 |
| 上线和发布的区别 | 现在已上线：只有你能用。发布后使用者才能打开；发布给谁、什么时候发布由你定 |
| 使用说明 | 每种人第一次打开看到什么、先做什么（正式版按模板建每个人自己的一份数据，打开是空的）；平时怎么用，按业务顺序一句话；一段时间没人用会自动休眠，再打开时第一次稍慢 |
| 试用数据 | 试用里的数据不会带到正式版；要用的设定已经写进应用 |
| 验收结论 | 每条验收条目的结论，开发者和需求方是否都说了「可以上线」 |
| 还没验证的和风险 | 没法验证的项、能力缺口、上线后要留意什么 |
| 花费 | 做这个应用一共花了多少（和上限比）；以后每用一次约多少，按 PRD 的用量每周约多少 |
| 改已上线的应用时 | 正在用的人会看到什么变化，已有数据怎么处理；平台限制（例如使用者手上的应用不随发布自动更新）照实写 |
| 你要做的 | 1. 打开正式版，用一个没试过的真实样例走一遍；2. 有定时任务的，在正式版的「自动化」面板打开，先点「立即运行」看一次结果，再等第一次到点触发，告诉我结果对不对；3. 在发布管理页发布；4. 把应用分享给要用的人 |

给后续 Agent 的部分写进工单和阶段文档 G7，不发给开发者：应用名、上线版本、是否已发布；部署状态（`success`）与 `deployment_id`、`source_sha256`、`deployed_scaffold_version`（低于建议线时写「当前 vX 低于建议线 vY，建议下一轮升级」；有 `scaffold_upgrade_notice` 原样写）；场景包定版版本、已验证路线与 `run_id`、豁免的路线与理由；数据模板 ID 与版本；真跑 `project_id` 与结论，或省略真跑的原因；验收清单通过项数、不适用项、未验证项；修订时 `compare_asset_versions` 取的前后配置差异。

## 4. 开发者要看、要做的

- 读交付报告，确认写给使用者的用法对。
- 按「你要做的」四步自测、打开定时任务、发布。
- 决定发布给谁、什么时候发布；改已上线的应用时，确认对正在用的人的影响能接受。

交接消息开头「【⑤ 上线 → 已完成】」，「要你做的」就是交付报告里的四步。

## 5. 不给开发者的

定版过程、版本号、结单门、容器地址。

## 6. 产出与落盘

- 工单：交付报告（`entry_type="result"`），`complete` 成功。
- 阶段文档 G7：交付报告全文、给后续 Agent 的部分；「阶段评分」一节按 [../design/阶段评分.md](../design/阶段评分.md) 记录。
- 方案页 `status` 改为 `done`，`.pv-summary` 写上线结论，`.pv-meta` 写开发期累计花费；「已验证 / 未验证」与交付报告一致。
- 阶段标记：G7 `passed`。

## 7. 结束条件

- 上线的是 ④ 验收过的那一版：`resolve` 能取到上线版本，且 `entry_url` 非空；
- `task_manager(action="complete")` 成功，交付报告已写入工单与方案页；
- 开发者已发布或说了暂不发布。

## 8. 出问题怎么办

| 现象 | 先看 | 回到 |
|---|---|---|
| 定版被拒 | [../reference/部署与版本.md](../reference/部署与版本.md) 定版错误码 | ④ 或 ③ |
| 结单被拒 | 返回里的路线状态；补一次路线冒泡或真跑，或问开发者后写豁免 | ③ 或 ④ |
| 开发者上线后要改 | [../tasks/修订.md](../tasks/修订.md)，新需求从 ① 走 | — |
| 要下线、回滚、删除 | [../reference/部署与版本.md](../reference/部署与版本.md)，每一步都要开发者确认 | — |
