# G7 预发布与交付：确定"现在交付的版本就是验过的版本"

> 阶段层文件。这是整套业务应用的总出口，**不把能力容器（场景包）工单结单误认为应用已交付**。方法在 [P6](../modules/P6-验证与证据裁决.md)（最终测试）、[P7](../modules/P7-版本部署与上线.md)（定稿、发布、迁移、回滚）、[P8](../modules/P8-诊断归因与改进验证.md)（后续问题入口）。

## 1. 进入依据

候选应用使用闭环（G6）通过；发布范围确定；存在准确的 能力容器 / 应用 / 数据模板 版本关系。

## 2. 本阶段建设

1. **对最终预部署物运行完整适用验收集**：全部业务承诺、功能、路线、数据操作、关键非功能要求；开发中的增量复验不代替此门（P6 的 A4 §4 自动化测试门三类 + §5 真联调与授权边界取证）。
2. **汇总证据**：真实产物、端到端操作、错误恢复、权限、耗时费用；必要时做已授权的受控试用。
3. **版本绑定与迁移**：能力容器、应用、数据模板版本一致；模板迁移彩排；升级后已有用户数据的处理（P7 的 A5 闸门码表）。
4. **四种动作分清**：能力容器上线、应用部署、应用定稿上线、目录发布；只执行明确授权的动作，之后反读最终入口与版本。
5. **交付**：运行边界、遗留事项、诊断路径、恢复方案；回滚应用不等于数据库可降级。交付报告含价值假设原文、能力矩阵终版、分工理由、剩余风险、观察指标基线（首次可用交付耗时、用户投入分钟数、纠错与返工次数、采用比例、确认率、每次成功费用）；客户初始化清单只做一次。

## 3. 给开发者看什么

**交付核对单**：本次承诺、实际可用能力、当前版本、通过证据、未覆盖范围、发布影响；每个阻断项直接可见，不埋进日志。

## 4. 要确认哪些边界

发布对象与人群；风险接受范围；上线授权；费用边界；试用退出条件；故障处理责任。未授权的自动通知、跨应用操作、公共策略更新不随发布附带启用。

## 5. 门禁 Checklist（G7）

- `G7-01` 交付范围的 G 门禁有对应 U 用例与专业验收证据；每项注明目标版本、适用范围、失败 / 阻断 / 偏差。
- `G7-02` 最终部署版本完成全部适用行为用例、专业测试与关键组合旅程：首次发起 → 必要补充 → 离开返回 → 修订 → 确认 → 再次使用。
- `G7-03` 应用、能力容器、工具依赖、数据模板版本一致；最近变更没有使已有证据失效。
- `G7-04` 迁移与恢复策略有验证依据；恢复不静默丢用户数据；不把删除当停用。
- `G7-05` 发布动作有授权；上线后反读入口与版本成立才称已上线；部署成功不等于用户已可用。
- `G7-06` 效果回传关联、下一轮使用、受控改进对照分别有结论（U6-05/U6-06）；无长期样本不宣称业务收益提高；U7/U8 仅在纳入范围且实测通过时交付。

## 6. 证据与结论

产出：交付清单、最终测试报告、版本清单、上线反读、迁移 / 恢复记录、后续问题入口；工单 `autotest`、`integration`、`delivery_report`，结单。

## 7. 失败回退

失败回问题所属阶段，不以关工单为目标放宽标准。交付后的真实问题与效果证据确定影响范围后重入 G1（P8）。

## 继承与调整

A4 最终测试 + A5 发布 / 迁移 + S5 / SD 版本与影响分析；应用验收是总出口。主责 P6 / P7 / P8。
