# 开发文档：在 Studio 里交给开发者的四份 HTML

宿主提供 Studio 制作工具（工具列表里有 `studio_write_proposal`）时，PRD、方案、制作进度、验收报告各写成一份 HTML，显示在 Studio 的「开发文档」里，代替方案页。四份共用一套样式和组件，照这里的模板写，不自己设计版式。工具机制见 [../../reference/开发者中心与工作区.md](../../reference/开发者中心与工作区.md)「Studio 宿主」；没有这些工具时写方案页，见 [../方案页.md](../方案页.md)。

## 哪一段写哪一份

| 文档 | 第一次写 | 之后更新 | documentType | 要开发者确认 |
|---|---|---|---|---|
| PRD | ① 按轮问问完、开发者回「对」之后，写第 1 版 | 开发者批注后出新一版 | `prd` | 要，确认这一版 |
| 方案 | ② 取舍、验收要求和费用变化问清之后 | 按修改意见出新一版 | `proposal` | 要，只确认一次整版 |
| 制作进度 | ③ 开始时 | 有实质进展时，见 [制作进度.md](制作进度.md)「什么时候更新、改哪些」 | `progress` | 不要 |
| 验收报告 | ④ 报告过了硬门之后 | 按反馈重测后出新一版；⑤ 上线后在最后补「上线结果」，再出一版 | `acceptance` | 开发者看完回「可以上线」 |

- 只写当前段的文档：① 里只有 PRD，② 里才有方案，依此类推。还没到的段不写，也不写「暂无」「未开始」的占位页。
- 开工时记下的业务目标、范围和待明确事项按 [../../SKILL.md](../../SKILL.md)「开工」记在阶段文档，不交 PRD 草稿。

## 怎么写一份

1. 读 [样式.md](样式.md)、这份文档的版式文件（[PRD.md](PRD.md)、[方案.md](方案.md)、[制作进度.md](制作进度.md)、[验收报告.md](验收报告.md)，末尾有完整样例）和 [检查清单.md](检查清单.md)。内容写什么按版式文件开头指向的段文件或 design 文件。
2. 在应用工程里写 `docs/studio/<documentType>/index.html`：开头照 [样式.md](样式.md) 原样复制，正文照抄版式文件的骨架，把每个【填：…】换成真实内容（版式文件末尾样例里的门店、数字、`project_id`、截图文件名只用来示意，写的都是你自己查到、跑到的）。标着「重复」的块按实际数量复制，多余的删掉；`<!-- -->` 注释写完后全部删掉。方案另写 `docs/studio/proposal/acceptance.json`。
3. 页面只用来读：不放按钮、输入框、表单和「确认这一版」之类的入口，也不写请开发者去在线预览、演示预览或正式入口里点、试、查的话（不请开发者代测见 [../../SKILL.md](../../SKILL.md)「红线」）。
4. 写文档前的澄清题不放进页面：在聊天里用表单问（[../../reference/Studio表单与卡片.md](../../reference/Studio表单与卡片.md)），答过的写进文档对应位置。
5. 按检查清单逐条自查，P0 全部满足才交；自查结果写进当段阶段文档，不发给开发者。
6. 调 `studio_write_proposal`：`documentType` 按上表，`version` 写 `<documentType>-<版本号>`（例如 `prd-2`、`progress-7`），`files` 放 `index.html`，方案加 `acceptance.json`。保存成功只代表存好了，不代表开发者已确认。
7. 同时发交接消息（[../交接消息.md](../交接消息.md)）：说文档在「开发文档」里、这一版改了什么，不把文档全文贴进聊天。

更新时用 `studio_read_creation` 按 `documentType` 读上一版，在它的 `index.html` 上只改变化的部分，`version` 的版本号加一；只更新当段这一份，不顺带重写另外三份，也不回写已确认的 PRD 和方案。

## 确认怎么登记

PRD 和方案要开发者确认；什么算「确认这一版」、新一版要不要重新确认，见 [../PRD.md](../PRD.md)「版本、批注和确认」。整版确认规则见 [../选择题与判断题.md](../选择题与判断题.md)「整版确认」。Studio 里这样登记：

- 在聊天里同意的（文字或语音转写都算）：用 `studio_read_creation` 读这份文档当前的 `artifactId`、`version`、`digest`；调 `studio_confirm_proposal`，传 `documentType`（`prd` 或 `proposal`）、这三项和开发者原话 `userStatement`；再用 `studio_read_creation` 读回已确认。
- 在确认卡上点了确认的：宿主已登记，用 `studio_read_creation` 读回已确认。
- 读回已确认才往下走：PRD 读到确认之前只查不建，方案读到确认之后才进 ③。已确认范围内的修订以宿主返回的当前确认状态为准，不自行增加确认步骤。
- 给开发者只说文档内容、实际确认状态和下一步；`artifactId`、`version`、`digest` 这类核对字段只记进阶段文档。
