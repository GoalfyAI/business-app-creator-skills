# G6 预览验收

把应用部署成在线预览，必要时用真实样例真跑一次，由开发者在开发者中心的「在线预览」里自己走一遍并确认。验证只有两层：冒泡管改，真跑和开发者验收管收。

## 1. 进入条件

- G5 出口：本地 `npm run verify` 全绿。
- 确认页里的场景包上线已获同意（开发者对确认页说过「可以」）。

## 2. 做什么

1. **上线场景包**（部署预览前的平台要求）：`finalize_asset_version_online(asset_type="scenario_pack", draft_asset_id=<草稿行>, change_note=…)`。它上线为开发者的个人资产，不进目录、别人看不到。上线后反读版本号记进工单。之后再改场景包，要重新上线新版本。
2. **打包部署**：应用根 `npm run verify:release` 全绿后 `npm run pack`；`business_ui_bundle(action="download_template")` 再核一次脚手架门槛；`business_ui_bundle(action="prepare_upload")` → 按返回地址 PUT 源码包 → `complete_upload` → `deploy(source_sha256)` → `status(deployment_id)` 到 `success`。`status` 服务端最多等约 45 秒，没结束用同一 `deployment_id` 续等。
3. **反读入口**：`business_ui_manage(action="get")` 读预览入口；记下 `deployment_id`、`source_sha256`、`deployed_scaffold_version`。`deploy` 返回带 `scaffold_upgrade_notice` 时原样记进开发记录，交付报告要写。
4. **真跑一次**（有模型行，或路线要写库、调外部接口时做；只有规则步骤且冒泡已覆盖时可省，省了写明原因）：先说清费用与副作用，开发者同意后执行：
   1. `manage_goalfymax_project(action="run", task_id, idempotency_key, scenario_package_ids=[<已上线版本的物理行 ID>], submit_data={…}, business_ui_id=<有应用数据要写时才传>)`；
   2. `manage_goalfymax_project(action="wait", project_id)` 等到终态，中途表单或审阅用 `reply`；
   3. `get_project_execution_logs(action="workflow_trace", project_id)` 看每步，模型行的输出人眼核一遍；
   4. 写库的结果去应用数据管理页或库里查一条。
   失败在同一草稿改再跑；每次只改一处，不同时改脚本和路线。
5. **交给开发者验收**：告诉开发者在开发者中心右侧「在线预览」里操作——它用绑定的 `business_ui_id` 换一次性凭据，带真实身份和真实路线。说明能操作什么、数据写在开发工作集里、哪些是示例数据、预览里的真实付款和授权是真的。你不另起浏览器替开发者点。该入口若只提供 Web 宿主，不能据此声称真实移动客户端已验收。
6. **分开记录双端证据**：从 G5 取出手机视口布局、Web Bridge 和 Native 通信模拟的本地结果，与本段在线预览的真实身份、路线和部署结果分别记录。Native 模拟不能证明真实 iOS/Android 的安全区、系统键盘、原生文件、返回和前后台恢复；没有真实客户端验收时明确列为未验证，不写「移动端已通过」。
7. **按反馈改**：开发者提的改动改完重新 `verify:release` 并部署；改了场景包的先重新上线场景包。
8. **人判项与 UI 复查**：按 [../checklists/验收清单.md](../checklists/验收清单.md) 逐条写「通过 / 不适用 + 一句依据」；请开发者在在线预览中按应用工程的 `frontend/docs/responsive-development.md` 复查主要页面的样式一致性、状态反馈和窄屏操作。做不到的列为未验证项，本地截图不能冒充在线预览证据。

## 3. 产出与落盘

- 工单 checkpoint：场景包上线版本、`deployment_id`、`source_sha256`、`deployed_scaffold_version`、真跑的 `project_id` 与结论、开发者确认预览的原话、分层的双端证据与未验证项。
- 本段阶段文档写验收清单逐条结论。
- 方案页「进度」一节：在线预览已可用；开发者验收结论与未验证项。
- 阶段状态：G6 `passed`，G7 `in_progress`。

## 4. 给开发者看什么

「在线预览已部署：请在开发者中心右侧『在线预览』里试 <主要功能>。要改哪里直接说；觉得可以就回复『可以上线』。」附双端本地验证结论与未验证项清单，说明在线预览实际使用的宿主。

## 5. 出口

- 最近一次部署 `status=success`，预览入口可用；
- 开发者明确确认预览（说「可以上线」或等价表述）；
- 验收清单逐条有结论，未验证项已记录。

## 6. 出问题怎么办

| 现象 | 先看 | 回到 |
|---|---|---|
| 部署 `status` 失败 | 返回里的构建日志尾部；本地先 `npm run verify:release` | G5 |
| 部署被脚手架闸门拒绝 | [../reference/脚手架与预置件.md](../reference/脚手架与预置件.md) 错误码表 | 升级后重来 |
| 在线预览打不开或提示未就绪 | 部署状态、`business_ui_id` 与环境是否一致；`PREVIEW_NOT_READY` 记为阻塞 | 本段第 2 步 |
| 真跑卡 `waiting-input` | 用 `reply` 回表单；没人答就是正常挂起 | 本段 |
| 真跑内容不对 | 模型行提示词或输出字段 | G4 |
| 页面行为不对 | 页面块或生成页 | G5 |
| 疑似平台问题 | `submit_dev_feedback` 报上去，绕过后继续 | — |
