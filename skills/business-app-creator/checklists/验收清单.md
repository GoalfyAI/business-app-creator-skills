# 验收清单（人判项）

机器能判的交给 `otpe_manage(action="verify")`、`npm run verify` / `npm run verify:release`、路线冒泡和结单门，这里不重复。下面是只能由你判断的项，④ 逐条写「通过 / 不适用」加一句依据，写进阶段文档 G6 与工单 checkpoint；做不到的列为没法验证，写进试用清单和交付报告。

| 查什么 | 证据 | 不过怎么办 |
|---|---|---|
| 1. PRD「每一步谁来做」每一行都能在资产里找到：脚本步骤有脚本，模型步骤有 FA 且模型是 PRD 定的那一档，人的步骤有页面或表单 | 施工单与实际资产 ID、FA 模型配置对照 | 回 ③ 补 |
| 2. 使用者在「在线试用」里能走完每条路线：从入口到看到结果，中途要补的信息有地方补 | 开发者在「在线试用」里的操作结果 | 回 ③ 修页面或路线 |
| 3. 每种人都能完成自己的事、看到 PRD「谁来用」写的东西 | 按每种人的验收条目的结论 | 回 ③；少了一种人回 ① |
| 4. 结果看得懂：没有路线 ID、项目 ID、`PRJ-…` 任务标题、Runtime/编排等内部术语、字段名、原始 JSON 和原始时间串直接给使用者看；`npm --prefix frontend run check` 无「界面直接显示」警告 | 页面描述或本地布局回归截图 | 回 ③ 改展示 |
| 5. 「会停下的情况」真的按 PRD 发生：至少人为制造一次失败看表现 | 失败那次的 `run_id` 或 `project_id` 与页面表现 | 回 ③ 改失败出口 |
| 6. 模型步骤的输出用真实样例人眼核过一次，不只看形状；要人判断的条目已交给开发者 | 真跑或 `full_run` 冒泡的输出摘录 | 回 ③ 改提示词、模型档位或输出字段 |
| 7. 数据管理页只开放使用者该改的列；系统和路线写的列只读并标来源 | 页面与列注释对照 | 回 ③ |
| 8. 只读权限下发起和写入入口都置灰并说明原因 | 用只读身份或 `permission='view'` 看一次 | 回 ③ |
| 9. 费用与副作用和 PRD 一致：没有多调工具、多发消息、多写正式数据；每个按钮实际花费和估算差得不多，差得多的已告诉开发者 | 真跑日志里的工具调用清单与 `cost_credits` | 回 ③，或回 ① 补确认 |
| 10. 用量：按 PRD 的用量上限（一次最多多少条）跑得完，超出时有提示 | 用接近上限的样例真跑一次的结果，或做不到时写进没法验证 | 回 ③ 改分批；做不到回 ① |
| 11. 离开再回来：关掉页面、换设备后任务和结果能找回，从正确位置继续 | 刷新或重新打开预览后的状态 | 回 ③ |
| 12. 交付报告里每一句「已验证」都能指到证据，没验证的明确列出 | 报告与工单 checkpoint 对照 | 改报告 |
| 13. 空库也能用：没有数据时页面有引导或首次设置入口；上线后必须存在的设定不依赖试用数据 | 清空或换新工作集后的页面表现 | 回 ③ |
| 14. 按验收条目逐条验收：开发者（和需求方）以使用者身份从首页进入照做，每条有「对 / 不对」结论；不只看页面能打开、表单能跑 | 每条的结论、原话与部署编号 | 不对的回 ③ 改，改完只重测该条 |
| 15. 首屏与导航按使用者的业务任务组织：首页直接给目标、依据和下一步；导航顺序与完成业务的顺序一致；界面上没有 mock、运行状态、日志等平台信息 | 首页与导航的页面描述，或开发者给的截图、本地布局回归截图 | 回 ③ |
| 16. 页面样子与 PRD「界面」一致：开发者给的参考网站、截图、原型都做到了，不是只换了品牌色和圆角的起始应用 | 参考图与对应页面的并排截图（本地布局回归或开发者提供）或逐条对照 | 回 ③ |

按应用类型追加：

- 有中途表单：挂着表单时再提交入口表单，界面给出「上一张表单还没完成」而不是改走新项目。
- 有写库路线：同一业务重复发起不产生重复行。
- 有文件交付：附件能在交付审阅页下载，内容是本次运行的产物。
- 有自动化：`business_ui_automation(action="run_once")` 跑一次，运行记录与消息中心的表现符合 PRD；要验真实到点触发，让开发者本人在应用上线后从「我的资产」进正式入口，在自动化面板开规则等到点（不必发布到目录）。
- 有授权或充值：取消、失败后重试、解除后列表刷新都走一遍；不用生产真实授权或真实支付做自动化测试。
