# U 业务行为验收明细

> 回答"在这个情境下，应用应该怎样做，怎样才算失败"。**表中"通过标准"是应验证的行为，不是当前能力声明。**一个行为在 G3 只能记"设计已确认"，G5 记"后台验证通过"，G6 记"用户操作通过"——三个结论分别记录，不共用一个 passed。未确定的规则记待确认；未验证的能力记待验证 / 阻断；不得用通用答案替用户做选择。不存在的能力可标不适用，说明理由，不能为凑清单擅自增加功能。

## 0. 谁在哪个阶段处理

| 行为组 | G1/G2 先确定什么 | G3 须交开发者确认的设计 | G4/G5/G6 的验证分工 |
|---|---|---|---|
| U1 开始、续用与历史 | 谁在什么情况下进入；哪些历史真的存在 | 新建 / 继续 / 查看历史的入口及最小输入 | G5 验任务归属与恢复查询；G6 用不同初始状态实际进入 |
| U2 信息准备与真正使用 | 数据 / 文件能否取得；什么信息影响结果 | 来源、必需 / 缺省 / 推断、冲突与时效、接收节点 | G4 验解析 / 传递；G5 验真实消费与隔离；G6 验带入与纠正 |
| U3 Agent 连续推进 | 工具能调用之外，能否作必要判断 | 自动 / 补充 / 业务决策 / 授权 / 拒绝的边界 | G4 验判断；G5 验路线推进与停点；G6 验无须逐步指挥 |
| U4 离开与异常恢复 | 状态查询、产物复用、停止和重入的实际能力 | 每种中断的恢复位置、保留范围、重复执行边界 | G4 验失败单元；G5 验状态与副作用；G6 验返回、补充、重试 |
| U5 结果检查与反复修改 | 旧产物能否读取，目标修改能否做到 | 原产物 / 版本、保留约束、依赖影响、确认与真实交付 | G4 验修改能力；G5 验版本 / 重算范围；G6 验检查、连续改与确认 |
| U6 留存、偏好与效果回传 | 哪些信息值得复用，证据从哪来 | 归属、作用范围、纠正撤销、下一读取点、比较标准 | G5 验读写与下一轮执行；G6 验纠正 / 回传入口；G7 验声明范围 |
| U7 跨应用 Agent，条件适用 | 是否在范围内；数据发现与权限能力 | 可见数据、允许操作、执行对象、确认方式 | G5 验真实授权与操作；G6 验结果与归属可理解 |
| U8 临时编排，条件适用 | 是否需要；平台能表达哪种动态行为 | 固定路线与临时计划的分工、预算、变更与停止规则 | G4 验必要单元；G5 验真实计划 / 轨迹；G6 验干预与完成边界 |

## 1. 实例化流程，由开发 Agent 主持

1. 对 U1–U8 逐项判断适用性并给理由，结合实际业务补充明细；涉及既有承诺的删减由开发者确认；不支持某项能力不等于该项不适用。
2. 把通用称呼替换成真实业务对象、页面、路线、数据字段、产物与版本；把"简短、够快、低成本"改成已确认样例或阈值。
3. 会改变产品行为的边界展示推荐与替代，开发者确认业务取舍；技术细节与测试编写由 Agent 完成。
4. 每条行为关联设计节点、实现资产与分阶段证据；复验用当前版本，不拿过去的运行结论代替。
5. 既检查一个情境的独立处理，也检查"首次使用 → 中断 → 修改 → 再次使用"的组合；边界组合按业务风险选取，不机械穷举。

**每个可执行验收项的完整记录**：编号｜适用条件与承诺｜前置状态及数据｜输入或操作｜预期结果｜失败判据｜开发者要看的信息｜设计 / 实现责任｜证据类型及版本｜实际结果。仅写"支持幂等"不算实例化。

## U1 用户能否进入正确任务

展示 / 确认：把零历史、已有资料、处理中、已完成四种入口摆在一起，让开发者确认"用户进来第一件事是什么"。

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U1-01 首次使用，无历史资料，发起已支持任务 | 只收集完成本次任务必需的信息；可选资料不阻止开始；必需缺项说明用途与补充入口 | 被迫先完成无关建档；空必需信息被放行 | 零数据页面操作、必需字段清单、实际发起输入 |
| U1-02 已有有效资料，再次发起同类任务 | 复用匹配资料，用户只处理本次变化；提交前可纠正；手填的本次值不被晚到的带入值覆盖 | 重复初始化、反复问已知事实、覆盖本次输入 | 带入来源、手填 / 带入时序、实际提交值 |
| U1-03 同时有未完成任务与历史结果，重新进入 | 能区分并进入正确任务 / 结果；继续旧任务不误开新任务；查看历史不触发执行 | 打开历史就重跑；只能靠重新发起找回工作 | 导航过程、任务标识、发起调用记录 |

## U2 信息能否准备好并真正影响执行

展示 / 确认："本次输入说明"：字段值、来源、所属对象 / 时间、是否推断、缺失或冲突、交给哪个节点。不让用户理解技术 Schema 才能纠错。

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U2-01 缺少不能推断的必需事实 | 在依赖该事实的动作前请求补充；无法补齐时按规则给出不能完成的原因 | 捏造数值；缺数据仍输出貌似完整结论 | 缺项提示、暂停 / 失败状态、未执行的依赖动作 |
| U2-02 缺少可选资料，按设计允许默认处理 | 使用已确认缺省策略继续；缺省影响结果时用户可辨认 | 可选缺项变阻塞；采用未约定的业务假设 | 缺省规则、执行输入与输出差异 |
| U2-03 使用允许推断的信息，用户随后纠正 | 推断有依据且与事实可区分；影响关键判断时按约定确认；纠正值进入当前执行 | 推断伪装成事实；纠正只改页面不改执行 | 推断来源、确认 / 纠正记录、节点实际输入 |
| U2-04 本次输入与旧资料冲突，或旧资料过期 | 按已确认优先级 / 有效期处理；无规则时只询问冲突点 | 无提示沿用旧值；过期当当前；临时编造优先级 | 两份资料及版本、处理决定、最终消费值 |
| U2-05 选择 A 对象但提供了 B 的素材 / 授权 | 校验归属与适用范围；不匹配项排除或要求确认；未授权资料不可读 | 名称相似即混用；切对象后仍携带上一对象材料 | 选择值、资料归属 / 授权、执行所用资料清单 |
| U2-06 数据已保存，实际运行一项受其影响的任务 | 从真实节点输入能定位选用数据及版本；关键判断使用正确字段；改字段行为随之变化 | 只证明库里有数据；字段未传、传错节点、传入未用 | 数据快照、脱敏节点输入、关键判断 / 对照产物 |

## U3 Agent 能否在授权范围内连续推进

展示 / 确认：逐个标出"自动执行 / 补充事实 / 业务选择 / 动作授权"的停点，各注明为什么需要人、回答影响什么、回答后从哪继续。运行 Agent 不把技术选型问题转嫁给终端用户。

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U3-01 信息、能力、授权齐备，用户提交业务目标 | 已定步骤连续执行到交付或约定停点；不要求点名工具或逐步"继续" | 每步停下请示；只给建议不执行 | 实际轨迹、停点及原因、用户参与记录 |
| U3-02 执行中发现只能由用户补充的信息 | 说明缺什么、为何影响后续、补充入口；回答后带入同一上下文继续 | 要重新描述整项任务；重复询问；回答未进入下游 | 待办 / 表单、补充前后上下文、下游输入 |
| U3-03 仅授权制作，结果已生成，存在发送 / 发布能力 | 停在制作终点；如需外发，说明对象、内容、影响并取得授权；无权限不调用 | 因工具可用就顺带发送；审阅等同外发授权 | 授权记录、动作审计、外部回执或未执行事实 |
| U3-04 中途补充要求或改变目标 | 判断属于补参 / 局部修订 / 目标变更 / 新任务；影响已执行部分时说明重用 / 重做范围并确认 | 忽略新要求；偷偷扩大范围；新任务覆盖旧结果 | 新要求、分类理由、影响说明、后续运行关联 |
| U3-05 提出应用不支持的需求 | 说明缺的是能力 / 数据 / 权限，给出下一步；保留当前工作；扩大范围先确认再验证 | "理解了"就承诺能完成；虚构工具 / 数据；卡住后丢原任务 | 能力 / 权限核对、范围回应、原任务状态 |

## U4 离开、缺信息或部分失败后能否继续

展示 / 确认：分别演示"仍在执行 / 等待补充 / 结果未知 / 部分成功 / 确认失败 / 取消中或已停止"。关闭页面不是取消；超时不是失败；暂停不等于可从任意脚本行续跑。

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U4-01 后台任务运行中关闭页面再打开 | 持续执行或明确暂停；返回后读真实状态，找到已完成结果与待处理项 | 因关页丢任务；旧内存状态当当前；返回自动重建任务 | 关闭前后运行记录、服务端状态、页面恢复 |
| U4-02 等待补充，用户离开后回来提交 | 恢复正确待处理项、已有输入、有效成果；按设计重入位置继续 | 回复了历史表单；进错任务；补充后无后续 | 活动交互、补充内容、恢复位置、新旧运行关系 |
| U4-03 提交后网络超时，状态未知 | 先按同一逻辑操作查询 / 对账；成功取回、仍执行等待、失败才重试；无法确认则明确未知 | 超时即重跑收费 / 外发；未知显示成失败 / 成功 | 请求关联标识、查询结果、外部调用次数 |
| U4-04 多项产物部分成功部分失败，用户重试 | 成功部分可用；按依赖只重做失败及受影响部分；必须重算时说明依据 | 全部覆盖；无理由重跑全部；保留已失效结果 | 产物依赖表、前后版本、实际重试步骤与输出 |
| U4-05 同一逻辑请求重复点击 / 回调重复 / 客户端重发 | 记录与已完成动作不重复；用户看到同一结果；重试若额外计费须在约定范围 | 重复任务 / 记录 / 外发或未授权调用；只测按钮禁用 | 请求去重、数据库对照、供应商调用 / 费用记录；费用不可查不得声称已验 |
| U4-06 要求停止，承诺支持时 | 在平台实际支持边界停止；区分停止请求与停止完成；已发生动作与成本如实说明 | 显示已取消却继续派发；声称已撤销；承诺不存在的原子回滚 | 停止回执、之后派发记录、已完成动作清单 |

## U5 结果是否可检查并能在确认前反复修改

展示 / 确认：先展示完整产物，再对照"只调整表达"与"改变基础事实 / 范围"两种修改；确认哪些必须保留、哪些联动、修改后是否再审。普通生成输入与修改输入分开设计。

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U5-01 任务完成，产物含文字、图表或文件 | 能查看约定的完整内容、必要来源与不足；组合部分可一起核对；文件能打开 | 只有成功提示或路径；关键产物缺失；部分当完整 | 产物清单、内容 / 来源核对、浏览器实际预览 |
| U5-02 对 V1 提出"只简化建议，保留数据与图表" | 修改单元取得 V1 内容、版本与约束；仅变更目标部分；原版保留 | 未读 V1 便重生成；改错版本；无关内容变化 | 修改输入、V1/V2 对照、调用轨迹与版本关系 |
| U5-03 修改周期或多处出现的事实 | 识别受影响数据、图表、结论并全部更新；完成前不把混合版当确认版 | 只改一处；无依据重做无关部分 | 修改影响表、来源数据、一致性检查 |
| U5-04 修改执行失败 | 原可用版本仍可查看 / 下载；失败候选清楚标记；可重试或继续用旧版 | 先删旧版；失败候选覆盖确认版；无恢复选择 | 失败记录、旧文件可用性、当前确认版本指针 |
| U5-05 V1 改成 V2 后继续修改或确认 | 每次意见绑定版本；草稿 / 修改版 / 确认版可区分；迟到旧结果不覆盖新确认 | 多轮意见混用；旧结果晚到变最新确认；看不清改的是哪版 | 修改 / 确认记录、版本谱系、乱序完成后的页面状态 |
| U5-06 取用结果或执行承诺的提交 / 发布 | 下载得到正确版本；外部动作有可靠回执并关联对象；未完成 / 未知清楚呈现 | "文件生成了"代表已发布；发错版本或账号；无回执报成功 | 实际取用文件、用户授权、外部回执与版本 / 对象关联 |

## U6 信息、修改和效果能否让下一次更省事

展示 / 确认：让开发者看到"一条资料 / 偏好从哪来、适用于谁、持续多久、下次在哪用、怎么撤销"；区分用户编辑、模型建议、已确认事实、推断偏好、效果观察，不写成一份通用记忆。

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U6-01 多对象 / 账号 / 任务保存输入、素材、产物、修改 | 每条记录可追溯对象、任务、运行 / 产物版本、访问范围；同名不串用；后端拒绝无权读写 | 只按名称匹配；另一对象 / 用户能读写；产物不知属于哪次 | 关联记录、不同对象与用户的读写测试 |
| U6-02 确认稳定事实或长期偏好，下次发起任务 | 正确范围内减少重复输入；指定节点实际读取并使用；仍可查看纠正 | 保存了但执行未读；只改界面默认；反复解释同一要求 | 保存来源、下一次输入与节点消费记录、结果核对 |
| U6-03 本次临时要求或一次修改 | 只作用于本次；一次修改不自动成长期偏好；推断候选按机制处理 | 单次风格传到所有任务；纠错当审美；悄改公共策略 | 作用范围记录、下一任务 / 另一对象的对照输入 |
| U6-04 纠正事实、撤销偏好或新旧冲突 | 按优先级处理；后续不沿用失效规则；已有运行是否更新按边界定；生产不覆盖用户编辑列 | 撤销只改页面；模型输出覆盖用户决定；历史事实被改写 | 修改与撤销记录、后续检索 / 输入、用户列与生产列对照 |
| U6-05 业务结果或用户反馈到达，含迟到 / 重复 | 低负担选对应任务 / 产物；记录来源、时间、是否明确原因；重复不重计；未知不记零；迟到不冒充当时已知 | 错绑最新任务；强迫重填；推断原因冒充用户原话 | 反馈操作、关联版本、事件 / 记录时间、去重与缺失标记 |
| U6-06 声称历史反馈或新策略使效果更好 | 同一或可比条件比较基线 / 候选；按已确认标准判断；随机性大时补样本 | 只展示两份不同内容就称变好；只挑成功反馈；用费用掩盖退化 | 输入 / 策略 / 模型版本、样本范围、逐例评分与成本、未验证维度 |

## U7 跨应用 Agent，仅纳入范围时

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U7-01 请求跨应用汇总，部分应用无权限或数据缺失 | 逐应用确认真实可读范围；明确未覆盖部分 | 假设能看到所有应用；旁路读取无权数据 | 应用能力清单、权限 / 查询结果、覆盖范围 |
| U7-02 从一个应用要求修改另一个应用的数据 | 确认目标实例、对象、动作、授权；只在支持的接口执行；结果可在目标应用核验 | 当前权限当全局；返回已修改但目标未变 | 授权、目标操作回执、目标数据前后对照 |
| U7-03 跨应用任务缺必要业务上下文 | 给执行端匹配目标、对象、已确认信息与能力；只补问缺口；状态不混用 | 只有自然语言转发；丢对象 / 时间约束；结果无法归属 | 执行上下文、缺口询问、跨应用任务 / 结果关联 |

## U8 固定路线与临时编排，仅纳入范围时

| 编号与前置 / 操作 | 通过标准 | 失败判据 | 应查看的证据 |
|---|---|---|---|
| U8-01 新要求仍可由已有路线与参数表达 | 复用已验证路线；确有必要才加临时步骤 | 每次重新规划；已有能力未用却新增资产 | 选路依据、参数变化、实际调用 / 资产清单 |
| U8-02 超出固定路线但在获批范围内 | 临时计划由真实可用能力组成，输入输出可衔接，有可验证终点；能力不足回 U3-05 | 编造工具 / 依赖；只输出计划便报完成；草图当已支持动态调度 | 能力核验、计划、真实轨迹与交付 |
| U8-03 执行中须扩大数据范围、费用或外部动作 | 暂停受影响动作，说明变更与保留成果；取得授权后更新计划并留痕；拒绝时按约定结束 | 以自主编排为由越权；持续试错超预算；无法解释路径 | 计划版本、预算 / 权限变化、确认记录、停止与完成事实 |

## 2. 从设计一直验到交付：U5-02 完整实例

业务情境：多门店周报已产生 V1，用户在确认前要求"只把经营建议写简短，保留本周数据和图表"，案例设计，非已运行产品。

先确认的规则：哪些段落是经营建议；保留哪些数据 / 图表；"简短"用哪份样例或长度规则；以哪版为修改基线；是否需要重新确认；允许的耗时与费用边界。Agent 先提建议和样例，不把问题留给开发者补完。

| 阶段 | 本阶段建设与展示 | 通过所需证据 |
|---|---|---|
| G1 | 展示 V1 与目标修改样例，确认交付包含审核前修订 | 修改范围与合格样例已确认 |
| G2 | 用真实可读的旧报告试改，展示能保留什么、哪里做不到 | 实际修改样本满足关键约束 |
| G3 | 设计修改入口与路线，展示原版 → 修改版 → 确认版关系与失败出口 | 原产物内容 / 引用、版本、意见、保留约束、受影响步骤、独立验收用例 |
| G4 | 实现修改执行单元，展示输入与修改差异 | 真实收到 V1 及约束；建议满足样例；数据 / 图表一致；缺 V1 时明确不能修改 |
| G5 | 接通版本保存、受影响步骤调度、失败恢复 | V2 关联 V1；无关取数不重跑；失败不覆盖旧版；重复请求不重复写确认 |
| G6 | 从页面选 V1 提交意见，预览 V2，再修改、比较、确认 | 操作得到对应版本；旧版保留；迟到旧运行不覆盖新确认 |
| G7 | 最终部署版本重跑正常修改、失败、连续修改、迟到结果 | 各层证据匹配本次交付版本 |

最小可执行用例记录：前置，测试实例内存在可打开的 V1，记录其数据、图表、建议；操作，选 V1 提交意见；期望（得到 V2，仅建议按标准变化，数据 / 图表一致，V1 保留，V2 不经审阅不成确认版）；失败判据（未拿到 V1 却声称完成、改错版本、无关数据变化、图表丢失、覆盖 V1、未审阅就确认）；异常变体，修改单元失败时 V1 仍可用；统计周期改变走 U5-03；证据（修改节点输入、V1/V2 对照、调用记录、版本关系、页面操作；文件时间戳变化不等于业务内容变化）；结论记录，设计确认、能力试验、单元、后台、页面、最终部署各自状态与版本。

## 3. 门禁怎样汇总

G3 交付适用行为的**已确认规则与测试设计**；G4 交付执行单元的**实际输入输出与边界证据**；G5 交付**真实执行与数据证据**；G6 交付**用户实际完成的操作证据**；G7 核对最终版本。一条门禁涉及多个行为时先逐项列 通过 / 失败 / 阻断 / 不适用 再汇总；不以条目数量衡量完整性，看每项业务承诺是否有规则、实现和证据。
