# 能力试用

## 识别信号

- 开发者想先验证某个外部能力（MCP、API、模型、Skill 包）好不好用、值不值得做进应用。
- 开发者给了工具链接、包或供应商名，问「能不能用」「效果怎么样」。

## 先读什么

1. 建 write 工单。
2. 平台上先查重：`list_assets` / `get_asset`；有就直接取样，不重复接入。
3. 要接入的按 [../reference/依赖与MCP接入.md](../reference/依赖与MCP接入.md) 预览、注册、配授权卡。
4. 取样：安全只读的工具用 `otpe_tool_test` 真调，核对返回结构；需要模型的，建一个极简试用包：`clone_asset` 官方基础包得到草稿 + 一个上线的工具集 + 写明「是什么、何时用、注意什么」的 `apc_skill`，用一两条真实样例跑。
5. 试用会产生真实调用费用：先说清费用和样例数，开发者同意后再跑。

## 从哪一段进

从 G2 的第 2 步（真调一次）进。结论写成三句话交开发者：能做什么（附样例结果）、不能做什么、建议做进应用还是放弃。开发者决定做进应用时，转新建（进 G1 写确认页）或修订；试用包在工单里标明用途，正式制作不沿用它，除非开发者明确要求。
