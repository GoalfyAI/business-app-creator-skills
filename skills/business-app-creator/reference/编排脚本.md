# 编排脚本

## 适用场景

写或改编排型 TPE 脚本、定 `_output` 与失败出口、写事件契约、判断冒泡结果能证明什么时读。第一次写脚本前还要读 `get_diagnosis_doc(topic="otpe_single")`；原语签名和字段以它和 `otpe_manage` 的当前 Schema 为准。

## 规则

### 脚本骨架

- 入口 `async def run(input, ctx)`；返回值按 `output_schema` 逐字段组装，不把工具或 FA 的返回整包转交。
- 每个 `tool()` 带 `_rationale`（为什么调）与 `_output`（按工具真实返回结构声明，只声明脚本要读的字段）。
- 脚本里用到的每个工具和 FA 都要在预加载工具集清单里声明，且工具集已上线。FA 用反读到的 `mr_name`。
- 技术失败让异常冒泡，**禁止**捕获后伪装成业务成功，**禁止**用空字符串或虚构路径凑成功对象。
- 有外部副作用的动作（发信、写外部系统、付款）按 `ctx.dry_run` 判断，冒泡时跳过。
- 写库的步骤按「会被再执行一次」写：带唯一键或先查后写。
- 脚本来源：短脚本传 `script`；长脚本或多轮修改用 `script_url`；只改一个片段且 Schema 支持时用 `script_patch`。只改输入输出或依赖时不重传脚本。

### 失败出口怎么写

| 确认页「做不成怎么办」 | 脚本写法 |
|---|---|
| 停下来告诉用户 | 不捕获，让异常冒泡；平台按失败类别归因 |
| 标记状态继续 | `try/except` 只包那一次 `tool()`；读异常的 `recoverable` 决定写 `optional_source_retry_later` 还是 `optional_source_unavailable`；输出带 `status` 与 `warnings` |
| 重试一次 | 同上，except 里再调一次；工具内部已重试的（异常带 `attempts`）不再叠加 |
| 业务条件不满足（证据不足、缺前置数据） | 发 `stage_failed` 或以明确的 `status` 正常返回，不抛异常 |

**异常上带的事实**（平台较新版本起）：`exc.failure_class`（`tool_error` / `fa_error` / `shell_exit` / `contract_error`）、`exc.recoverable`（`True` 是限流、超时、冷启动，可换时机重发；`False` 是鉴权、参数、余额，别再试；`None` 判不出）、`exc.attempts`（工具层已试次数）。目标环境没有这些属性时只按 `str(exc)` 分支。**禁止**把整段逻辑包进 `try`：脚本自己的 `KeyError` / `TypeError` 会被当成可选步骤失败吞掉。

**FA 的输出要给部分成功留出口**：每次 `tool(FA, _output=…)` 都声明 `status`，枚举至少含 `completed`（全部做完、数据真实）、`partial`（做了一部分，未做的不补不编）、`blocked`（一条没做成，数据字段留空），再配一个 `note` 写做到哪、还差什么、为什么停；缺的是最终用户补得上的输入时加 `needs_input` 作为 `blocked` 的细分。读应用库这类只读查询以 `found` 布尔作出口即可。只允许成功态时模型会编造数据去满足 schema，收得越紧越倾向编造。**门禁先裁业务状态**：上游 FA 返回非成功状态（如 `needs_input`、`blocked`）时，脚本不进写库、不进下游，也不原样重试。

**上下文预算**：FA 报 `FA_CONTEXT_BUDGET_EXCEEDED` 时调高轮次没用，要减少单次传入：大段素材传路径、一次处理一个对象。报 `FA_STEP_BUDGET_EXCEEDED` 先看 `partial` 出口有没有写好，再按预估步数调轮次。

### 事件契约

- 只有需要业务路线可观察性、应用状态、表单握手或交付审阅时才声明；声明了就进 Business Runtime 语义，正式运行必须经路线（单条 TPE 也建单节点路线）。
- 硬门：首个业务动作前发 `stage_started`；每个正常 `return` 前发 `stage_result`；可解释的业务失败发 `stage_failed`。`artifact_ready`、`delivery_ready` 由平台自动发，脚本**禁止**声明或调用。
- `payload_schema.required` 必须含平台字段：`stage_started` 要 `stage_key`、`stage_name`；`stage_result` 要 `stage_key`；`stage_failed` 要 `stage_key`、`error_code`、`message`；`attention_required` 要 `level`、`title`、`message`。`additionalProperties` 必须为 `false`。
- `event_type`、`event_key` 用字符串字面量，不动态拼；载荷不放内部 ID、原始工具返回、提示词或未脱敏错误。阶段名用最终用户能懂的业务语言。
- **禁止**在每个 `tool()` 后机械发事件；不为进度条声明 `stage_progress`。
- 契约随 `otpe_manage(action="create"|"update", business_event_contracts=[…])` 一起写，写后 `get_asset(asset_type="tpe")` 反读。

### 文件产物

- 要交付的文件写进 `ctx.output_dir`，在 `output_schema` 声明为 `format: workspace-file-path` 并返回真实路径，路线的交付映射也要引用它；入口素材、上游产物要作为本次附件时先复制进 `ctx.output_dir`。
- 要给用户看的列表、正文、结论以业务字段出现在返回值里，不只落文件。

### 冒泡与真跑能证明什么

| 验证 | FA | 工具、shell、文件 | 带 `ctx.dry_run` 判断的外部动作 | 能证明 |
|---|---|---|---|---|
| preview | 不执行 | 不执行 | 不执行 | 脚本与契约静态合法 |
| 冒泡 bubble | 桩（按 `_output` 造值） | 真实执行 | 跳过 | 管路通、形状对 |
| 冒泡 `full_run=true` | 真实调用 | 真实执行 | 跳过 | 模型行真实输出；有费用，先取得同意 |
| 真跑 `manage_goalfymax_project(run)` | 真实调用 | 真实执行 | 执行 | 端到端结果 |

冒泡终态在发起后约 2 小时内可以用同一 `run_id` 复读，`verify(tpe_id, run_id)` 靠它出报告。

### 三种模板

线上路线主要是三种形状：拉数落库、拉数判读、生成写库。挑一种改业务词，不从零写。模板里的写库遵守 [数据模板.md](数据模板.md)「谁建行」：模板一是没有后端参与的同步类路线，按业务键幂等写入；有应用后端参与的路线，新行由后端生产回流接口建，写库 FA 只更新已建行。

#### 一、拉数落库

```python
async def run(input, ctx):
    await emit_business_event(
        event_type="stage_started",
        event_key="sync_started",
        payload={"stage_key": "sync", "stage_name": "正在同步数据"},
    )

    listed = await tool(
        "<工具的 mr_name>",
        account_id=input["account_id"],
        _rationale="取回名下全部记录，后面的步骤都以它为准",
        _output={
            "type": "object",
            "required": ["items"],
            "properties": {"items": {"type": "array", "items": {"type": "object",
                "required": ["id", "name"],
                "properties": {"id": {"type": "string"}, "name": {"type": "string"}}}}},
        },
    )
    rows = [{"external_id": it["id"], "name": it["name"]} for it in listed["items"]]

    write = await tool(
        "<写库 FA 的 mr_name>",
        operation="write",
        query="把这批记录写入 accounts 表：按 external_id 幂等，已有的更新，没有的新增",
        context_hint="表 accounts；字段 external_id, name；只写 [editable:agent] 列",
        rows_json=json.dumps(rows, ensure_ascii=False),
        _rationale="把同步结果落到台账，供应用展示",
        _output={"type": "object", "required": ["found"], "properties": {"found": {"type": "boolean"}, "written": {"type": "integer"}}},
    )

    await emit_business_event(
        event_type="stage_result",
        event_key="sync_completed",
        payload={"stage_key": "sync", "summary": f"同步 {len(rows)} 条"},
    )
    return {"status": "completed", "count": len(rows), "written": write.get("written", 0)}
```

#### 二、拉数判读

```python
async def run(input, ctx):
    await emit_business_event(
        event_type="stage_started",
        event_key="diagnosis_started",
        payload={"stage_key": "diagnosis", "stage_name": "正在拉取数据并诊断"},
    )

    notes = await tool(
        "<拉数工具的 mr_name>",
        user_id=input["account_id"],
        limit=30,
        _rationale="取最近 30 条笔记作为诊断依据",
        _output={"type": "object", "required": ["items"], "properties": {"items": {"type": "array", "items": {"type": "object",
            "properties": {"title": {"type": "string"}, "likes": {"type": "integer"}, "published_at": {"type": "string"}}}}}},
    )
    if len(notes["items"]) < 5:
        await emit_business_event(
            event_type="stage_result",
            event_key="diagnosis_completed",
            payload={"stage_key": "diagnosis", "summary": "笔记不足 5 条，证据不足"},
        )
        return {"status": "insufficient_evidence", "note_count": len(notes["items"]), "findings": [], "summary": "笔记不足 5 条，暂不下结论"}

    result = await tool(
        "<判读 FA 的 mr_name>",
        query="按定位、内容问题、风险、建议四类给出诊断",
        notes_json=json.dumps(notes["items"], ensure_ascii=False),
        _rationale="由模型对笔记做判读",
        _output={
            "type": "object",
            "required": ["status", "summary", "findings"],
            "properties": {
                "status": {"type": "string", "enum": ["completed", "insufficient_evidence"]},
                "summary": {"type": "string"},
                "findings": {"type": "array", "items": {"type": "object",
                    "required": ["kind", "title", "reason"],
                    "properties": {"kind": {"type": "string"}, "title": {"type": "string"}, "reason": {"type": "string"}}}},
            },
        },
    )

    await emit_business_event(
        event_type="stage_result",
        event_key="diagnosis_completed",
        payload={"stage_key": "diagnosis", "summary": result["summary"]},
    )
    return {"status": result["status"], "note_count": len(notes["items"]), "findings": result["findings"], "summary": result["summary"]}
```

#### 三、生成写库

```python
async def run(input, ctx):
    await emit_business_event(
        event_type="stage_started",
        event_key="draft_started",
        payload={"stage_key": "draft", "stage_name": "正在生成草稿"},
    )

    profile = await tool(
        "<读库 FA 的 mr_name>",
        operation="read",
        query="读取商家档案 merchant_profile 这一行的 category / city",
        context_hint="表 merchant_profile；没有行返回 found=false",
        _rationale="生成时要用商家档案做本地化",
        _output={"type": "object", "required": ["found"], "properties": {"found": {"type": "boolean"}, "row": {"type": "object"}}},
    )
    if not profile["found"]:
        await emit_business_event(event_type="stage_failed", event_key="draft_failed",
                                  payload={"stage_key": "draft", "error_code": "profile_missing", "message": "商家档案未填写"})
        return {"status": "needs_input", "missing": ["merchant_profile"], "draft_title": "", "draft_body": ""}

    draft = await tool(
        "<生成 FA 的 mr_name>",
        query="把选题写成一篇正文草稿",
        topic=input["topic"],
        profile_json=json.dumps(profile["row"], ensure_ascii=False),
        _rationale="由模型生成正文",
        _output={"type": "object", "required": ["draft_title", "draft_body", "hashtags"],
                 "properties": {"draft_title": {"type": "string"}, "draft_body": {"type": "string"}, "hashtags": {"type": "array", "items": {"type": "string"}}}},
    )

    await tool(
        "<写库 FA 的 mr_name>",
        operation="write",
        query="把草稿写入 note_records 表作为草稿候选，不代发",
        context_hint="表 note_records；字段 title, content, status='draft'；只写 [editable:agent] 列",
        title=draft["draft_title"], content=draft["draft_body"],
        _rationale="存为候选草稿，用户在应用里决定发不发",
        _output={"type": "object", "required": ["found"], "properties": {"found": {"type": "boolean"}}},
    )

    await emit_business_event(
        event_type="stage_result",
        event_key="draft_completed",
        payload={"stage_key": "draft", "summary": draft["draft_title"]},
    )
    return {"status": "completed", "draft_title": draft["draft_title"], "draft_body": draft["draft_body"], "hashtags": draft["hashtags"]}
```

```json
[
  {"event_type": "stage_started", "event_key": "<stage>_started", "event_version": "1.0", "description": "开始<stage>",
   "payload_schema": {"type": "object", "additionalProperties": false, "required": ["stage_key", "stage_name"],
                      "properties": {"stage_key": {"type": "string"}, "stage_name": {"type": "string"}}}},
  {"event_type": "stage_result", "event_key": "<stage>_completed", "event_version": "1.0", "description": "<stage>完成",
   "payload_schema": {"type": "object", "additionalProperties": false, "required": ["stage_key", "summary"],
                      "properties": {"stage_key": {"type": "string"}, "summary": {"type": "string"}}}},
  {"event_type": "stage_failed", "event_key": "<stage>_failed", "event_version": "1.0", "description": "<stage>失败",
   "payload_schema": {"type": "object", "additionalProperties": false, "required": ["stage_key", "error_code", "message"],

```

模板三里用到了 `stage_failed`，用模板一、二时删掉第三条契约。

## 常见错误

- `_output` 抄了工具的全部字段，或和真实返回对不上，verify 报 `static_contract`。
- 脚本写成 tool → FA → tool → FA 长链，把「看结果再决定查什么」放在脚本里。
- 捕获全部异常后返回 `status="completed"`。
- FA 返回 `needs_input` 仍继续写库。
- 分段返回的工具只拿首段就下结论（判失败与上一条返回只隔几十毫秒）；工具自述的不确定态（如 `state="undetermined"`）不是失败。
- 为消除报错给无用途的路径补文件声明。
