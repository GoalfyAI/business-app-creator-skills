# 证据与「未测」

判每一条验收条目时读。

## 什么算证据

只认你自己这次取得的东西。部署成功本身、开发者的口头回报、他在在线预览或演示预览（含 Studio 里的演示）里看到的、已发布的版本，都不算。宿主提供的检查工具的机器结果可以作补充，和你在演示版上的操作分开记，不能代替页面条目的演示版操作。

| 条目要看的 | 怎么测 | 「通过」要的证据 |
|---|---|---|
| 业务结果：报告、内容、识别结果、写进库的记录、发出的消息 | `workspace` 实际跑；条目点名的样例没跑到的，照条目再跑一次 | 这次实际跑的 `project_id`、`workflow_trace` 里对应步骤的摘要、库里查到的那一行（不写库的写拿到的产出） |
| 页面上的操作和显示：点哪、跳到哪、空态、提示文字、必填校验、打回和重新生成、只读置灰、离开再回来 | 演示版上用无头浏览器照条目操作 | 操作步骤、截图路径或断言原文、打开过的演示版路由 |
| 到点或有新记录时自动开始的 | `business_ui_automation(action="bubble")` 按自动化入口跑一次 | 冒泡的 `run_id` 与结果；「到点真触发」另列一条记「未测」 |
| ② 标「要人判断」的：能不能直接对外、语气像不像、业务判断对不对 | 照样做一遍，不下结论 | 实际结果原文附进报告，结论「好不好你说了算」 |

读写应用库的条目只有冒泡证据（读库返回 `not_a_business_app_project`、写库被 `ctx.dry_run` 跳过）时，记录写「冒泡无法验证真实读写」，不算通过，要回去用 `workspace` 实际跑；开发者说先别放到在线预览的记「未测」。

页面条目还要按 ③ 记下的业务含义核对文案和动作，加载中、空态、只读、暂停、失效都要看。只读置灰在演示版 Mock 里设 `permission='view'` 验；Mock 做不到时记「未测」（平台登录身份）。

## 「未测」只能用于这几类

演示版能看的部分拆成一条照常测，其余部分结论「未测」、后三列写「无」，原因照下表原文写。第三列告诉开发者「没验证」意味着什么，让他自己判断要不要在意；不写成请他去看、去试，那是请他代测。

| 情况 | 原因原文 | 这意味着 |
|---|---|---|
| 依赖平台登录身份：按真实账号显示的内容、协作者打开自己的草稿、要另一种账号才看得到的 | 「要用真实账号登录才看得到：平台登录身份」 | 按真实账号显示的内容没确认过 |
| 依赖真实宿主桥接：从宿主消息提醒跳进应用、宿主弹出的授权与付款窗口、真实授权和付款 | 「要在 GoalfyMax 里打开才看得到：提醒、授权和付款窗口」 | 从提醒跳进应用、授权和付款这几处没确认过 |
| 依赖 Studio 里的真实窗口（只用于 Studio 宿主下 ② 单独写的「在 Studio 里打开看各页面」那一条）；其他页面条目照演示版结论写，不写成在 Studio 里也通过，也不因此记「未测」 | 「要在 Studio 窗口里打开才看得到」 | 页面在 Studio 窗口里的样子没确认过，内容和演示一致 |
| 演示版起不来，按「演示版页面验收」修过仍不行 | 「演示版跑不起来」，加做过的处理和错误原文 | 页面上的操作没确认过 |
| 开发者说先别放到在线预览，条目依赖已部署版本 | 「你说先不放到在线预览」 | 放到在线预览后的表现没确认过 |
| 条目要开发者手上的真实样本，他没有或没给 | 「缺你手上的样本：<哪一份>」 | 用你的真实样本时的结果没确认过 |
| 已部署，但部署后的页面你不能打开：线上能不能打开、线上页面的保存和读取走不走得通 | 「在线预览里的页面我打不开」 | 在线预览里页面能不能打开、保存和读取走不走得通没确认过；后台和数据库那一侧已经测过的写在别的条目里 |
| 到点真触发 | 「到点触发要等真实时间」 | 到点会不会自动开始没确认过；发布并在应用的「自动化」面板打开规则后才会自动跑 |
| 使用者从目录或分享打开 | 「从目录或分享打开要先发布」 | 使用者从目录或分享打开的样子没确认过 |
| 失败条目按条目里的做法造不出这次失败，换过其他做法也不行 | 「测试中造不出这种失败」，加试过哪些做法 | 真遇到这种失败时页面怎么提示没确认过 |

写方案时就知道测不了的事，不写成验收条目，直接放进报告的未测（`agenticapp-stage-2-plan` 的验收条目写法）。

不在这张表里的情况不能记「未测」：要么测出结论，要么记「没通过」。
