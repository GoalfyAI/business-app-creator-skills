# 上线结果模板

只放这个应用自己的东西，用业务话写，结论先行，每一句「通过」「已验证」都能指到证据。

## 给开发者的部分

写进工单和交付物，发给开发者：

| 项 | 写什么 |
|---|---|
| 上线的版本 | 已上线的是第几版、和上一版比改了什么；照抄入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)「部署、上线、发布」里对开发者说上线时补的那一句。协作者提请时写「已提请，等属主上线」和草稿版本、变更说明 |
| ④ 验过什么 | 通过几条、「好不好你说了算」几条及开发者的意见、开发者选了接受的没通过条目；实际跑出的结果一句话 |
| 未测的 | ④ 有「未测」条目时单列：逐条写条目、原因和 ④ 未测表「这意味着」那一列，让他知道哪些行为没有验证。没有就写「没有」 |
| 实际花了多少 | 这一阶段 N；一共 N，其中验证 N、失败重跑 N（分法见入口 [平台对象与用词.md](../../agenticapp-creator/references/平台对象与用词.md)「积分」）；上限 N。以后每用一次约多少，按 PRD 的用量每周约多少。读不到的按入口「说的话要有依据」写 |
| 发布会怎样 | 照抄：「发布后你自己和已安装的使用者会用上这一版；正式入口和到点自动运行在发布后才能用，你自己也一样；发不发、发给谁由你定」 |
| 发布要准备的 | 描述、Logo、版本更新说明，已按下面「发布要准备的材料」备好 |
| 你可以做的事 | 编号列出，都由开发者自己决定做不做：① 在发布管理页发布，选发给谁，填上准备好的描述、Logo、更新说明；② 有定时任务的，发布后在应用的「自动化」面板打开规则才会自动跑，外部数据有固定更新时间的写清规则时间要在它之后（按北京时间）；③ 把应用分享给使用者，可以附上下面的使用说明 |

## 发布要准备的材料

开发者自己正式使用、到点自动运行、给使用者用，都要先发布；发布页要求这三样：

| 材料 | 给什么 | 怎么写 |
|---|---|---|
| 描述 | 可直接粘贴的一段文字 | 给使用者看：这个应用帮谁做什么、打开后先做什么，两三句业务话，不写平台术语和内部名称 |
| Logo | 「已备好」加文件名，不给完整路径 | 用工程里已有的 Logo 图片（③ 已按 `agenticapp-tool-frontend` 做好） |
| 版本更新说明 | 可直接粘贴的一段文字 | 第一次上线写「首个版本」加主要功能；改已上线的应用写和上一版比改了什么、使用者会看到什么变化、已有数据怎么处理 |

## 附在交接消息里的几句

在上线结果后面附，不单独成节，不放进交付物的上线结果：

- **怎么打开**：发布后开发者和使用者从 GoalfyMax 打开这个应用，或从目录、分享打开；发布前开发者想自己看，用 Studio「在线预览」或发布管理页「预览」。不写容器地址。
- **使用说明**：使用者第一次打开看到什么、先做什么（每人一份自己的数据，打开是空的；在线预览里的数据不会带过去），平时怎么用，按业务顺序一句话；有授权的按 `agenticapp-tool-integration`「交报告前核对」列出要授权的平台。
- **平台提醒**：平台通用的提醒照实写一句，例如刚发布一两分钟内可能启动失败、一段时间没人用会休眠；改已上线的应用时，发布后正在用的人会看到什么变化、已有数据怎么处理。新 SDK 应用补一句：发布新 SDK 版本受灰度名单控制；有运行中的执行时发布会失败，要等执行结束或由你决定取消。旧应用迁到新 SDK 的，写明发布后旧版本里停在等使用者的执行会被平台取消并通知使用者。
- **还没验证的和风险**：④ 里开发者选了接受的没通过条目、能力缺口。

## 交接消息

```text
【⑤ 收尾 → 已完成】
刚做完：这次制作收尾了。<第几版>已上线，是你自己的正式版；要自己正式使用或给别人用，需要你在发布管理页发布，发不发布由你决定。
<上线结果>
<附在交接消息里的几句>
下一步：没有。之后要改什么直接告诉我，我接着改；只是想问问题也直接问。
要你做的：看上线结果；发不发布、发给谁由你定，发布要用的描述、Logo、更新说明已备好，不用回复我。
花了多少：这一阶段 <N>；一共 <N>；上限 <N>。
```

他说过先别放时没有上线结果，用这一支：

```text
【⑤ 收尾 → 已完成】
刚做完：验收报告交给你了，这一版按你说的没有放到在线预览，也没有上线。
下一步：没有。想改直接告诉我。
要你做的：看验收报告。
花了多少：这一阶段 <N>；一共 <N>；上限 <N>。
```

- 「要你做的」不写「请你发布」，也不等他回「发布了」再结单。全文不写请他看、点、补测、留意的话：上线后他会照你的话去做，「发布后请优先看一眼」「点一次『导出这周』就能确认」「第一个月看看积分记录」都是把你没做完的验证交给他。没验证的事写进「未测的」，只说没确认过什么。
- 协作者提请时交接消息只说：「已提请，等属主上线。」后续说法见 `agenticapp-role-collab`「提请属主上线」。

## 给后续 Agent 的部分

写进工单和阶段文档 G7，不发给开发者：

- 应用名、上线版本、是否已发布（结单时写「未发布，由开发者决定」）；
- 部署状态（`success`）与部署证据：`deployment_id`、`source_sha256`、`deployed_scaffold_version`；低于建议线时写「当前 vX 低于建议线 vY，建议下一轮升级」；有 `scaffold_upgrade_notice` 原样写；
- 场景包上线版本（新 SDK 应用写应用版本上挂的编排与 `tpe_ids`）、已验证路线与 `run_id`、豁免的路线与理由；
- 数据模板 ID 与版本；
- ④ 实际跑的 `project_id` 与结论，或省略实际跑的原因；
- 验收清单通过项数、不适用项、未测的条目与原因；
- 修订时 `compare_asset_versions` 取的前后配置差异；
- 发布级校验有存储提示时，从应用根的 `.pack/storage-check-summary.json` 或 `verify:release` 末尾的提示行读取，原样写入。
