# 工具组配置详解（二）：选中工具与工具描述质量

注册工具组时选工具、检查工具描述质量，或 Agent 频繁调错工具、填错参数时读。

本文分 2 份：[工具组配置-接入方式.md](工具组配置-接入方式.md)、[工具组配置-选中工具与描述质量.md](工具组配置-选中工具与描述质量.md)。

## 选中工具

从 MCP 服务暴露的工具列表中勾选需要使用的工具。只有选中的工具才会对 Agent 可见。

### 配置范式

- 不要全选，只选当前工具资产需要的工具
- 检查每个工具的描述是否准确清晰
- 如果工具描述不够好，在工具详情中修改描述

### 工具描述质量标准

工具描述不是 API 文档，而是**写给 LLM 的行为编程指令**。好的工具描述应该：

1. **包含路由逻辑**：何时用、何时不用
2. **包含防御性约束**：参数格式要求、禁止操作
3. **包含操作流程引导**：不只描述功能，还描述使用流程

**合格的工具描述**（以一个数据查询工具为例）：

```
执行只读 SQL 查询，返回结构化数据。

### When to Use
- 需要从数据库获取特定数据时
- 生成报表或做数据分析时

### When NOT to Use
- 写入或修改数据 → 本工具为只读，使用 `update_record` 工具
- 查系统日志 → 使用 `search_logs` 工具

### CRITICAL REQUIREMENTS
- 查询结果 MUST 使用 LIMIT（默认 100）
- NEVER 查询 passwords 或 credit_cards 表
- 时间格式 MUST 为 YYYY-MM-DD
```

**不合格的工具描述**：

```
查询数据库。
```

问题：太简短，LLM 不知道何时用、有什么限制、参数怎么填。

### 工具描述迭代

当发现 Agent 在使用工具时出现问题（调错工具、参数填错、执行后未验证等），应该通过修改 MCP 层的工具描述来解决，而不是在上层配置中补充说明。

常见 Bad Case 与修改位置：

| Bad Case 类型 | 修改位置 | 修改策略 |
| --- | --- | --- |
| 工具选择错误 | Description → When NOT to Use | 添加排他性说明 + 替代工具 |
| 参数格式错误 | Input Schema → description + enum/pattern | 添加格式约束 + 示例 |
| 执行上下文混淆 | Description → CRITICAL REQUIREMENTS | 明确执行环境边界 |
| 操作后未验证 | Description → Usage Notes | 添加验证流程要求 |

> 详细的工具描述迭代流程和模式库，参见 [工具描述迭代规范.md](工具描述迭代规范.md)。

### 诊断要点

- 每个选中工具的描述是否足够准确清晰
- 描述是否包含了路由逻辑（何时用/何时不用）
- 参数的 description 是否说明了格式要求和示例
- 如果 Agent 频繁调错工具或填错参数，问题是否出在工具描述质量（而非上层配置）
