# 工具组配置详解（一）：分层原则、名称描述与接入方式

接入工具组时定名称、描述、接口类型和连接配置，或判断工具描述该在哪一层改时读。

本文分 2 份：[工具组配置-接入方式.md](工具组配置-接入方式.md)、[工具组配置-选中工具与描述质量.md](工具组配置-选中工具与描述质量.md)。

一个工具组对接一个 MCP 服务，包含一组可调用的工具。

> 同一个 MCP 可以创建多个工具组，按能力域需求划分，相关工具放一个工具组。

---

## 核心原则：工具描述属于 MCP 层

**每个工具在 MCP 层已自带完整的描述和参数说明。上层配置（工具集技能、场景包 Skill 文件）不应重复这些内容。**

Agent 判断"一个工具怎么用、参数怎么填"时，只看工具自带的描述（名称、功能说明、参数说明），不会从其他地方获取单个工具的使用方式。因此：

| 关注点 | 负责层级 | 不应出现在 |
| --- | --- | --- |
| 工具做什么、参数怎么填、返回什么 | **MCP 工具描述** | 工具集技能、场景 Skill 文件 |
| 工具描述质量不好 | **MCP 层修改工具描述** | 在上层配置中补充说明来弥补 |
| 多个工具怎么搭配 | 工具集技能 | MCP 工具描述 |
| 业务流程怎么走 | 场景 Skill 文件 | 工具集技能、MCP 工具描述 |

> 如果工具描述写得不够好，应该直接在工具详情中修改描述，而不是在工具集技能或场景 Skill 文件中补充。工具描述的编写和迭代规范详见 [工具描述最佳实践-模板与字段.md](工具描述最佳实践-模板与字段.md) 和 [工具描述迭代规范.md](工具描述迭代规范.md)。
>
> 如果 MCP 服务以 HTTP/SSE 模式部署且涉及内部状态，需要按项目做数据隔离。

## 名称

工具组的名称。

### 配置范式

> 体现这组工具的能力范围。

**合格示例**：
```
客户信息查询工具
订单管理工具
邮件发送工具
数据库查询工具
```

**不合格示例**：
```
工具1           ← 没有业务含义
MCP测试         ← 看不出能力范围
```

---

## 描述

该工具组的功能说明。

### 配置范式

> 简洁描述这组工具能做什么。

**合格示例**：
```
提供客户信息的查询、更新和标签管理能力
```

```
提供订单的创建、查询、状态更新和退款处理能力，对接内部订单系统
```

## 接口类型

MCP 服务的连接方式，决定工具如何部署和运行。

| 接口类型 | 部署方式 | 适用场景 |
| --- | --- | --- |
| **Streamable HTTP** | 填写你的 MCP 服务地址 | 推荐方式，MCP 最新标准协议 |
| **SSE** | 填写你的 MCP 服务地址 | 旧版协议，仅用于兼容老服务 |
| **Stdio** | 上传代码包到平台 | 无需自建服务器，上传代码包由平台托管运行 |

**怎么选？**
- 有自己的服务器 → 推荐 **Streamable HTTP**
- 没有服务器 → 选 **Stdio**，上传代码包即可

---

## Streamable HTTP / SSE 配置

### MCP 服务地址

MCP 服务的 URL 地址。填写后点击「获取工具」，平台会连接该地址并拉取工具列表。

如果服务需要认证，请先填写请求头或环境变量，再点击获取工具。

### 请求头

HTTP 请求的自定义请求头，如认证 Token 等。

**示例**：
```
Authorization: Bearer your-api-token
```

### 环境变量

MCP 服务运行时需要的环境变量，如 API Key 等。

---

## Stdio 配置

工具包在平台托管的沙盒环境中运行，无需自建服务器。

### 获取方式

**方式一：使用公网包**

粘贴 Claude Desktop 格式的 MCP 配置即可，平台会自动解析。

**示例**：
```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-filesystem"],
      "env": {
        "HOME": "/home/user"
      }
    }
  }
}
```

**方式二：上传私有包**

本地上传代码包到平台。支持：
- **Node.js**：`npm pack` 生成的 `.tgz` 文件
- **Python**：`.whl` 或 `.tar.gz` 格式

### 上传阶段环境变量

上传验证阶段使用的环境变量，用于需要认证才能安装的私有包。

常见用途：
- `NPM_TOKEN`：访问私有 npm 仓库
- `PIP_INDEX_URL`：指定 Python 包源

> 仅在上传验证时使用，与运行时环境变量不同。

### 配置微调

上传成功后系统自动填充以下配置，通常不需要修改：

#### 启动命令（Command）

工具包的启动命令。
- Python 推荐：`uvx`、`uv run`、`python -m`
- Node.js 推荐：`npx`、`node`

#### 命令参数（Args）

传递给启动命令的参数列表。最终执行：`启动命令 参数1 参数2 ...`

#### 运行时环境变量（Env）

工具每次被调用时注入的环境变量。常见用途：
- API 密钥
- `DEBUG=true`：开启调试
- `LOG_LEVEL=info`：设置日志级别

> 与上传阶段的环境变量不同，这里的环境变量在每次工具运行时注入。

### Stdio 模式限制

- 首次调用需启动沙盒，有初始化延迟
- 沙盒有资源配额限制（CPU、内存、执行时长）
- 会话超时后需重新初始化
- 适合轻量级、无状态的工具；复杂业务场景建议使用 Streamable HTTP
