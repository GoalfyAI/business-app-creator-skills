# 工具集配置详解（一）：名称、描述与成员

建工具集（`create_toolset`）时定名称、描述、装哪些工具和 FA，或诊断工具集划分时读。

本文分 2 份：[工具集配置-名称描述与成员.md](工具集配置-名称描述与成员.md)、[工具集配置-技能与Skill文件.md](工具集配置-技能与Skill文件.md)。

工具集是工具和 FastAgent 的组合包，按能力域/业务模块组织。设计初衷是避免 Agent 一次性拿到所有工具导致上下文过长、执行效果下降。

> 按**能力域/业务模块**划分，而非按工具类型划分。例如"客户管理工具集"包含客户查询工具 + 客户信息更新工具 + 客户画像分析 FA，而不是把所有"查询类"工具放一起。

---

## 名称

工具集的名称。

### 配置范式

> 格式：`{操作对象}管理工具集`或`{能力域}工具集`，不带业务场景名。

工具集名称应体现**功能模块**而非业务场景，因为同一个工具集可能被多个场景共用。

**合格示例**：
```
客户管理工具集
订单处理工具集
库存管理工具集
数据查询工具集
内容发布工具集
```

**不合格示例**：
```
投诉处理工具集         ← 绑定了特定场景，应按操作对象命名（如"工单管理工具集"）
查询类工具             ← 按工具类型划分，不是按能力域
第二批工具             ← 没有业务含义
```

### 诊断要点

- 名称是否体现能力域而非特定场景
- SA 能否仅凭名称判断这个工具集的能力范围

---

## 描述

工具集的功能说明。挂载模式下，描述是调用方（SA 或 TA）能看到的**唯一信息**——技能、工具、FA 全部不可见，调用方完全凭这一段描述决定是否 load_toolset。

### 配置范式

> 2-3 句话：操作什么对象 + 能做什么操作。通用化，不绑场景。

描述质量直接决定调用方的路由准确性。描述写不好，调用方要么找不到该用的工具集，要么频繁误加载不需要的工具集。

> **有 TPE 时**：工具集如果在 TPE 下，描述的读者是 TA。写法标准不变——通用化，不绑场景。同一个工具集可能同时被场景包（SA 用）和 TPE（TA 用）引用，描述应对两种读者都适用。

**合格示例**：
```
提供客户信息查询、客户资料更新、客户标签管理、客户分群等客户关系管理能力
```

```
提供工单的创建、查询、更新、关闭、分配和升级等工单全生命周期管理能力
```

```
提供数据库查询、数据导出和查询结果缓存等数据查询能力，支持 MySQL 和 PostgreSQL
```

```
提供商品信息查询、SKU 维护、库存同步和价格批量更新等商品运营能力，支持对接 Shopify 和 Amazon
```

**不合格示例**：
```
一些有用的工具         ← SA 无法判断何时加载
处理各种客户相关的事    ← 太模糊，"各种"没有信息量
```

### 诊断要点

- 挂载模式下，调用方（SA/TA）能否仅凭描述判断何时需要加载
- 描述是否涵盖了工具集内所有工具和 FA 的能力范围
- 描述是否与其他工具集有明显的能力边界区分

---

## 包含的工具和 FA

选择该工具集包含的工具和 FastAgent。同一个工具可以被多个工具集包含——例如"写入文件"工具可能同时出现在文档编写工具集和代码开发工具集中，因为两个能力域都需要它。工具集加载后，SA 可调用其中的所有工具和 FA。

### 配置范式

**组织原则**：
- 把完成同一功能模块所需的工具和 FA 放到一个工具集
- 一个工具集应该能独立完成一类任务，尽量不依赖其他工具集
- 不要把所有工具都堆到一个工具集里
- FA 放在**其主要操作对象所属的功能模块工具集**中

**FA 归属判断**：这个 FA 主要操作什么对象？→ 放在那个对象的工具集里。

> FA 的内部工具选择不受所属工具集限制。FA 可以使用来自任何 MCP 的工具，按需配置。所属工具集只决定 SA 何时能"看到"这个 FA。

**合格示例**：

「监控告警工具集」包含：

```
来源：监控平台 MCP
- get_alert_detail：获取告警详情
- list_active_alerts：列出活跃告警
- acknowledge_alert：确认告警
- resolve_alert：关闭告警
- get_server_status：获取服务器状态
- get_dependency_map：获取服务依赖关系
- verify_metric：验证指标是否恢复

包含的 FA：
- 故障根因分析 Agent：分析多维度监控数据定位故障根因
```

**不合格示例**：
- 一个工具集包含大量跨多个业务模块的工具 ← 应按能力域拆分为多个工具集

### 诊断要点

- 工具集是否按能力域划分（而非按场景或工具类型）
- 工具集内的工具和 FA 是否围绕同一操作对象
- 工具集内的工具数量是否合理（工具过多时考虑按能力域拆分）
- FA 是否放在了正确的工具集中（按主要操作对象归属）
