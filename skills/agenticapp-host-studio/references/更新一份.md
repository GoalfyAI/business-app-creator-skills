# 更新一份开发文档

已经保存过的开发文档要出新一版时读。

1. 用 `studio_read_creation(documentType=当前类型, includeProposalContent=true)` 读取宿主当前保存的版本，按 `nextCursor` 拼完整正文，记下这次读到的 `artifactId`。本地 `docs/studio/<documentType>/data.json` 可能仍是旧版，尤其是经右栏升级或由其它会话保存以后。
2. 把返回的 `index.html` 放入本次修订的独立目录，运行 `node <本 Skill 目录>/scripts/build_studio_doc.mjs extract index.html <本次修订目录>` 还原 `data.json` 和方案 Demo。原样保存工具返回的 `acceptance.json`。旧页没有数据块时，以刚读到的页面重建数据。若本次明确要改方案而原方案缺少可执行验收清单，按普通方案规则编写本次拟执行的清单，既有历史验收记录仍引用原来源。
3. 在还原的数据上只改本次要改的部分，`version` 接着已保存版本加一，`updated` 写这次的实际时间，`changes` 用一句一项记录改动。仍可把明确要提交的未保存本地改动合入这一版。生成、看过和保存沿用 SKILL.md「怎么写一份」第 3–6 步，路径使用本次修订目录。保存必须把第 1 步读到的 `artifactId` 作为 `baseArtifactId`。冲突时从第 1 步重读并整合。只更新本次要改的文档。

两处例外：
- ④ 里验收报告每出一版有没通过的条目（含开发者提的修改），制作进度在同一条回复里跟着更新：还没开始改时，时间轴加一条事件逐条列出没通过的（等他决定的标 `blocked`）、`now` 写「验收有 N 条没通过」和正在改还是等他决定，功能格子不动；开始改时格子按 `agenticapp-stage-4-acceptance`「按反馈改」退回，`changes` 写改的是哪条、为什么改；改好测过再改回「做好了，……」。④ 不另起一份进度。
- 已确认的 PRD 和方案什么时候出新一版，按 `agenticapp-stage-1-requirements` 的版本与确认规则。

验收报告出新一版（例如 ⑤ 收尾时补「上线结果」）时，沿用的截图仍放在 `shots/`、随 `files` 一起提交；不把图片转成 `data:` 内嵌，内嵌图片会让保存失败。
