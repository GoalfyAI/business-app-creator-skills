# 表单与记忆卡

Studio 宿主下要在回复里发表单（按轮问的一轮、收集参数或文件）或记忆卡（说明这一轮用了开发者偏好）时读。问什么、一轮问哪些按 `agenticapp-stage-1-requirements` 的按轮问，这里只管怎么写成表单。没有 Studio 工具的宿主不输出这里的任何标签：会被原样显示出来。

## 先跑脚本，再原样粘贴

Studio 只认格式完全正确的 JSON；写错时开发者看到的是一句「表单无法显示」，或者控件被悄悄换成单行文本。所以表单和记忆卡一律由脚本校验并生成，不手写标签、不凭记忆拼 JSON：

1. 按 [表单控件.md](表单控件.md) 写表单体 JSON（只写 `lang`、`submitLabel`、`questions`；`id` 和 `title` 走参数），交给脚本：

   ```bash
   node <本 Skill 目录>/scripts/studio_card.mjs form --id round-2 --title "需求确认 · 第 2 轮" - <<'JSON'
   {"lang":"zh-CN","submitLabel":"提交回答","questions":[ … ]}
   JSON
   ```

   `--id` 只能用小写英文、数字、`-`；`--title` 1–30 个字符，不能含 `"`、`<`、`>`。记忆卡用 `studio_card.mjs memory -`，只写 `summary` 和 `used`。
2. 脚本退出码非 0 时，按它列出的每一条改 JSON 再跑，直到输出一整行 `<question-form …>…</question-form>`（或 `<od-card …>…</od-card>`）；脚本通过了才发。
3. 把脚本输出的那一整行原样复制进最终回复，一个字符都不改；要改内容，改 JSON 重新跑。
4. 表单是这条最终回复的最后一段：前面写交接消息正文（入口「交接」），表单之后不再写任何字、不再调用工具，等开发者提交。记忆卡放在正文开头或交接消息正文之后、表单之前。
5. 表单和记忆卡直接放在正文里，不放进代码块、引用块或列表，不在过程说明（commentary）里发；一条回复最多一张表单、一张记忆卡。

排查「为什么没显示」时，把整条最终回复存成文件，用 `studio_card.mjs reply <文件>` 校验。

## 按轮问怎么写成表单

| 按轮问的规矩 | 表单里怎么写 |
|---|---|
| 一轮 | 一张表单，标签写 `id`（`round-1`、`round-2`……，同一应用不重复）和 `title`（例如「需求确认 · 第 2 轮」）；JSON 写 `lang: "zh-CN"`、`submitLabel: "提交回答"`、`questions` |
| 一轮超过 5 题 | 一张表单最多 5 题，一条回复只能放一张：先发前 5 题，开发者提交后接着发下一张；剩下的题仍算这一轮，不因换张推迟到下一轮重排 |
| 一道题 | 一个 `questions` 元素：`id` 用题号（`q7`），`label` 写「Q7 从哪开始：……」，`type` 有选项的用 `radio`（多选用 `checkbox`），没有现成选项的用 `textarea` |
| 选项 | `options` 每项写 `label`（给开发者看的话）、`value`（稳定的短英文）、`description`（选了会怎样） |
| 「其他，说说你的想法」 | 不另写选项，用 `allowCustom: true`、`customLabel: "其他，说说你的想法"` |
| 推荐答案 | 写进推荐那项的 `label` 末尾「（推荐）」，并在 `description` 里写为什么推荐；不用 `defaultValue` 预选 |
| 只有开发者知道的事实题 | `textarea`，不标推荐，`placeholder` 写「照实说；拿不准写『不确定』」 |
| 方向题 | 单独一张表单，只这一题 |

- 表单前的正文照常写「刚做完 / 下一步 / 要你做的 / 花了多少」；「要你做的」写「在下面的表单里答」。
- 开发者不点表单、直接在对话里回「是」或逐题写，照按轮问「什么算定了」算。表单里没有「全部按推荐」的按钮，开发者要一次接受全部推荐，在对话里回「是」。
- ① 的「确认这一版」、② 的整版确认不用表单，用开发文档和确认卡（SKILL.md「确认怎么登记」）。

## 答案怎么回来

- 开发者提交后，下一条用户消息以 `[form answers — <表单 id>]` 开头，下面每题一行 `- <题目>: <答案>`；选择题回的是选项的 `label`，文件题回的是文件名，附件随消息一起到。
- 写着 `(skipped)` 的题是开发者点了「跳过·你来判断」，算他对这一题说「你看着办」：有推荐的题按 `agenticapp-stage-1-requirements` 按轮问「什么算定了」按推荐定下、标「按默认」，不再问；事实题照那里回「你定」的一条，下一轮再问一次。方向题，以及要他同意才能做的题（试跑、入口「红线」里的外部副作用、入口「花费」里用到 80% 后继续或提高上限）被跳过不算答了，也不算同意，下一轮接着问。
- 开发者没提交就在聊天里发了消息（例如追问某题），Studio 会关掉这张表单，再也交不了，他在表单里选过、填过的你也收不到：这张表单里他没在聊天里答的题同样按没回答处理。回答完他的问题后用新表单（`id` 换新的）接着问，不请他回旧表单提交。

## 记忆卡

这一轮的做法用到了 `dev_preferences` 里开发者写过的偏好时，可以发一张记忆卡，告诉开发者用了哪几条；没用到就不发。卡片体只写：

| 字段 | 写法 |
|---|---|
| `summary` | 一句话，≤80 字，例如「本轮按你的 2 条开发偏好写」 |
| `used` | 1–10 项，每项写 `type`（`profile`、`project`、`rule`、`feedback`、`reference`、`user` 之一；开发偏好一般写 `project` 或 `rule`）、`name`（这条偏好的一句话，≤40 字）、可选 `id` |

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 手写标签没跑脚本，漏了逗号、`label` 里的英文双引号没转义，整张表单显示不出来 | 一律用脚本生成 |
| `type` 写成同义词或拼错（`dropdown`、`datetime`、`toggle`），控件被换成单行文本 | 只用 [表单控件.md](表单控件.md) 的 17 种原名 |
| 选项写成字符串数组、`value` 用中文，答案对不上题 | 选项写成对象，`value` 用短英文 |
| 给选择题写 `defaultValue` 预选推荐项，10 分钟后被自动提交成开发者的选择 | 推荐写在 `label` 末尾「（推荐）」 |
| 改动脚本输出后再粘贴（加换行、改引号、套代码块），或在 `</question-form>` 后面继续写「请填写上面的表单」 | 原样粘贴，表单是最后一段 |
| 一条回复发了两张表单，或表单发在过程说明里、随后又继续调用工具 | 一条回复最多一张，放在最终回复里 |
