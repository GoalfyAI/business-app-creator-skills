# 开发文档检查清单

生成脚本跑通之后、保存之前，逐条对一遍。脚本拦得住的（字段齐不齐、结论数、未测类别、禁用词、Demo 联网）不在这里；这里是要看了页面才判断得出的。

## 先截图

```bash
python3 <本 Skill 目录>/scripts/build_studio_doc.py shot docs/studio/<documentType>/index.html frontend
```

它在 `docs/studio/<documentType>/.shots/` 下存 400px 和 900px 两张整页截图，并报页面脚本的错误（方案里多半是 Demo 脚本写错了）。打开两张图看；截不了图（前端没装浏览器）就按下面逐条读 `data.json`，并在阶段文档里记「没截图，原因：…」。`.shots/` 不放进 `files`。

## 每份都看

- [ ] 400px 下没有文字被截断、挤成一字一行、互相盖住；900px 下没有大片空白。
- [ ] 开发者读得懂：没有工具名、资产编号、英文表名、文件路径；同一个东西全文一个叫法，用开发者自己说过的词。
- [ ] 数字都有来处：实际跑、真调、开发者给的，或写明「估算」「预期」。
- [ ] 写的是当前段的文档，没提前写后面段的。

## 需求说明

- [ ] 概述四行，每行一句话就看懂；流程图一眼看得出业务从哪开始、到哪结束。
- [ ] 每个节点的输入、输出、重要信息写的是这一步的事，不是整个环节的重复。
- [ ] 环节最后一步写了怎样算做成；会记下来的东西写在保存那一步。

## 方案

- [ ] 每个 Demo 是完整页面，400px 下缩放后字还看得清；编号不遮字。
- [ ] 每个按钮点了有反应，「重置示例」能回到原样；点编号能对上下面的说明。
- [ ] 第一条说明写了输入、最后一条写了输出，中间只写操作。
- [ ] 运行条件的五件事写全：施工单里的每次写入、发送、外部调用都在里面；没定的写成他能答的问题。

## 制作进度

- [ ] 时间轴每个时间都能在工作记录里找到；没做的没写时间。
- [ ] 完成数和你在进度消息里说的一致。

## 验收报告

- [ ] 过了 `agenticapp-stage-4-acceptance`「交报告前的三道硬门」。
- [ ] 每条路径的每一步，点开看到的依据就是那几条条目的结果。
- [ ] 截图看得出结论说的那件事；页面上没有请开发者去预览或正式入口里试的话。
