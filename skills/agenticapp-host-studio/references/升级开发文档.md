# 升级开发文档

在 Studio 收到「请升级本会话的开发文档」时，从消息取升级编号，先只传 `id` 调 `studio_document_upgrade`。以返回的应用、原文档与 `guidePath` 为准。从这份指南所在 Skill 读取数据说明、Demo 示例与生成器。升级编号不成立时停止写入。

## 先定范围

读取原会话、原文档和当前工程。用工具返回的游标读完正文，优先采用开发者已经确认的需求和方案。用源码、阶段记录和验收回执判断实际做到哪。已关联平台应用时，能用 `business_ui_manage(action="resolve")` 就只读核对有无正式上线版本，否则沿用能核对的上线回执。计划与实现有出入时，按实际实现写制作进度，并保留原确认对应的文档。

调用 `studio_document_upgrade`，传 `id` 和 `through` 登记已到达的最后一段。已上线用 `acceptance`，生成需求说明、方案、制作进度、验收报告。做到方案阶段用 `proposal`，至少生成需求说明和方案。以工具返回的 `expected` 为最终范围，跳过 `saved` 或 `modern` 中的文档。

## 一份份填数据

按 `expected` 顺序完成**当前一份的填写、生成、校验、保存和读回**，随后处理下一份。颜色、背景、字号、布局和交互由同一个生成器和「开发文档外壳.html」提供。只写数据、Demo 和可核对的附件。每份用对应数据说明里的完整样例做起点，把样例全部换成本应用内容。

- **需求说明**写清谁使用、怎么用、会得到什么。用原需求、已确认的方案和实际页面补齐角色、流程和示例。示例值可以自拟，写成给读者看的操作示例。
- **方案**整理制作范围、运行条件、功能和页面。每项功能写一个可操作的轻量 Demo。已实现的按实际界面和行为还原，计划内还没实现的写成「设计示例」。Demo 只用示例数据，不联网、不读写业务数据。沿用已核对可执行的原 `acceptance.json`，或直接生成阅读页。
- **制作进度**按源码和阶段记录写实际交付范围、制作里程碑和应用现状。没有确切时间的历史事件可省略 `time`。后台已实现但试跑情况不在原记录里时，后台状态写「做好了」。
- **验收报告**用 `historicalSummary` 写应用当前的交付情况和可使用的功能，已有上线结论时可直接写进概况。把能核对的真实结果填入 `items`，有业务路径依据的填 `paths`。没有可核对条目时用交付概况生成整份报告，省去条目和数字。不得把上线或示例写成验收通过。

开发者在右栏直接看文档。省去「缺少信息」「清单未留存」「请重新确认」等提示，也不要用缺项占位符填正文。历史事实写具体，能从应用推导的流程和示例写完整。通过结论、历史确认、截图、时间、费用和上线版本按实际依据写。

## 从生成器直接保存

1. 在工具返回的 `outputDirectory` 下给每份建同名子目录，例如 `proposal/`，把 `data.json`、Demo 和适用附件放进去。截图文件名用 ASCII 字母、数字、点、短横线或下划线。只在本次目录准备文件，原工程和旧文档继续保留。
2. 用 `node "<Skill>/scripts/build_studio_doc.mjs" <类型> "<目录>/<类型>/data.json" --document-upgrade` 生成。版本沿原版号递增，无法认出原版号时从 1 开始，`updated` 写本次整理时间。生成报错就改数据或 Demo，再跑一遍。对照 [检查清单](检查清单.md) 看一眼页面和 Demo，再用同一个生成器的 `verify "<目录>/<类型>/index.html"` 核验。生成后保留原产物字节，别手写或编辑 `index.html`，也别自行替换样式。
3. 调 `studio_write_proposal`，传 `upgradeId`、`documentType`、`version`、`baseArtifactId`、`generatedFiles`。`generatedFiles` 只填生成器最后一行列出的文件名，例如 `["index.html", "acceptance.json"]`。宿主直接接收文件。若旧宿主未返回 `outputDirectory`，用本次专用暂存目录生成，以 `files` 提交生成器原样输出的 UTF-8 文件，报告里的截图证据保留文字并省去图片附件。基线用宿主给的 `baseline`，没有原文档传 `null`。
4. 读回 `studio_document_upgrade(id=升级编号)`，所选类型进入 `saved` 再处理下一份。明确的格式错误就改数据重新生成。旧机器验收清单校验失败时，从暂存目录和保存文件列表移除该清单，重新生成方案阅读页并保存。版本冲突时保留别人保存的新版和本轮已保存的文档，继续处理其余能安全保存的文档。保存结果未知时用原写调用的 `nativeTurnId` 和 `callId` 通过 `studio_read_creation` 核对。完成或确认中止后只清理本次暂存目录。

全部完成后告诉开发者从「开发文档」查看。确有保存失败时指出需要继续的文档。原确认归原版，升级只保存阅读版。不要登记新确认、发送确认卡、重跑验收、改工程或触发上线发布。下次用户修改应用时走正常流程。
