# ② 方案

这一段让开发者确认「你们是按我的想法在做」：交给他一版整版方案：制作范围、运行条件（数据从哪来、要准备什么、哪些地方花钱、谁能看能改、会不会对外做事）、每个功能怎么完成和页面长什么样，只请他确认一次。他确认方案，就同意了运行条件里的花钱和对外动作。验收条目和施工单写好留给 ③ ④，不进方案正文。

这一段最常见的错有两种。一是**做法不对**：计数、求和交给模型；该人把关的直接写库；一次全量跑到超时；同一业务再做一次产生重复记录；只有单条脚本没有完整路线，或没看已有资产就重复新建。这些错到 ③ 用真实数据跑时才暴露，只能退回 ② 重编、再确认一次。二是**验收条目照不着做**：写成测不了的话，条目名里的动作没写全，④ 只能记「未测」。

规矩以入口 `agenticapp-creator` 为准。要的东西变了 → 回 `agenticapp-stage-1-requirements`；方案已确认 → `agenticapp-stage-3-build`。

## 开始前确认

- ① 交了棒：当前这一版 PRD 已确认；阶段文档 G2 的核实对照表里每一步都有能力来源。
- 从修订进来的，只编、只说明受影响的功能。
- 手边有 `agenticapp-stage-1-requirements` 的「按轮问」（问法与 ① 共用，题号接着 ① 往下编）。

## 按这个顺序做

1. **找出取舍**。按 PRD 每个刚需在心里过一遍做法（不写给开发者），从「按轮问」里 ② 的起步方向开始，列出两种以上做法都成立、选哪种使用者感受得到的地方；对话中冒出新取舍随时加。只有一种做法成立的、使用者感受不到的你自己定（入口「开发者确认什么」）。
2. **要看效果才能选的先试跑**。例如报告看 6 篇要多久、看全要多久：用 ① 的真实样例，按 `agenticapp-stage-1-requirements`「能力试用」把关键模型步骤跑一次，输出、用时、花费写进题干。花钱先问（入口「花费」）。依赖试跑结果的题等结果出来再问，其余照常发。
3. **按轮问**。按「按轮问」问取舍和验收要求：PRD 和 ① 里已定的不再问；验收要求只问缺失或矛盾的；问到没有空着的为止。每轮交接消息开头「【② 方案 → 等你确认】」。没有取舍可问、验收要求也已明确时，在交接消息里说一句「做法和验收要求已明确」，直接往下做。
4. **整理已定事项**。按功能整理取舍和验收要求，沿用已有答案，不为复述再次要确认；仍有歧义的先问清。
5. **编施工单**。按 [references/施工单.md](references/施工单.md) 逐个映射 PRD 流程图的节点，定路线数和数据怎么进出。用到的写法在 `agenticapp-tool-workflow`（FA、编排脚本、路线、审阅）、`agenticapp-tool-automation`（自动化）、`agenticapp-tool-data-template`（表、列、入口字段、谁建行）、`agenticapp-tool-frontend`（页面）里，编的时候就加载来读。分批、分片按 `agenticapp-ref-platform-limits`。
6. **写制作范围和功能与页面**。照 [assets/方案.md](assets/方案.md) 第 1、3 部分。
7. **写验收条目**。照 [references/验收条目.md](references/验收条目.md)，PRD 每个环节至少一条；存放见 [assets/方案.md](assets/方案.md)「验收条目」。
8. **写运行条件**。按施工单和 G2 的核实结论写五件事（[assets/方案.md](assets/方案.md) 第 2 部分）：重算制作还要花多少、上线后每用一次多少，施工单里每一次写入、发送、外部调用都要列进去。读写应用库的路线 ④ 部署后才能真跑，拿不到实测时估算并写出算法，之后有实测就换。超出 ① 的上限时，生成方案前先出选择题，答复后再定稿。
9. **一次发出整版方案**，按下面「整版确认」等他确认。

## 整版确认

- 一次发出：制作范围、运行条件、功能与页面，交接消息里写验收条目的条数。「要你做的」写「看这一版方案，没问题就确认；哪里要改直接说」。不附逐项判断题，不另发第二张整版确认表单。
- 什么算确认：对当前这一版的明确同意，规则同 `agenticapp-stage-1-requirements`「PRD的写法」里的「版本、批注和确认」。Studio 下按 `agenticapp-host-studio`「确认怎么登记」；其他宿主在对话里确认，记下当前版本和原话。
- 收到修改意见：只澄清还没明确的改动和受影响的取舍，保留其他已答事项；出新一版、说明改了什么，再确认一次整版。要改的是要什么、不要什么时，退回 ① 改 PRD。

## 这一段要做对的判断

| 判断什么 | 依据 | 判错的表现 |
|---|---|---|
| 每一步交给谁 | 确定性的给脚本，要判断的给模型，有风险的留给人；计数、求和由脚本算，不信模型给的数（`agenticapp-tool-workflow`） | 计数、求和交给模型；该人把关的产出直接写库 |
| 串行、并行还是分批 | PRD 的用量 × `agenticapp-ref-platform-limits` | 一次全量跑，超时；长数据整批交给模型读不全 |
| 更新还是新增，业务键是什么 | 「数据怎么进出」 | 同一业务再做一次产生重复记录 |
| 每列谁写 | 每列恰好一个写入方，使用者和路线都要写的拆两列（`agenticapp-tool-data-template`） | 使用者和路线写同一列 |
| 每个外部调用失败了怎么办 | PRD 节点的「做不成时」→ 失败出口；FA 输出给部分成功留出口 | 失败出口缺失；一批里几条失败就整批作废或编数补齐 |
| 模型档位与费用 | 够用的最便宜一档（`agenticapp-stage-1-requirements`「谁来做」） | 档位和任务难度不配，或超出上限没问 |
| 做法完整 | PRD 每一行在施工单里找得到；G2 有可复用的就复用；路线组装完整 | 只有单条脚本没有路线；没看已有资产就重复新建 |
| 验收条目能逐条照做 | [references/验收条目.md](references/验收条目.md) | 条目测不了；条目名「编辑并停用商品」只写了停用 |
| 开发者看得懂方案 | 业务话，例子用真实数据 | 方案里出现资产 ID、模型名、字段名 |

## 你可能会这么想 → 实际

| 想法 | 实际 |
|---|---|
| 方案写好了再问取舍 | 取舍和验收要求在生成方案前问清；方案生成后只确认一次整版 |
| 每个已答的事项再请他逐条确认一遍 | 已答的直接沿用，不为复述要确认 |
| 用哪一档模型请他选 | 档位你定；只有换档会超上限或明显改变结果时才当取舍问 |
| 只有脚本步骤，不用路线 | 也建一条最小路线，只作平台要求的挂载依赖 |
| 施工单多写一次发送也没关系 | 写进运行条件「会不会自动对外做事」：方案里列过才算他同意过（入口「红线」花钱和对外动作），没列的发出去就是没经他同意 |
| 页面怎么排随便定 | 按 ① 问到的界面答案写进「功能与页面」，确认后是页面的最高依据 |

## 记下来

- **阶段文档 G3**：取舍题的「已定的事」（是什么、谁说的或按默认、哪一轮定的）和试跑记录、施工单、整版确认依据（版本、确认卡回执或对话原话）及修改意见和改动、验收条目定稿、运行条件的花费算法。依据 PRD 第几版写清，只记和 PRD 不一样的地方。
- **方案页**：「开发内容」补运行条件和功能与页面，`#needs` 补要他准备的，见 [assets/方案.md](assets/方案.md)。
- **工单 checkpoint**：`方案已确认`，附资产清单摘要、路线与表名、验收条目数。
- **阶段标记与阶段记录**：G3 标 `passed`，用 `business_ui_stage` 写 G3 一条（`agenticapp-tool-workspace`「阶段记录」）。只在工作区里标记不算。

## 交棒

全部满足，再加载 `agenticapp-stage-3-build`：

- 取舍和验收要求在生成方案前已问清，已有答案沿用，施工单按定下的取舍写；
- 开发者确认了当前这一版整版方案（Studio 下读回这一版已确认）；
- 验收条目与问清的要求一致，PRD 每个环节至少一条；
- 方案里每个功能的每一行都写了，含「做不成时」；运行条件五件事都写了，施工单里的写入、发送、外部调用都列在里面；
- PRD 每一步在施工单里都找得到；费用没超上限（或超出部分开发者已选过）；
- `workspace.json` 的 G3 标 `passed`，并已调 `business_ui_stage` 写了 G3。

写完 G3 后，**下一个动作是发第一条进度**（`agenticapp-stage-3-build` 第 1 步：全部功能列进进度表，多数是「没开始」，并保存制作进度），然后才建表、建资产、写代码。测试里 Agent 读了这一步，仍在 G3 之后直接建了 5 张表，开发者到验收前都没看到一条进度。

## 出问题

| 现象 | 处理 |
|---|---|
| 某一行编不出来（没有对应能力） | 回 ①：对照 G2 改 PRD，告诉开发者做不到和替代 |
| 编完费用超出上限 | 生成方案前出选择题 |
| 取舍要看效果，试跑跑不了（读写应用库要部署后才能跑、工具被平台问题挡住） | 用 ① 真调拿到的数据和同类步骤的估算写题干，标「估算」，照常问；只是还没跑完的，等结果 |
| PRD 里有只能由平台方做的事（改使用者的安装记录、改生产库） | 施工单不编这一项；按入口「报错和平台问题」报，交接消息说清影响哪个功能；退回 ① 把那一处改成平台问题和对开发者的影响，确认后再回来 |
| 一条路线步骤太多、业务说明讲不清 | 考虑拆成两条（`agenticapp-stage-1-requirements`「谁来做」的填写规则），业务说明里讲清 |
