# 归因对照

诊断时判断一个错误归制作侧还是平台侧时读。先看返回里给的出口和提示；本表只补返回里没说清的部分。一个错误码的处置只在一处写：编排、冒泡类和新 SDK 执行类（`EXECUTION_*`、`APP_VERSION_*`）见 `agenticapp-tool-workflow`「编排报错对照」，协作类见 `agenticapp-role-collab`，其余到对应工具 Skill 的「常见错误」查。

## `ORCH_NODE_FAILED` 按失败类别归因

它是兜底错误码，失败类别在 `workflow_trace` 的排查信息里。下表只写归属；每一类往哪查、怎么处理，见 `agenticapp-tool-workflow`「编排报错对照」。

| 失败类别 | 归属 |
|---|---|
| `business_gate` | 脚本按规则主动停止，不是故障 |
| `contract_error`、`script_bug`、`shell_exit` | 制作侧 |
| `tool_error` | 看上游工具 |
| `fa_error` | FA 预算用尽或异常退出 |
| `timeout` | 先查最慢的一步 |

信息是「结果为空」，且判失败与上一条工具返回只隔几十毫秒的，归制作侧脚本。

## 读日志时会碰到的

- 卡在 `waiting-input`：中途表单或审阅在等人回答，是正常挂起。
- FA 每一轮做了什么、`download` 报不存在或受保护目录、冒泡回执里的 `project_id` 能读多久，查法见 `agenticapp-tool-workflow`「编排报错对照」。
- 路线、工具集、授权卡、表单挂起这类错误码的含义和处置，见 `agenticapp-tool-workflow`、`agenticapp-tool-integration` 的「常见错误」。

## 应用侧问题

读应用工程源码和部署记录：

| 前端看到的 | 多半是 |
|---|---|
| `BAD_GATEWAY` | 后端响应信封违约 |
| `TIMEOUT` | 异步路由漏了错误处理，或查询过慢 |

运行结果和代码对不上时，先核对那次运行跑的是哪一版，做法见 `agenticapp-tool-deploy`「实际跑」。

## 归到平台侧的

按入口「报错和平台问题」报，`attribution` 按那里的说明选。
