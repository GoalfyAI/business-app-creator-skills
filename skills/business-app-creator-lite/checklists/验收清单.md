# 验收清单（人判项）

机器能判的都在 `otpe_manage(action="verify")`、`npm run verify` 和路线冒泡里，不重复。下面是只能由你判断、并要写进工单检查点的项，每条给「通过 / 不适用」加一句依据。

1. 分工表每一行都能在资产里找到对应：规则行有脚本步骤，模型行有 FA，人行有页面或表单。
2. 用户在预览里能走完每条路线：从入口到看到结果，中途需要补的信息有地方补。
3. 结果内容看得懂：没有内部 ID、字段名、原始 JSON 直接摆给用户。
4. 「做不成怎么办」那一列真的发生了对应的事：至少人为制造一次失败看它怎么表现。
5. 模型行的输出经过人眼核对一次真实样例，不只看形状。
6. 数据管理页只开放了该用户改的列；系统写的列只读并标明来源。
7. 只读权限下所有发起和写入入口置灰并说明原因。
8. 费用与副作用与确认页一致，没有多调工具、多发消息。
9. 一次真跑的 run_id、场景包版本、数据模板版本、应用版本已记进工单。
10. 交付报告里的每一句「已验证」都能指到证据；未验证的明确列出。
