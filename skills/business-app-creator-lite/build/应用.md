# 3.3 数据模板与应用

## 数据模板（有「会存下来的东西」才做）

1. `dataset_template_workspace(action="open", task_id, name, description)` 记下 `data_uid`；返回的连接串填进 `backend/.env`，不进工单和聊天。
2. 每张表 `dataset_template_workspace(action="create_table", task_id, data_uid, table_name, target_columns=[…])`：至少一列 `primary_key=true`；每列 `comment` 以 `[editable:user|agent|system]` 开头再写中文名，选项列在注释里加 `{options:a|b|c}`；审计列固定带上：`created_at`、`updated_at`、`updated_by`、`last_run_id`、`row_version`、`deleted_at`（都是 `system`）。谁写哪列按分工表：用户填的 `user`，模型 / 路线写回的 `agent`。
3. `inspect` 反读一次，确认列与注释都在。
4. `extract(task_id, data_uid, template_name, template_description)` 出模板版本，记下 `template_id` 与 `version`。

## 应用

1. **身份**：`business_ui_manage(action="create", task_id, name, scenario_pack_id=<场景包家族 id>, operation_id=<稳定键>)` 得到 `business_ui_id`；本地 `npm run scaffold:bind -- --business-ui-id <id>`；有模板就 `business_ui_manage(action="update", business_ui_id, dataset_template_id, dataset_template_version, task_id)`（版本钉整数）；`dataset_template_workspace(action="bind", task_id, data_uid, business_ui_id)` 把开发工作集绑到应用。
2. **数据页一条命令**：把 `inspect` 返回的 `columns` 原样存成 `<表名>.json`（形如 `{"table","label","columns":[…]}`），执行
   `npm run gen:pages -- --table <表名> --label <中文名> --spec <表名>.json`
   它生成列表 / 详情 / 新建 / 编辑页、五份 OpenAPI、后端 CRUD 与测试，并接好路由、导航和挂载；再跑一次不会覆盖。
3. **业务页用页面块**：先读 `frontend/registry.json`。三必备页面、入口表单、项目层、表单应答、交付审阅已经在 `App.tsx` 里，路线从 `schema/packs` 自动推导（场景包契约要写进 `frontend/schema/packs/<pack>/`，见 `frontend/schema/README.md`）。首页看板写在 `pages/HomePage` 的 `HomeBlock` children 里，用 `StatRow / TrendLine / DataTable`。要定制的块复制到 `pages/` 改，不改 `ui/`、`blocks/` 源码。
4. **后端接口**：生成的 CRUD 够用就不写；要统计或生产回流时在 `backend/src/common` 上包一层（`createCrudService` 的 `applyGeneratedResult` 写 agent 列），先写 `frontend/schema/api/<operationId>.yaml` 再实现。
5. **本地跑**：`npm run check`（前端契约门禁）、`npm run verify`（8 步）。`npm run dev` 起本地链路在工作台预览。

## 不要做的

- 不写占位页、不留 demo 路由（交付前 `npm run check:release` 会拦）。
- 不用 antd 重画已有的块；不引新图表库。
- 不手写 OpenAPI 与后端 CRUD（生成器出的可改）。
